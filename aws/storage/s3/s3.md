S3 Overview
Welcome to this section on Amazon S3. This section is very important because Amazon S3 is one of the main building blocks of AWS. It is advertised as infinitely scaling storage. In fact, a lot of the web relies on Amazon S3. Many websites use Amazon S3 as a backbone, and many AWS services also use Amazon S3 for integrations.

In this section, we will take a step-by-step approach to Amazon S3 to learn its main features. There are many use cases for Amazon S3 because at its core, it is storage. Imagine S3 is used for backup and storage. It could be for your files, your disks, and so on. It is also used for disaster recovery purposes. For example, you can move your data to another region so that if a region goes down, your data is backed up somewhere else.

Amazon S3 is used for archival purposes. You can archive files in Amazon S3 and retrieve them later at a much lower cost. It is also used for hybrid cloud storage. If you have storage on premises but want to expand into the cloud, you can use Amazon S3. Other uses include hosting applications, hosting media such as video files and images, creating data lakes to store large amounts of data for big data analytics, delivering software updates, and hosting static websites.

Two notable use cases are Nasdaq, which stores seven years of data in the S3 Glacier service, Amazon S3's archival service, and Sysco, which runs analytics on its data to gain business insights from Amazon S3.

Amazon S3 stores files in buckets. Buckets can be seen as top-level directories. The files in these S3 buckets are called objects. Buckets are created in your AWS account and must have a globally unique name. This means the bucket name must be unique across all regions and all AWS accounts worldwide. This is the only entity in AWS that must be globally unique. Buckets are defined at the region level. Although S3 appears to be a global service, buckets are actually created in a specific AWS region. This is a common mistake for beginners.

There is a naming convention for S3 buckets. While you do not need to memorize it, it is good to know. Bucket names must have no uppercase letters and no underscores. They must be between three and 63 characters long. They must not be formatted as an IP address. Bucket names must start with a lowercase letter or number. You can use letters, numbers, and hyphens as prefixes.

Now, let's talk about objects. Objects are files and they have what is called a key. An Amazon S3 object key is the full path of your file. For example, if you look at a bucket, the top-level directory is the bucket itself. The key of a file named "myfile.txt" is simply "myfile.txt". If you want to nest it in folders, the key becomes the full path, such as "myfolder1/anotherfolder/myfile.txt".

Therefore, the key is composed of a prefix and an object name. For example, the prefix could be "myfolder1/anotherfolder" and the object name could be "myfile.txt". Amazon S3 does not have a concept of directories per se, although the console UI makes it appear that way and allows you to create directories. In reality, everything in Amazon S3 is a key, which is essentially a very long name containing slashes. Keys consist of a prefix and an object name.

What are objects? Their values are the content of the body. You can upload any file you want into Amazon S3. The maximum object size is five terabytes, which is 5,000 gigabytes. If you upload a file larger than five gigabytes, you must use multipart upload to upload the file in several parts. For example, if you have a five terabyte file, you must upload at least 1,000 parts of five gigabytes each.

Objects can also have metadata, which is a list of key-value pairs. Metadata can be set by the system or by the user to indicate some attributes about the file. Objects can have tags, which are Unicode key-value pairs up to 10 in number. Tags are useful for security and lifecycle management. Additionally, objects can have a version ID if versioning is enabled.

This concludes the introduction to Amazon S3. To explore further, let's proceed to the AWS console to get started.

Key Takeaways
Amazon S3 is a highly scalable storage service used widely across the web and AWS ecosystem.
S3 stores data as objects within buckets, which are region-specific and require globally unique names.
Objects in S3 have keys representing their full path, combining prefixes and object names, though S3 does not have true directories.
Objects can be up to five terabytes in size and support multipart uploads for large files, along with metadata, tags, and versioning.
