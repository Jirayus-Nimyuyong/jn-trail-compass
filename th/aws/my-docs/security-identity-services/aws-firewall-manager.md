# AWS Firewall Manager Cheat Sheet

**AWS Firewall Manager** เป็นบริการจัดการความปลอดภัยที่ช่วยให้คุณสามารถกำหนดค่าและจัดการกฎไฟร์วอลล์จากส่วนกลาง ครอบคลุมหลายบัญชี AWS และแอปพลิเคชันต่างๆ ภายใน AWS Organizations

* **ความง่าย:** คุณตั้งค่ากฎไฟร์วอลล์เพียงครั้งเดียว และบริการจะนำไปใช้กับบัญชีและทรัพยากรต่างๆ ของคุณโดยอัตโนมัติ (รวมถึงทรัพยากรที่สร้างขึ้นใหม่ในอนาคต)
* **ขอบเขต:** ครอบคลุมมากกว่าแค่ WAF โดยสามารถจัดการ VPC Security Groups, Network ACLs, AWS Network Firewall, DNS Firewall และ Shield Advanced ได้ด้วย

---

## คุณสมบัติเด่น (Key Features)

### 1. การจัดการจากส่วนกลาง (Centralized Management)
* **เชื่อมต่อกับ AWS Organizations:** ดึงข้อมูลบัญชีและทรัพยากรใหม่ๆ มาใช้โดยอัตโนมัติ เพื่อใช้พอร์ตความปลอดภัยทันทีที่สร้างทรัพยากร
* **กลุ่มทรัพยากรหลายบัญชี:** จัดกลุ่มทรัพยากรตามบัญชี, ประเภททรัพยากร หรือแท็ก (Tag) เพื่อใช้นโยบายที่ละเอียด (เช่น "ใช้กฎ WAF นี้กับ ALB ทั้งหมดที่มีแท็ก Stage:Prod")
* **การป้องกันตามประเภททรัพยากรและแท็ก:** นโยบายจะครอบคลุมทรัพยากรประเภทนั้นๆ ทั้งหมด หรือทรัพยากรใหม่ที่มีแท็กระบุไว้โดยอัตโนมัติ

### 2. ประเภทนโยบายที่รองรับ (Supported Policy Types)
* **AWS WAF:** ติดตั้งกฎ WAF (Web ACLs) ไปยัง ALB, API Gateway และ CloudFront โดยรองรับการเพิ่มกฎส่วนกลางเข้าไปใน Web ACL เดิมที่มีอยู่ได้โดยไม่ทับกฎเดิมของทีมแอปพลิเคชัน
* **AWS Shield Advanced:** เปิดใช้งานการป้องกัน DDoS บน ELB, Elastic IPs และ CloudFront อัตโนมัติสำหรับทุกบัญชีสมาชิกในองค์กร
* **Amazon VPC Security Groups:** ตรวจสอบและแก้ไขกฎที่อนุญาตมากเกินไป (เช่น เปิดพอร์ต 22 ให้ทุกคน) หรือบังคับใช้ Security Group หลักกับทุกอินสแตนซ์
* **Amazon VPC Network ACLs:** จัดการ Network ACL ระดับ Subnet จากส่วนกลาง
* **AWS Network Firewall:** ติดตั้งเอนด์พอยต์และกลุ่มกฎไฟร์วอลล์ใน VPC ทั่วทั้งองค์กรเพื่อกรองทราฟฟิก Layer 3-7
* **Amazon Route 53 Resolver DNS Firewall:** ติดตั้งกฎกรอง DNS เพื่อบล็อกการสืบค้นไปยังโดเมนอันตราย
* **ไฟร์วอลล์จากบุคคลที่สาม:** จัดการไฟร์วอลล์จากพาร์ทเนอร์ใน Marketplace เช่น Palo Alto Networks และ Fortinet

### 3. การบังคับใช้ตามลำดับชั้น (Hierarchical Enforcement)
* **มอบอำนาจและบังคับใช้:** คุณสามารถบังคับใช้กฎความปลอดภัย "ที่จำเป็น" จากส่วนกลาง (เช่น "บล็อกทราฟฟิกจากประเทศที่ถูกคว่ำบาตร") ในขณะที่อนุญาตให้ทีมแอปพลิเคชันในแต่ละบัญชีเพิ่มกฎเฉพาะของตนเองได้

### 4. การปฏิบัติตามข้อกำหนดและรายงาน (Compliance & Reporting)
* **แดชบอร์ดความสอดคล้อง:** แสดงสถานะว่าบัญชีหรือทรัพยากรใดปฏิบัติตาม (Compliant) หรือไม่ปฏิบัติตามนโยบายของคุณ
* **การแจ้งเตือน SNS:** ส่งการแจ้งเตือนเมื่อพบทรัพยากรที่ไม่เป็นไปตามนโยบาย

## การทำงาน (How It Works)
* **เงื่อนไข:** ต้องใช้งาน **AWS Config** และ **AWS Organizations** และต้องระบุบัญชี **Delegated Administrator** เพื่อจัดการนโยบายความปลอดภัย
* **การบังคับใช้:** Firewall Manager สามารถแก้ไขปัญหาได้ 2 แบบ:
    * **Auto Remediate:** แก้ไขโดยอัตโนมัติ (เช่น ใส่กฎที่หายไปกลับเข้าไปใหม่)
    * **Manual:** เพียงแค่แจ้งเตือนคุณเมื่อพบสิ่งที่ไม่เป็นไปตามนโยบาย

---

## กรณีการใช้งานทั่วไป (Common Use Cases)
* **Day 1 Protection:** มั่นใจได้ว่าทุก VPC ใหม่ที่สร้างขึ้นในองค์กรจะได้รับ Network Firewall และกฎกรอง DNS โดยอัตโนมัติ
* **DDoS Standardization:** ลงทะเบียน Elastic IP สำหรับ Production ทั้งหมดเข้าสู่การป้องกันของ Shield Advanced โดยอัตโนมัติ
* **Audit Compliance:** สแกน Security Groups อย่างต่อเนื่องเพื่อให้แน่ใจว่าไม่มีใครเผลอเปิดพอร์ต SSH (22) ออกสู่อินเทอร์เน็ต
