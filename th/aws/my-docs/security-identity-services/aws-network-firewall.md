# AWS Network Firewall Cheat Sheet

**AWS Network Firewall** เป็นบริการไฟร์วอลล์เครือข่ายแบบ Managed ที่รองรับการตรวจสอบสถานะ (Stateful) และเป็นบริการตรวจจับและป้องกันการบุกรุก (IDS/IPS) สำหรับ Amazon VPC ของคุณ ช่วยให้คุณสามารถใช้การป้องกันเครือข่ายที่ละเอียดและปรับขนาดได้โดยอัตโนมัติตามปริมาณทราฟฟิก

* **การป้องกัน Layer 3-7:** กรองทราฟฟิกได้ทั้งในระดับเครือข่าย (IP/Port) และระดับแอปพลิเคชัน (Domain/HTTP Host)
* **โครงสร้างพื้นฐานแบบ Managed:** ปรับขนาดความจุไฟร์วอลล์อัตโนมัติตามปริมาณงาน พร้อม SLA 99.99%
* **Suricata Engine:** ใช้เอนจินโอเพนซอร์ส Suricata ทำให้คุณสามารถนำเข้าชุดกฎ (Rulesets) และลายเซ็นชุมชนที่มีอยู่แล้วมาใช้งานได้
* **การจัดการแบบศูนย์กลาง:** ทำงานร่วมกับ AWS Firewall Manager เพื่อบังคับใช้นโยบายในหลายบัญชี AWS และหลาย VPC ภายในองค์กร

---

## คุณสมบัติเด่น (Features)
* **การควบคุมและการตรวจสอบ:** ทำงานร่วมกับ CloudTrail และจัดการสิทธิ์ผ่าน KMS รวมถึงรองรับ ABAC (การควบคุมการเข้าถึงตามแอตทริบิวต์)
* **การจัดการคีย์:** หมุนเวียนคีย์ KMS อัตโนมัติทุกปี หรือหมุนเวียนตามความต้องการ (On-demand)
* **ประเภทคีย์:** รองรับทั้งคีย์สมมาตร (AES 256-bit), คีย์อสมมาตร, คีย์ ECC และ HMAC รวมถึงอัลกอริทึม Post-Quantum สำหรับ TLS
* **การรองรับขั้นสูง:** รองรับเอนด์พอยต์แบบ Dual-Stack (IPv4/IPv6), การเก็บคีย์ภายนอก (External Key Store) และการทดสอบสิทธิ์ผ่าน Dry-Run API
* **การประมวลผลข้อมูล:** รองรับการเข้ารหัสแบบซอง (Envelope Encryption) และการระบุบริบทการเข้ารหัส (Encryption Context)
* **ความพร้อมใช้งานสูง:** จัดเก็บคีย์หลายสำเนาเพื่อความทนทานระดับ 99.999999999%
* **ความเป็นส่วนตัว:** เชื่อมต่อผ่าน VPC Private Endpoints โดยทราฟฟิกจะอยู่ภายในเครือข่าย AWS เท่านั้น

## แนวคิดหลัก (Concepts)
* **Firewall:** ตรรกะการกรองทราฟฟิกสำหรับ Subnet ใน VPC โดยการเปลี่ยนกฎ Stateful จะมีผลกับทราฟฟิกใหม่เท่านั้น ส่วนกฎ Stateless จะมีผลกับทุกแพ็กเก็ต
* **Firewall Policies:** กำหนดกฎและการตั้งค่าที่ไฟร์วอลล์จะใช้กรองทราฟฟิกขาเข้าและขาออก สามารถใช้ร่วมกับไฟร์วอลล์หลายตัวได้
* **Rule Groups:** ชุดของกฎที่ใช้ตรวจสอบทราฟฟิกและกำหนดการดำเนินการเมื่อตรวจพบข้อมูลที่ตรงกัน แบ่งเป็นประเภท Stateless (ตรวจทีละแพ็กเก็ตไม่สนบริบท) และ Stateful (ตรวจโดยพิจารณาบริบทของการไหลของข้อมูล)
* **Firewall Subnet:** Subnet ที่กำหนดไว้เฉพาะสำหรับวางเอนด์พอยต์ของไฟร์วอลล์

---

## การตรวจสอบและติดตาม (Monitoring)
* **เครื่องมือ:** ทำงานร่วมกับ CloudWatch, CloudWatch Logs, CloudTrail, AWS Config และ S3
* **ตรรกะการบันทึก Log (หัวข้อสำคัญ):**
    * **ข้อจำกัด:** การบันทึก Log จะทำได้เฉพาะทราฟฟิกที่ส่งไปยัง **Stateful Engine** เท่านั้น (ทราฟฟิกที่จัดการโดย Stateless Engine เพียงอย่างเดียวจะไม่ถูกบันทึกใน Flow/Alert logs)
    * **ประเภท Log:**
        * **Flow Logs:** บันทึกการไหลของทราฟฟิกมาตรฐาน (5-tuple)
        * **Alert Logs:** รายงานทราฟฟิกที่ตรงกับกฎ Stateful (เช่น ตรวจพบ IPS Signature)
    * **ปลายทาง:** S3, CloudWatch Logs, Amazon Data Firehose

## กรณีการใช้งาน (Use Cases)
* **Egress Filtering:** ป้องกันเซิร์ฟเวอร์ใน Private Subnet ไม่ให้สื่อสารกับ Command & Control (C2) ของบอตเน็ต
* **Compliance:** ตอบโจทย์ข้อกำหนด PCI-DSS สำหรับระบบตรวจจับการบุกรุก (IPS) ภายใน VPC
* **VPC-to-VPC Inspection:** วางไฟร์วอลล์ใน "Transit VPC" เพื่อตรวจสอบทราฟฟิกที่วิ่งระหว่างสภาพแวดล้อมภายในที่ต่างกัน (เช่น Prod คุยกับ Dev)

---

## ข้อจำกัด (Limits & Constraints)
* **ทรูพุต (Throughput):** ปรับขนาดอัตโนมัติสูงสุด **100 Gbps** ต่อหนึ่ง Availability Zone
* **ทราฟฟิกที่เข้ารหัส:** หากไม่ได้ตั้งค่า TLS Inspection ไฟร์วอลล์จะไม่สามารถมองเห็นเนื้อหาภายในแพ็กเก็ต HTTPS ได้ (จะเห็นเพียง SNI/Domain)
* **ตารางเส้นทาง (Route Tables):** คุณต้องจัดการ Route Tables ด้วยตนเองเพื่อบังคับให้ทราฟฟิกวิ่งไปที่เอนด์พอยต์ของไฟร์วอลล์ (ไม่ได้ทำงานแบบโปร่งใสเหมือน Security Group)

## ค่าบริการ (Pricing)
* **ค่าธรรมเนียมรายชั่วโมง:** คิดตามเอนด์พอยต์ต่อชั่วโมง (ประมาณ $0.395/ชม.)
* **ค่าธรรมเนียมทราฟฟิก:** คิดตามปริมาณข้อมูลที่ประมวลผล (ประมาณ $0.065/GB)
* **เคล็ดลับระดับโปร (NAT Gateway Credit):** หากคุณติดตั้ง NAT Gateway และ Network Firewall ใน Availability Zone เดียวกัน AWS จะ **ยกเว้นค่าบริการรายชั่วโมงของ NAT Gateway** ให้ คุณจะจ่ายเพียงค่ารายชั่วโมงของไฟร์วอลล์ + ค่าข้อมูล ซึ่งทำให้ NAT Gateway แทบจะ "ฟรี" ในส่วนของค่ารายชั่วโมง
