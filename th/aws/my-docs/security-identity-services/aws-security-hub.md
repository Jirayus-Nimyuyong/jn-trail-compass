# AWS Security Hub Cheat Sheet

**AWS Security Hub** ให้ภาพรวมที่ครอบคลุมเกี่ยวกับสถานะความปลอดภัยข้ามบัญชี AWS ต่างๆ โดยการรวบรวม จัดระเบียบ และจัดลำดับความสำคัญของข้อมูลความปลอดภัย (Findings) จากบริการของ AWS, เครื่องมือจากพาร์ทเนอร์ และการตรวจสอบการปฏิบัติตามข้อกำหนดแบบอัตโนมัติ ช่วยในการประเมินการปฏิบัติตามมาตรฐานอุตสาหกรรมและแนวทางปฏิบัติที่ดีที่สุด

### คุณสมบัติเด่น (Features)
* **การรวบรวมข้อมูลความปลอดภัยจากส่วนกลาง:** รวบรวมการแจ้งเตือนความปลอดภัยจากบริการต่างๆ เช่น Amazon GuardDuty, Inspector, Macie, IAM Access Analyzer, Firewall Manager และ Audit Manager
* **รองรับหลายบัญชีผ่าน AWS Organizations:** จัดการสถานะความปลอดภัยในบัญชีสมาชิกปัจจุบันและที่จะเกิดขึ้นในอนาคตทั้งหมดได้จากส่วนกลาง
* **การตรวจสอบการปฏิบัติตามข้อกำหนดอัตโนมัติ:** รันการตรวจสอบความถูกต้องและการตั้งค่าอย่างต่อเนื่องตามมาตรฐาน เช่น CIS AWS Foundations Benchmark และกรอบการทำงานอื่นๆ (ต้องเปิดใช้งาน AWS Config)
* **แดชบอร์ดสรุปข้อมูล:** รวมข้อมูลความปลอดภัยจากทุกบัญชีไว้ในแดชบอร์ดเดียวเพื่อแสดงสถานะความปลอดภัยโดยรวม
* **การส่งต่อเหตุการณ์และระบบอัตโนมัติ:** ส่งต่อข้อมูลความปลอดภัยไปยังระบบออกตั๋ว (Ticketing), แชท, อีเมล หรือระบบแก้ไขอัตโนมัติผ่าน Amazon CloudWatch Events
* **การจัดเก็บข้อมูล:** ข้อมูลความปลอดภัยจะถูกเก็บไว้ใน Security Hub เป็นเวลาอย่างน้อย **30 วัน**
* **พฤติกรรมระดับภูมิภาค:** Security Hub จะรับและประมวลผลข้อมูลเฉพาะในภูมิภาค (Region) ที่เปิดใช้งานเท่านั้น

---

### แนวคิดหลัก (Core Concepts)
* **Finding (ข้อมูลความปลอดภัย):** การตรวจพบปัญหาด้านความปลอดภัยหรือการไม่ปฏิบัติตามข้อกำหนด
* **Insight (ข้อมูลเชิงลึก):** มุมมองที่จัดกลุ่มข้อมูลความปลอดภัยที่เกี่ยวข้องกันตามตัวกรองและการรวมกลุ่ม
* **Control (การควบคุม):** มาตรการป้องกันที่เป็นตัวแทนของข้อกำหนดด้านความปลอดภัย
* **Compliance Standard (มาตรฐานการปฏิบัติตามข้อกำหนด):** ชุดของการควบคุมที่ถูกจับคู่กับกรอบการทำงานหรือเกณฑ์มาตรฐาน (Benchmarks)
* **Custom Action (การดำเนินการแบบกำหนดเอง):** กลไกสำหรับส่งข้อมูลความปลอดภัยที่เลือกไปยัง CloudWatch Events เพื่อสร้างเวิร์กโฟลว์อัตโนมัติ

---

### โครงสร้างการตรวจสอบการปฏิบัติตามข้อกำหนด
* **Standard (มาตรฐาน)** ประกอบด้วยการควบคุม (Controls) หลายรายการ
* **Control (การควบคุม)** หนึ่งรายการ อาจใช้กับทรัพยากร (Resources) ได้หลายตัว
* **Compliance Check (การตรวจสอบ)** คือการประเมินการควบคุมหนึ่งรายการเทียบกับทรัพยากรตัวเดียว

---

### ความปลอดภัย (Security)
* **ข้อมูลส่วนตัว:** Security Hub ประมวลผลเฉพาะ Metadata และข้อมูลที่เกี่ยวข้องกับความปลอดภัยเท่านั้น ไม่มีการเก็บความลับ (Secrets) ของลูกค้า
* **การควบคุมการเข้าถึง:** ควบคุมผ่านนโยบาย IAM และรองรับการใช้แท็ก (Tag-based access control)
* **เครือข่าย:** สามารถใช้ VPC Endpoints เพื่อให้ทราฟฟิกของ API อยู่ภายในเครือข่าย AWS เท่านั้น
* **บทบาทบริการ:** ใช้ Service-Linked Role เพื่อให้ Security Hub สามารถรวบรวมข้อมูลและตั้งค่าองค์ประกอบ AWS Config ที่จำเป็นสำหรับการตรวจสอบได้

---

### กรณีการใช้งาน (Use Cases)
* รวมศูนย์การแจ้งเตือนด้านความปลอดภัยจากทุกบริการของ AWS ไว้ในที่เดียว
* ตรวจสอบการปฏิบัติตามมาตรฐาน CIS Benchmarks หรือมาตรฐานอื่นๆ ที่รองรับ
* จัดการสถานะความปลอดภัยสำหรับหลายบัญชีในองค์กร
* ระบุการตั้งค่าที่ผิดพลาด (Misconfigurations) หรือสถานะทรัพยากรที่ไม่ปลอดภัย
* สร้างเวิร์กโฟลว์การแก้ไขปัญหาแบบอัตโนมัติผ่าน CloudWatch Events

---

### ค่าบริการ (Pricing)
การคิดค่าบริการขึ้นอยู่กับองค์ประกอบ 2 ส่วน:
1. **จำนวนการตรวจสอบการปฏิบัติตามข้อกำหนด (Compliance checks)** ที่ดำเนินการ
2. **จำนวนเหตุการณ์การนำเข้าข้อมูลความปลอดภัย (Finding ingestion events)**
* บิลจะเรียกเก็บรายเดือนแยกตามบัญชีและตามภูมิภาค (Region)
