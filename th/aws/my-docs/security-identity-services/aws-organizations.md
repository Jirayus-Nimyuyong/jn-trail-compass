# AWS Organizations Cheat Sheet

**AWS Organizations** เป็นบริการด้านการจัดการที่ช่วยให้สามารถควบคุมดูแลบัญชี AWS หลายบัญชีได้จากส่วนกลาง รองรับการควบคุมด้วย **นโยบาย (Policy)**, **การรวมใบแจ้งหนี้ (Consolidated Billing)**, **การจัดการบัญชีแบบลำดับขั้น**, และ **การกำกับดูแลทั่วทั้งองค์กร**

### คำศัพท์สำคัญ (Key Terms)
* **Organization:** กลุ่มของบัญชี AWS ที่ถูกจัดการร่วมกันจากส่วนกลาง
* **Management Account:** บัญชีหลักที่สร้างและบริหารจัดการองค์กร ทำหน้าที่เป็นบัญชีผู้ชำระเงิน (Payer account)
* **Member Account:** บัญชีใดๆ (นอกเหนือจากบัญชีหลัก) ที่เป็นส่วนหนึ่งขององค์กร
* **Administrative Root:** คอนเทนเนอร์ระดับสูงสุดในลำดับขั้นขององค์กร ซึ่ง OU และบัญชีทั้งหมดจะอยู่ภายใต้รูทนี้
* **Organizational Unit (OU):** การจัดกลุ่มบัญชีในเชิงตรรกะ สามารถมี OU ย่อยซ้อนกันได้
* **Policy:** เอกสารรูปแบบ JSON ที่กำหนดการควบคุมเพื่อนำไปใช้กับบัญชีหรือ OU
* **Service Control Policy (SCP):** ตัวกรองสิทธิ์การใช้งานทั่วทั้งองค์กร เพื่อกำหนดว่าบริการหรือการกระทำใดที่อนุญาตให้ใช้ได้

---

### คุณสมบัติ (Features)
#### 1. การจัดการบัญชีจากส่วนกลาง
* สร้างบัญชี AWS ใหม่หรือเชิญบัญชีที่มีอยู่แล้วเข้ามาในองค์กร
* จัดระเบียบบัญชีเป็น **Organizational Units (OUs)** ตามลำดับขั้น (ลึกได้สูงสุด 5 ระดับ)
* การย้ายบัญชี: ย้ายบัญชีจากองค์กรหนึ่งไปยังอีกองค์กรหนึ่งได้
* รองรับองค์กรขนาดใหญ่: จัดการบัญชีสมาชิกได้สูงสุดถึง 10,000 บัญชี (ต้องขออนุมัติโควตา)

#### 2. การรวมใบแจ้งหนี้ (Consolidated Billing)
* ใช้วิธีการชำระเงินเพียงวิธีเดียวสำหรับทุกบัญชี
* ดูค่าใช้จ่ายทั้งหมดรวมกันในที่เดียว และเข้าถึงส่วนลดจากการใช้งานรวมในปริมาณมาก

#### 3. การกำกับดูแลด้วยนโยบาย (Policy-Based Governance)
* ใช้ **Service Control Policies (SCPs)** กับองค์กร, OU หรือบัญชีรายตัว
* **Resource Control Policies (RCPs):** ควบคุมสิทธิ์สูงสุดที่สามารถใช้งานได้สำหรับทรัพยากรต่างๆ
* นโยบายจะถูกถ่ายทอดตามลำดับขั้น (Inheritance)

#### 4. การเพิ่มประสิทธิภาพความปลอดภัย
* **Security Hub policies:** จัดการการตั้งค่า Security Hub จากส่วนกลางข้ามทุกบัญชี
* **Centralized root access:** จัดการข้อมูลประจำตัว (Credentials) ของผู้ใช้ Root ในบัญชีสมาชิกเพื่อป้องกันการเข้าถึงที่ไม่ได้รับอนุญาต
* **Permissions boundaries:** มั่นใจได้ว่านโยบาย IAM จะไม่สามารถเกินขอบเขตที่ SCP กำหนดไว้ได้
* **ABAC:** รองรับการกำหนดสิทธิ์ตามแท็ก (Tag-based) ข้ามบัญชี, OU และผู้ใช้

#### 5. การตรวจสอบและการแจ้งเตือน
* **Account state monitoring:** ติดตามสถานะบัญชี (ใช้งานอยู่, ถูกระงับ, หรือปิดตัวลง) ผ่าน Console, CLI หรือ SDK
* **AWS User Notifications:** ตั้งค่าและดูการแจ้งเตือนจากส่วนกลางข้ามทุกบัญชี

---

### ชุดคุณสมบัติ (Feature Sets)
1.  **Consolidated Billing:** รองรับการจัดการการเรียกเก็บเงินขั้นพื้นฐานสำหรับทุกองค์กร
2.  **All Features Enabled:** รวมการรวมใบแจ้งหนี้และ **คุณสมบัติขั้นสูง** เช่น SCPs (แนะนำให้ใช้โหมดนี้)

---

### กรณีการใช้งาน (Use Cases)
* **การแยกสภาพแวดล้อม:** แยกบัญชี Dev, Test, Prod เพื่อความปลอดภัยและจำกัดวงความเสียหาย (Blast Radius)
* **การกำกับดูแลจากส่วนกลาง:** บังคับใช้นโยบายที่จำเป็น เช่น จำกัดภูมิภาค (Regions) ที่ไม่ได้รับอนุญาต หรือป้องกันไม่ให้ปิดการใช้งาน CloudTrail
* **การควบคุมทางการเงิน:** ติดตามต้นทุนจากส่วนกลาง จัดสรรงบประมาณตาม OU หรือทีม และลดค่าใช้จ่ายผ่านการใช้งานรวม (Volume discounts)

---

### ความปลอดภัย (Security)
* **SCPs:** ทำหน้าที่เป็น "ขอบเขตภายนอก" (Outer boundary) เพื่อจำกัดสิทธิ์ IAM แม้ผู้ใช้จะมีสิทธิ์ Administrator ในบัญชีสมาชิก แต่หาก SCP ไม่อนุญาต ก็จะไม่สามารถใช้งานบริการนั้นได้
* **Management Account:** มีอำนาจสูงสุดในการบริหารจัดการและชำระค่าใช้จ่าย
* **Member Account:** ถูกควบคุมผ่าน SCPs และสามารถสังกัดได้เพียง **หนึ่งองค์กร** ในเวลาเดียวกันเท่านั้น

---

### ค่าบริการ (Pricing)
**บริการ AWS Organizations นั้นฟรี** คุณจะเสียเฉพาะค่าบริการจากการใช้งานทรัพยากร AWS ในบัญชีสมาชิกตามปกติเท่านั้น
