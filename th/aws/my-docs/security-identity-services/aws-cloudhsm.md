# AWS CloudHSM Cheat Sheet

**AWS CloudHSM** เป็นบริการ Hardware Security Module (HSM) บนคลาวด์ที่ช่วยให้คุณสร้างและใช้งานคีย์เข้ารหัสของคุณเองบน AWS Cloud ได้อย่างง่ายดาย ช่วยให้คุณจัดสรรและจัดการอินสแตนซ์ HSM แบบใช้งานคนเดียว (Single-tenant) ที่ผ่านการรับรองมาตรฐาน **FIPS 140-2 Level 3** ภายใน VPC ของคุณเอง

* **การเข้าถึงแบบ Single-Tenant:** คุณมีสิทธิ์เข้าถึงฮาร์ดแวร์ HSM โดยเฉพาะ ไม่มีการแชร์ร่วมกับลูกค้ารายอื่น
* **การควบคุม:** คุณเป็นผู้จัดการ HSM, ผู้ใช้งาน และคีย์เอง ส่วน AWS จะจัดการเรื่องการจัดสรรฮาร์ดแวร์, การสำรองข้อมูล และการเชื่อมต่อเครือข่าย
* **การปฏิบัติตามมาตรฐาน FIPS:** ได้รับการรับรอง FIPS 140-2 Level 3 (ในขณะที่ AWS KMS โดยทั่วไปจะเป็น Level 2)
* **รองรับ API มาตรฐานอุตสาหกรรม:** รองรับ PKCS #11, Java Cryptography Extensions (JCE) และ Microsoft CNG/KSP

---

### คุณสมบัติและการอัปเดต (Features/Updates)
* **ประเภท HSM และโหมด Cluster ใหม่:** รองรับ `hsm2m.medium` ทั้งใน Cluster แบบ FIPS และ non-FIPS
* **การสำรองข้อมูลและกู้คืน:** สำรองข้อมูลอัตโนมัติแบบเข้ารหัส เก็บไว้ได้ 90 วัน สามารถกู้คืนหรือคัดลอก (Clone) Cluster ไปยังภูมิภาคอื่นได้
* **การจัดการผู้ใช้และคีย์:** รองรับ Quorum Authentication (M of N), คีย์แบบเซสชัน (ชั่วคราว) และคีย์แบบโทเค็น (คงทนและซิงโครไนซ์อัตโนมัติ)
* **เครื่องมือ CLI ใหม่:** `cloudhsm-cli` (Client SDK 5) รองรับทั้งการจัดการผู้ใช้และคีย์ในตัวเดียว
* **การตรวจสอบ:** มาตรวัด CloudWatch (HsmUnhealthy, HsmTemperature) และการบันทึก Log API ผ่าน CloudTrail

---

### กรณีการใช้งาน (Use Cases)
* **ลดภาระการประมวลผล SSL/TLS:** ทำการยุติการเชื่อมต่อ SSL (SSL Termination) สำหรับเว็บเซิร์ฟเวอร์ (เช่น NGINX, Apache) อย่างปลอดภัยภายใน HSM
* **ผู้ออกใบรับรอง (CA):** ปกป้อง Private Keys ของผู้ออกใบรับรองในระบบโครงสร้างพื้นฐานกุญแจสาธารณะ (PKI)
* **TDE (Transparent Data Encryption):** จัดเก็บคีย์เข้ารหัสสำหรับ Oracle Database TDE หรือ SQL Server TDE
* **การจัดการสิทธิ์ดิจิทัล (DRM):** ปกป้องลิขสิทธิ์และคีย์ใบอนุญาตต่างๆ

### แนวคิดหลัก (Concepts)

#### Clusters
* คือกลุ่มของ HSM แต่ละเครื่องที่จะซิงโครไนซ์ข้อมูลกันโดยอัตโนมัติ
* **ความพร้อมใช้งานสูง (HA):** สร้าง Cluster ได้ตั้งแต่ 1 ถึง 28 เครื่อง เพื่อความพร้อมใช้งานสูงสุดควรวาง HSM ไว้ใน Availability Zones (AZ) ที่ต่างกัน
* **การโหลดบาลานซ์:** คำขอจะถูกกระจายไปยัง HSM ทุกเครื่องใน Cluster โดยอัตโนมัติ

#### ประเภทผู้ใช้งาน HSM (HSM Users)
CloudHSM มีระบบจัดการผู้ใช้ภายในของตัวเอง แยกจาก AWS IAM:
* **Precrypto Officer (PRECO):** ผู้ใช้ชั่วคราวบน HSM ที่เพิ่งติดตั้งใหม่ ใช้สำหรับสร้าง Crypto Officer คนแรกเท่านั้น
* **Crypto Officer (CO):** จัดการผู้ใช้ (สร้าง/ลบ) เปลี่ยนรหัสผ่านได้ แต่**ไม่สามารถ**ทำการเข้ารหัสหรือใช้งานคีย์ได้
* **Crypto User (CU):** ทำการเข้ารหัส (Encrypt, Decrypt, Sign) และจัดการคีย์ เป็นผู้ใช้ที่แอปพลิเคชันของคุณต้องใช้งาน
* **Appliance User (AU):** ผู้ใช้ระบบที่ AWS ใช้เพื่อการซิงโครไนซ์และคัดลอกข้อมูล ไม่สามารถล็อกอินได้

#### Quorum Authentication (M of N)
* ระบบที่ต้องมีผู้อนุมัติจำนวน M คน จากผู้ใช้ทั้งหมด N คน เพื่ออนุญาตการดำเนินการด้านการบริหารจัดการที่สำคัญ (เช่น การลบ Cluster)

#### ประเภทคีย์ (Keys)
* **Session Keys:** คีย์ชั่วคราวที่อยู่ในหน่วยความจำเฉพาะตอนแอปเชื่อมต่ออยู่ ทำงานเร็วแต่จะหายไปเมื่อตัดการเชื่อมต่อ
* **Token Keys:** คีย์ถาวรที่จัดเก็บในฮาร์ดแวร์ของ HSM และจะซิงโครไนซ์ไปยัง HSM ทุกเครื่องใน Cluster โดยอัตโนมัติ

---

### การตรวจสอบ (Monitoring)
* **AWS CloudTrail:** บันทึกการเรียก API (เช่น CreateCluster, DeleteHsm)
* **CloudWatch Logs:** บันทึก HSM Audit Logs (การล็อกอิน, เหตุการณ์เกี่ยวกับคีย์)
* **มาตรวัด CloudWatch ที่สำคัญ:**
    * `HsmUnhealthy` – อินสแตนซ์ HSM ล้มเหลว
    * `HsmTemperature` – อุณหภูมิของฮาร์ดแวร์
    * `HsmUsersAvailable` – ติดตามจำนวนสล็อตผู้ใช้ที่ว่างอยู่ (สูงสุด 1024)

---

### ค่าบริการ (Pricing)
* **ค่าธรรมเนียมรายชั่วโมง:** คิดตามจำนวน HSM ต่อชั่วโมง (หากต้องการ HA ต้องใช้ 2 เครื่อง ค่าใช้จ่ายจะเพิ่มเป็น 2 เท่า)
* **ไม่มีค่าใช้จ่ายล่วงหน้า:** จ่ายตามการใช้งานจริง (เศษของชั่วโมงคิดเป็น 1 ชั่วโมง)
* **การสำรองข้อมูล:** **ฟรี** (จัดเก็บใน S3 Bucket ที่ AWS เป็นเจ้าของ)
