# AWS Audit Manager Cheat Sheet

**AWS Audit Manager** เป็นบริการแบบ Managed ที่ช่วยคุณตรวจสอบการใช้งาน AWS อย่างต่อเนื่อง เพื่อลดความยุ่งยากในการจัดการความเสี่ยงและการปฏิบัติตามกฎระเบียบหรือมาตรฐานอุตสาหกรรม โดยจะรวบรวมหลักฐานโดยอัตโนมัติเพื่อพิสูจน์ว่าการควบคุม (นโยบาย, ขั้นตอน และกิจกรรม) ของคุณทำงานได้อย่างมีประสิทธิภาพ

### คุณสมบัติหลัก
* **การรวบรวมหลักฐานอัตโนมัติ:** เก็บข้อมูลจากบริการ AWS อย่างต่อเนื่อง (เช่น CloudTrail, Config และ Security Hub) เพื่อตรวจสอบความถูกต้อง
* **รายงานที่พร้อมรับการตรวจสอบ (Audit-Ready):** สร้าง "รายงานการประเมิน" (PDF/ZIP) ที่สรุปหลักฐานสำหรับผู้ตรวจสอบ
* **คลังกรอบการทำงาน (Framework Library):** มีกรอบมาตรฐานสำเร็จรูป (PCI DSS, HIPAA, SOC 2, NIST และ **แนวทางปฏิบัติที่ดีที่สุดสำหรับ Generative AI**) หรือสร้างขึ้นเองได้
* **ความถูกต้องของข้อมูล:** หลักฐานทั้งหมดถูกจัดเก็บในรูปแบบที่แก้ไขไม่ได้ (Immutable) และปลอดภัย (ใช้การแฮช/เข้ารหัส) เพื่อให้มั่นใจว่าไม่มีการปลอมแปลง

---

### คุณสมบัติเด่น (Features)
* **Evidence Finder:** เครื่องมือค้นหาเพื่อสืบค้นและกรองหลักฐานข้ามการประเมินต่างๆ ได้อย่างรวดเร็ว (รองรับการส่งออกเป็น CSV)
* **Delegation Workflow:** เจ้าของงานตรวจสอบสามารถมอบหมายชุดการควบคุมเฉพาะให้ผู้เชี่ยวชาญ (SMEs) ตรวจสอบและรับรองความถูกต้องได้
* **การเชื่อมต่อ GRC:** ส่งออกหลักฐานไปยังเครื่องมือ Governance, Risk, and Compliance (GRC) ภายนอก เช่น MetricStream ได้อัตโนมัติ
* **แหล่งข้อมูลอัตโนมัติ:** ดึงหลักฐานจาก CloudTrail (กิจกรรมผู้ใช้), AWS Config (การตั้งค่าทรัพยากร), Security Hub (ผลการตรวจความปลอดภัย) และ License Manager (การใช้งานไลเซนส์)
* **Common Controls (ใหม่):** ฟีเจอร์ "เขียนครั้งเดียว ใช้ได้หลายที่" ช่วยให้การควบคุมเดียวสามารถเก็บหลักฐานสำหรับหลายมาตรฐานพร้อมกัน (เช่น Identity Management สำหรับทั้ง HIPAA และ PCI) เพื่อลดความซ้ำซ้อน

---

### แนวคิดสำคัญ (Concepts)
1. **Framework (กรอบการทำงาน):** พิมพ์เขียวสำหรับการตรวจสอบที่รวมการควบคุมที่เกี่ยวข้องไว้ด้วยกัน (เช่น "PCI DSS v4.0 Framework")
2. **Control (การควบคุม):** กฎหรือข้อกำหนดเฉพาะ (เช่น "ต้องเปิดใช้งาน MFA สำหรับ Root") แบ่งเป็นแบบมาตรฐาน (AWS กำหนด) และแบบกำหนดเอง (คุณสร้างเอง)
3. **Assessment (การประเมิน):** อินสแตนซ์ที่ใช้งานจริงของกรอบการทำงานที่นำไปใช้กับขอบเขตเฉพาะ (เช่น "การตรวจสอบ PCI สำหรับบัญชี Production")
4. **Evidence (หลักฐาน):** ข้อมูลจริงที่รวบรวมได้ มีทั้งแบบ**อัตโนมัติ** (Snapshot ทรัพยากร, Log) และแบบ**จัดการเอง** (เอกสารที่อัปโหลด เช่น ผังองค์กร, ใบเซอร์การอบรม)

---

### การทำงาน: วงจรชีวิตของการประเมิน (The Assessment Lifecycle)
1. **เลือก Framework:** เลือกมาตรฐานสำเร็จรูปหรือสร้างขึ้นเอง
2. **กำหนดขอบเขต (Scope):** เลือกบัญชี AWS และบริการที่ต้องการตรวจสอบ
3. **เปิดใช้งานการประเมิน:** ระบบจะเริ่มรวบรวมหลักฐานโดยอัตโนมัติ (รายวัน/รายสัปดาห์)
4. **รีวิว:** เจ้าของงานหรือผู้รับมอบหมายตรวจสอบหลักฐานและระบุสถานะ "ปฏิบัติตาม" หรือ "ไม่ปฏิบัติตาม"
5. **สร้างรายงาน:** จัดทำรายงานฉบับสมบูรณ์สำหรับผู้ตรวจสอบภายนอก

---

### ความปลอดภัย (Security)
* ใช้ **IAM Service-Linked Roles** เพื่อเชื่อมต่อกับแหล่งข้อมูล
* ข้อมูลถูกเข้ารหัสโดยใช้คีย์ **AWS KMS**

---

### กรณีการใช้งาน (Use Cases)
* **การเตรียมการตรวจสอบ:** ลดเวลาการรวบรวมหลักฐานสำหรับ SOC 2 หรือ ISO 27001 จากระดับสัปดาห์เหลือเพียงไม่กี่วัน
* **การปฏิบัติตามข้อกำหนดอย่างต่อเนื่อง:** เฝ้าระวังไม่ให้สภาพแวดล้อมใช้งานจริงหลุดจากมาตรฐาน HIPAA หลังจากติดตั้งระบบ
* **การตรวจสอบผู้จำหน่าย (AI):** ใช้กรอบงาน Generative AI Best Practices เพื่อตรวจสอบเวิร์กโหลด AI ของตนเองก่อนเปิดให้ลูกค้าใช้งาน

---

### ค่าบริการ (Pricing)
AWS Audit Manager คิดค่าบริการตามการใช้งาน (Usage-based) ไม่ใช่ค่าธรรมเนียมรายเดือนคงที่
* **หน่วยวัด:** คิดเงินต่อ **การประเมินทรัพยากร (Resource Assessment)** * **คำจำกัดความ:** เกิดขึ้นทุกครั้งที่ Audit Manager เก็บหลักฐาน 1 ชิ้นสำหรับ 1 ทรัพยากร (เช่น ตรวจสอบ 1 S3 Bucket เทียบกับ 1 Control = 1 Resource Assessment)
* **ราคา:** ประมาณ **$1.25 ต่อ 1,000 การประเมินทรัพยากร**
* **Free Tier:** ลูกค้าใหม่ใช้ฟรี **35,000 การประเมินทรัพยากรต่อเดือน** นาน 2 เดือนแรก
* **เคล็ดลับสำหรับการสอบ:** หากเปิดใช้งานกรอบงานที่ซับซ้อน (เช่น NIST 800-53) ในบัญชีที่มีทรัพยากรนับพัน ค่าใช้จ่ายจะเพิ่มขึ้นอย่างรวดเร็ว เพราะทุกทรัพยากรจะถูกตรวจสอบกับทุกการควบคุมที่เกี่ยวข้องทุกวัน
