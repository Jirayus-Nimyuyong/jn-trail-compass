# Amazon Inspector Cheat Sheet

**Amazon Inspector** เป็นบริการจัดการช่องโหว่แบบอัตโนมัติ (Automated Vulnerability Management) ที่จะทำการสแกนเวิร์กโหลดบน AWS อย่างต่อเนื่อง เพื่อค้นหาช่องโหว่ของซอฟต์แวร์และการเปิดเผยพอร์ตเครือข่ายที่ไม่ได้ตั้งใจ

> **หมายเหตุเกี่ยวกับรุ่นเก่า:** บริการนี้มาแทนที่ "Amazon Inspector Classic" โดยรุ่นใหม่นี้จะทำงานแบบต่อเนื่อง อัตโนมัติ และเชื่อมต่อกับ AWS Organizations (รุ่น Classic ต้องตั้งเวลาสแกนเองและใช้ Agent เฉพาะ)

### ความสามารถหลัก (Key Capabilities)
* **การสแกนอย่างต่อเนื่อง:** ตรวจจับและสแกนทรัพยากรใหม่โดยอัตโนมัติ และจะสแกนซ้ำเมื่อมีการเปลี่ยนแปลง (เช่น ลงซอฟต์แวร์ใหม่, มีฐานข้อมูล CVE ใหม่ หรือเปลี่ยนโครงสร้างพื้นฐาน)
* **ครอบคลุมหลายทรัพยากร:** สแกน Amazon EC2, รูปภาพคอนเทนเนอร์ใน Amazon ECR, ฟังก์ชัน AWS Lambda และโค้ดของนักพัฒนา (CI/CD pipelines)
* **การจัดการแบบรวมศูนย์:** เชื่อมต่อกับ **AWS Organizations** ช่วยให้ผู้ดูแลระบบที่ได้รับมอบหมายสามารถจัดการผลการสแกนจากทุกบัญชีได้ในที่เดียว
* **โหมดการสแกน:** เลือกใช้ได้ทั้งแบบ **ใช้ Agent (SSM)** หรือ **ไม่ใช้ Agent (Agentless)** สำหรับอินสแตนซ์ EC2

---

### คุณสมบัติเด่น (Features)
* **SBOM Generator:** สร้างรายการส่วนประกอบซอฟต์แวร์ (Software Bill of Materials), ติดตามข้อมูลไลเซนส์ และสแกน Dockerfiles เพื่อหาการตั้งค่าที่ผิดพลาด
* **การรองรับทรัพยากรล่าสุด:**
    * **EC2:** รองรับ Fedora 42, Ubuntu 25.04 และ MacOS
    * **ECR:** รองรับ Alpine 3.22 และ BusyBox
    * **Lambda:** รองรับ Node.js 20.x, Python 3.13 และ AL2 runtime
* **การสแกนโค้ด:** สแกนทั้งโค้ดที่เขียนเองและไลบรารีภายนอก รวมถึงโครงสร้างพื้นฐานในรูปแบบโค้ด (IaC)
* **การเชื่อมต่อ CI/CD:** ทำงานร่วมกับ GitHub Actions, CodePipeline และ CodeCatalyst
* **Agentless EC2 Scanning:** สแกนอินสแตนซ์ผ่านการวิเคราะห์ EBS Snapshot โดยไม่ต้องติดตั้ง Agent
* **CIS Benchmark:** ทำการตรวจสอบความปลอดภัยตามมาตรฐาน Center for Internet Security (CIS) สำหรับระบบปฏิบัติการ

---

### ประเภทของเครื่องมือสแกน (Scanning Engines)

1. **EC2 Scanning:**
   * **Agent-Based (SSM):** ใช้ **AWS Systems Manager (SSM) Agent** ที่มีอยู่แล้วในเครื่องเพื่อตรวจสอบซอฟต์แวร์ (ไม่ต้องลง Agent ของ Inspector แยกต่างหาก)
   * **Agentless (Hybrid):** สแกนผ่านการทำ Snapshot ของ EBS Volume เหมาะสำหรับเครื่องที่ไม่ได้จัดการผ่าน SSM หรือเครื่องที่ลง Agent ไม่ได้

2. **ECR Scanning:**
   * **On-Push:** สแกนภาพคอนเทนเนอร์ทันทีเมื่อถูก Push ขึ้นไปที่ Registry
   * **Continuous:** สแกนซ้ำต่อเนื่องเมื่อมีการพบช่องโหว่ใหม่ (CVEs) ในฐานข้อมูลกลาง

3. **Lambda Scanning:**
   * **Standard Scanning:** สแกนพวก Dependencies (เช่น pip packages, npm modules) ในฟังก์ชันและ Layers
   * **Code Scanning:** สแกน **โค้ดที่เขียนเอง** เพื่อหาจุดบกพร่อง เช่น Injection flaws, ข้อมูลรั่วไหล หรือการเขียนรหัสผ่านทิ้งไว้ในโค้ด (Hardcoded secrets)

---

### รายงานผลการตรวจสอบ (Assessment Reports)
ผลการตรวจพบ (Findings) จะประกอบด้วย:
* บทสรุปสำหรับผู้บริหาร
* ทรัพยากรที่ได้รับผลกระทบ (EC2, Lambda, ECR ฯลฯ)
* รายละเอียดของช่องโหว่และรหัสอ้างอิง CVE
* **ขั้นตอนการแก้ไขที่แนะนำ**
* แพ็กเกจหรือส่วนประกอบของโค้ดที่มีปัญหา
