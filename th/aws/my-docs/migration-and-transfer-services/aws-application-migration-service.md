# AWS Application Migration Service (AWS MGN) Cheat Sheet

โซลูชันการย้ายระบบแบบ **Lift-and-shift** อัตโนมัติ ที่ช่วยให้การย้ายแอปพลิเคชันมายัง AWS ทำได้ง่ายขึ้น รวดเร็วขึ้น และมีค่าใช้จ่ายที่ถูกลง
* ระบบจะทำการแปลงเซิร์ฟเวอร์ต้นทางให้สามารถทำงานบน AWS ได้อย่างเป็นธรรมชาติ (Native)

---

## รูปแบบการทำงาน (How It Works)
1. ติดตั้ง **AWS Replication Agent** บนเซิร์ฟเวอร์ต้นทาง
2. หากคุณใช้ฟีเจอร์การคัดลอกข้อมูลแบบไม่ใช้เอเย่นต์ (Agentless) สำหรับ vCenter คุณต้องเพิ่มเซิร์ฟเวอร์ต้นทางโดยการติดตั้ง **AWS MGN vCenter Client**
3. คัดลอกข้อมูล (Replicate) เซิร์ฟเวอร์ต้นทางมายัง AWS
4. ทำการทดสอบการยอมรับ (Acceptance tests) บนเซิร์ฟเวอร์
5. ดำเนินการเปิดใช้งานอินสแตนซ์จริง (**Cutover instance**)

---

## แนวคิดหลัก (Concepts)

### การตั้งค่าการคัดลอกข้อมูล (Replication Settings)
* กำหนดวิธีการคัดลอกข้อมูลจากเซิร์ฟเวอร์ต้นทางมายัง AWS
* **Replication Settings Template:** ระบุวิธีการคัดลอกข้อมูลที่จะใช้กับเซิร์ฟเวอร์ใหม่ทุกเครื่อง
* เซิร์ฟเวอร์สำหรับคัดลอกข้อมูล (Replication servers) จะถูกเปิดและปิดการใช้งานโดยอัตโนมัติเมื่อจำเป็น
* **Launch Template:** ควบคุมวิธีที่ MGN จะเปิดใช้งานอินสแตนซ์ใน AWS

### การตั้งค่าหลังการเปิดใช้งาน (Post-launch Settings)
* ในการเปิดใช้งานฟังก์ชันหลังการเปิดเครื่อง คุณต้องอนุญาตให้ MGN ติดตั้ง **SSM Agent** บนเซิร์ฟเวอร์ของคุณ
* คุณสามารถกำหนดค่าใน **Post-launch settings template** ได้ดังนี้:
    * จัดการการติดตั้ง Target instance แบบอัตโนมัติ
    * เตรียมเซิร์ฟเวอร์ที่ย้ายมาสำหรับการกู้คืนภัยพิบัติ (Disaster Recovery)
    * แปลงระบบปฏิบัติการ (OS)
    * เปลี่ยนสิทธิการใช้งาน (License) และการสมัครสมาชิก (Subscription)

### เซิร์ฟเวอร์ต้นทาง (Source Servers)
* การติดตั้ง **AWS Replication Agent** ในแต่ละเครื่อง จะทำให้เซิร์ฟเวอร์ต้นทางถูกเพิ่มเข้าไปใน AWS MGN โดยอัตโนมัติ
* **Agentless snapshot replication:** ช่วยให้คุณคัดลอกข้อมูลเซิร์ฟเวอร์ต้นทางมายัง AWS ได้โดยไม่ต้องติดตั้ง Agent (ทำได้จากสภาพแวดล้อม vCenter)

### การตั้งค่าการเปิดใช้งาน (Launch Settings)
* **General launch settings:** ปรับแต่งการตั้งค่าเฉพาะของเซิร์ฟเวอร์
* **EC2 launch template:** ใช้เทมเพลตเพื่อเปิดใช้งานอินสแตนซ์สำหรับทดสอบ (Test) และใช้งานจริง (Cutover)
* คุณสามารถสั่ง Test หรือ Cutover ได้ทั้งแบบทีละเครื่อง หรือหลายเครื่องพร้อมกัน
* **Launch history:** ช่วยติดตามและจัดการการดำเนินงานทั้งหมดที่ผ่านมา

---

## การเครือข่าย (Networking)
* ข้อมูลที่คัดลอกจากต้นทางจะถูกเก็บไว้ใน **Staging area subnet**
* ข้อมูลใน Subnet นี้จะถูกส่งผ่าน **TCP พอร์ต 443** ไปยัง API Endpoint: `https://mgn.{region}.amazonaws.com/`
* ข้อมูลจากเซิร์ฟเวอร์ต้นทางจะถูกส่งมายัง Staging area subnet ผ่าน **TCP พอร์ต 1500**
* อินสแตนซ์สำหรับ Test และ Cutover จะถูกเปิดใช้งานใน Subnet ที่ระบุไว้ใน EC2 Launch Template ของแต่ละเครื่อง

---

## การตรวจสอบ (Monitoring)
* **CloudWatch:** ตรวจสอบทรัพยากร AWS และแอปพลิเคชันแบบเรียลไทม์ พร้อมตั้งค่าการแจ้งเตือน (Alarms)
* **CloudTrail:** บันทึกการเรียกใช้งาน API และเหตุการณ์ที่เกี่ยวข้องลงใน S3 Bucket
* **EventBridge:** ส่งเหตุการณ์ (Event) เมื่อการเปิดใช้งานเซิร์ฟเวอร์ต้นทางเสร็จสมบูรณ์

---

## ความปลอดภัย (Security)
* ใช้ **Global condition context keys** ในนโยบายทรัพยากรเพื่อจำกัดสิทธิ์ของ AWS MGN: `aws:SourceArn` และ `aws:SourceAccount`
* ในการติดตั้ง Agent คุณต้องสร้าง AWS Credentials ซึ่งมีทั้งแบบ:
    * **Persistent IAM credentials:** (แบบถาวร)
    * **Non-persistent IAM credentials:** (แบบชั่วคราว)

---

## ค่าบริการ (Pricing)
คุณจะถูกเรียกเก็บเงินสำหรับ:
* โครงสร้างพื้นฐาน AWS ใดๆ ที่ถูกจัดเตรียมไว้เพื่อรองรับการคัดลอกข้อมูล (Replication)
* ทรัพยากรที่ถูกใช้งานเมื่อคุณเปิดอินสแตนซ์สำหรับทดสอบ (Test) หรือใช้งานจริง (Cutover)
