# AWS Server Migration Service (AWS SMS) Cheat Sheet

> **หมายเหตุสำคัญ:** ปัจจุบัน AWS ได้ยกเลิกการให้บริการ AWS Server Migration Service (AWS SMS) แล้ว และแนะนำให้ใช้ **AWS Application Migration Service (AWS MGN)** เป็นบริการหลักในการย้ายระบบแทน

เป็นบริการแบบ **ไม่ใช้เอเย่นต์ (Agentless)** สำหรับการย้ายเวิร์กโหลดจาก On-premises จำนวนมากมายัง AWS ซึ่งเป็นบริการที่ถูกพัฒนาขึ้นมาแทนที่ Amazon EC2 VM Import
* **SMS ช่วยจัดการการย้ายเซิร์ฟเวอร์โดย:**
    * ทำการคัดลอกข้อมูลส่วนที่เพิ่มขึ้น (Incremental replication) ของเซิร์ฟเวอร์ที่ใช้งานอยู่มายัง AWS Cloud แบบอัตโนมัติ
    * อนุญาตให้ลูกค้าตั้งเวลาการคัดลอกข้อมูล (Replication)
    * ติดตามความคืบหน้าของการคัดลอกข้อมูลกลุ่มเซิร์ฟเวอร์ผ่านหน้า Management Console
* ข้อมูลเซิร์ฟเวอร์ที่คัดลอกมาจะถูกบันทึกเป็น **Amazon Machine Image (AMI) ใหม่** ซึ่งสามารถนำไปเปิดใช้งานเป็นอินสแตนซ์ EC2 ได้ หากใช้การจัดกลุ่มแอปพลิเคชัน SMS จะเปิดใช้งานเซิร์ฟเวอร์ผ่าน **CloudFormation stack** โดยใช้เทมเพลตที่สร้างขึ้นอัตโนมัติ
* AWS SMS จะสร้าง **EBS Snapshot ใหม่** ในทุกๆ รอบการคัดลอกข้อมูล โดยจะคัดลอกข้อมูลจาก On-premises มาพักไว้ที่ S3 ชั่วคราว และจะลบออกจาก S3 ทันทีหลังจากสร้าง EBS Snapshot เสร็จสิ้น
* สามารถย้าย Virtual Machines จาก **VMware vSphere** และ **Windows Hyper-V** มายัง AWS ได้
* คุณสามารถคัดลอกเซิร์ฟเวอร์ On-premises มายัง AWS ได้สูงสุด **90 วันต่อเครื่อง** หลังจากนั้นงานจะถูกยุติโดยอัตโนมัติ (สามารถขอขยายเวลาได้ผ่าน AWS)
* รองรับการย้ายข้อมูลขนาดใหญ่ได้สูงสุดถึง **16 TB**

## AWS Server Migration Service Connector
* เป็น Virtual Machine (FreeBSD) ที่กำหนดค่าไว้ล่วงหน้า (ฟอร์แมต OVA) คุณต้องติดตั้ง SMS Connector นี้ในสภาพแวดล้อม VMware vCenter ของ On-premises ก่อนเริ่มใช้งาน
* รองรับ Proxy แบบใช้รหัสผ่าน (Password-based) แต่**ไม่รองรับ** Proxy แบบ NTLM
* สามารถกำหนดค่าให้ใช้กับ SCVMM หรือ Hyper-V แบบ Standalone ได้
* หากต้องการย้าย VM จากทั้ง VMware และ Hyper-V พร้อมกัน ต้องใช้ SMS Connector แยกกันสองตัว

## คุณสมบัติเพิ่มเติม
* **รองรับการย้ายหลายเซิร์ฟเวอร์ (Multi-server migration):** สามารถย้ายแอปพลิเคชันทั้ง Stack แทนที่จะย้ายทีละเครื่อง โดยใช้เทมเพลต CloudFormation ที่ระบบสร้างให้ (แก้ไขไม่ได้)
* **การทำงานต่อจากจุดที่ล้มเหลว (Resume failed jobs):** มีความสามารถในการรันงานคัดลอกข้อมูลต่อจากจุดที่ล้มเหลวได้ทันที ไม่ต้องเริ่มใหม่ทั้งหมด ช่วยให้การย้ายระบบขนาดใหญ่มีประสิทธิภาพและประหยัดเวลา

---

## ความปลอดภัย (Security)
* ข้อมูลที่คัดลอกจะถูกเข้ารหัสระหว่างรับ-ส่งด้วย **TLS**
* AWS SMS Connector จะเก็บข้อมูลเฉพาะ **Inventory พื้นฐานของ VM และ Snapshot** เท่านั้น ไม่มีการเก็บข้อมูลที่ละเอียดอ่อนอื่นๆ

---

## ค่าบริการ (Pricing)
* คุณจะเสียค่าใช้จ่ายจากการใช้งาน **S3** และ **EBS Snapshot** ที่ถูกสร้างขึ้นโดยกระบวนการของ AWS SMS
