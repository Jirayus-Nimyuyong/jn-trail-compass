# กลยุทธ์การย้ายระบบ 7 รูปแบบ (The Seven Common Migration Strategies - 7 R’s)

### 1. Rehost (“lift and shift”)
* ย้ายแอปพลิเคชันไปยัง AWS โดยไม่มีการเปลี่ยนแปลงโค้ดหรือการตั้งค่าหลัก
* เหมาะสำหรับการย้ายระบบขนาดใหญ่หรืองานแบบ Legacy ที่องค์กรต้องการความรวดเร็วเพื่อให้บรรลุวัตถุประสงค์ทางธุรกิจ
* แอปพลิเคชันอาจนำมาปรับโครงสร้างใหม่ (Re-architect) ได้ง่ายขึ้นเมื่อรันอยู่บนคลาวด์แล้ว เพราะส่วนที่ยากที่สุดคือการย้ายข้อมูลและทราฟฟิกได้ทำสำเร็จไปแล้ว

### 2. Replatform (“lift, tinker and shift”)
* มีการปรับแต่งคุณสมบัติบางอย่างเพื่อให้เข้ากับคลาวด์และได้รับประโยชน์ที่ชัดเจน โดยที่ยังไม่ได้เปลี่ยนสถาปัตยกรรมหลักของแอปพลิเคชัน
* **เครื่องมือช่วย Replatform:**
    * **Amazon RDS:** สำหรับฐานข้อมูลเชิงสัมพันธ์ โดย AWS จะจัดการตัวแอปพลิเคชันฐานข้อมูลให้ คุณจึงโฟกัสแค่การใช้งานข้อมูล
    * **AWS Elastic Beanstalk:** แพลตฟอร์มแบบ Managed เต็มรูปแบบที่คุณแค่ Deploy โค้ด แล้ว AWS จะจัดการเรื่อง Scaling, Load balancing และการจัดเตรียมทรัพยากรให้ทั้งหมด

### 3. Repurchase (“drop and shop”)
* เปลี่ยนจากซอฟต์แวร์แบบซื้อขาด (Perpetual licenses) ไปใช้โมเดล SaaS (Software-as-a-Service)
* เหมาะสำหรับงานที่สามารถอัปเกรดเป็นเวอร์ชันใหม่ได้ง่าย ช่วยให้ได้ฟีเจอร์ที่ทันสมัยและการติดตั้งที่ราบรื่นขึ้น
* ตัวอย่าง: เลิกใช้โซลูชัน VPN ในเครื่อง แล้วไปซื้อซอฟต์แวร์ VPN สำเร็จรูปจาก AWS Marketplace เช่น OpenVPN สำหรับ AWS แทน

### 4. Refactor / Re-architect
* จินตนาการและออกแบบสถาปัตยกรรมแอปพลิเคชันใหม่โดยใช้ฟีเจอร์แบบ Cloud-native
* มักขับเคลื่อนด้วยความต้องการทางธุรกิจที่ต้องการเพิ่มฟีเจอร์ การสเกล หรือประสิทธิภาพที่สภาพแวดล้อมเดิมทำได้ยาก
* **หมายเหตุ:** เป็นกลยุทธ์ที่มีค่าใช้จ่ายสูงที่สุด

### 5. Relocate
* การย้ายในระดับ Hypervisor (Lift and shift ระดับ Virtualization)
* คือการย้ายแพลตฟอร์มการจำลองเสมือน (Virtualization) จากเครือข่าย On-premises ไปยังคลาวด์ เหมาะอย่างยิ่งหากไลเซนส์เดิมรองรับบนคลาวด์และต้องการรักษาความซับซ้อนในการจัดการให้อยู่ในระดับต่ำถึงปานกลาง
* ตัวอย่าง: หากเซิร์ฟเวอร์เดิมรันบน VMWare vSphere คุณสามารถย้ายไปยัง AWS โดยใช้บริการ **VMWare Cloud on AWS** ได้

### 6. Retire
* ตรวจสอบสินทรัพย์ไอทีที่ไม่มีประโยชน์แล้วและสามารถปิดการใช้งานได้ เพื่อช่วยลดภาระและหันไปโฟกัสกับทรัพยากรที่มีการใช้งานจริง

### 7. Retain
* เก็บแอปพลิเคชันบางส่วนไว้ที่เดิม (On-premises) หากแอปนั้นยังไม่พร้อมย้าย หรือแอปเพิ่งได้รับการอัปเกรดไปและคุณยังไม่อยากเข้าไปเปลี่ยนแปลงอะไรในตอนนี้

---

### ลำดับความซับซ้อน (Complexity)
กลยุทธ์เหล่านี้เรียงลำดับจากความซับซ้อนน้อยไปมาก (ซึ่งเวลาและค่าใช้จ่ายจะเพิ่มขึ้นตามความซับซ้อน แต่ก็เปิดโอกาสในการเพิ่มประสิทธิภาพได้มากขึ้นด้วย):
> **Retire (ง่ายสุด)** < **Retain** < **Relocate** < **Rehost** < **Repurchase** < **Replatform** < **Re-architect/Refactor (ซับซ้อนสุด)**

## เครื่องมือทั่วไปสำหรับการย้ายระบบ (General Migration Tools)
* **AWS Migration Hub:** จุดศูนย์กลางสำหรับติดตามความคืบหน้าของการย้ายแอปพลิเคชันจากเครื่องมือต่างๆ
* **AWS Application Discovery Service:** เก็บข้อมูลการตั้งค่าและการใช้งานเซิร์ฟเวอร์เพื่อช่วยในการวางแผน
* **AWS Application Migration Service (MGN):** บริการย้าย Workload จำนวนมากมายัง AWS แบบอัตโนมัติ
* **AWS Database Migration Service (DMS):** ช่วยย้ายฐานข้อมูลมายัง AWS โดยที่ฐานข้อมูลต้นทางยังทำงานได้ปกติ
* **AWS Snowball:** อุปกรณ์ฮาร์ดแวร์สำหรับขนส่งข้อมูลขนาดระดับ Petabyte เข้า-ออก AWS
* **AWS Direct Connect:** ลิงก์เชื่อมต่อเครือข่ายเฉพาะตัวระหว่างศูนย์ข้อมูลของคุณกับ AWS
* **AWS DataSync:** บริการออนไลน์ที่ช่วยเร่งการย้ายข้อมูลระหว่าง Storage ในเครื่อง (NAS/SAN) กับ Storage บน AWS
* **Amazon Data Firehose:** บริการโหลดข้อมูลแบบ Streaming เข้าสู่ AWS
* **AWS Marketplace:** แหล่งซื้อซอฟต์แวร์และไลเซนส์จากพาร์ทเนอร์ของ AWS
