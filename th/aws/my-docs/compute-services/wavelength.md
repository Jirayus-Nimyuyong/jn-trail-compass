# AWS Wavelength Cheat Sheet

**AWS Wavelength** ช่วยให้นักพัฒนาสามารถสร้างแอปพลิเคชันที่ต้องการโครงสร้างพื้นฐานแบบ Edge Computing เพื่อส่งมอบความหน่วงที่ต่ำเป็นพิเศษ (**Ultra-low latency**) ไปยังอุปกรณ์พกพาและผู้ใช้งานปลายทาง
* โดยการติดตั้งบริการประมวลผล (Compute) และจัดเก็บข้อมูล (Storage) มาตรฐานของ AWS ไว้ที่ขอบของเครือข่ายผู้ให้บริการสื่อสาร (**Communications Service Providers - CSP**) ซึ่งโดยปกติคือเครือข่าย 5G
* **Wavelength Zones** สามารถใช้เพื่อขยาย **Amazon VPC** เพื่อรันแอปพลิเคชันที่ต้องการความหน่วงต่ำมาก โดยใช้บริการ, API, เครื่องมือ และฟังก์ชันการทำงานเดียวกันกับ AWS ปกติ

---

## คุณสมบัติ (Features)
* **การประมวลผล:** รองรับอินสแตนซ์มาตรฐานของ AWS ทั้งแบบ General Purpose, Memory Optimized และแบบที่เร่งความเร็วด้วย GPU สำหรับงาน Edge ที่หลากหลาย
* **การจัดเก็บข้อมูล:** ให้บริการ Block Storage แบบถาวรผ่าน Amazon EBS gp2 พร้อมความสามารถในการทำ Snapshot และการกู้คืน (Restore) ไปยังภูมิภาคหลัก (Parent Regions)
* **เครือข่าย:** ขยาย VPC เดิมไปยัง Wavelength Zones ผ่าน **Carrier Gateways** เพื่อการเชื่อมต่อโดยตรงกับเครือข่าย 5G ด้วยความหน่วงต่ำ
* **Container Orchestration:** สามารถจัดการแอปพลิเคชันแบบคอนเทนเนอร์ได้โดยใช้บริการที่คุ้นเคยอย่าง Amazon EKS และ Amazon ECS
* **การจัดการ:** ผสานการทำงานร่วมกับเครื่องมือการจัดการมาตรฐานของ AWS ได้อย่างราบรื่น รวมถึง CloudFormation, CloudWatch และ Auto Scaling

### กรณีการใช้งาน (Use cases):
* **เกมและสื่อบันเทิง:** การสตรีมเกมแบบเรียลไทม์ และการแสดงผลคอนเทนเนอร์ AR/VR คุณภาพสูงไปยังอุปกรณ์พกพาโดยมีอาการหน่วงน้อยที่สุด
* **ยานยนต์อัจฉริยะ:** การประมวลผลข้อมูลโทรมาตร (Telemetry) จากยานพาหนะแบบเกือบเรียลไทม์ เพื่อสนับสนุนระบบช่วยเหลือผู้ขับขี่ขั้นสูง (ADAS) และความปลอดภัยในการขับขี่อัตโนมัติ
* **โรงงานอัจฉริยะ:** การรัน AI/ML เพื่อวิเคราะห์วิดีโอที่ส่วน Edge เพื่อตรวจจับข้อบกพร่องในการผลิตหรืออันตรายด้านความปลอดภัยในโรงงานทันที
* **การแพทย์ทางไกล:** การวิเคราะห์ภาพทางการแพทย์แบบเรียลไทม์และการวินิจฉัยทางไกล ซึ่งความหน่วงเป็นเรื่องวิกฤตสำหรับการโต้ตอบระหว่างหมอและคนไข้

## แนวคิดของ AWS Wavelength (AWS Wavelength Concepts)

### Wavelength Zone (WZ)
* เป็นส่วนขยายเชิงตรรกะของภูมิภาค (Region) ซึ่งเป็นจุดที่โครงสร้างพื้นฐานของ Wavelength ถูกติดตั้งและจัดการโดย Control Plane ของภูมิภาคนั้นๆ
* ใช้ WZs สำหรับส่วนประกอบของแอปพลิเคชันที่ต้องการความหน่วงต่ำมาก, แบนด์วิดท์ที่เพิ่มขึ้น หรือคุณภาพบริการที่ดีขึ้นบนเครือข่ายมือถือ 5G
* **การออกแบบ:** AWS แนะนำให้ออกแบบแอปพลิเคชันในรูปแบบ **Hub and Spoke** ร่วมกับภูมิภาคหลัก เพื่อความคุ้มค่าและประสิทธิภาพ
* **การค้นหาตำแหน่ง:** ในการค้นหา WZ endpoint ที่ใกล้ที่สุด คุณต้องลงทะเบียนอินสแตนซ์ EC2 กับบริการค้นหาอย่าง **AWS Cloud Map**
* **หมายเหตุ:** Wavelength Zones ไม่ได้มีให้บริการในทุกภูมิภาคของ AWS โดยจะผูกติดกับสถานที่ทางภูมิศาสตร์เฉพาะและพันธมิตรผู้ให้บริการโทรคมนาคมเท่านั้น

### Carrier Gateway
* ทำหน้าที่เชื่อมต่อระหว่าง WZ และผู้ให้บริการโทรคมนาคม
* รองรับทั้งทราฟฟิกขาเข้า (Inbound) จากเครือข่ายผู้ให้บริการ และทราฟฟิกขาออก (Outbound) ไปยังเครือข่ายผู้ให้บริการและอินเทอร์เน็ต
* รองรับทราฟฟิก **IPv4**
* ใช้งานได้เฉพาะกับ VPC ที่มี Subnet ของ WZ เท่านั้น
* ทำหน้าที่ **NAT (Network Address Translation)** เพื่อแปล Private IP ของอินสแตนซ์ Wavelength ให้เป็น Carrier IP address

## ส่วนประกอบที่จำเป็น
เพื่อให้สามารถใช้โครงสร้างพื้นฐาน Edge Computing 5G ของ AWS Wavelength ได้ คุณจำเป็นต้องมี:
* VPC, Subnet และ Network Border Group
* ทรัพยากรประมวลผล (Compute), บริการจัดเก็บข้อมูล (Storage) และ Carrier Gateways ใน WZs

---

## ค่าบริการ (AWS Wavelength Pricing)
* ราคาของทรัพยากร AWS (EC2, EBS) ใน Wavelength Zones จะ**แตกต่าง**จากราคาในภูมิภาคหลัก (Parent Region)
* **On-Demand:** อินสแตนซ์ใน WZs ส่วนใหญ่จะให้บริการในรูปแบบจ่ายตามจริง (On-Demand)
* **Savings Plans:** คุณสามารถลดค่าใช้จ่ายได้โดยใช้ **Compute Savings Plans** และ **EC2 Instance Savings Plans** ซึ่งสามารถนำมาใช้กับ Wavelength ได้เช่นเดียวกับในภูมิภาคหลัก
