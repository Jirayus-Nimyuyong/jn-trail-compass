# AWS Serverless Application Repository (SAR) Cheat Sheet

**AWS Serverless Application Repository (SAR)** เป็นพื้นที่เก็บข้อมูลส่วนกลางแบบ Managed สำหรับแอปพลิเคชัน Serverless ช่วยให้ทีม, องค์กร และนักพัฒนาทั่วไปสามารถจัดเก็บและแบ่งปันแอปพลิเคชันที่นำกลับมาใช้ใหม่ได้ รวมถึงช่วยให้การประกอบและติดตั้งใช้งานสถาปัตยกรรม Serverless รูปแบบใหม่ๆ ทำได้ง่ายขึ้น
* ทำหน้าที่เป็นห้องสมุดสำหรับ "รูปแบบ Serverless สำเร็จรูป" (ซึ่งกำหนดโดย AWS SAM templates) ที่คุณสามารถติดตั้งใช้งาน (Deploy) ลงในบัญชีของคุณได้ทันที โดยไม่ต้องทำการ Clone หรือ Build โค้ดด้วยตัวเอง
* แต่ละแอปพลิเคชันจะประกอบด้วย AWS SAM template ที่ระบุทรัพยากร AWS ที่จะถูกนำมาใช้งาน

---

## การเผยแพร่แอปพลิเคชัน (Publishing Applications)
* ใช้ **AWS SAM template** ในการกำหนดโครงสร้างแอปพลิเคชันของคุณ
* ในการเผยแพร่ (Publish) แอปพลิเคชัน Serverless คุณสามารถอัปโหลดโค้ดผ่านช่องทางดังนี้:
    * AWS Management Console
    * AWS SAM CLI
    * AWS SDKs
* เมื่อคุณเผยแพร่แอปพลิเคชันในตอนแรก สถานะจะถูกตั้งค่าเป็น **Private** (ส่วนตัว) ซึ่งเข้าถึงได้เฉพาะบัญชี AWS ที่สร้างขึ้นเท่านั้น
* คุณสามารถตั้งค่าการแชร์และการ Deploy แอปพลิเคชันได้ 3 รูปแบบ:
    1. **Private (ส่วนตัว):** ไม่แชร์กับบัญชี AWS อื่น เข้าถึงได้เฉพาะบัญชีผู้สร้างเท่านั้น
    2. **Privately Shared (แชร์แบบส่วนตัว):** แชร์กับบัญชี AWS เฉพาะเจาะจง หรือแชร์ให้ทั้งองค์กร (AWS Organization) วิธีนี้ช่วยให้การกระจายเครื่องมือภายในบริษัทไปยังทุกบัญชีทำได้ง่ายขึ้น (เข้าถึงได้ในภูมิภาคที่สร้างขึ้น)
    3. **Publicly Shared (แชร์แบบสาธารณะ):** แชร์กับทุกคน เข้าถึงได้จากทุกภูมิภาค (All Regions) แอปพลิเคชันสาธารณะจะรวมลิงก์ไปยัง Source Code ไว้ด้วย
* หากแอปพลิเคชันสาธารณะถูก Deploy ไปยังภูมิภาคอื่น AWS SAR จะคัดลอกไฟล์ Artifact สำหรับการติดตั้งไปยัง **Amazon S3** ในภูมิภาคปลายทางให้โดยอัตโนมัติ
* คุณสามารถแชร์ **Lambda layers** เพื่อนำไปติดตั้งใช้งานในบัญชี AWS อื่นได้

## การติดตั้งใช้งานแอปพลิเคชัน (Deploying Applications)
* ในการติดตั้งใช้งาน คุณต้องได้รับสิทธิ์อนุญาตตามที่ระบุไว้ในหัวข้อการแชร์ข้างต้น
* เมื่อ Deploy แอปพลิเคชันที่มีการสร้าง **IAM roles** หรือนโยบาย (Policies) คุณต้องกดยอมรับ (Acknowledge) อย่างชัดเจนว่าแอปพลิเคชันมีการสร้างทรัพยากรเหล่านี้ หากใช้ CLI/API คุณต้องระบุ Capabilities เช่น `CAPABILITY_IAM`, `CAPABILITY_NAMED_IAM` หรือ `CAPABILITY_AUTO_EXPAND`
* คุณสามารถปรับแต่งการตั้งค่าแอปพลิเคชันในระหว่างการ Deploy ได้ โดยการระบุค่าให้กับ **Template Parameters** ที่ผู้เผยแพร่กำหนดไว้ (เช่น ตั้งชื่อตาราง DynamoDB เอง หรือระบุ API Key)
* ก่อนการติดตั้ง AWS SAR จะตรวจสอบเทมเพลตในเรื่องต่อไปนี้:
    * IAM roles
    * นโยบายทรัพยากรของ AWS (Resource policies)
    * แอปพลิเคชันแบบซ้อน (Nested applications) ที่ระบุในเทมเพลต
* คุณสามารถค้นหาและเรียกดูได้เฉพาะแอปพลิเคชันที่คุณมีสิทธิ์เข้าถึงเท่านั้น (แอปที่สร้างเอง, แอปที่แชร์มาให้คุณแบบส่วนตัว หรือแอปสาธารณะ)

---

## การตรวจสอบ (Monitoring)
* สร้าง Trail ใน **AWS CloudTrail** เพื่อบันทึกการเรียกใช้งาน API ทั้งหมด
* แม้จะไม่ได้ตั้งค่า Trail ไว้ คุณยังสามารถดูเหตุการณ์ล่าสุดได้ที่หน้า **Event history** ในคอนโซลของ CloudTrail

---

## ค่าบริการ (Pricing)
* **ไม่มีค่าธรรมเนียมเพิ่มเติม** ในการใช้บริการ Serverless Application Repository เอง
* คุณจ่ายเฉพาะค่าทรัพยากร AWS พื้นฐานที่ถูกสร้างขึ้นเมื่อคุณติดตั้งใช้งานแอปพลิเคชันเท่านั้น (เช่น ค่าบริการ Lambda, S3 หรือ DynamoDB ที่รันอยู่เบื้องหลัง)
