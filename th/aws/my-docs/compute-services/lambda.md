# AWS Lambda Cheat Sheet

**AWS Lambda** เป็นบริการประมวลผลแบบ **Serverless และขับเคลื่อนด้วยเหตุการณ์ (Event-driven)** ที่จะรันโค้ดของคุณเพื่อตอบสนองต่อเหตุการณ์ต่างๆ และจัดการโครงสร้างพื้นฐานเบื้องหลังให้โดยอัตโนมัติ
* คุณจ่ายเฉพาะค่าเวลาประมวลผล โดยคิดค่าบริการตามจำนวนคำขอ (Request) และตามจำนวนมิลลิวินาทีที่ใช้รันโค้ด
* Lambda Function เป็นแบบ **Stateless** (ไม่มีการเก็บสถานะ) และไม่มีความผูกพันกับเซิร์ฟเวอร์ตัวใดตัวหนึ่ง
* Lambda สเกลในแนวราบ (Horizontal) โดยอัตโนมัติ โดยรันอินสแตนซ์จำนวนเท่าที่จำเป็นตามปริมาณเหตุการณ์ที่เข้ามา
* สามารถติดตั้งโค้ดได้ทั้งแบบไฟล์ ZIP หรือ Container Image (สูงสุด 10 GB)
* รองรับการจัดสรรหน่วยความจำตั้งแต่ 128 MB ถึง 10 GB โดย CPU, เครือข่าย และ I/O จะสเกลตามสัดส่วนของหน่วยความจำ
* รองรับมาตรฐานความปลอดภัยระดับโลก เช่น SOC, HIPAA, PCI และ ISO
* **รองรับภาษาต่างๆ (Native):** Node.js, Java, C#, Go, Python, Ruby, PowerShell

---

## คุณสมบัติ (Features)
* รันโค้ดบน **Firecracker microVMs** ที่มีความปลอดภัยและความพร้อมใช้งานสูง สเกลจากศูนย์จนถึงระดับสูงสุดได้โดยอัตโนมัติ
* **ประสิทธิภาพ:** ลดปัญหา Cold Start ด้วยการใช้ **Provisioned Concurrency** (เพื่อความหน่วงที่คงที่) และ **SnapStart** (สำหรับ Java, Python, .NET) เพื่อการเริ่มต้นที่เร็วขึ้น
* **การเชื่อมต่อ:** เชื่อมต่อกับบริการ AWS อื่นๆ ได้มากกว่า 220 บริการ และสามารถเมานต์ (Mount) **Amazon EFS** เพื่อใช้พื้นที่เก็บข้อมูลร่วมกันแบบถาวรได้
* **การตรวจสอบ:** ส่งล็อกและมาตรวัดไปยัง Amazon CloudWatch และ AWS X-Ray โดยอัตโนมัติ

## AWS Lambda Managed Instances (ใหม่!)
โหมดการประมวลผลแบบใหม่ที่ให้คุณรัน Lambda บน **อินสแตนซ์ Amazon EC2 เฉพาะเจาะจง** (รวมถึง GPU และ Graviton4) ที่ AWS จัดการให้เต็มรูปแบบ เพื่อเชื่อมช่องว่างระหว่างความง่ายของ Serverless และการควบคุมฮาร์ดแวร์ของ EC2

* **การทำงาน:** คุณกำหนด "Capacity Provider" เพื่อระบุ VPC, ประเภทอินสแตนซ์ และนโยบายการสเกล
* **Multiconcurrency:** ต่างจาก Lambda มาตรฐาน (1 Request ต่อ 1 Environment) โดยโหมดนี้หนึ่งอินสแตนซ์สามารถประมวลผลหลาย Request พร้อมกันได้
* **ประโยชน์:** เข้าถึงฮาร์ดแวร์ที่ Lambda ปกติไม่มี เช่น GPU สำหรับ AI/ML, ไม่มี Cold Start เพราะเครื่องเปิดรออยู่ตลอด และประหยัดค่าใช้จ่ายได้มากสำหรับงานปริมาณสูงที่คาดการณ์ได้ (ใช้ร่วมกับ Savings Plans ได้)
* **ค่าบริการ:** จ่ายตามค่าเครื่อง EC2 มาตรฐาน + ค่าธรรมเนียมการจัดการประมาณ 15% + ค่า Request (ไม่คิดค่าบริการตามระยะเวลาการรันเป็นมิลลิวินาที)

## ส่วนประกอบของแอปพลิเคชัน Lambda
* **Function:** สคริปต์หรือโปรแกรมที่รันใน Lambda
* **Execution Environment:** microVM ที่แยกส่วนและปลอดภัยสำหรับรัน Function
* **Runtime:** ตัวกลางระหว่างบริการ Lambda และโค้ดของคุณเพื่อให้รันภาษาต่างๆ ได้
* **Environment Variables:** คู่ Key-value สำหรับเก็บการตั้งค่า เช่น การเชื่อมต่อฐานข้อมูลหรือ API Keys
* **Layers:** กลไกการแจกจ่ายไลบรารีหรือ Dependency เพื่อให้โค้ดหลักมีขนาดเล็ก
* **Event Source:** บริการที่เป็นตัวกระตุ้น (Trigger) ให้ Function ทำงาน

## การเรียกใช้งาน (Invoking Lambda Functions)
รองรับการเรียกใช้งาน 2 รูปแบบหลัก:
1. **Synchronous (แบบประสานเวลา):** รอจนกว่า Function จะประมวลผลเสร็จแล้วจึงส่งผลลัพธ์กลับ (เช่น API Gateway, ALB, Cognito)
2. **Asynchronous (แบบไม่ประสานเวลา):** Lambda จะเก็บเหตุการณ์ไว้ในคิวภายในและตอบกลับด้วย HTTP **202 (Accepted)** ทันที โดยประมวลผลต่อในเบื้องหลัง (เช่น S3, EventBridge, CloudWatch Logs) มีขนาด Payload สูงสุด 256 KB

---

## การจัดการ Concurrency
* **Concurrency:** จำนวนอินสแตนซ์ที่รันพร้อมกันในขณะนั้น
* **Reserved Concurrency:** การจองจำนวน Concurrency ไว้ให้ Function ใดเครื่องหนึ่งโดยเฉพาะ เพื่อรับประกันว่าจะมีทรัพยากรพร้อมรันเสมอ และเป็นการจำกัดจำนวนรันสูงสุดไปในตัว
* **Provisioned Concurrency:** การเตรียมอินสแตนซ์ให้พร้อมใช้งานไว้ล่วงหน้า เพื่อลดความหน่วง (Latency) และ Cold Start

## Lambda Function URL
* ฟีเจอร์ที่ให้คุณสร้าง **HTTPS Endpoint** ส่วนตัวสำหรับ Lambda Function ได้โดยตรง
* ไม่จำเป็นต้องมีตัวกลางอย่าง API Gateway อีกต่อไป
* รูปแบบ URL: `https://<url-id>.lambda-url.<region>.on.aws`
* รองรับ **IPv4 และ IPv6** (Dual-stack)
* **การยืนยันตัวตน:** มี 2 แบบคือ `AWS_IAM` (ใช้สิทธิ์ IAM) และ `NONE` (สาธารณะ ใครมี URL ก็เรียกได้)
* สามารถตั้งค่า **CORS** เพื่อความปลอดภัยในการเรียกใช้งานจากเบราว์เซอร์ได้

## Lambda@Edge
* ช่วยให้รัน Lambda Function เพื่อปรับแต่งเนื้อหาที่ส่งผ่าน **CloudFront** ณ ตำแหน่ง Edge Location ที่ใกล้กับผู้ใช้งานมากที่สุด
* ทำงานตอบสนองต่อเหตุการณ์ของ CloudFront เช่น Viewer Request, Origin Request, Origin Response และ Viewer Response

---

## AWS Lambda SnapStart
* ช่วยเร่งความเร็วแอปพลิเคชัน Java โดยการใช้ Snapshot ที่เริ่มต้นระบบไว้แล้วมาเริ่มรันใหม่แทนการเริ่มจากศูนย์
* ช่วยลดเวลา Cold Start ได้อย่างมหาศาลโดยไม่ต้องจัดเตรียมทรัพยากรเพิ่มเติม

---

## ค่าบริการ (Pricing)
คิดค่าบริการตามจำนวนคำขอและระยะเวลาที่โค้ดทำงาน
* **ปัจจัยหลัก:** จำนวน Request, ระยะเวลาประมวลผล (คิดทุกๆ 1 มิลลิวินาที), การตั้งค่าหน่วยความจำ
* **Free Tier:** ฟรี 1 ล้านคำขอต่อเดือน และ 400,000 GB-seconds ต่อเดือน
* **ค่าใช้จ่ายเพิ่มเติม:** Provisioned Concurrency, SnapStart, ค่าจัดเก็บ ECR และการโอนข้อมูลผ่าน VPC
