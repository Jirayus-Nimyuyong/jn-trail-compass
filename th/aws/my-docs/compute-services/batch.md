# AWS Batch Cheat Sheet

**AWS Batch** เป็นบริการที่มีการจัดการเต็มรูปแบบ (Fully Managed) ซึ่งช่วยให้คุณสามารถรันงานประมวลผลแบบกลุ่ม (Batch Computing) บน AWS Cloud ได้
* ระบบจะจัดเตรียมทรัพยากรการประมวลผล (Compute Resources) ในปริมาณและประเภทที่เหมาะสมที่สุดโดยอัตโนมัติ (เช่น อินสแตนซ์ที่เน้น CPU หรือหน่วยความจำ) ตามปริมาณงานและข้อกำหนดเฉพาะของงานที่ส่งเข้ามา
* ช่วยขจัดความจำเป็นในการติดตั้งและจัดการซอฟต์แวร์ประมวลผลแบบกลุ่ม หรือการดูแล Cluster ของเซิร์ฟเวอร์
* เป็นบริการระดับภูมิภาค (**Regional Service**) ที่ช่วยให้การรันงาน Batch ข้ามหลาย Availability Zones (AZs) ภายในภูมิภาคเป็นเรื่องง่าย

---

## คุณสมบัติ (Features)
* **การจัดการทรัพยากรอัตโนมัติ:** AWS Batch จะเลือกที่รันงานและเปิดใช้งานทรัพยากรเพิ่มเติมเองเมื่อจำเป็น โดยจะเลือกประเภทอินสแตนซ์ที่เหมาะสมที่สุดตามความต้องการของงาน
* **รองรับโครงสร้างพื้นฐานที่หลากหลาย:** จัดการสภาพแวดล้อมการประมวลผลและคิวงานเพื่อให้รันงานนับพันได้บน Amazon EC2, EC2 Spot Instances, AWS Fargate หรือ Amazon EKS
* **การจัดการเวิร์กโฟลว์ (Workflow Management):** สามารถส่งงานที่เป็นส่วนหนึ่งของ Pipeline หรือ Workflow โดยกำหนดความเชื่อมโยงระหว่างกันได้ (เช่น งาน B จะเริ่มได้ก็ต่อเมื่องาน A สำเร็จแล้ว)
* **Fair-share Scheduling:** มีนโยบายการจัดลำดับงานที่ช่วยให้มั่นใจว่าทรัพยากรจะถูกจัดสรรอย่างเป็นธรรมระหว่างผู้ใช้หรือ Workload ต่างๆ เพื่อป้องกันไม่ให้ผู้ใช้รายใดรายหนึ่งผูกขาด Cluster
* **Multi-node Parallel Jobs:** รองรับการรันแอปพลิเคชัน HPC (High Performance Computing) ขนาดใหญ่ที่ต้องการการเชื่อมต่อกันอย่างใกล้ชิดและรันข้ามหลายอินสแตนซ์ EC2
* **การลดค่าใช้จ่าย:** ระบบจะเฝ้าติดตามความคืบหน้าของงานอย่างใกล้ชิด และจะลบทรัพยากรออกโดยอัตโนมัติเมื่อไม่ต้องการใช้งานแล้วเพื่อลดค่าใช้จ่าย

## ส่วนประกอบ (Components)

### 1. งาน (Jobs)
คือหน่วยของงาน (เช่น Shell Script, ไฟล์ Linux Executable หรือ Docker Container Image) ที่คุณส่งไปยัง AWS Batch
* **ประเภทของงาน:**
    * **Single:** รันบน EC2 Instance หรือ Fargate Task ตัวเดียว
    * **Array:** งานแบบกลุ่มขนาด 2 ถึง 10,000 งาน ที่ใช้พารามิเตอร์และ Job Definition ร่วมกัน แต่รันแยกกันแบบขนานได้
    * **Multi-node Parallel:** สำหรับงาน HPC ขนาดใหญ่หรือการเทรนโมเดล GPU แบบกระจายตัว โดยระบบจะเริ่มจาก **Main Node** ก่อนแล้วจึงเริ่ม **Child Nodes** (ไม่รองรับบน Spot Instances)
* **ความเชื่อมโยง (Dependencies):** งานหนึ่งสามารถมีงานที่ต้องรอก่อนหน้า (Dependencies) ได้สูงสุด 20 งาน
* **สถานะของงาน (States):**
    * **SUBMITTED:** ส่งงานเข้าคิวแล้ว แต่ยังไม่ได้ถูกประเมินโดย Scheduler
    * **PENDING:** รอยู่ในคิวแต่ยังรันไม่ได้เพราะติด Dependency หรือรอทรัพยากร
    * **RUNNABLE:** ไม่มี Dependency ค้างอยู่ พร้อมที่จะถูกจัดตารางเวลาเมื่อทรัพยากรพร้อม
    * **STARTING:** กำลังเริ่มรัน Container
    * **RUNNING:** กำลังทำงานอยู่ (Exit Code 0 = สำเร็จ, ค่าอื่น = ล้มเหลว)
    * **SUCCEEDED / FAILED:** งานจบการทำงานแล้ว (สถานะจะถูกเก็บไว้ 24 ชั่วโมง)
* **การรันซ้ำและ Timeout:** สามารถตั้งค่ากลยุทธ์การ Retry อัตโนมัติเมื่องานล้มเหลว และตั้งค่า Timeout เพื่อจำกัดเวลาทำงานสูงสุดได้

### 2. คำจำกัดความของงาน (Job Definitions)
ระบุวิธีการรันงาน ซึ่งประกอบด้วย:
* **IAM Role:** เพื่อให้สิทธิ์ในการเข้าถึงทรัพยากรอื่นๆ ของ AWS
* **ความต้องการทรัพยากร:** หน่วยความจำ (Memory) และ CPU
* **คุณสมบัติ Container:** สภาพแวดล้อม (Environment Variables) และจุดเชื่อมต่อพื้นที่เก็บข้อมูล (Mount Points)

### 3. คิวงาน (Job Queues)
สถานที่ที่งานจะพักอยู่จนกว่าจะถูกจัดตารางเวลาลงในสภาพแวดล้อมการประมวลผล
* สามารถเชื่อมโยงคิวงานกับ Compute Environment ได้หลายแห่ง
* สามารถกำหนดลำดับความสำคัญ (Priority) ระหว่างสภาพแวดล้อมการประมวลผลหรือระหว่างคิวงานเองได้
* **Scheduling Policy:** สามารถผูกนโยบายเพื่อทำ **Fair Share Scheduling** โดยใช้ "Share Identifier" ในการจัดสรรทรัพยากรตามน้ำหนักที่กำหนดให้แต่ละผู้ใช้หรือโปรเจกต์

### 4. สภาพแวดล้อมการประมวลผล (Compute Environment)
ชุดของทรัพยากรประมวลผล (เช่น EC2) ที่ใช้รันงาน
* **Managed Compute Environment:** AWS Batch จะจัดการขนาดและประเภทอินสแตนซ์ให้เองตามที่คุณกำหนด เลือกได้ทั้ง On-Demand หรือ Spot Instances
* **Unmanaged Compute Environment:** คุณต้องจัดการทรัพยากรด้วยตัวเอง โดยต้องนำอินสแตนซ์เข้ามาใน ECS Cluster ที่ AWS Batch กำหนดให้เอง

## ความปลอดภัย (Security)
* ใช้ **IAM Policies** และ **Roles** ในการควบคุมสิทธิ์การเข้าถึงทรัพยากร AWS Batch
* **Service-Linked Role:** ใช้บทบาท `AWSServiceRoleForBatch` เพื่อให้ AWS Batch เรียกใช้บริการอื่นๆ (EC2, ECS, EKS) แทนคุณ
* **EKS Auth:** หากใช้ EKS, AWS Batch จะจัดการ `aws-auth` ConfigMap เพื่อให้สิทธิ์แก่โหนดที่จัดเตรียมขึ้นมาเอง

---

## การตรวจสอบ (Monitoring)
* **CloudWatch Events:** รับการแจ้งเตือนสถานะงานแบบ Real-time (รับประกันการส่งข้อมูลอย่างน้อยหนึ่งครั้ง)
* **CloudTrail:** บันทึกการเรียกใช้งาน API ทั้งหมดของ AWS Batch

---

## ค่าบริการ (Pricing)
* **ไม่มีค่าธรรมเนียมเพิ่มเติมสำหรับ AWS Batch** คุณจ่ายเฉพาะค่าทรัพยากรที่คุณสร้างขึ้นเพื่อจัดเก็บและรันแอปพลิเคชันของคุณ (เช่น ค่าเครื่อง EC2 หรือ Fargate) เท่านั้น
