# Amazon OpenSearch Service Cheat Sheet

**Amazon OpenSearch** ช่วยให้คุณสามารถค้นหา วิเคราะห์ และสร้างภาพข้อมูล (Visualize) ได้แบบเรียลไทม์ บริการนี้จะจัดการเรื่องความจุ, การขยายระบบ (Scaling), การลงแพตช์ และการดูแลคลัสเตอร์แทนคุณ โดยที่คุณยังสามารถเข้าถึง Elasticsearch APIs ได้โดยตรง

* Amazon OpenSearch Service ต่อยอดมาจากโปรเจกต์โอเพนซอร์ส OpenSearch และรองรับการทำงานร่วมกับ Elasticsearch APIs รุ่นเก่า ในขณะที่มุ่งเน้นไปที่ฟีเจอร์และเครื่องมือเฉพาะของ OpenSearch

---

### แนวคิดหลัก (Concepts)
* **Domain:** มีความหมายเหมือนกับ Elasticsearch Cluster คือกลุ่มของอินสแตนซ์และการตั้งค่าทรัพยากรที่คุณระบุ
* **Indices:** คุณสามารถสร้างดัชนี (Indices) ได้หลายรายการในโดเมนเดียว โดยระบบจะกระจายดัชนีและ Replica ไปยังอินสแตนซ์ต่างๆ โดยอัตโนมัติ
* **Blue/Green Deployment:** ใช้ในกระบวนการอัปเดตโดเมน โดยการรันสภาพแวดล้อมคู่ขนานกันเพื่อสลับใช้งานเมื่อการอัปเดตซอฟต์แวร์เสร็จสิ้น เพื่อลดเวลา Downtime
* **Alerting:** ระบบแจ้งเตือนเมื่อข้อมูลในดัชนีตรงตามเงื่อนไขที่กำหนด (เช่น ตรวจพบ HTTP 503)
* **SQL Support:** รองรับการคิวรีด้วยไวยากรณ์ SQL ที่คุ้นเคย (เช่น Group by, Where) ควบคู่ไปกับความสามารถในการค้นหาแบบ Full-text

### ฟีเจอร์การค้นหาขั้นสูง
* **Neural Search:** ใช้โมเดล Machine Learning เพื่อทำ Semantic Search (ค้นหาตามความหมายและบริบท) แทนการจับคู่คำสำคัญ (Keywords) เพียงอย่างเดียว
* **GPU Acceleration:** รองรับการเร่งความเร็วด้วย GPU สำหรับ Vector Indexes เพื่อการค้นหาเวกเตอร์ที่รวดเร็วขึ้น
* **Hybrid Search:** รวมคะแนน (Scores) จากการค้นหาแบบ Keyword และ Semantic เข้าด้วยกันเพื่อเพิ่มความแม่นยำของผลลัพธ์

---

### พื้นที่จัดเก็บข้อมูล (Storage)
* เลือกได้ระหว่าง **On-instance storage** (สูงสุด 3 PB) หรือ **Amazon EBS**
* **Snapshots:** ระบบจะสำรองข้อมูลโดเมนและสถานะของคลัสเตอร์โดยอัตโนมัติไปยัง Amazon S3 เพื่อใช้ในการกู้คืน (Recovery)
* **หมายเหตุ:** การย้ายข้อมูล (Migration) ไปยังโดเมนใหม่ต้องใช้ Manual Snapshot ที่คุณเก็บไว้ใน S3 Bucket ของตัวเอง

---

### การนำข้อมูลเข้า (Data Ingestion)
* **เครื่องมือ:** ใช้ **Logstash** (Open-source pipeline) หรือบริการของ AWS เช่น **Kinesis Data Firehose**, **AWS IoT**, หรือ **CloudWatch Logs**
* **Visualization:** ใช้ **OpenSearch Dashboards** (มาแทนที่ Kibana สำหรับโดเมน OpenSearch) ในการวิเคราะห์และสร้างภาพข้อมูล
* **Streaming Data:** สามารถโหลดข้อมูลผ่าน **AWS Lambda** จากแหล่งต่างๆ เช่น S3, DynamoDB, และ Kinesis
* **Logs:** บริการนี้จะส่ง Log 3 ประเภทไปยัง CloudWatch:
    1. Error logs (บันทึกข้อผิดพลาด)
    2. Search slow logs (ตรวจสอบประสิทธิภาพการค้นหา)
    3. Index slow logs (ตรวจสอบกระบวนการทำดัชนี)

---

### ความปลอดภัย (Security)
* รองรับมาตรฐาน **HIPAA, PCI DSS, SOC, และ ISO**
* เชื่อมต่อผ่าน **VPC** (ปลอดภัยภายในเครือข่าย AWS) หรือผ่านอินเทอร์เน็ตสาธารณะ
* **การยืนยันตัวตน:** ใช้ **Amazon Cognito** และ **AWS IAM**
* **การเข้ารหัส:** รองรับการเข้ารหัสข้อมูลทั้งในขณะจัดเก็บ (At-rest) และระหว่างการส่งผ่าน (In-transit)
* **นโยบายการเข้าถึง (Policies):**
    * **Resource-based:** กำหนดที่ตัวโดเมน
    * **Identity-based:** กำหนดที่ผู้ใช้หรือบทบาท IAM
    * **IP-based:** จำกัดตามหมายเลข IP หรือ CIDR blocks

---

### ความพร้อมใช้งาน (Availability)
* สามารถ Deploy ข้าม **Availability Zones (AZ)** ได้สูงสุด 3 โซน
* **Dedicated Master Nodes:** จะถูกกระจายไปยัง 3 AZ โดยอัตโนมัติเพื่อรักษาสถียรภาพของคลัสเตอร์และคะแนนเสียง (Quorum) แม้ว่าคุณจะเลือกใช้งานเพียง 2 AZ ก็ตาม
* **Replicas:** แนะนำให้สร้าง Replica อย่างน้อย 1 ชุดสำหรับแต่ละดัชนีเพื่อให้ระบบสามารถกระจายข้อมูลข้ามโซนได้ (Cross-zone replication)

---

### ข้อจำกัด (Limitations)
* เลือกได้เพียงอย่างเดียวระหว่าง **VPC** หรือ **Public Endpoint** และไม่สามารถสลับเปลี่ยนภายหลังได้
* ไม่สามารถย้ายโดเมนไปยัง VPC อื่นหลังจากที่สร้างไปแล้วได้
* ไม่รองรับ VPC ที่ใช้ Dedicated Tenancy

---

### ค่าบริการ (Pricing)
* จ่ายตามจำนวนชั่วโมงการใช้งาน **EC2** และขนาดรวมของ **EBS** ที่เชื่อมต่ออยู่
* สามารถใช้ **Reserved Instances** เพื่อลดค่าใช้จ่ายในระยะยาวได้

### กรณีการใช้งาน (Use Cases)
* วิเคราะห์ Log (Log Analytics)
* ตรวจสอบการทำงานของแอปพลิเคชันแบบเรียลไทม์
* วิเคราะห์ความปลอดภัย (Security Analytics)
* ค้นหาข้อความแบบเต็มรูปแบบ (Full Text Search)
* วิเคราะห์พฤติกรรมการคลิกบนเว็บไซต์ (Clickstream Analytics)
