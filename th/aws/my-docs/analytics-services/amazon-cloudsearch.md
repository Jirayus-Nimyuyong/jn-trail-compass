# Amazon CloudSearch Cheat Sheet

บริการแบบ Managed เต็มรูปแบบบนคลาวด์ของ AWS ที่ช่วยให้การตั้งค่า จัดการ และขยายระบบการค้นหา (Search Solution) สำหรับเว็บไซต์หรือแอปพลิเคชันของคุณทำได้ง่าย

### คุณสมบัติเด่น (Features)
* สามารถใช้ CloudSearch เพื่อทำดัชนี (Index) และค้นหาได้ทั้งข้อมูลแบบมีโครงสร้าง (Structured Data) และข้อความทั่วไป (Plain Text)
* **การค้นหาข้อความเต็มรูปแบบ (Full text search):** พร้อมการประมวลผลข้อความเฉพาะตามภาษา
* **ความสามารถในการค้นหา:** * Boolean search (ตัวดำเนินการบูลีน)
    * Prefix searches (ค้นหาจากคำนำหน้า)
    * Range searches (ค้นหาตามช่วงข้อมูล)
    * Term boosting (การเน้นความสำคัญของคำ)
    * Faceting (การจัดหมวดหมู่ผลลัพธ์)
    * Highlighting (การเน้นคำที่ค้นพบ)
    * Autocomplete Suggestions (การแนะนำคำอัตโนมัติ)
* **รูปแบบผลลัพธ์:** รองรับ JSON หรือ XML สามารถเรียงลำดับและกรองผลลัพธ์ตามค่าในฟิลด์ ตัวอักษร ตัวเลข หรือนิพจน์ที่กำหนดเอง (Custom expressions)
* **การปรับขนาด:** ปรับขนาดอัตโนมัติตามปริมาณข้อมูลที่อัปโหลด ความเสถียร และความซับซ้อนของคำขอค้นหา
* **การเชื่อมต่อ:** สามารถทำงานร่วมกับ **API Gateway** ได้

### เอนด์พอยต์ที่สำคัญ (Endpoints)
CloudSearch ใช้เอนด์พอยต์แยกกันตามโดเมนและบริการ:
* **Document Service Endpoint:** `http://doc-domainname–domainid.us-east-1.cloudsearch.amazonaws.com` — ใช้สำหรับอัปโหลดเอกสาร
* **Search Endpoint:** `http://search-domainname–domainid.us-east-1.cloudsearch.amazonaws.com` — ใช้สำหรับส่งคำขอค้นหา

### แนวคิดหลัก (Concepts)
* **Search Domain:** หน่วยพื้นฐานที่ต้องสร้างเพื่อเริ่มค้นหาข้อมูล หากมีชุดข้อมูลหลายชุดที่แยกกัน สามารถสร้างได้หลายโดเมน
* **Search Partition:** ส่วนของข้อมูลที่เก็บไว้ในอินสแตนซ์การค้นหาหนึ่งเครื่อง โดเมนหนึ่งอาจมีหนึ่งหรือหลายพาร์ทิชัน และจำนวนพาร์ทิชันสามารถเปลี่ยนได้ตามจำนวนเอกสารที่ถูกทำดัชนี
* **Facet:** ฟิลด์ดัชนีที่เป็นตัวแทนของหมวดหมู่ ใช้เพื่อกรองผลลัพธ์ให้แคบลงและดูจำนวนผลลัพธ์ในแต่ละหมวดหมู่ (Hits)
* **Analysis Scheme:** ชุดการวิเคราะห์เฉพาะภาษาที่ควบคุมการทำข้อความให้เป็นมาตรฐาน (Normalized), การตัดคำ (Tokenized) และการหาคำหลัก (Stemmed) เพื่อใช้ในระหว่างการทำดัชนี
* **Relevance Score:** คะแนนความเกี่ยวข้องที่ระบบคำนวณให้ โดยปกติผลลัพธ์จะเรียงตามคะแนนนี้เพื่อให้ได้ผลลัพธ์ที่ตรงกับคำค้นหามากที่สุด

---

### การปรับขนาด (Scaling)
1.  **Scaling for Traffic (ขยายตามทราฟฟิก):** เมื่อโหลดใกล้เต็ม CloudSearch จะเพิ่มอินสแตนซ์ที่ซ้ำกัน (Duplicate) เพื่อเพิ่มกำลังการประมวลผล และจะลดจำนวนลงเมื่อทราฟฟิกลดเพื่อประหยัดค่าใช้จ่าย
2.  **Scaling for Data (ขยายตามข้อมูล):** เมื่อข้อมูลมีขนาดใหญ่เกินความจุ CloudSearch จะเปลี่ยนไปใช้อินสแตนซ์ประเภทที่ใหญ่ขึ้น หากยังไม่พอจะทำการแบ่งพาร์ทิชันดัชนีข้ามหลายอินสแตนซ์ และจะลดขนาดลงเมื่อข้อมูลลดลง

### ความทนทานต่อความเสียหาย (Fault Tolerance)
* สามารถเปิดใช้งานตัวเลือก **Multi-AZ** เพื่อสร้างอินสแตนซ์สำรองใน Availability Zone ที่สองในภูมิภาคเดียวกัน เพื่อให้ระบบพร้อมใช้งานเสมอ (High Availability) โดยรองรับสูงสุด 2 AZs

---

### การตรวจสอบและติดตาม (Monitoring)
* ดูข้อมูลโดเมนผ่าน Console, CLI หรือ SDK
* ตรวจสอบสถานะผ่าน **Amazon CloudWatch**
* บันทึกการเรียกใช้ API ผ่าน **AWS CloudTrail**

### ค่าบริการ (Pricing)
คิดค่าบริการตามการใช้งานรายเดือนในด้านต่างๆ ดังนี้:
* จำนวนอินสแตนซ์การค้นหา (Search Instances)
* การอัปโหลดเอกสารแบบชุด (Document batch uploads)
* คำขอ IndexDocuments
* การถ่ายโอนข้อมูล (Data transfer)
