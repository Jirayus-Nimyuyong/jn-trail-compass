# Amazon MSK Cheat Sheet

บริการ Apache Kafka แบบจัดการให้เบ็ดเสร็จ (Fully Managed) เพื่อใช้ในการนำเข้าและประมวลผลข้อมูลสตรีมมิ่งแบบเรียลไทม์

### แนวคิดหลัก (Concepts)

* **Configuration (การตั้งค่า):** หากคุณไม่ระบุการตั้งค่าเอง ระบบจะใช้ค่าเริ่มต้น (Default) ให้ สามารถใช้การตั้งค่าแบบกำหนดเอง (Custom Configuration) กับคลัสเตอร์ใหม่หรือที่มีอยู่เดิมได้ เพื่อระบุคุณสมบัติและค่าต่างๆ ตามต้องการ
* **เวอร์ชันที่รองรับ:** ปัจจุบัน Amazon MSK รองรับ Apache Kafka เวอร์ชัน **3.8.x, 3.9.x, 4.0.x และ 4.1.x** พร้อมรายละเอียดการอัปเกรดและการทำงานร่วมกัน

### MSK Serverless
ประเภทคลัสเตอร์ที่ช่วยให้คุณรัน Apache Kafka ได้โดยไม่ต้องจัดการหรือปรับขนาดความจุของคลัสเตอร์เอง
* **ขยายตัวได้สูง:** รองรับจำนวน Partition ที่สูงขึ้น ช่วยให้สเกลเวิร์กโหลดการสตรีมได้มากขึ้นต่อหนึ่งคลัสเตอร์
* **การจัดการอัตโนมัติ:** จัดสรรและปรับขนาดความจุโดยอัตโนมัติ พร้อมจัดการ Partition ใน Topic ให้
* **การเชื่อมต่อ:** ทำงานร่วมกับ **PrivateLink** (การเชื่อมต่อส่วนตัว), **IAM** (การยืนยันตัวตน), **Glue Schema Registry**, **Kinesis Data Analytics (Flink)** และ **Lambda**

### MSK Connect
ช่วยในการสตรีมข้อมูลเข้าและออกจากคลัสเตอร์ Apache Kafka
* **Connector:** ทำหน้าที่คัดลอกข้อมูลจากแหล่งสตรีมมิ่งหรือคลัสเตอร์ไปยังจุดหมาย (Data Sink) อย่างต่อเนื่อง
    * **Source connectors:** นำข้อมูลจากระบบภายนอกเข้าสู่ Kafka Topics
    * **Sink connectors:** ส่งข้อมูลจาก Kafka Topics ออกไปยังระบบภายนอก (เช่น S3, OpenSearch และปัจจุบันรองรับ **EventBridge**)
* **Worker:** กระบวนการ JVM ที่รันตรรกะของ Connector โดยความจุจะถูกกำหนดด้วยจำนวน Worker และหน่วย **MSK Connect Units (MCUs)**
* **Capacity Modes:** เลือกได้ระหว่าง **Provisioned** (ระบุจำนวนที่แน่นอน) หรือ **Autoscaled** (ระบุค่าขั้นต่ำและสูงสุด)
* **Plugin:** โค้ดที่กำหนดตรรกะของ Connector ซึ่งสามารถนำไปใช้ซ้ำได้

### การเชื่อมต่อกับ Amazon MSK Cluster
* **การเข้าถึง:** โดยค่าเริ่มต้น คลัสเตอร์จะเข้าถึงได้เฉพาะจาก Client ที่อยู่ใน VPC เดียวกันเท่านั้น
* **ประเภท Broker:** รองรับทั้งแบบ **Standard** และ **Express** (แบบ Express มีโควตา Throughput ที่สูงกว่าและรองรับ Partition จำนวนมาก)
* **การเชื่อมต่อจากภายนอก:** สามารถทำได้โดยเปิด Public Access, ใช้ VPC Peering, Direct Connect, Transit Gateway หรือ VPN
* **การย้ายข้อมูล (Migration):** ใช้ **MirrorMaker** เพื่อย้ายจาก Kafka ทั่วไปมายัง MSK หรือย้ายระหว่างคลัสเตอร์ MSK
* **Cruise Control:** ใช้สำหรับ Rebalance คลัสเตอร์, ตรวจจับและแก้ไขสิ่งผิดปกติ รวมถึงตรวจสอบสถานะความสมบูรณ์ของคลัสเตอร์

---

### ความปลอดภัย (Security)
* **การควบคุมสิทธิ์:** ใช้ **IAM** เพื่อควบคุมว่าใครสามารถดำเนินการใดบนคลัสเตอร์ได้บ้าง
* **เครือข่าย:** ใช้ Security Group แยกต่างหากเพื่อจำกัดการเข้าถึงโหนด ZooKeeper
* **Express Brokers:** รองรับการต่ออายุใบรับรอง (Certificate) แบบไม่ขัดจังหวะการทำงาน ช่วยลดเวลา Downtime

### การตรวจสอบและติดตาม (Monitoring)
* **CloudWatch:** ใช้เก็บ Metrics และวิเคราะห์คลัสเตอร์ รวมถึงการตรวจสอบ **Consumer Lag** (ความล่าช้าในการประมวลผลของผู้รับข้อมูล)
* **Broker Logs:** สามารถส่ง Log ไปยัง CloudWatch Logs, S3 หรือ Amazon Data Firehose
* **MSK Connect Monitoring:** ติดตาม Throughput ผ่านเมทริกซ์ `SinkConsumerByteRate` และ `SourceProducerByteRate`

---

### ค่าบริการ (Pricing)
* **MSK มาตรฐาน:** จ่ายตามจำนวนอินสแตนซ์ของ Broker และปริมาณพื้นที่จัดเก็บ (Storage)
* **MSK Serverless:** จ่ายตามจำนวนคลัสเตอร์, Partition และปริมาณพื้นที่จัดเก็บ
* **MSK Connect:** จ่ายตามจำนวนและขนาด (MCUs) ของแต่ละ Kafka Connect Worker
