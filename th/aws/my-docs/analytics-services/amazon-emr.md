# Amazon EMR Cheat Sheet

**Amazon EMR** เป็นแพลตฟอร์มคลัสเตอร์แบบ Managed ที่ช่วยให้การรันเฟรมเวิร์ก Big Data เช่น Apache Hadoop และ Apache Spark บน AWS ทำได้ง่ายขึ้น เพื่อประมวลผลและวิเคราะห์ข้อมูลจำนวนมหาศาล

* สามารถประมวลผลข้อมูลเพื่อการวิเคราะห์และงานด้าน Business Intelligence (BI) โดยใช้ EMR ร่วมกับ Apache Hive และ Apache Pig
* ใช้ EMR ในการแปลงข้อมูล (Transform) และย้ายข้อมูลเข้า-ออกจากแหล่งเก็บข้อมูลหรือฐานข้อมูลอื่นๆ ของ AWS

---

### คุณสมบัติเด่น (Features)
* **EMR Notebooks:** สภาพแวดล้อมแบบ Managed ที่อ้างอิงจาก Jupyter Notebook ช่วยในการจัดเตรียมข้อมูล, สร้างภาพข้อมูล (Visualize) และทำงานร่วมกัน
* **ความยืดหยุ่น (Elasticity):** ปรับเพิ่มหรือลดความจุได้ตามความต้องการ ทั้งแบบอัตโนมัติหรือจัดการเอง
* **แหล่งเก็บข้อมูลหลากหลาย:** รองรับ S3, Hadoop Distributed File System (HDFS) และ DynamoDB
* **เครื่องมือ Big Data ครบครัน:** รองรับเครื่องมือจาก Hadoop (Hive, Pig, HBase, Impala) และเฟรมเวิร์กอื่นๆ (Spark, Presto) ผ่าน Bootstrap Actions

---

### ส่วนประกอบของ EMR (Components)
* **Clusters:** คอลเลกชันของอินสแตนซ์ EC2 แบ่งเป็น 2 ประเภท:
    1. **Transient cluster:** คลัสเตอร์ชั่วคราวที่จะปิดตัวเองอัตโนมัติเมื่อทำงานเสร็จ
    2. **Long-running cluster:** คลัสเตอร์ที่รันต่อเนื่องจนกว่าคุณจะสั่งปิดเอง
* **Nodes (โหนด):** อินสแตนซ์แต่ละเครื่องในคลัสเตอร์ แบ่งหน้าที่เป็น 3 ประเภท:
    1. **Master node:** จัดการคลัสเตอร์ ประสานงานการกระจายข้อมูลและงาน (ทุกคลัสเตอร์ต้องมี 1 โหนด)
    2. **Core node:** รันงานและเก็บข้อมูลใน HDFS (คลัสเตอร์แบบ Multi-node ต้องมีอย่างน้อย 1 โหนด)
    3. **Task node:** รันงานอย่างเดียว ไม่เก็บข้อมูลใน HDFS (เป็นตัวเลือกเสริม)

---

### สถาปัตยกรรม (EMR Architecture)
* **Storage (การจัดเก็บ):**
    * **HDFS:** ระบบไฟล์แบบกระจายตัวที่ขยายขนาดได้ ข้อมูลจะถูกเก็บไว้ในอินสแตนซ์ภายในคลัสเตอร์ (เป็นแบบชั่วคราว ข้อมูลจะหายไปเมื่อปิดคลัสเตอร์)
    * **EMRFS:** ส่วนขยายที่ทำให้ EMR เข้าถึงข้อมูลใน S3 ได้โดยตรงเสมือนเป็นระบบไฟล์ปกติ
* **Resource Management:** ใช้ **YARN** ในการจัดการทรัพยากรส่วนกลางและจัดตารางงาน (Scheduling)
* **Processing Frameworks:** เอนจินที่ใช้ประมวลผล เช่น Hadoop MapReduce และ Apache Spark

---

### การปรับขนาด (Scaling)
* **Deploy หลายคลัสเตอร์:** เปิดคลัสเตอร์ใหม่เพิ่มเมื่อต้องการความจุ และปิดเมื่อเลิกใช้งาน
* **Resize คลัสเตอร์เดิม:** เพิ่มอินสแตนซ์เพื่อเพิ่มพลังประมวลผลชั่วคราว หรือลดจำนวนลงเพื่อประหยัดค่าใช้จ่าย โดย EMR จะเลือกโหนดที่ว่าง (Idle) เพื่อไม่ให้กระทบงานที่รันอยู่

---

### ความพร้อมใช้งานสูง (High Availability)
* สามารถเปิดใช้ Master Node **3 เครื่อง** เพื่อทำ High Availability หากเครื่องหลักล้มเหลว ระบบจะทำการ Failover ไปยังเครื่อง Standby อัตโนมัติ

---

### การตรวจสอบและการรักษาความปลอดภัย (Monitoring & Security)
* **การตรวจสอบ:** เชื่อมต่อกับ **CloudTrail** (บันทึก API), **CloudWatch** (ติดตามประสิทธิภาพ) และสามารถจัดเก็บ Log ไฟล์ไว้ใน S3 เพื่อวิเคราะห์ย้อนหลัง
* **IAM:** จัดการสิทธิ์ผ่าน IAM Policies และ IAM Roles สำหรับบริการ EMR และตัวอินสแตนซ์
* **การรักษาความปลอดภัยเครือข่าย:** ใช้ **Security Groups** ควบคุมทราฟฟิก และรองรับการรันใน **VPC**
* **การยืนยันตัวตน:** รองรับโปรโตคอล **Kerberos** (เวอร์ชัน 5.10.0 ขึ้นไป)
* **การเข้ารหัส:** รองรับการเข้ารหัสข้อมูลใน S3 ทั้งฝั่ง Server และ Client ผ่าน EMRFS

---

### ค่าบริการ (Pricing)
* คิดค่าบริการเป็น **รายวินาที** (ขั้นต่ำ 1 นาที) สำหรับแต่ละโหนดที่ใช้งาน
* ค่าบริการ EMR เป็นส่วนที่ **จ่ายเพิ่ม** นอกเหนือจากค่าอินสแตนซ์ EC2 ปกติ และค่า EBS (ถ้ามี)
