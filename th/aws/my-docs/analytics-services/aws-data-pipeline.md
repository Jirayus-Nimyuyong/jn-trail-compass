# AWS Data Pipeline Cheat Sheet

**หมายเหตุสำคัญ:** AWS Data Pipeline **ไม่เปิดให้บริการสำหรับลูกค้าใหม่แล้ว** แต่ท่อส่งข้อมูล (Pipelines) เดิมที่ยังมีอยู่จะยังคงทำงานและจัดการได้โดยผู้ใช้ปัจจุบัน

### ภาพรวม (Overview)
* เป็นบริการเว็บสำหรับ **จัดตารางเวลาการเคลื่อนย้ายและประมวลผลข้อมูล** อย่างสม่ำเสมอใน AWS Cloud
* เป็นบริการ **Managed ETL** (Extract-Transform-Load) ที่เชื่อมต่อได้ทั้งระบบจัดเก็บข้อมูลบน On-premises และบนคลาวด์
* มีการเชื่อมต่อแบบ Native กับ: **S3, DynamoDB, RDS, EMR, EC2 และ Redshift**

### คุณสมบัติเด่น (Features)
* ช่วยลดภาระในการพัฒนาและบำรุงรักษาระบบจัดการข้อมูลรายวัน ทำให้คุณโฟกัสไปที่การสร้างอินไซต์จากข้อมูลได้มากขึ้น
* มี **Built-in Activities** สำหรับงานทั่วไป เช่น การคัดลอกข้อมูลระหว่าง S3 และ RDS หรือการรัน Query บน Log ใน S3
* รองรับฐานข้อมูลผ่าน JDBC, RDS และ Redshift

---

### ส่วนประกอบหลัก (Components)
1.  **Pipeline Definition:** การกำหนดตรรกะทางธุรกิจ (Business Logic) ของการจัดการข้อมูล
2.  **Pipeline:** ตัวจัดตารางเวลาและรันงาน โดยการสร้างอินสแตนซ์ EC2 เพื่อทำงานตามกิจกรรมที่กำหนดไว้
3.  **Task Runner:** แอปพลิเคชันที่คอยตรวจสอบงาน (Poll) และดำเนินการตามงานนั้นๆ (เช่น คัดลอกไฟล์ไปยัง S3 หรือเปิด EMR Cluster)
    * สามารถใช้ Task Runner ที่ AWS เตรียมไว้ให้ หรือเขียนขึ้นเองก็ได้ (Custom Task Runner)

---

### การกำหนดท่อส่งข้อมูล (Pipeline Definition)
Data Pipeline จะกำหนดงาน จัดตารางเวลา และมอบหมายงานให้ Task Runner โดยส่วนประกอบมีดังนี้:
* **Data Nodes:** ตำแหน่งของข้อมูลขาเข้า (Input) หรือตำแหน่งที่ต้องการจัดเก็บข้อมูลขาออก (Output)
* **Activities:** คำนิยามของงานที่ต้องทำตามตารางเวลา โดยใช้ทรัพยากรประมวลผล
* **Preconditions:** เงื่อนไขที่ต้องเป็นจริงก่อนที่งานจะเริ่มรันได้
    * **System-managed:** AWS จัดการให้โดยไม่ต้องใช้ทรัพยากรประมวลผลของเรา
    * **User-managed:** รันบนทรัพยากรประมวลผลที่คุณระบุเท่านั้น
* **Resources:** ทรัพยากรด้านการประมวลผลที่ใช้ทำงานตามที่ Pipeline กำหนด
* **Actions:** สิ่งที่จะให้ระบบทำเมื่อตรงตามเงื่อนไขที่ระบุ (เช่น ส่งแจ้งเตือนเมื่อ Activity ล้มเหลว)
* **Schedules:** กำหนดเวลาและความถี่ในการรันงาน (ต้องมีวันเริ่มต้นและความถี่เสมอ)

---

### รายละเอียดการทำงาน
* **Instances:** เมื่อ Pipeline ทำงาน ระบบจะรวบรวมส่วนประกอบต่างๆ เพื่อสร้างเป็น "Instance" ที่พร้อมทำงานจริง
* **Attempts:** หากงานล้มเหลว ระบบจะพยายามรันใหม่ (Retry) จนกว่าจะสำเร็จหรือครบจำนวนครั้งสูงสุดที่อนุญาต
* **Task Runners:** เมื่อติดตั้งแล้ว มันจะคอยถาม (Poll) AWS Data Pipeline ว่ามีงานที่เกี่ยวข้องกับ Pipeline ที่เราเปิดใช้งานอยู่หรือไม่ เมื่อได้รับมอบหมายงานแล้วจะทำงานและรายงานสถานะกลับไป

---

### AWS Data Pipeline vs Amazon SWF
* ทั้งคู่มีการติดตามผล (Execution tracking), จัดการการรันใหม่ (Retry) และการจัดการข้อผิดพลาด (Exception)
* **Data Pipeline:** ออกแบบมาโดยเฉพาะเพื่อจัดการขั้นตอนที่พบบ่อยในเวิร์กโหลดที่ **ขับเคลื่อนด้วยข้อมูล (Data-driven workflows)**

### ค่าบริการ (Pricing)
* คิดค่าบริการตาม **ความถี่** ที่ Activity และ Precondition ถูกตั้งให้รัน และ **ตำแหน่งที่รัน** (รันบน AWS หรือรันบน On-premises)
