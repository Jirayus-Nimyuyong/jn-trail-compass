# AWS Lake Formation Cheat Sheet

**AWS Lake Formation** เป็นบริการสำหรับจัดการและสร้าง Data Lake (ทะเลข้อมูล) 
* ทำหน้าที่จัดเก็บและทำบัญชีข้อมูล (Catalog) จากฐานข้อมูลและ Object Storage ก่อนจะถ่ายโอนไปยัง Data Lake บน S3 แห่งใหม่
* คุณสามารถใช้ ML Algorithms เพื่อทำความสะอาดและจำแนกข้อมูล รวมถึงรักษาความปลอดภัยของข้อมูลที่ละเอียดอ่อนด้วยการควบคุมสิทธิ์ที่ละเอียดในระดับคอลัมน์, แถว และเซลล์

### การทำงาน (How It Works)
1. **ระบุแหล่งข้อมูล:** ค้นหาแหล่งข้อมูลที่มีอยู่ เช่น S3 หรือฐานข้อมูล และย้ายข้อมูลไปยัง Data Lake
2. **เตรียมข้อมูล:** ข้อมูลจะถูก Crawl (สำรวจ), Catalog (จัดทำบัญชี) และจัดเตรียมให้พร้อมสำหรับการวิเคราะห์
3. **การเข้าถึง:** ให้สิทธิ์ผู้ใช้เข้าถึงข้อมูลผ่านบริการวิเคราะห์ที่พวกเขาต้องการ

---

### แนวคิดหลัก (Concepts)

#### 1. Data Lake
* การเก็บข้อมูลถาวรใน **Amazon S3** ทั้งข้อมูลแบบมีโครงสร้างและไม่มีโครงสร้าง รวมถึงข้อมูลดิบและข้อมูลที่ผ่านการแปลงแล้ว
* เมื่อคุณลงทะเบียนตำแหน่ง S3 เส้นทาง (Path) นั้นและโฟลเดอร์ย่อยทั้งหมดจะถูกลงทะเบียนด้วย
* **Amazon S3 Tables** สามารถจัดทำบัญชีใน Glue Data Catalog และลงทะเบียนเป็นตำแหน่งข้อมูลของ Lake Formation เพื่อการเข้าถึงที่มีการกำกับดูแล

#### 2. Data Catalog
* คลังเก็บเมทาดาตาถาวร (Metadata Store) ที่ช่วยให้ระบบต่างๆ สามารถค้นหาและติดตามข้อมูลที่กระจัดกระจาย (Data Silos) เพื่อใช้ในการคิวรีและแปลงข้อมูล
* **Federated Catalogs:** รองรับการกำกับดูแลแบบรวมศูนย์ทั้งใน S3 Data Lakes, Redshift, ฐานข้อมูล Operational และแหล่งข้อมูลบุคคลที่สาม
* **Data Catalog Views:** สร้าง View เพื่อควบคุมและสรุปการเข้าถึงข้อมูลพื้นฐานผ่าน Glue APIs, Athena หรือ Redshift

#### 3. Governed Tables (ตารางที่มีการกำกับดูแล)
เป็นฟีเจอร์เฉพาะของ Lake Formation ที่มีความสามารถดังนี้:
* **ACID transactions:** รับประกันความถูกต้องของข้อมูล
* **Automatic data compaction:** บีบอัดข้อมูลอัตโนมัติเพื่อเพิ่มประสิทธิภาพ
* **Time-travel queries:** คิวรีย้อนกลับไปดูสถานะข้อมูลในอดีตได้

#### 4. Blueprint & Workflow
* **Blueprint:** เทมเพลตสำเร็จรูปสำหรับการนำข้อมูลเข้าสู่ Data Lake (เช่น Database snapshot, Incremental database)
* **Workflow:** ตัวกำหนดแหล่งข้อมูลและตารางเวลาสำหรับการนำเข้าข้อมูล เป็นตัวประสานงาน (Orchestrator) ระหว่าง Glue jobs, crawlers และ triggers

### ความปลอดภัย (Security)
* **การเข้ารหัส:** ใช้ **AWS KMS** เพื่อเข้ารหัสและถอดรหัสข้อมูลใน S3
* **ประเภทของสิทธิ์:** * **Metadata access:** การเข้าถึงทรัพยากรใน Data Catalog
    * **Underlying data access:** การเข้าถึงตำแหน่งข้อมูลจริงใน S3
* **Credential Vending API:** ให้ข้อมูลประจำตัวชั่วคราวแก่ Engine ที่ได้รับอนุญาตเพื่อเข้าถึงข้อมูลแทนผู้ใช้
* **Tag-based access control (TBAC):** ใช้แท็กในการจัดการสิทธิ์สำหรับทรัพยากรจำนวนมากเพื่อให้ง่ายต่อการควบคุม
* **Data Filter:** สร้างตัวกรองข้อมูลเพื่อจำกัดการมองเห็นข้อมูลบางส่วน (ระดับแถว/คอลัมน์) ในผลลัพธ์การคิวรี

### ค่าบริการ (Pricing)
* คิดค่าบริการตาม **จำนวนคำขอธุรกรรม (Transaction requests)** และ **พื้นที่จัดเก็บเมทาดาตา (Metadata storage)**
* คิดค่าบริการจากการ **กรองข้อมูล (Data filtering)** หรือจำนวนไบต์ที่สแกนโดย Storage API
* คิดค่าบริการตามจำนวนไบต์ที่ประมวลผลโดย **Storage Optimizer**
