# Amazon Redshift Cheat Sheet

บริการคลังข้อมูล (Data Warehouse) ระดับ **Petabyte** แบบ Managed เต็มรูปแบบ
* Redshift ช่วยขยายการคิวรีคลังข้อมูลไปยัง Data Lake ของคุณ โดยคุณสามารถรันการวิเคราะห์กับข้อมูลระดับ Petabyte ที่เก็บไว้ใน Redshift และข้อมูลระดับ Exabyte ที่เก็บไว้ใน S3 ได้โดยตรง
* Redshift เป็นฐานข้อมูลประเภท **OLAP** (Online Analytical Processing)
* รองรับการติดตั้งทั้งแบบ **Single-AZ** และ **Multi-AZ** (สำหรับ RA3) รวมถึงมีตัวเลือกแบบ **Serverless** ที่จัดสรรและปรับขนาดความจุโดยอัตโนมัติ

---

### คุณสมบัติเด่น (Features)
* **การจัดเก็บและประมวลผล:** ใช้การเก็บข้อมูลแบบแนวคอลัมน์ (**Columnar Storage**), การบีบอัดข้อมูล และ Zone Maps เพื่อลดปริมาณ I/O และใช้สถาปัตยกรรมแบบ **Massively Parallel Processing (MPP)** เพื่อประมวลผล SQL แบบขนาน
* **ประสิทธิภาพ:** ใช้ Machine Learning เพื่อเพิ่ม Throughput ตามเวิร์กโหลด และใช้ **Result Caching** เพื่อให้การตอบสนองคิวรีที่รันซ้ำทำได้รวดเร็วในระดับต่ำกว่าวินาที
* **การสำรองข้อมูล:** สำรองข้อมูลไปยัง **S3** อัตโนมัติและต่อเนื่อง และสามารถทำ Replication ไปยัง Region อื่นเพื่อใช้ในการกู้คืนระบบ (Disaster Recovery)
* **Multi-AZ:** สำหรับ RA3 จะทำงานแบบ Active-Active ข้าม Availability Zones เพื่อให้ความพร้อมใช้งานสูง (High Availability) โดยมีค่า **RPO เป็นศูนย์**
* **Zero-ETL Integrations:** วิเคราะห์ข้อมูลจาก **Amazon Aurora** และ **Amazon DynamoDB** ได้เกือบเรียลไทม์โดยไม่ต้องสร้างท่อส่งข้อมูล (ETL Pipelines) ที่ซับซ้อน
* **Query Editor v2:** เครื่องมือเขียน SQL บนเว็บ รองรับ **Amazon Q** ที่ใช้ภาษาธรรมชาติ (Natural Language) ในการเขียนคิวรี

---

### ตัวเลือกการติดตั้ง (Deployment Options)
1. **Amazon Redshift Serverless:**
    * ปรับขนาดอัตโนมัติตามความต้องการโดยไม่ต้องจัดการคลัสเตอร์ ความจุวัดหน่วยเป็น **Redshift Processing Units (RPUs)**
    * **เหมาะสำหรับ:** เวิร์กโหลดที่เปลี่ยนแปลงบ่อย คาดการณ์ไม่ได้ หรือโปรเจกต์ใหม่ที่ต้องการความง่าย
2. **Amazon Redshift Provisioned:**
    * จัดการคลัสเตอร์ด้วยตนเอง แบ่งประเภทโหนดเป็น:
        * **RA3:** (แนะนำ) แยกส่วนประมวลผลและจัดเก็บออกจากกัน (**Redshift Managed Storage - RMS**) ทำให้สเกลแยกกันได้
        * **DC2:** เน้นประสิทธิภาพการประมวลผลสำหรับข้อมูลขนาดเล็กที่ต้องการความหน่วงต่ำ

---

### ส่วนประกอบของโหนด (Nodes)
* **Leader Node:** รับคิวรีจาก Client, วางแผนการทำงาน (Execution Plans), ประสานงานกับ Compute Nodes และรวบรวมผลลัพธ์ส่งกลับให้ Client
* **Compute Nodes:** รันงานตามแผนที่ได้รับและส่งข้อมูลระหว่างกันเพื่อประมวลผล
* **ประเภทโหนด:**
    * **Dense Storage (DS):** สำหรับข้อมูลขนาดใหญ่มาก (ใช้ HDD)
    * **Dense Compute (DC):** สำหรับงานที่เน้นประสิทธิภาพสูง (ใช้ SSD)

---

### คุณสมบัติการคิวรีและนำเข้าข้อมูล
* **Redshift Spectrum:** คิวรีข้อมูลระดับ Exabyte ใน S3 ได้โดยไม่ต้องโหลดข้อมูลลงเครื่อง รองรับรูปแบบ **Apache Iceberg, Delta Lake และ Hudi**
* **Streaming Ingestion:** นำเข้าข้อมูลโดยตรงจาก **Kinesis Data Streams** หรือ **Amazon MSK** ด้วย SQL โดยไม่ต้องพักข้อมูลใน S3 ก่อน ทำให้มีความหน่วงต่ำมาก
* **Redshift ML:** สร้างและติดตั้งโมเดล Machine Learning โดยใช้ SQL (ทำงานร่วมกับ **Amazon SageMaker Autopilot**)
* **Data Sharing:** แชร์ข้อมูลสดๆ ข้ามคลัสเตอร์, ข้ามบัญชี หรือข้าม Region โดยไม่ต้องคัดลอกข้อมูล
* **Cross-Database Query:** คิวรีข้ามฐานข้อมูลที่อยู่ในคลัสเตอร์เดียวกันได้ (เฉพาะ RA3)

---

### การสำรองข้อมูล (Snapshots)
* **อัตโนมัติ:** ทำทุก 8 ชั่วโมง หรือเมื่อข้อมูลเปลี่ยนไป 5 GB ต่อโหนด มีระยะเวลาเก็บรักษา (Retention) เริ่มต้น 1 วัน
* **ด้วยตนเอง (Manual):** เก็บไว้ได้ตลอดไปแม้ลบคลัสเตอร์แล้ว และแชร์ให้บัญชีอื่นได้
* **พื้นที่ฟรี:** Redshift ให้พื้นที่เก็บ Snapshot ฟรีเท่ากับความจุของคลัสเตอร์คุณ

---

### ความปลอดภัยและการตรวจสอบ (Security & Monitoring)
* **เครือข่าย:** ใช้ VPC Security Groups (หรือ Redshift Security Groups สำหรับรุ่นเก่า) และรองรับ **Enhanced VPC Routing** เพื่อจัดการทราฟฟิกผ่าน VPC ของคุณเอง
* **การเข้ารหัส:** สามารถเลือกเข้ารหัสคลัสเตอร์ตอนสร้างได้ (Snapshot จะถูกเข้ารหัสตามไปด้วย)
* **การตรวจสอบ:** บันทึก **Database Audit Logging** ลง S3 (เก็บข้อมูลการเชื่อมต่อ, การล็อกอิน, คิวรีที่รัน) และดู Performance Metrics ผ่าน **CloudWatch**

---

### ค่าบริการ (Pricing)
* **Provisioned:** จ่ายรายวินาทีตามประเภทและจำนวนโหนด (รองรับ **Reserved Instances** สัญญา 1 หรือ 3 ปีเพื่อลดค่าใช้จ่าย)
* **Serverless:** จ่ายตามความจุประมวลผลที่ใช้ (RPUs) และพื้นที่จัดเก็บ (RMS)
* **Spectrum:** จ่ายตามปริมาณไบต์ (Bytes) ที่สแกนข้อมูลใน S3
