# Amazon Kinesis Cheat Sheet
ช่วยให้การรวบรวม ประมวลผล และวิเคราะห์ข้อมูลแบบ Streaming เรียลไทม์เป็นเรื่องง่าย รองรับทั้งวิดีโอ, เสียง, Application Logs, Clickstreams และข้อมูล IoT เพื่อนำไปใช้ใน Machine Learning หรือการวิเคราะห์อื่นๆ

---

## 1. Kinesis Video Streams
บริการแบบ Managed สำหรับสตรีมวิดีโอสดจากอุปกรณ์ขึ้น AWS Cloud เพื่อประมวลผลแบบเรียลไทม์หรือวิเคราะห์แบบ Batch

### คุณสมบัติและส่วนประกอบ
* **รองรับอุปกรณ์จำนวนมาก:** เชื่อมต่อและสตรีมจากอุปกรณ์นับล้านได้
* **การจัดเก็บ:** กำหนดระยะเวลาจัดเก็บข้อมูล (Retention) ได้ตามต้องการ ข้อมูลจะถูกดัชนี (Index) ตาม Timestamp
* **Serverless:** ไม่ต้องตั้งค่าหรือจัดการโครงสร้างพื้นฐาน
* **ความปลอดภัย:** บังคับใช้การเข้ารหัส TLS ขณะรับส่งข้อมูล และเข้ารหัสข้อมูลที่จัดเก็บ (At rest) ด้วย AWS KMS
* **ส่วนประกอบหลัก:** * **Producer:** แหล่งกำเนิดข้อมูล
    * **Stream:** ทรัพยากรที่ใช้ขนส่งและจัดเก็บวิดีโอ (ข้อมูลถูกเก็บเป็น **Fragments** และ **Chunks**)
    * **Consumer:** แอปพลิเคชันที่นำวิดีโอไปดูหรือวิเคราะห์
* **การเล่นวิดีโอ (Playback):** รองรับ **HLS** สำหรับการดูสด และ **GetMedia API** สำหรับการสร้างแอปประมวลผลที่มีความหน่วงต่ำ

## 2. Kinesis Data Streams
บริการนำเข้าและประมวลผลข้อมูลที่มีความทนทานสูงและขยายตัวได้มหาศาล (Massively Scalable)

### แนวคิดหลัก (Concepts)
* **Shard:** หน่วยพื้นฐานของความจุ (Throughput)
    * 1 Shard รองรับการเขียน (Ingest) **1,000 records/sec** หรือ **1 MB/sec**
    * รองรับการอ่าน (Output) **2 MB/sec**
    * **Enhanced Fan-out:** ช่วยให้ Consumer แต่ละรายได้ Throughput แยกกันที่ 2 MB/sec (ไม่ต้องแชร์กับใคร)
* **Data Record:** หน่วยข้อมูลที่เก็บใน Stream ประกอบด้วย Sequence Number, Partition Key และ Data Blob (ขนาดสูงสุด **1 MB**)
    * *หมายเหตุ:* Kinesis รองรับขนาด Record รวมสูงสุดได้ถึง **10 MiB** ในบางกรณี
* **Retention:** เก็บข้อมูลได้นาน **24 ชั่วโมง** และขยายได้สูงสุด **7 วัน**
* **Partition Key:** ใช้จัดกลุ่มและกำหนดว่าข้อมูลจะไปลงที่ Shard ไหน (เช่น User ID)
* **Scaling:** เพิ่มหรือลดจำนวน Shard ได้ตลอดเวลาตามปริมาณข้อมูล

### ความปลอดภัยและราคา
* **ความปลอดภัย:** เข้ารหัสอัตโนมัติด้วย **AWS KMS** และรองรับ **VPC Endpoint**
* **ราคา:** คิดตามจำนวน Shard รายชั่วโมง และหน่วย PUT Payload (ต่อล้านหน่วย)

## 3. Kinesis Data Firehose
วิธีที่ง่ายที่สุดในการโหลดข้อมูล Streaming ไปยังแหล่งเก็บข้อมูล (Data Stores) และเครื่องมือวิเคราะห์

### คุณสมบัติหลัก
* **Fully Managed:** ปรับขนาดอัตโนมัติตามปริมาณข้อมูล
* **จุดหมายปลายทาง (Destinations):** ส่งข้อมูลไปยัง **S3, Redshift, OpenSearch, Splunk** และ HTTP Endpoints อื่นๆ (เช่น Datadog, MongoDB)
* **การแปลงข้อมูล (Transformation):** * สามารถเรียก **AWS Lambda** เพื่อแปลงข้อมูลก่อนส่ง
    * แปลงรูปแบบไฟล์จาก JSON เป็น **Parquet หรือ ORC** ก่อนเก็บใน S3 เพื่อประหยัดพื้นที่และคิวรีได้เร็วขึ้น
* **Buffering:** ข้อมูลจะถูกรวมกลุ่มตามขนาด (Buffer Size) หรือเวลา (Buffer Interval) ก่อนส่งไปยังปลายทาง

## 4. Kinesis Data Analytics
วิเคราะห์ข้อมูล Streaming และตอบสนองต่อความต้องการทางธุรกิจแบบเรียลไทม์โดยใช้ SQL หรือ Java (Apache Flink)

### คุณสมบัติหลัก
* **Serverless:** ไม่ต้องจัดการโครงสร้างพื้นฐาน ปรับขนาดแบบ Elastic ตามปริมาณข้อมูล
* **SQL Features:** ใช้มาตรฐาน ANSI SQL เพื่อสร้าง Query วิเคราะห์ข้อมูลสดๆ รองรับการทำ Anomaly Detection (ตรวจจับสิ่งผิดปกติ)
* **Java Features (Apache Flink):** สำหรับการประมวลผลที่ซับซ้อน รองรับการประมวลผลแบบ **Exactly-once** (ข้อมูลแต่ละตัวถูกประมวลผลเพียงครั้งเดียวอย่างแม่นยำ)
* **Kinesis Processing Unit (KPU):** หน่วยวัดความจุ (1 KPU = Memory 4 GB + Compute + Network)
* **Application Storage:** ให้พื้นที่เก็บสถานะแอปพลิเคชัน (State) 50 GB ต่อ KPU ซึ่งจะถูกเข้ารหัสและบันทึกแบบ Incremental (Checkpoints)

### ราคา
* คิดราคาเป็นรายชั่วโมงตามจำนวน **KPU** ที่ใช้งานเฉลี่ย
* สำหรับ Java แอปพลิเคชัน จะมีค่า KPU เพิ่มเติม 1 หน่วยสำหรับการจัดการ (Orchestration) และค่าพื้นที่จัดเก็บข้อมูล (Storage/Backups)
