# Amazon Athena Cheat Sheet

**Amazon Athena** เป็นบริการคิวรีข้อมูลแบบโต้ตอบ (Interactive Query) ที่ช่วยให้การวิเคราะห์ข้อมูลใน **Amazon S3** และแหล่งข้อมูลอื่นๆ ทำได้ง่ายโดยใช้ภาษา **SQL** มาตรฐาน

### คุณสมบัติเด่น (Features)
* **Serverless:** ไม่ต้องบริหารจัดการเซิร์ฟเวอร์
* **Query Editor:** มีตัวแก้ไขคิวรีในตัวบนหน้าคอนโซล
* **Engine:** ใช้เอนจินพื้นฐานจาก Trino (Open source distributed SQL) ที่ปรับแต่งมาเพื่อความหน่วงต่ำ (Low latency) และการวิเคราะห์แบบเฉพาะกิจ (Ad hoc)
* **รูปแบบข้อมูลที่รองรับ:** CSV, JSON, ORC, Avro และ Parquet
* **การทำงานแบบขนาน:** ประมวลผลคิวรีแบบ Parallel โดยอัตโนมัติ ทำให้ได้ผลลัพธ์รวดเร็วแม้ในชุดข้อมูลขนาดใหญ่
* **การเชื่อมต่อ:**
    * ทำงานร่วมกับ **Amazon QuickSight** เพื่อสร้างภาพข้อมูล (Visualization)
    * เชื่อมต่อกับ **AWS Glue Data Catalog** เพื่อเก็บ Schema ข้อมูล
    * รองรับ **Amazon S3 Tables** ทำให้สร้างและคิวรีตารางได้โดยตรงจาก S3 console
* **Managed Query Results:** เก็บและจัดการข้อมูลผลลัพธ์คิวรีใน S3 โดยไม่มีค่าใช้จ่ายเพิ่มเติมสำหรับตัวฟีเจอร์การจัดการ

---

### การคิวรี (Queries)
* **ข้อมูลภูมิสารสนเทศ:** รองรับการคิวรีข้อมูล Geospatial
* **ประวัติคิวรี:** เก็บประวัติการคิวรีไว้นาน 45 วัน
* **User-Defined Functions (UDFs):** สร้างฟังก์ชันเองได้โดยรันผ่าน **AWS Lambda** (รองรับแบบ Scalar UDF ที่ประมวลผลทีละแถว)
* **ประเภทข้อมูล:** รองรับทั้งแบบพื้นฐาน (Integer, Varchar) และแบบซับซ้อน (Map, Array, Struct)
* **ไดรเวอร์ JDBC:** มีการอัปเดตไดรเวอร์เพื่อให้เชื่อมต่อกับแอปพลิเคชันภายนอกได้ดีขึ้น

---

### Athena Federated Queries (การคิวรีแบบรวมศูนย์)
ช่วยให้คิวรีข้อมูลจากแหล่งอื่นที่ไม่ใช่ S3 ได้โดยใช้ **Data Connector** (รันบน Lambda)
* **แหล่งข้อมูลที่รองรับ (Pre-built):** MySQL, PostgreSQL, Oracle, SQL Server, DynamoDB, Redshift, OpenSearch, DocumentDB, CloudWatch Logs, Apache Kafka
* **Custom Connector:** สามารถเขียนคอนเนคเตอร์เองได้โดยใช้ Athena Query Federation SDK

---

### การปรับแต่งประสิทธิภาพ (Optimizing Performance)
1.  **Data Partitioning (การแบ่งส่วนข้อมูล):** แบ่งข้อมูลตาม วันที่, ประเทศ หรือภูมิภาค เพื่อจำกัดปริมาณข้อมูลที่ต้องสแกน
2.  **Columnar Formats:** เปลี่ยนรูปแบบข้อมูลเป็นแนวคอลัมน์ เช่น **Parquet** หรือ **ORC**
3.  **Compression:** บีบอัดไฟล์ข้อมูล
4.  **Splittable Files:** ทำให้ไฟล์สามารถแยกอ่านแบบขนานได้
    * ไฟล์ **Avro, Parquet, ORC** แยกอ่านได้เสมอไม่ว่าจะบีบอัดแบบใด
    * ไฟล์ข้อความ (CSV, JSON) จะแยกอ่านได้ก็ต่อเมื่อบีบอัดด้วย **BZIP2** หรือ **LZO** เท่านั้น

---

### การควบคุมค่าใช้จ่าย (Cost Controls)
ใช้ **Workgroups** เพื่อแยกคิวรีตามทีมหรือแอปพลิเคชัน และบังคับใช้การจำกัดค่าใช้จ่าย:
* **Per-query limit:** จำกัดปริมาณการสแกนข้อมูลต่อหนึ่งคิวรี (หากเกิน คิวรีจะถูกยกเลิก)
* **Per-workgroup limit:** จำกัดปริมาณการสแกนข้อมูลรวมทั้งหมดของกลุ่มตามรายชั่วโมงหรือรายวัน

---

### Partition Projection
ฟีเจอร์ที่ช่วยให้ Athena "คาดการณ์" ข้อมูล Partition ได้จากสูตรที่ตั้งไว้ แทนการไปดึงข้อมูลจาก AWS Glue Data Catalog
* **ประโยชน์:** ลดเวลาและค่าใช้จ่ายในการโหลดข้อมูล Partition สำหรับชุดข้อมูลขนาดใหญ่มาก
* **เหมาะสำหรับ:** ข้อมูลที่มีรูปแบบชัดเจน เช่น ตัวเลขต่อเนื่อง (1, 2, 3), วันที่ (20260101, 20260102) หรือรหัสภูมิภาค

---

### ความปลอดภัย (Security)
* ควบคุมการเข้าถึงด้วย **IAM policies**, ACLs และ S3 bucket policies
* รองรับการคิวรีข้อมูลที่ถูกเข้ารหัสไว้ใน S3
* **คำแนะนำ:** ควรใช้การเข้ารหัสแบบ **SSE-KMS** สำหรับผลลัพธ์คิวรีเพื่อความปลอดภัยที่สูงขึ้น

---

### ค่าบริการ (Pricing)
* จ่ายตามการใช้งานจริง: **คิดตามปริมาณข้อมูลที่ถูกสแกนในแต่ละคิวรี**
* **คิวรีที่ล้มเหลว (Failed queries) จะไม่ถูกคิดเงิน**
* **เทคนิคประหยัดเงิน:** การบีบอัดข้อมูล, แบ่ง Partition และเปลี่ยนเป็น Columnar format จะช่วยลดปริมาณข้อมูลที่สแกนลงได้อย่างมาก ส่งผลให้ค่าใช้จ่ายถูกลงและทำงานเร็วขึ้น
