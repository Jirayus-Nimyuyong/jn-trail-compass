# Amazon S3 Cheat Sheet

**Amazon S3** จัดเก็บข้อมูลในรูปแบบของ **วัตถุ (Objects)** ภายใน **ถัง (Buckets)**
* **Object:** ประกอบด้วยตัวไฟล์ และข้อมูลเมทาดาตา (Metadata) ที่อธิบายไฟล์นั้น
* **Key:** คือตัวระบุเอกลักษณ์ (Unique Identifier) ของวัตถุภายใน Bucket
* **ความจุ:** ไม่จำกัด (Virtually unlimited)

---

## Buckets (ถังเก็บข้อมูล)
* **ชื่อ Bucket:** ต้องไม่ซ้ำกันทั่วโลก (Global Unique) และต้องเป็นชื่อที่ตรงตามมาตรฐาน DNS เมื่อสร้างแล้วเปลี่ยนชื่อไม่ได้
* **จำนวน:** ค่าเริ่มต้นสร้างได้ 10,000 Buckets ต่อบัญชี (ขอขยายได้ถึง 1 ล้าน)
* **ภูมิภาค (Region):** เลือกที่ตั้งทางภูมิศาสตร์ได้ แต่เมื่อเลือกแล้วเปลี่ยนไม่ได้
* **Directory Buckets:** ประเภทใหม่สำหรับ **S3 Express One Zone** เพื่อความหน่วงระดับมิลลิวินาทีเลขหลักเดียว



---

## รูปแบบความสอดคล้องของข้อมูล (Data Consistency Model)
* **Strong Read-After-Write Consistency:** S3 ให้ความสอดคล้องของข้อมูลแบบรุนแรงสำหรับทุกคำขอ (PUT, DELETE, GET, LIST) ทันทีที่เขียนหรือลบสำเร็จ คำขอถัดไปจะได้รับข้อมูลเวอร์ชันล่าสุดเสมอ
* **ข้อยกเว้น (Eventual Consistency):** การเปลี่ยนค่าคอนฟิกในระดับ Bucket (เช่น การเปิด Versioning) อาจใช้เวลาสั้นๆ ในการกระจายค่าไปทั่วระบบ

---

## ชั้นการจัดเก็บข้อมูล (Storage Classes)

| ชั้นการจัดเก็บ | การใช้งาน | ความทนทาน | AZ |
| :--- | :--- | :--- | :--- |
| **S3 Standard** | ข้อมูลที่เข้าถึงบ่อยทั่วไป | 11 9's | >=3 |
| **S3 Express One Zone** | งานที่ต้องการความเร็วสูงสุด (ความหน่วงต่ำมาก) | 11 9's | 1 |
| **S3 Intelligent-Tiering** | ข้อมูลที่รูปแบบการเข้าถึงไม่แน่นอน (ปรับชั้นอัตโนมัติ) | 11 9's | >=3 |
| **S3 Standard-IA** | ข้อมูลที่เข้าถึงไม่บ่อย แต่ต้องได้ข้อมูลทันที | 11 9's | >=3 |
| **S3 One Zone-IA** | เหมือน Standard-IA แต่เก็บ AZ เดียว (ประหยัดกว่า) | 11 9's | 1 |
| **S3 Glacier Instant Retrieval** | ข้อมูลเก็บนาน เข้าถึงน้อยมาก แต่ต้องได้ในระดับมิลลิวินาที | 11 9's | >=3 |
| **S3 Glacier Flexible Retrieval** | ข้อมูลเก็บถาวร (Archive) รอได้ระดับนาทีถึงชั่วโมง | 11 9's | >=3 |
| **S3 Glacier Deep Archive** | เก็บถาวรราคาถูกที่สุด รอได้ 12-48 ชั่วโมง | 11 9's | >=3 |

## การตั้งค่า Bucket (Bucket Configurations)
* **Versioning:** แนะนำให้เปิดใช้งานเป็น Best Practice เพื่อป้องกันการลบหรือเขียนทับโดยไม่ตั้งใจ
* **Static Website Hosting:** กำหนดให้ Bucket ทำหน้าที่เป็นเว็บไซต์นิ่งได้
* **Replication:** คัดลอกข้อมูลอัตโนมัติข้ามภูมิภาค (CRR) หรือภายในภูมิภาคเดียวกัน (SRR)
* **Lifecycle:** ตั้งกฎการย้ายชั้นข้อมูลหรือลบข้อมูลอัตโนมัติเพื่อประหยัดค่าใช้จ่าย
* **Transfer Acceleration:** ใช้โครงข่าย Edge ของ CloudFront เพื่อให้การอัปโหลด/ดาวน์โหลดข้ามโลกเร็วขึ้น

---

## Amazon S3 Objects (วัตถุ)
* วัตถุมีขนาดได้สูงสุด **50 TB** (แต่ถ้าไฟล์ใหญ่กว่า 5 GB ต้องใช้ Multipart Upload API)
* **Metadata:** มีทั้งแบบระบบ (เช่น วันที่สร้าง, ขนาด) และแบบที่ผู้ใช้กำหนดเอง
* **Object Lock:** ป้องกันการลบหรือเขียนทับ (WORM - Write Once, Read Many) เหมาะสำหรับงานที่ต้องทำตามกฎข้อบังคับ
* **S3 Select:** ช่วยให้ดึงเฉพาะข้อมูลที่ต้องการภายใน Object (เช่น เลือกบางคอลัมน์ในไฟล์ CSV/JSON) เพื่อเพิ่มประสิทธิภาพและลดต้นทุน

---

## Amazon S3 Tables (ใหม่!)
* ออกแบบมาสำหรับจัดเก็บข้อมูลในรูปแบบตาราง (Tabular data) เช่น ธุรกรรมประจำวัน
* เก็บในรูปแบบ **Apache Iceberg** ซึ่งปรับแต่งมาเพื่อการทำ Analytics
* ให้ประสิทธิภาพ (TPS) และทรูพุตในการคิวรีสูงกว่า Bucket ทั่วไป

---

## ความปลอดภัย (Security)
* **Bucket Policies:** ควบคุมการเข้าถึงแบบรวมศูนย์ (JSON)
* **Access Control Lists (ACLs):** ปัจจุบันถูกปิดใช้งานเป็นค่าเริ่มต้น (แนะนำให้ใช้ Bucket Policies แทน)
* **Access Grants:** เชื่อมต่ออัตลักษณ์จาก Directory (เช่น Active Directory) เข้ากับข้อมูล S3 โดยตรง
* **การเข้ารหัส (Encryption):**
    * **SSE-S3:** ใช้คีย์ที่ S3 จัดการ (เป็นค่าเริ่มต้นสำหรับทุก Bucket)
    * **SSE-KMS:** ใช้คีย์จาก AWS KMS (ตรวจสอบย้อนหลังได้)
    * **SSE-C:** ลูกค้าเป็นผู้จัดการคีย์เอง
* **MFA Delete:** ต้องใช้รหัสผ่านแบบชั่วคราว (MFA) ในการลบเวอร์ชันของวัตถุ

---

## การตรวจสอบ (Monitoring)
* **CloudWatch Alarms:** ติดตามมาตรวัดต่างๆ เช่น การใช้งานความจุ
* **CloudTrail:** บันทึกการเรียกใช้งาน API ทั้งหมด
* **S3 Storage Lens:** หน้าจอ Dashboard วิเคราะห์การใช้งานพื้นที่เก็บข้อมูลทั่วทั้งองค์กร

---

## ค่าบริการ (Pricing)
1. **Storage:** จ่ายตามขนาดและระยะเวลาที่เก็บ
2. **Requests:** จ่ายตามจำนวนครั้งที่เรียกใช้ (GET, PUT, LIST)
3. **Retrievals:** จ่ายเมื่อดึงข้อมูลจากชั้น IA หรือ Glacier
4. **Data Transfer:** จ่ายเมื่อโอนข้อมูลออกสู่อินเทอร์เน็ต (การโอนเข้าฟรี)
5. **Early Deletes:** ค่าธรรมเนียมหากลบข้อมูลก่อนระยะเวลาขั้นต่ำ (เช่น IA ต้องเก็บอย่างน้อย 30 วัน)
