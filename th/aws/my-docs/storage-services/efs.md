# Amazon EFS Cheat Sheet

**Amazon Elastic File System (Amazon EFS)** เป็นบริการจัดเก็บไฟล์แบบ Managed เต็มรูปแบบ ที่ช่วยให้การตั้งค่าและปรับขนาดพื้นที่เก็บข้อมูลบน AWS Cloud เป็นเรื่องง่าย
* เป็นระบบไฟล์แบบ Serverless ที่มีความยืดหยุ่นสูง (Elastic) เพียงแค่ตั้งค่าและปล่อยให้ระบบทำงานเอง (Set-and-forget) โดยที่คุณไม่ต้องเตรียมทรัพยากร (Provision) หรือจัดการความจุด้วยตัวเอง

---

## คุณสมบัติ (Features)
* AWS จัดการโครงสร้างพื้นฐานทั้งหมดให้คุณ ลดความยุ่งยากในการติดตั้ง แพตช์ และดูแลการตั้งค่าระบบไฟล์ที่ซับซ้อน
* รองรับโปรโตคอล **Network File System เวอร์ชัน 4 (NFSv4.1 และ NFSv4.0)**
* สามารถเมานต์ (Mount) เข้ากับอินสแตนซ์ EC2 ที่รัน Linux หรือ macOS (Big Sur ขึ้นไป) ได้ **ไม่รองรับ Windows**
* นอกจาก EC2 ยังสามารถเมานต์กับ ECS tasks, EKS pods และ Lambda functions ได้ด้วย
* อินสแตนซ์ EC2 หลายตัวสามารถเข้าถึงไฟล์เดียวกันได้พร้อมกัน (Shared Storage)
* **ความทนทาน:** เก็บข้อมูลและ Metadata กระจายไปหลาย Availability Zones (สำหรับคลาส Standard) หรือภายใน AZ เดียว (สำหรับคลาส One Zone)
* ปรับขนาดได้ถึงระดับ Petabyte และรองรับการเข้าถึงแบบขนาน (Massively Parallel)



* ให้ความสอดคล้องของข้อมูลที่แข็งแกร่ง (Strong consistency) และการล็อกไฟล์ (File locking)
* ควบคุมการเข้าถึงด้วยสิทธิ์แบบ **POSIX** (Portable Operating System Interface)
* ใช้ **AWS DataSync** เพื่อโอนย้ายข้อมูลจาก On-premises มายัง EFS ได้รวดเร็ว
* รองรับการสำรองข้อมูลแบบ Incremental อัตโนมัติด้วย **AWS Backup**
* **Replication Failback:** ช่วยซิงค์ข้อมูลกลับจากระบบไฟล์ปลายทางมายังต้นทางเพื่อทำ Disaster Recovery (DR)

---

## คลาสการจัดเก็บข้อมูลและการจัดการวงจรชีวิต (Storage Classes & Lifecycle)
* **EFS Standard:** สำหรับไฟล์ที่เข้าถึงบ่อย กระจายหลาย AZ
* **EFS Infrequent Access (IA):** ราคาประหยัด สำหรับไฟล์ที่เข้าถึงไม่บ่อย
* **EFS Archive:** คลาสใหม่ล่าสุด ราคาถูกลงกว่า IA ถึง 50% สำหรับข้อมูลที่เข้าถึงปีละไม่กี่ครั้ง
* **EFS One Zone / One Zone-IA:** เก็บข้อมูลใน AZ เดียว ราคาถูกกว่าแต่ความพร้อมใช้งานต่ำกว่า
* **Lifecycle Management:** ย้ายไฟล์ข้ามคลาสโดยอัตโนมัติ (เช่น จาก Standard ไป IA ไป Archive) ตามระยะเวลาที่ไม่ได้เข้าถึง (7, 14, 30, 60 หรือ 90 วัน)

---

## โหมดประสิทธิภาพ (Performance Modes)
* **General Purpose (ค่าเริ่มต้น):** เหมาะสำหรับงานที่ไวต่อความหน่วง (Latency-sensitive)
* **Max I/O:** สเกลทรูพุตและจำนวนการประมวลผลต่อวินาทีได้สูงมาก แต่ความหน่วงจะสูงขึ้นเล็กน้อย เหมาะกับ Big Data, งานประมวลผลวิดีโอ หรือการวิเคราะห์จีโนม

---

## โหมดทรูพุต (Throughput Modes)
* **Elastic (แนะนำ/ค่าเริ่มต้น):** ปรับขนาดตามการใช้งานจริงโดยอัตโนมัติ จ่ายเท่าที่ใช้ ไม่ต้อง Provision เหมาะกับงานที่คาดเดาไม่ได้
* **Provisioned:** กำหนดทรูพุตที่ต้องการเองโดยไม่ขึ้นกับปริมาณข้อมูลที่เก็บ
* **Bursting:** ทรูพุตสเกลตามขนาดของไฟล์ (ปัจจุบันถือเป็นโหมดรองจาก Elastic)

---

## จุดเชื่อมต่อและเป้าหมายการเมานต์ (Mount Targets & Access Points)
* **Mount Targets:** สร้างในแต่ละ AZ ภายใน VPC เพื่อให้ IP Address สำหรับ NFSv4 endpoint
* **DNS Name:** รูปแบบคือ `file-system-id.efs.aws-region.amazonaws.com`
* **Access Points:** ช่วยจัดการการเข้าถึงชุดข้อมูลที่ใช้ร่วมกัน โดยบังคับใช้ User/Group ของ OS และ Directory เฉพาะสำหรับแต่ละคำขอที่ผ่าน Access Point

---

## การจัดการระบบไฟล์ (Managing File Systems)
* รองรับการเข้ารหัสทั้งขณะรับ-ส่ง (In transit) และขณะจัดเก็บ (At rest)
* **การลบระบบไฟล์:** เป็นการทำลายข้อมูลที่ไม่สามารถเรียกคืนได้ ควร Unmount ก่อนลบเสมอ
* **DataSync:** ใช้คัดลอกไฟล์ระหว่าง EFS ข้ามภูมิภาคหรือข้ามบัญชีได้
* **การตรวจสอบ:** ใช้ **Amazon CloudWatch** เพื่อดูปริมาณการใช้พื้นที่และประสิทธิภาพ (เช่น `PercentIOLimit` เพื่อดู IOPS utilization)

---

## ความปลอดภัย (Security)
* ต้องมี Credentials ที่ถูกต้องและมีสิทธิ์ในการเข้าถึงทรัพยากร (IAM)
* โดยเริ่มต้นมีเฉพาะ Root user (UID 0) เท่านั้นที่มีสิทธิ์ R/W/E ใน Root Directory (`/`)
* ใช้ **Security Groups** ทั้งในฝั่ง EC2 และฝั่ง EFS Mount Targets
* สามารถใช้ IAM เพื่อระบุตัวตนของ NFS clients และจัดการสิทธิ์เฉพาะรายเครื่องได้

---

## การเปรียบเทียบ: EFS vs EBS vs S3



### ประสิทธิภาพ (Performance)
| บริการ | ความหน่วง (Latency) | การสเกลทรูพุต |
| :--- | :--- | :--- |
| **Amazon EFS** | ต่ำและสม่ำเสมอ | หลาย GB ต่อวินาที |
| **Amazon EBS (Provisioned IOPS)** | ต่ำที่สุดและสม่ำเสมอ | ระดับ Single GB ต่อวินาที |
| **Amazon S3** | ต่ำ (เมื่อผสมประเภทคำขอ) | หลาย GB ต่อวินาที |

### การจัดเก็บและการเข้าถึง (Storage & Access)
| บริการ | ความพร้อมใช้งาน/ความทนทาน | การเข้าถึง |
| :--- | :--- | :--- |
| **Amazon EFS** | กระจายหลาย AZ | อินสแตนซ์นับพันเชื่อมต่อพร้อมกันจากหลาย AZ |
| **Amazon EBS** | ภายใน AZ เดียว | เชื่อมต่อได้ 1 อินสแตนซ์ต่อ 1 วอลลุ่ม (ยกเว้น Multi-attach) |
| **Amazon S3** | กระจายหลาย AZ | เชื่อมต่อนับล้านผ่านเว็บ |

### กรณีการใช้งาน (Use Cases)
* **EFS:** Big data, งานวิดีโอ, Content Management, Home directories
* **EBS:** Boot volumes, ฐานข้อมูล (SQL/NoSQL), Data warehousing, ETL
* **S3:** Backups, Data lake, เก็บไฟล์ภาพ/วิดีโอสำหรับเว็บไซต์

## ค่าบริการ (Pricing)
* จ่ายตามพื้นที่จัดเก็บที่ใช้จริงต่อเดือน (Standard > IA > Archive)
* **Elastic Throughput:** จ่ายตามปริมาณข้อมูลที่อ่าน/เขียน (GB)
* **Data Access:** มีค่าธรรมเนียมในการอ่านไฟล์จาก IA/Archive และการย้ายไฟล์ข้ามคลาส
