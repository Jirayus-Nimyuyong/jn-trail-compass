# AWS Elastic Disaster Recovery (AWS DRS) Cheat Sheet

**AWS Elastic Disaster Recovery (AWS DRS)** เป็นบริการที่มีการจัดการเต็มรูปแบบ (Fully Managed) เพื่อการกู้คืนระบบจากภัยพิบัติที่รวดเร็ว เชื่อถือได้ และคุ้มค่า สำหรับเซิร์ฟเวอร์ทั้งแบบ Physical, Virtual และ Cloud-based บน AWS
* ระบบจะทำการคัดลอกข้อมูลในระดับบล็อก (Block-level replication) อย่างต่อเนื่องจากสภาพแวดล้อมต้นทาง เช่น โครงสร้างพื้นฐาน On-premises หรือผู้ให้บริการคลาวด์รายอื่น ไปยัง Subnet พื้นที่พักข้อมูล (Staging area) ใน AWS
* ในกรณีที่เกิดภัยพิบัติหรือระหว่างการซ้อมแผน AWS DRS จะช่วยให้สามารถเปิดใช้งานอินสแตนซ์กู้คืน (Recovery Instances) ที่พร้อมทำงานได้ทันทีบน AWS เพื่อให้แน่ใจว่าจะมีเวลาหยุดทำงาน (Downtime) และการสูญเสียข้อมูล (Data Loss) น้อยที่สุด

---

## คุณสมบัติ (Features)
* **การคัดลอกข้อมูลต่อเนื่อง (Continuous Replication):** คัดลอกข้อมูลระดับบล็อกเนทีฟจากต้นทางสู่ AWS
* **การจัดการแบบอัตโนมัติ (Automated Orchestration):** จัดการกระบวนการ Failover (สลับไปใช้ระบบสำรอง), การกู้คืน และการ Failback (สลับกลับระบบหลัก) อัตโนมัติ
* **การทดสอบที่ไม่กระทบระบบจริง (Non-disruptive Testing):** สามารถซ้อมแผนการกู้คืนได้โดยไม่ส่งผลกระทบต่อสภาพแวดล้อมที่ใช้งานจริง (Production)
* **การกู้คืนย้อนหลัง (Point-in-time Recovery):** รองรับการทำ Snapshot ย้อนหลังตามจุดเวลาที่ต้องการ
* **รองรับ OS หลากหลาย:** ใช้งานได้กับทั้ง Windows และ Linux เวอร์ชันต่างๆ
* **Failover ข้าม Region และข้าม AZ:** รองรับการกู้คืนภัยพิบัติทั้งในระดับภูมิภาคและระดับโซนภายใน AWS
* **การคัดลอกข้อมูลผ่าน Agent:** ติดตั้ง Agent ขนาดเล็ก (Lightweight) บนเครื่องต้นทาง
* **ประเภทอินสแตนซ์ที่ยืดหยุ่น:** สามารถเลือกประเภทอินสแตนซ์กู้คืนที่แตกต่างจากเซิร์ฟเวอร์ต้นทางเพื่อปรับแต่งต้นทุนหรือประสิทธิภาพได้
* **รองรับ AWS Outposts:** ช่วยให้สามารถกู้คืนระบบแบบ On-premises โดยมีความหน่วงต่ำ (Low-latency)
* **การทำงานร่วมกับบริการอื่น:** เชื่อมต่อกับ CloudWatch, CloudTrail, IAM และ AWS Systems Manager

---

## กรณีการใช้งาน (Use Cases)
* **On-premises to AWS:** ตั้งค่า DR สำหรับศูนย์ข้อมูลจริงหรือเสมือนมายัง AWS
* **Cloud-to-AWS:** ปกป้อง Workload จากคลาวด์อื่น (เช่น Azure, GCP) โดยการคัดลอกมายัง AWS
* **AWS-to-AWS:** ปกป้องอินสแตนซ์ EC2 โดยการคัดลอกไปยัง Region อื่น
* **การย้ายระบบ (Migration):** ย้ายแอปพลิเคชันเข้าสู่ AWS โดยแทบไม่มี Downtime
* **การปฏิบัติตามข้อกำหนด:** บรรลุเป้าหมาย RTO/RPO ตามที่กฎระเบียบหรือความต่อเนื่องทางธุรกิจกำหนด
* **การทดสอบ Failover:** ซ้อมแผนกู้คืนโดยไม่ขัดจังหวะการทำงานของระบบหลัก

---

## แนวทางปฏิบัติที่ดี (Best Practices)
* **ซ้อมแผนสม่ำเสมอ:** กำหนดตารางซ้อมกู้คืนเพื่อตรวจสอบค่า RTO และฟังก์ชันการทำงานของแอปพลิเคชัน
* **ตรวจสอบสถานะการคัดลอก:** ใช้ CloudWatch ติดตามค่า Replication Lag และ Alert เมื่อสถานะเป็น "Stalled" หรือ "Lagging"
* **ปรับทรัพยากร Staging ให้เหมาะสม:** ใช้เครื่อง Staging ขนาดเล็กเพื่อประหยัดต้นทุน แต่ต้องมั่นใจว่าเครื่อง Recovery มีประสิทธิภาพเพียงพอต่อการใช้งานจริง
* **ความปลอดภัยของพื้นที่ Staging:** ใช้ Security Group ที่เข้มงวดกับ Staging Subnet เพื่อป้องกันการเข้าถึงข้อมูลที่กำลังคัดลอก
* **ตรวจสอบ Quotas:** มั่นใจว่า Region ปลายทางมี Quota ของ EC2 และ EBS เพียงพอสำหรับการรันเครื่องทั้งหมดพร้อมกัน

---

## ขั้นตอนการกู้คืนและสลับกลับ (Recovery and Failback)
1. **การเตรียมตัว (Preparing for failover):** ตรวจสอบว่าเครื่องต้นทางมีสถานะ "Healthy" และทำการซ้อม (Drill) เพื่อยืนยันการตั้งค่า Launch Settings
2. **การทำ Failover:** เริ่มดำเนินการเมื่อไซต์ต้นทางล่ม โดยจะเปิดเครื่อง Recovery Instances จาก Snapshot ย้อนหลังที่เลือกไว้
3. **การทำ Failback:** เมื่อไซต์หลักกลับมาใช้งานได้ จะทำการคัดลอกข้อมูลกลับจาก AWS ไปยังต้นทางเดิม (ต้องใช้ Failback Client) เพื่อให้แน่ใจว่าไม่มีข้อมูลสูญหายระหว่างทาง
4. **การกู้คืนข้าม AZ:** ปกป้องระบบจากการล่มของ AZ เดียว โดยการคัดลอกอินสแตนซ์ไปยัง AZ อื่นภายใน Region เดียวกัน

---

## ความปลอดภัย (Security)
* **การเข้ารหัส:** ข้อมูลถูกเข้ารหัสผ่าน TLS ระหว่างรับ-ส่ง และเข้ารหัส EBS เมื่อจัดเก็บ
* **การควบคุมการเข้าถึง:** ใช้ IAM Policy และ Role เพื่อจำกัดสิทธิ์เข้าถึง DRS
* **VPC Isolation:** สามารถสั่งรันเครื่องกู้คืนใน VPC ที่แยกส่วนเป็นเอกเทศได้
* **การบันทึก Log:** บันทึกกิจกรรมทั้งหมดผ่าน CloudTrail
* **รองรับ PrivateLink:** ใช้ AWS PrivateLink เพื่อหลีกเลี่ยงการส่งข้อมูลผ่านอินเทอร์เน็ตสาธารณะ

---

## ค่าบริการ (Pricing)
* **ค่าธรรมเนียมการคัดลอก:** $0.028 ต่อชั่วโมง ต่อเซิร์ฟเวอร์ต้นทาง (ประมาณ $20 ต่อเดือน)
* **ทรัพยากร Staging:** จ่ายค่า EBS Snapshot (ต่อ GB/เดือน) และค่าเครื่อง EC2 ที่ใช้พักข้อมูล
* **ค่าธรรมเนียมการซ้อม/กู้คืน:** ค่า EC2 และ EBS ที่เกิดขึ้นระหว่างการซ้อมหรือการกู้คืนจริงจะถูกคิดแยกต่างหาก
* **การสลับกลับ (Failback):** DRS ไม่คิดค่าบริการในการส่งข้อมูลกลับ แต่จะเสียค่าธรรมเนียมการโอนข้อมูลออก (Outbound data transfer) ตามปกติของ AWS

💡 **คำแนะนำ:** คุณสามารถลดค่าใช้จ่ายได้โดยการลบ Recovery Instances และ EBS Volume ทิ้งทันทีหลังจากจบการซ้อมแผน
