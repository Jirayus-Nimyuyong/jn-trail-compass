# Amazon S3 Glacier Cheat Sheet

**Amazon S3 Glacier** เป็นโซลูชันสำหรับการจัดเก็บข้อมูลระยะยาว (Archival) ที่ปรับแต่งมาเพื่อข้อมูลที่เข้าถึงไม่บ่อย หรือ "Cold data"
* Glacier เป็นบริการเว็บที่ทำงานบนพื้นฐานของ **REST**
* คุณสามารถจัดเก็บจำนวน Archive และปริมาณข้อมูลได้ไม่จำกัด
* ปัจจุบันคุณสามารถระบุชั้นการจัดเก็บเป็น Glacier (Flexible Retrieval) หรือ Deep Archive ได้ทันทีในขณะที่สร้างวัตถุ (ผ่าน S3 APIs)
* ออกแบบมาเพื่อให้อัตราความทนทาน (Durability) เฉลี่ยต่อปีอยู่ที่ 99.999999999% โดย Glacier จะจัดเก็บข้อมูลแบบซิงโครนัสกระจายไปหลาย Availability Zones (AZs) ก่อนจะยืนยันการอัปโหลดที่สำเร็จ
* เพื่อป้องกันการเสียหายของข้อมูลระหว่างการส่ง Glacier จะอัปโหลด **Checksum** ไปพร้อมกับข้อมูล และตรวจสอบความถูกต้องของข้อมูลทั้งตอนอัปโหลดและตอนดึงข้อมูลกลับ (Retrieval)
* Glacier ทำงานร่วมกับ **Amazon S3 Lifecycle Rules** เพื่อช่วยจัดเก็บข้อมูลลงคลังโดยอัตโนมัติและลดต้นทุนการจัดเก็บโดยรวม
* ข้อมูลที่ถูกเรียกคืน (Restore) จะถูกทำสำเนาไว้ชั่วคราว (โดยปกติอยู่ในชั้น Standard) ตามระยะเวลาที่คุณระบุ

---

## รูปแบบข้อมูล (Data Model)

### 1. Vault (ห้องนิรภัย)
* เป็นคอนเทนเนอร์สำหรับเก็บ Archive
* แต่ละ Vault มีที่อยู่ (Address) เฉพาะตัวในรูปแบบ: `https://region-specific endpoint/account-id/vaults/vaultname`
* เก็บ Archive ได้ไม่จำกัดจำนวน และการทำงานของ Vault จะแยกตามภูมิภาค (Region)

### 2. Archive (เอกสารจัดเก็บ)
* เป็นหน่วยพื้นฐานของการจัดเก็บใน Glacier เช่น รูปภาพ, วิดีโอ หรือเอกสาร
* แต่ละ Archive มีที่อยู่เฉพาะตัวในรูปแบบ: `https://region-specific-endpoint/account-id/vaults/vault-name/archives/archive-id`
* ขนาดสูงสุดของหนึ่ง Archive คือ **40 TB**

### 3. Job (งาน)
* คุณสามารถทำการคิวรี (Select Query), ดึงข้อมูล Archive หรือดึงรายการสิ่งของใน Vault (Inventory)
* **Glacier Select** จะรันการคิวรี ณ จุดที่เก็บข้อมูลและเขียนผลลัพธ์ออกไปยัง Amazon S3
* หนึ่ง Vault สามารถมีหลาย Job ทำงานพร้อมกันได้

### 4. Notification Configuration (การตั้งค่าการแจ้งเตือน)
* เนื่องจาก Job ต้องใช้เวลาในการดำเนินการ Glacier จึงมีระบบแจ้งเตือนเมื่อ Job เสร็จสิ้น

## การดำเนินงานของ Glacier (Operations)
* การดึงข้อมูล Archive (Asynchronous - ไม่ประสานเวลา)
* การดึงรายการ Inventory ของ Vault (Asynchronous)
* การสร้างและลบ Vault
* การดูรายละเอียดของ Vault (Description)
* การตั้งค่า, ดึงข้อมูล และลบการแจ้งเตือนบน Vault
* การอัปโหลดและลบ Archive (คุณ**ไม่สามารถ**อัปเดต Content ของ Archive เดิมที่มีอยู่ได้)

---

## รายละเอียดเกี่ยวกับ Vault
* ชื่อ Vault ต้องไม่ซ้ำกันภายในบัญชีและภูมิภาคที่สร้าง
* คุณจะลบ Vault ได้ก็ต่อเมื่อ**ไม่มี Archive หลงเหลืออยู่**จากการตรวจสอบ Inventory ครั้งล่าสุด และไม่มีการเขียนข้อมูลลงไปใหม่หลังจากนั้น
* **Vault Inventory:** รายชื่อ Archive ทั้งหมดใน Vault ซึ่งระบบจะอัปเดตประมาณวันละครั้ง การดาวน์โหลด Inventory เป็นการทำงานแบบ Asynchronous
* **Tags:** สามารถติดป้ายกำกับ (Key-value pairs) ให้กับ Vault ได้
* **Glacier Vault Lock:** ช่วยบังคับใช้นโยบายการปฏิบัติตามกฎระเบียบ (Compliance) เช่น "Write once read many" (WORM) เมื่อล็อกนโยบายแล้วจะไม่สามารถแก้ไขได้อีก

---

## รายละเอียดเกี่ยวกับ Archive
* รองรับการอัปโหลด, ดาวน์โหลด และลบ (การดาวน์โหลดเป็นแบบ Asynchronous)
* สามารถอัปโหลดแบบส่วนเดียวหรือแบบหลายส่วน (**Multipart**) ซึ่งแบบหลายส่วนรองรับ Archive ขนาดใหญ่ได้ถึงประมาณ 10,000 x 4 GB
* **ไม่สามารถอัปโหลดหรือลบ Archive ผ่านหน้า Management Console ได้** ต้องใช้ AWS CLI, SDK หรือ REST API เท่านั้น
* หลังอัปโหลดแล้ว**ไม่สามารถแก้ไขเนื้อหาหรือคำอธิบายได้** หากต้องการเปลี่ยนต้องลบแล้วอัปโหลดใหม่เท่านั้น
* Glacier ไม่รองรับการเก็บ Metadata เพิ่มเติมสำหรับ Archive

---

## Glacier Select
* ช่วยให้คุณใช้คำสั่ง **SQL** อย่างง่ายในการกรองข้อมูลใน Glacier ได้โดยตรง
* สามารถวิเคราะห์ข้อมูลได้โดยไม่ต้อง Restore ข้อมูลกลับไปยังชั้นที่ "ร้อนกว่า" อย่าง S3 Standard
* มีระดับการเข้าถึงข้อมูล 3 แบบ:
    1. **Expedited:** ได้ข้อมูลภายใน 1–5 นาที
    2. **Standard:** ได้ข้อมูลภายใน 3–5 ชั่วโมง
    3. **Bulk:** ได้ข้อมูลภายใน 5–12 ชั่วโมง

---

## นโยบายการดึงข้อมูล (Data Retrieval Policies)
ใช้กำหนดขีดจำกัดการดึงข้อมูลเพื่อควบคุมค่าใช้จ่าย มี 3 ประเภท:
1. **Free Tier Only:** ดึงข้อมูลเฉพาะในส่วนที่ฟรีต่อวันเท่านั้นเพื่อไม่ให้เกิดค่าใช้จ่าย
2. **Max Retrieval Rate:** กำหนดอัตราการดึงข้อมูลสูงสุดต่อชั่วโมง (Bytes-per-hour)
3. **No Retrieval Limit:** ไม่จำกัดการดึงข้อมูล

---

## ความปลอดภัย (Security)
* เข้ารหัสข้อมูลที่จัดเก็บ (At rest) เป็นค่าเริ่มต้น และรองรับ SSL ขณะส่งข้อมูล
* ข้อมูลเป็นแบบ **Immutable** (ไม่สามารถเปลี่ยนแปลงได้)
* การเข้าถึงต้องใช้ Credentials ที่ได้รับสิทธิ์ผ่าน IAM และทุกคำขอต้องมีการลงลายมือชื่อดิจิทัล (Signed request)
* รองรับนโยบายเฉพาะในระดับ Vault (Vault Policies) ทั้งแบบ Identity-based และ Resource-based
* บันทึกกิจกรรมผ่าน **AWS CloudTrail**

---

## ค่าบริการ (Pricing)
* คิดตามปริมาณ GB ต่อเดือน
* คิดตามจำนวนคำขอและปริมาณข้อมูลที่ดึง (Retrieval) ตามระดับความเร็ว (Expedited, Standard, Bulk)
* คิดค่าธรรมเนียมการอัปโหลดและการโอนข้อมูลออก (Data Transfer Out)
* มีค่าธรรมเนียมการคิวรี (Glacier Select) ตามปริมาณข้อมูลที่สแกนและผลลัพธ์ที่ส่งกลับ
* **หมายเหตุสำคัญ:** มีค่าธรรมเนียมหากลบข้อมูลก่อนกำหนด (ภายใน 90 วันสำหรับ Flexible Retrieval หรือ 180 วันสำหรับ Deep Archive)

---

## ข้อจำกัด (Limits)
* หนึ่งบัญชี AWS สามารถมี Vault ได้สูงสุด **1,000 แห่ง**
