# Amazon EBS Cheat Sheet

**Amazon Elastic Block Store (EBS)** คือวอลลุ่มจัดเก็บข้อมูลระดับบล็อก (Block-level) สำหรับใช้งานร่วมกับอินสแตนซ์ EC2
* เหมาะสำหรับใช้เป็นที่จัดเก็บข้อมูลหลักสำหรับระบบไฟล์ (File Systems), ฐานข้อมูล (Databases) หรือแอปพลิเคชันใดๆ ที่ต้องการการอัปเดตข้อมูลแบบละเอียด (Fine granular) และการเข้าถึงที่เก็บข้อมูลระดับบล็อกดิบที่ยังไม่ได้ฟอร์แมต
* เหมาะสำหรับทั้งแอปพลิเคชันประเภทฐานข้อมูล (สุ่มอ่านและเขียน) และแอปพลิเคชันที่เน้นทรูพุตสูง (อ่านและเขียนต่อเนื่องยาวนาน)
* วอลลุ่ม EBS ใหม่จะให้ประสิทธิภาพสูงสุดทันทีที่พร้อมใช้งาน และไม่จำเป็นต้องทำ Initialization (หรือที่เคยเรียกว่า Pre-warming) อย่างไรก็ตาม บล็อกข้อมูลในวอลลุ่มที่ **Restore มาจาก Snapshot** จะต้องได้รับการ Initialize (ดึงข้อมูลจาก S3 ลงมาเขียนในวอลลุ่ม) ก่อนที่คุณจะเข้าถึงได้ *หมายเหตุ: คุณสามารถใช้ Fast Snapshot Restore (FSR) เพื่อหลีกเลี่ยงความหน่วงนี้ได้*
* การป้องกันการลบ (Termination Protection) ถูกปิดไว้เป็นค่าเริ่มต้น (ต้องเปิดเองหากต้องการเก็บข้อมูลไว้เมื่ออินสแตนซ์ถูกลบ)
* ค่าเริ่มต้นจำกัดวอลลุ่ม EBS ได้สูงสุด 5,000 ตัว และ Snapshot 10,000 ชุดต่อบัญชี (เป็น Soft limit ปรับเพิ่มได้)

## คุณสมบัติ (Features)
* **ตัวเลือกประเภทจัดเก็บข้อมูล:** มีทั้ง General Purpose SSD (gp2, gp3), Provisioned IOPS SSD (io1, io2), Throughput Optimized HDD (st1) และ Cold HDD (sc1) ขนาดสูงสุด **16 TiB** (หรือ 64 TiB สำหรับ io2 Block Express)
* **Multi-Attach:** คุณสามารถเมานต์วอลลุ่ม Provisioned IOPS (io1/io2) เข้ากับอินสแตนซ์ EC2 (ตระกูล Nitro) ได้สูงสุด 16 ตัวพร้อมกันภายใน AZ เดียวกัน
* **ความปลอดภัย:** รองรับการเข้ารหัส (Encryption) ข้อมูลที่เก็บอยู่ (Data-at-rest) และข้อมูลที่กำลังส่ง (In-transit) ระหว่าง EC2 และ EBS
* **Snapshot:** สามารถสร้างจุดบันทึกข้อมูลย่อย (Point-in-time snapshots) เก็บไว้ใน Amazon S3 และสามารถคัดลอกข้ามภูมิภาค (Region) ได้
* **Availability Zones (AZ):** วอลลุ่มถูกสร้างใน AZ เฉพาะ หากต้องการย้ายไป AZ อื่นหรือภูมิภาคอื่น ต้องสร้าง Snapshot แล้วนำไป Restore เป็นวอลลุ่มใหม่ในพื้นที่นั้น
* **Elastic Volumes:** ช่วยให้คุณเพิ่มขนาดวอลลุ่ม, ปรับประสิทธิภาพ (IOPS/Throughput) หรือเปลี่ยนประเภทวอลลุ่มได้ในขณะที่ใช้งานอยู่ โดยไม่ต้องหยุดอินสแตนซ์
* **Recycle Bin (ถังขยะ):** ฟีเจอร์กู้คืน Snapshot หรือวอลลุ่ม EBS ที่ถูกลบโดยไม่ตั้งใจ โดยกำหนดระยะเวลาเก็บรักษาก่อนจะลบถาวร
* **Torn Write Prevention (TWP):** มีในวอลลุ่ม io2 เพื่อรับประกันว่าการเขียนข้อมูลขนาด 16 KiB จะไม่ขาดช่วง (Partial write) เมื่อเกิดไฟดับหรือระบบล่ม ซึ่งสำคัญมากสำหรับฐานข้อมูลอย่าง MySQL/MariaDB

## ประเภทของวอลลุ่ม EBS (Types of EBS Volumes)

### 1. General Purpose SSD (gp3 / gp2)
* **gp3:** ให้ความเร็วพื้นฐานคงที่ที่ 3,000 IOPS และ 125 MiB/s (ปรับเพิ่มได้สูงสุด 16,000 IOPS และ 1,000 MiB/s โดยมีค่าใช้จ่ายเพิ่ม)
* **gp2:** ประสิทธิภาพพื้นฐาน 3 IOPS ต่อ GiB และสามารถ Burst ได้ถึง 3,000 IOPS หากมี Credit Balance เหลืออยู่

### 2. Provisioned IOPS SSD (io1 / io2)
* ออกแบบมาสำหรับงานที่เน้น I/O สูงและต้องการความเสถียรมาก เช่น ฐานข้อมูลขนาดใหญ่
* **io2:** มีความทนทาน (Durability) สูงถึง 99.999% และให้อัตราส่วน IOPS ต่อความจุสูงกว่า io1 ถึง 10 เท่าในราคาเดิม

### 3. Throughput Optimized HDD (st1)
* พื้นที่เก็บข้อมูลแบบแม่เหล็กราคาประหยัด เน้นทรูพุต (Throughput) มากกว่า IOPS เหมาะสำหรับงาน Big Data, Data Warehouse หรือ Log Processing

### 4. Cold HDD (sc1)
* เน้นราคาประหยัดที่สุด สำหรับข้อมูลที่เข้าถึงไม่บ่อย (Infrequently accessed)

## การเข้ารหัส (Encryption)
* ข้อมูลที่จัดเก็บ, การรับ-ส่งข้อมูล (I/O) และ Snapshot ที่สร้างจากวอลลุ่มที่เข้ารหัสจะถูกเข้ารหัสทั้งหมด
* ใช้ **AWS KMS** ในการจัดการกุญแจเข้ารหัส (Master Keys)
* สามารถเปิดใช้งาน "Encryption by Default" เพื่อให้วอลลุ่มใหม่ทั้งหมดในบัญชีถูกเข้ารหัสโดยอัตโนมัติ
* **หมายเหตุ:** ไม่สามารถสลับสถานะเข้ารหัสของวอลลุ่มเดิมได้โดยตรง แต่ทำได้โดยการ Copy Snapshot แล้วเลือกเข้ารหัสระหว่างการ Copy

---

## การแก้ไขขนาดและประสิทธิภาพ (Modifying Volumes)
* รองรับการขยายขนาด (Increase size) แต่ **ไม่รองรับการลดขนาด (Decrease size)**
* สถานะการแก้ไขจะเริ่มจาก *Modifying* -> *Optimizing* -> *Complete*
* หลังจากขยายวอลลุ่มในระบบ AWS แล้ว คุณต้องใช้คำสั่งในระดับ OS เพื่อขยายพาร์ทิชันและระบบไฟล์ (เช่น `resize2fs` สำหรับ ext4 หรือ `xfs_growfs` สำหรับ XFS)

## EBS Snapshots
* เป็นการสำรองข้อมูลแบบ **Incremental** (เก็บเฉพาะบล็อกข้อมูลที่เปลี่ยนแปลงจากครั้งล่าสุด) ช่วยประหยัดเวลาและค่าใช้จ่าย
* **EBS Snapshot Archive:** ชั้นเก็บข้อมูลราคาถูก (ลดค่าใช้จ่ายสูงสุด 75%) สำหรับ Snapshot ที่ต้องการเก็บไว้นาน (90 วันขึ้นไป) แต่เข้าถึงไม่บ่อย
* การลบ Snapshot จะลบเฉพาะข้อมูลที่มีเฉพาะใน Snapshot ชุดนั้นเท่านั้น ข้อมูลที่ถูกใช้อ้างอิงโดยชุดอื่นจะยังคงอยู่



---

## การเพิ่มประสิทธิภาพ (Improving Performance)
* ใช้ **EBS-Optimized Instances** เพื่อแยกช่องทาง I/O ของ EBS ออกจากทราฟฟิกเครือข่ายอื่นๆ
* เข้าใจรูปแบบงาน (Workload) ว่าเน้นสุ่มอ่านเขียน (Random) หรือเน้นปริมาณข้อมูลต่อเนื่อง (Sequential) เพื่อเลือกประเภทวอลลุ่มให้ถูกต้อง
* ใช้ **RAID 0** หากต้องการความเร็วสูงสุดจากการรวมประสิทธิภาพของหลายวอลลุ่มเข้าด้วยกัน
* ตรวจสอบประสิทธิภาพผ่าน **Amazon CloudWatch** อย่างสม่ำเสมอ

---

## ค่าบริการ (Pricing)
* คิดค่าบริการตามจำนวน GB ที่จองไว้ต่อเดือน (Provisioned storage)
* สำหรับรุ่น Provisioned IOPS จะมีการคิดค่า IOPS ที่จองไว้ด้วย
* Snapshot คิดตามปริมาณข้อมูลจริงที่เก็บใน S3 (Snapshot Archive จะราคาถูกกว่าแต่มีค่าธรรมเนียมตอนดึงข้อมูล)
* วอลลุ่มที่ไม่ได้ต่อเข้ากับอินสแตนซ์ (Detached) ยังคงเสียค่าบริการจนกว่าจะลบ (Delete) ทิ้ง
