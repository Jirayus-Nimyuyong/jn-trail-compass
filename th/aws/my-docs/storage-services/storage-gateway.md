# AWS Storage Gateway Cheat Sheet

**AWS Storage Gateway** เป็นบริการที่ช่วยเชื่อมต่อการจัดเก็บข้อมูลแบบ **Hybrid Storage** ระหว่างสภาพแวดล้อม On-premises (ภายในศูนย์ข้อมูลของคุณ) และ AWS Cloud
* ทำหน้าที่ผสานรวมแอปพลิเคชันและเวิร์กโฟลว์ระดับองค์กรเข้ากับบริการจัดเก็บข้อมูลแบบ Block และ Object ของ Amazon ผ่านโปรโตคอลมาตรฐานอุตสาหกรรม
* บริการนี้จะจัดเก็บไฟล์เป็น S3 Objects, จัดเก็บเทปเสมือน (Virtual Tapes) ใน **Amazon Glacier** และจัดเก็บ EBS Snapshots ที่สร้างโดย Volume Gateway ไว้ใน **Amazon EBS**

---

## รูปแบบโซลูชันการจัดเก็บข้อมูล (Storage Solutions)

### 1. Amazon S3 File Gateway (ชื่อเดิมคือ File Gateway)
* ติดตั้งซอฟต์แวร์ (Gateway) ในรูปแบบ Virtual Machine (VMware ESXi, Hyper-V หรือ Linux KVM) ในศูนย์ข้อมูลของคุณ
* **S3 Storage Classes ที่รองรับ:** Standard, Standard-IA, One Zone-IA และ Intelligent-Tiering
* **ความสามารถ:**
    * จัดเก็บและดึงข้อมูลไฟล์โดยตรงผ่านโปรโตคอล **NFS** (v3 หรือ 4.1) และ **SMB** (v2 และ 3)
    * เข้าถึงข้อมูลใน S3 ได้โดยตรงจากแอปพลิเคชันหรือบริการใดๆ บน AWS Cloud
    * จัดการข้อมูลใน S3 ด้วยนโยบาย Lifecycle, Cross-region replication และ Versioning
    * รองรับ **Amazon S3 Object Lock** (WORM) สำหรับการจัดเก็บไฟล์ที่ห้ามแก้ไข
    * การแก้ไข ลบ หรือเปลี่ยนชื่อไฟล์จากฝั่ง Client จะถูกเก็บเป็น **เวอร์ชันใหม่ (New versions)** ของ Object โดยไม่เขียนทับเวอร์ชันเก่า
    * Local Cache (แคชในเครื่อง) รองรับข้อมูลได้สูงสุด 64TB

### 2. Amazon FSx File Gateway
* **หมายเหตุ:** ตั้งแต่วันที่ **28 ตุลาคม 2024** เป็นต้นไป จะไม่เปิดรับลูกค้าใหม่ (ลูกค้าเดิมใช้งานได้ปกติ)
* นำเสนอระบบไฟล์ FSx ในรูปแบบ SMB Shares ให้กับผู้ใช้และแอปพลิเคชันในท้องถิ่น
* รองรับฟีเจอร์ระดับองค์กร เช่น Active Directory, NTFS permissions, DFS และ Shadow copies

### 3. Volume Gateway
ให้บริการพื้นที่เก็บข้อมูลแบบ Block Storage ที่คุณสามารถเมานต์เป็นอุปกรณ์ **iSCSI** ได้
* **Cached volumes:** เก็บข้อมูลหลักไว้ใน Amazon S3 และเก็บข้อมูลที่เข้าถึงบ่อยไว้ในเครื่อง (Local) เพื่อให้เข้าถึงได้เร็ว (ขนาด 1 GiB - 32 TiB ต่อ Volume)
* **Stored volumes:** เก็บข้อมูลทั้งหมดไว้ในเครื่อง (Local) เพื่อการเข้าถึงที่รวดเร็วที่สุด และสำรองข้อมูลแบบ Snapshot ไปยัง Amazon S3 เป็นระยะแบบ Asynchronous (ขนาด 1 GiB - 16 TiB ต่อ Volume, สูงสุด 512 TiB ต่อ Gateway)
* รองรับการย้าย Volume (Detach/Attach) ระหว่าง Gateway เพื่ออัปเกรดฮาร์ดแวร์หรือย้ายไปยัง EC2

### 4. Tape Gateway
ใช้สำหรับสำรองข้อมูลเก็บถาวรใน **Amazon Glacier** โดยจำลองอินเทอร์เฟซแบบ Virtual Tape Library (VTL)
* รองรับชั้นการจัดเก็บ **S3 Glacier Deep Archive** ซึ่งช่วยลดค่าใช้จ่ายรายเดือนได้สูงสุดถึง 75%
* รองรับคุณสมบัติ WORM และ Tape Retention Lock บนเทปเสมือน
* ขนาดเทปอยู่ระหว่าง 100 GiB ถึง 15 TiB และรองรับสูงสุด 1,500 เทปต่อหนึ่ง Gateway (ความจุรวมสูงสุด 1 PiB)

## ตัวเลือกในการติดตั้ง (Hosting Options)
* เป็น VM รันบน VMware ESXi หรือ Microsoft Hyper-V ในศูนย์ข้อมูล (On-premises)
* เป็น VM ใน VMware Cloud on AWS
* เป็นอุปกรณ์ฮาร์ดแวร์สำเร็จรูป (Hardware Appliance) ติดตั้งในศูนย์ข้อมูล
* เป็น AMI รันบนอินสแตนซ์ EC2

---

## ความปลอดภัยและการปฏิบัติตามข้อกำหนด (Security & Compliance)
* **การเข้ารหัส:** ใช้ **AWS KMS** ในการเข้ารหัสข้อมูลที่เขียนลงเทปเสมือน
* **การยืนยันตัวตน:** ใช้โปรโตคอล **CHAP** เพื่อยืนยันตัวตนการเชื่อมต่อ iSCSI และใช้ **IAM** ในการควบคุมการเข้าถึง
* **มาตรฐาน:** รองรับมาตรฐาน **HIPAA** และ **PCI DSS**

---

## ค่าบริการ (Pricing)
* คิดค่าบริการตาม**ประเภทและปริมาณพื้นที่จัดเก็บ**ที่คุณใช้, จำนวน**คำขอ (Requests)** และปริมาณ**ข้อมูลที่โอนออกจาก AWS (Data Transfer Out)**
* สำหรับ Tape Gateway จะคิดค่าบริการตามปริมาณข้อมูลที่คุณเขียนลงในเทปจริง ไม่ได้คิดตามขนาดความจุทั้งหมดของเทป
