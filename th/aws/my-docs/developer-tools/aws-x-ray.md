# AWS X-Ray Cheat Sheet

**AWS X-Ray** ใช้สำหรับวิเคราะห์และแก้ไขข้อผิดพลาด (Debug) ของแอปพลิเคชันแบบกระจายตัว (Distributed Applications) เช่น แอปพลิเคชันที่สร้างด้วยสถาปัตยกรรม Microservices โดย X-Ray จะช่วยระบุคอขวดของประสิทธิภาพ (Performance Bottlenecks), ข้อผิดพลาดในกรณีขอบเขต (Edge Case Errors) และปัญหาอื่นๆ ที่ตรวจพบได้ยาก

### แนวคิดหลัก (Concepts)

* **Segment (เซกเมนต์):** ให้ข้อมูลเกี่ยวกับชื่อทรัพยากรประมวลผลที่รันตรรกะแอปพลิเคชันของคุณ, รายละเอียดเกี่ยวกับคำขอ (Request) และรายละเอียดเกี่ยวกับงานที่ทำ
* **Subsegment (เซกเมนต์ย่อย):** ใช้แบ่งย่อยข้อมูลงานใน Segment เช่น การเรียกใช้บริการ AWS อื่น, HTTP API ภายนอก หรือฐานข้อมูล SQL
    * สำหรับบริการที่ไม่ได้ส่ง Segment ของตัวเอง (เช่น DynamoDB) X-Ray จะใช้ Subsegment เพื่อสร้าง **Inferred Segments** (เซกเมนต์ที่อนุมานขึ้น) และโหนดปลายทางบน Service Map
* **Service Graph (กราฟบริการ):** เอกสาร JSON ที่มีข้อมูลเกี่ยวกับบริการและทรัพยากรต่างๆ ในแอปพลิเคชัน ข้อมูลนี้จะถูกเก็บไว้เป็นเวลา **30 วัน**
* **Service Map (แผนผังบริการ):** การแสดงภาพที่สร้างจาก Service Graph เพื่อให้เห็นการเชื่อมต่อระหว่างบริการต่างๆ
* **Trace ID (รหัสการติดตาม):** ใช้ติดตามเส้นทางของคำขอหนึ่งรายการผ่านแอปพลิเคชันของคุณ
* **Trace (การติดตาม):** รวบรวม Segment ทั้งหมดที่เกิดขึ้นจากคำขอเดียว (เช่น HTTP GET/POST)
* **Sampling (การสุ่มตัวอย่าง):** เพื่อประสิทธิภาพ X-Ray จะไม่เก็บทุกคำขอ โดยค่าเริ่มต้นจะบันทึก **1 คำขอแรกในทุกวินาที และ 5% ของคำขอที่เหลือ**
* **Annotations (คำอธิบายประกอบ):** คู่ Key-Value แบบง่ายที่ **ถูกจัดทำดัชนี (Indexed)** เพื่อใช้ในการกรองหรือค้นหา Trace
* **Metadata (ข้อมูลเมทาดาตา):** คู่ Key-Value ที่ **ไม่ถูกจัดทำดัชนี** ใช้สำหรับเก็บข้อมูลเพิ่มเติมที่ต้องการบันทึกไว้แต่ไม่ใช้ในการค้นหา

### คุณสมบัติเด่น (Features)
* รองรับแอปพลิเคชันบน **Amazon EC2, ECS, Lambda และ Elastic Beanstalk**
* ให้มุมมองแบบ **End-to-end** ข้ามบริการต่างๆ เพื่อดูการไหลของคำขอ
* จับข้อมูลเมทาดาตาของฐานข้อมูล **MySQL, PostgreSQL** (รวมถึง RDS/Aurora) และ **DynamoDB** รวมถึง **Amazon SQS และ SNS**
* รองรับการนำเข้าข้อมูลผ่าน **OTLP** (OpenTelemetry Protocol)
* **Adaptive Sampling:** ปรับอัตราการสุ่มตัวอย่างแบบไดนามิก รวมถึงฟีเจอร์ Sampling Boost และ Anomaly Span Capture

---

### การทำงานของ X-Ray
X-Ray รับข้อมูลจากบริการต่างๆ ในรูปแบบ **Segments** จากนั้นจะรวมกลุ่ม Segment ที่มาจากคำขอเดียวกันเข้าเป็น **Traces** และประมวลผลออกมาเป็น **Service Graph**

* **X-Ray SDK:** มีตัวดักจับ (Interceptors) สำหรับ HTTP Request, ตัวจัดการสำหรับ AWS SDK Clients และตัวดักจับการเรียกใช้ Web Services ภายนอก
    * รองรับภาษา **Node.js, Java และ .NET**
    * SDK จะส่งข้อมูล JSON ไปยัง **X-Ray Daemon** ผ่านโปรโตคอล UDP
* **X-Ray Daemon:** ทำหน้าที่รวมข้อมูล (Buffer) และส่งขึ้น X-Ray เป็นชุด (Batches)

### การรวมระบบกับบริการ AWS (Service Integration)
มี 4 รูปแบบการรวมระบบ:
1.  **Active instrumentation:** สุ่มตัวอย่างและติดตามคำขอขาเข้า
2.  **Passive instrumentation:** ติดตามคำขอที่ถูกสุ่มตัวอย่างมาแล้วโดยบริการต้นทางอื่น
3.  **Request tracing:** เพิ่ม Tracing Header ให้กับทุกคำขอและส่งต่อไปยังปลายทาง
4.  **Tooling:** รัน X-Ray Daemon เพื่อรับข้อมูลจาก SDK

**ตัวอย่างบริการที่รองรับ:**
* **AWS Lambda:** รองรับทั้ง Active และ Passive โดยจะเพิ่มโหนดในแผนผัง 2 โหนด (สำหรับตัวบริการ Lambda และสำหรับฟังก์ชัน)
* **Amazon API Gateway:** ใช้กฎการสุ่มตัวอย่างเพื่อบันทึกข้อมูลและเพิ่มโหนดสำหรับ Gateway Stage
* **Elastic Load Balancing:** รองรับ Request Tracing บน Application Load Balancers

### ค่าบริการ (Pricing)
* จ่ายตามจำนวน Trace ที่ถูก **บันทึก (Recorded), เรียกดู (Retrieved) และสแกน (Scanned)**
* ขนาดสูงสุดของหนึ่ง Trace คือ **500 KB**
* ข้อมูล Trace จะถูกเก็บไว้ให้ฟรีเป็นเวลา **30 วัน**
