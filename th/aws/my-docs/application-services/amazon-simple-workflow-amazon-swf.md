# Amazon Simple Workflow (SWF) Cheat Sheet

**Amazon SWF** เป็นบริการติดตามสถานะ (State Tracker) และประสานงานภางกิจ (Task Coordinator) แบบ Managed เต็มรูปแบบบนคลาวด์ คุณสามารถสร้างเวิร์กโฟลว์ตามต้องการ พร้อมกำหนดภารกิจและตรรกะเงื่อนไขต่างๆ แล้วจัดเก็บไว้ใน SWF

### คุณสมบัติเด่น (Features)
* **การแยกส่วน (Separation):** แยกตรรกะการควบคุม (Control Flow) ออกจากหน่วยงานจริง (Units of Work) ที่เป็นตรรกะทางธุรกิจ
* **ความทนทาน:** SWF จัดการประวัติการทำงาน (Execution History) และรายละเอียดอื่นๆ กระจายไว้ใน 3 Availability Zones
* **ยืดหยุ่น:** เขียนส่วนประกอบของแอปพลิเคชันด้วยภาษาใดก็ได้ และรันได้ทั้งบนคลาวด์หรือ On-premises
* **การขยายขนาด:** ควบคุมจำนวน Worker และ Decider ได้อย่างอิสระตามความต้องการ
* **AWS Flow Framework:** ช่วยเหลือนักพัฒนาในการเขียนโปรแกรมแบบอซิงโครนัส (Asynchronous) ได้ง่ายขึ้น
* **ความน่าเชื่อถือ:** จัดการการรันงานใหม่ (Retry) อัตโนมัติด้วยวิธี Exponential Backoff และรองรับการใช้ Timers (ตัวตั้งเวลา) และ Signals (สัญญาณ) จากภายนอก

---

### แนวคิดหลัก (Concepts)

#### 1. Workflow (เวิร์กโฟลว์)
* ชุดของกิจกรรม (Activities) ที่ทำงานร่วมกันเพื่อให้บรรลุวัตถุประสงค์ พร้อมตรรกะในการประสานงาน
* รันอยู่ภายใต้ทรัพยากรที่เรียกว่า **Domain** เพื่อควบคุมขอบเขต (Account หนึ่งมีได้หลาย Domain แต่ละ Domain แยกขาดจากกัน)

#### 2. Activity Task (ภารกิจกิจกรรม)
* คำสั่งที่บอกให้ Activity Worker ทำหน้าที่ของมัน SWF จะจัดเก็บและมอบหมายงานเมื่อพร้อม และติดตามสถานะจนเสร็จสิ้น
* **Task List:** รายชื่อภารกิจที่ Worker จะมาดึงไปทำ หากไม่ระบุจะไปอยู่ที่ Default List
* **Lambda Task:** การเรียกใช้ AWS Lambda แทนกิจกรรมแบบดั้งเดิม

#### 3. Decision Task (ภารกิจการตัดสินใจ)
* แจ้งให้ **Decider** ทราบว่าสถานะของเวิร์กโฟลว์เปลี่ยนไป เพื่อให้ Decider กำหนดขั้นตอนถัดไป (ในหนึ่งเวิร์กโฟลว์จะมี Decision Task ที่ทำงานอยู่ได้เพียงอันเดียวในขณะใดขณะหนึ่ง)

#### 4. บทบาทต่างๆ (Roles)
* **Workflow Starter:** แอปพลิเคชันที่สั่งเริ่มการทำงานของเวิร์กโฟลว์
* **Activity Worker:** โปรแกรมที่รับงานไปทำจริง และส่งผลลัพธ์กลับมา
* **Decider:** ส่วนควบคุมตรรกะการประสานงาน ทำหน้าที่จัดตารางงาน ส่งข้อมูลให้ Worker และจบเวิร์กโฟลว์เมื่อเสร็จสิ้น
* **Polling:** ทั้ง Worker และ Decider จะสื่อสารกับ SWF โดยการถามข้อมูล (Long Polling)

#### 5. Workflow Execution History (ประวัติการทำงาน)
* ประกอบด้วยเหตุการณ์ (Events) ที่แสดงถึงการเปลี่ยนแปลงสถานะที่สำคัญ SWF จะส่งสำเนาประวัตินี้ไปให้ Decider พร้อมกับ Decision Task ทุกครั้ง

### AWS Flow Framework
* SDK ส่วนขยายสำหรับภาษา Java และ Ruby เพื่อช่วยเขียนโปรแกรมแบบกระจายตัวและอซิงโครนัสได้ง่ายขึ้น
* ช่วยจัดการ Exception (ข้อผิดพลาด) และช่วยในการประสานงานภารกิจได้อย่างมีประสิทธิภาพ

---

### ค่าบริการ (Pricing)
* จ่ายเมื่อเริ่มรันเวิร์กโฟลว์ และจ่ายทุกๆ รอบ 24 ชั่วโมงจนกว่าจะเสร็จ (24 ชั่วโมงแรกฟรี)
* มีค่าบริการสำหรับ "Markers" (การบันทึก Log กำหนดเอง), การเริ่ม Timer หรือการรับ Signals
* **การถ่ายโอนข้อมูล:** ฟรีภายใน Region เดียวกัน แต่คิดค่าบริการหากโอนถ่ายข้าม Region

---

### SQS vs SWF
* **SQS:** เน้นที่ **คิว (Queues)** สำหรับเก็บข้อความระหว่างแอปพลิเคชัน มีความสามารถในการขยายขนาดสูง
* **SWF:** เน้นที่ **การประสานงาน (Coordination)** ของงาน ติดตามสถานะและเหตุการณ์ทั้งหมดในแอปพลิเคชันให้โดยอัตโนมัติ
* **API:** SWF เน้นภารกิจ (Task-oriented) ในขณะที่ SQS เน้นข้อความ (Message-oriented)

---

### ขีดจำกัด (Limits)
* **Domain:** สูงสุด 100 รายการต่อบัญชี
* **ระยะเวลาทำงานสูงสุด:** 1 ปี (ทั้งตัวเวิร์กโฟลว์และรายกิจกรรม)
* **ประวัติการทำงาน:** สูงสุด 25,000 เหตุการณ์ต่อหนึ่งการรัน และเก็บประวัติไว้ได้นาน 90 วัน
* **กิจกรรม:** สั่งเริ่มงานได้สูงสุด 100 กิจกรรมต่อหนึ่งการตัดสินใจ (Decision)
