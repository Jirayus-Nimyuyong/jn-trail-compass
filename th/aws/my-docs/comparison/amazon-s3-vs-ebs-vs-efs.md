# การเปรียบเทียบ Amazon S3, EBS และ EFS

| หัวข้อ | Amazon S3 | Amazon EBS | Amazon EFS |
| :--- | :--- | :--- | :--- |
| **ประเภทการจัดเก็บ** | **Object Storage** เก็บข้อมูลได้ทุกประเภทและทุกรูปแบบ | **Block Storage** แบบถาวรสำหรับอินสแตนซ์ EC2 | **File Storage** ตามมาตรฐาน POSIX สำหรับอินสแตนซ์ EC2 |
| **คุณสมบัติเด่น** | เข้าถึงได้โดยใครก็ตามหรือบริการใดๆ ที่ได้รับอนุญาต | ให้ประสิทธิภาพสูงสุดสำหรับงานที่ต้องการ Latency ต่ำสุด จาก EC2 เพียงเครื่องเดียว | มีหน้าอินเทอร์เฟซแบบระบบไฟล์ มีความสอดคล้องของข้อมูลสูง และรองรับการเข้าถึงพร้อมกันจาก EC2 หลายเครื่อง |
| **รูปแบบความจุสูงสุด** | ไม่จำกัด (Virtually unlimited) | 16 TiB ต่อหนึ่ง Volume | ไม่จำกัดขนาดระบบ |
| **ขนาดไฟล์สูงสุด** | 5 Terabytes ต่อหนึ่ง Object | เท่ากับขนาดสูงสุดของ Volume ที่ใช้งาน | 47.9 TiB ต่อหนึ่งไฟล์ |
| **ประสิทธิภาพ (Latency)** | ต่ำ (สำหรับคำขอหลายประเภท) และทำงานร่วมกับ CloudFront ได้ดี | **ต่ำที่สุดและสม่ำเสมอ** มีตัวเลือก SSD ประสิทธิภาพสูง (Provisioned IOPS) และ General Purpose | ต่ำและสม่ำเสมอ สามารถใช้โหมด Max I/O เพื่อประสิทธิภาพที่สูงขึ้น |
| **ประสิทธิภาพ (Throughput)** | หลาย GB ต่อวินาที รองรับการอัปโหลดแบบ Multi-part | สูงสุด 2 GB ต่อวินาที มีตัวเลือก HDD สำหรับงานที่เน้น Throughput หรือข้อมูลที่เข้าถึงไม่บ่อย | **10+ GB ต่อวินาที** มีโหมด Bursting ที่สเกลตามขนาดไฟล์ และโหมด Provisioned สำหรับความเร็วคงที่ |
| **ความทนทาน (Durability)** | 99.999999999% (เลข 9 จำนวน 11 ตัว) เก็บข้อมูลกระจายหลาย AZ | เก็บข้อมูลสำรองภายใน **AZ เดียว** | เก็บข้อมูลกระจายหลาย AZ |
| **ความพร้อมใช้งาน (Availability)** | • Standard: 99.99%<br>• Standard-IA: 99.9%<br>• One Zone-IA: 99.5% | 99.999% | 99.9% (SLA) และทำงานแบบ Multi-AZ |
| **การขยายระบบ (Scalability)** | ขยายตัวได้สูงมาก (Highly scalable) | ต้องเพิ่ม/ลดขนาดหน่วยความจำเอง หรือติดตั้ง Volume เพิ่มเติมเข้ากับ EC2 | **Elastic** ปรับขนาดเพิ่มหรือลดอัตโนมัติเมื่อมีการเพิ่มหรือลบไฟล์ |
| **การเข้าถึงข้อมูล** | เชื่อมต่อได้ตั้งแต่หนึ่งถึงล้านการเชื่อมต่อผ่านเว็บ (REST API) | **EC2 เครื่องเดียวใน AZ เดียว** (ยกเว้นโหมด Multi-Attach ที่ต่อได้สูงสุด 16 เครื่องใน AZ เดียวกัน) | **เชื่อมต่อพร้อมกันได้หลายพันเครื่อง** ทั้ง EC2 หรือ On-premises ข้าม AZ, Region และ Account |
| **การควบคุมการเข้าถึง** | Bucket Policies, IAM Policies และระบบ Block Public Access | IAM Policies, Roles และ Security Groups | ผ่านจุดเชื่อมต่อใน VPC (Mount Target) และสิทธิ์ระดับ User/Group ตามมาตรฐาน POSIX |
| **วิธีการเข้ารหัส** | SSL (HTTPS), การเข้ารหัสฝั่ง Client และฝั่ง Server (SSE-S3, SSE-C, SSE-KMS) | เข้ารหัสข้อมูล At-rest และ In-transit ผ่าน EBS Encryption (ใช้ AWS KMS) | เข้ารหัสข้อมูล At-rest (AWS KMS) และ In-transit (TLS) |
| **การสำรองและกู้คืน** | ใช้ Versioning หรือ Cross-region replication | ใช้ฟีเจอร์ Snapshot ที่มีความทนทานสูง | การจำลองข้อมูล (Replication) ผ่านเครื่องมือภายนอกหรือ AWS DataSync |
| **ราคา** | คิดตามตำแหน่งของ Bucket ยิ่งใช้มากยิ่งราคาถูกลง | คิดตามปริมาณพื้นที่ (GB-month), ค่า IOPS และค่าเก็บ Snapshot ใน S3 | จ่ายตามปริมาณการใช้งานจริงต่อเดือน และค่า Throughput หากใช้โหมด Provisioned |
| **กรณีการใช้งาน** | เว็บเซิร์ฟเวอร์, CMS, สื่อและความบันเทิง, การสำรองข้อมูล, Big Data, Data Lake | Boot Volumes, ฐานข้อมูล Transactional และ NoSQL, Data Warehousing, ETL | แอปพลิเคชันองค์กร, Home Directories, สำรองฐานข้อมูล, เครื่องมือนักพัฒนา, Container Storage |
| **จุดเชื่อมต่อบริการ** | เข้าถึงได้ทั้งภายในและภายนอก VPC (ผ่าน URL ของ Bucket) | เข้าถึงได้เฉพาะภายใน VPC เท่านั้น | เข้าถึงได้เฉพาะภายใน VPC เท่านั้น |

-----

### **หมายเหตุเพิ่มเติม:**

  * S3 มีค่าใช้จ่ายด้านการจัดเก็บข้อมูลเพียวๆ ที่ถูกกว่า EBS และ EFS
  * EBS และ EFS มีประสิทธิภาพ (Performance) สูงกว่า S3
  * EBS ถูกออกแบบมาเพื่อใช้เป็น Volume (ไดรฟ์) สำหรับอินสแตนซ์ EC2 โดยเฉพาะ
