# การตรวจสอบสถานะ (Health Checks) ใน AWS

### **1. การตรวจสอบสถานะของ EC2 Instance (EC2 Instance Health Check)**
Amazon EC2 จะทำการตรวจสอบอินสแตนซ์ที่กำลังรันอยู่โดยอัตโนมัติ เพื่อระบุปัญหาด้านฮาร์ดแวร์และซอฟต์แวร์
* การตรวจสอบสถานะ (Status Checks) จะทำทุกๆ 1 นาที โดยจะส่งผลลัพธ์เป็น "ผ่าน" (Pass) หรือ "ล้มเหลว" (Fail)
* หากผ่านทุกขั้นตอน สถานะโดยรวมจะเป็น **OK** แต่หากมีขั้นตอนใดล้มเหลว สถานะจะเป็น **Impaired** (เสื่อมสภาพ)
* ระบบนี้ถูกฝังอยู่ใน EC2 จึงไม่สามารถปิดการใช้งานหรือลบออกได้ แต่คุณสามารถสร้างการแจ้งเตือน (Alarms) ตามผลลัพธ์การตรวจสอบได้
* **การตรวจสอบมี 2 ประเภท:**
    * **System Status Checks:** ตรวจสอบปัญหาที่ระดับโครงสร้างพื้นฐาน (Underlying problems) ที่ต้องให้ AWS เป็นผู้แก้ไข เมื่อการตรวจสอบนี้ล้มเหลว คุณสามารถรอให้ AWS แก้ไข หรือจะดำเนินการแก้ไขเอง (เช่น สั่ง Stop/Start อินสแตนซ์เพื่อให้ย้ายไปรันบนโฮสต์ใหม่)
    * **Instance Status Checks:** ตรวจสอบซอฟต์แวร์และการกำหนดค่าเครือข่ายของแต่ละอินสแตนซ์ โดย EC2 จะส่งคำขอ ARP ไปยัง ENI เพื่อเช็คความพร้อม หากล้มเหลวแสดงว่าเป็นปัญหาที่ต้องให้คุณ (ผู้ใช้) เป็นผู้แก้ไข

### **2. การตรวจสอบสถานะของ Elastic Load Balancer (ELB Health Check)**
Load Balancer จะส่งการ Ping, พยายามเชื่อมต่อ หรือส่งคำขอไปยัง EC2 อินสแตนซ์ที่ลงทะเบียนไว้เป็นระยะ เพื่อตรวจสอบความพร้อมใช้งาน
* อินสแตนซ์ที่พร้อมใช้งานจะมีสถานะเป็น **InService** ส่วนอินสแตนซ์ที่ไม่พร้อมใช้งานจะเป็น **OutOfService**
* **สิ่งที่ต้องระบุในการตั้งค่า Health Check:**
    * พอร์ตที่ระบุเฉพาะเจาะจง (Specific port)
    * โปรโตคอลที่ใช้ (HTTP/HTTPS จะถือว่าสำเร็จเมื่อได้รับ Response 200 ภายในเวลาที่กำหนด, TCP สำเร็จเมื่อเชื่อมต่อได้, SSL สำเร็จเมื่อทำ Handshake ผ่าน)
    * เส้นทางที่ใช้ Ping (Ping path)
* ELB Health Check **ไม่รองรับ WebSockets**
* Load Balancer จะส่งทราฟฟิกไปยังอินสแตนซ์ที่มีสถานะ Healthy เท่านั้น และจะกลับมาส่งให้ใหม่ก็ต่อเมื่ออินสแตนซ์นั้นกลับมาอยู่ในสถานะปกติแล้ว
* **Network Load Balancers (NLB)** มีการตรวจสอบ 2 แบบ:
    * **Active Health Checks:** ตัว Load Balancer ส่งคำขอไปยังเป้าหมายเป็นระยะ และปิดการเชื่อมต่อเมื่อตรวจสอบเสร็จ
    * **Passive Health Checks:** สังเกตการตอบสนองของเป้าหมายต่อการเชื่อมต่อปกติ ช่วยให้ตรวจพบปัญหาได้ก่อนที่ Active Health Check จะรายงานผล (ไม่สามารถปิดหรือตั้งค่าส่วนนี้ได้)

### **3. Auto Scaling และการตรวจสอบแบบกำหนดเอง (Custom Health Checks)**
อินสแตนซ์ทั้งหมดใน Auto Scaling Group จะเริ่มต้นด้วยสถานะ Healthy และจะถูกถือว่าปกติจนกว่า EC2 Auto Scaling จะได้รับการแจ้งเตือนว่าไม่ปกติจากแหล่งข้อมูลเหล่านี้:
* **Amazon EC2 (ค่าเริ่มต้น):** หากอินสแตนซ์อยู่ในสถานะอื่นที่ไม่ใช่ `running` หรือระบบเป็น `impaired` ระบบจะถือว่า Unhealthy และสั่งเปลี่ยนเครื่องใหม่ทันที
* **Elastic Load Balancing:** หากคุณเชื่อมต่อ Load Balancer เข้ากับ Auto Scaling Group ระบบจะตรวจสอบ **ทั้งสถานะ EC2 และสถานะจาก ELB** หากอันใดอันหนึ่งไม่ผ่าน จะถือว่าเครื่องนั้น Unhealthy
* **Custom Health Check:** คุณสามารถส่งข้อมูลสถานะโดยตรงจากระบบของคุณไปยัง Auto Scaling ได้เอง

**ข้อควรรู้เพิ่มเติม:**
* เมื่ออินสแตนซ์ถูกทำเครื่องหมายว่า Unhealthy ระบบจะกำหนดตารางเวลาเพื่อเปลี่ยนเครื่องใหม่ทันที (นอกจากคุณจะสั่งระงับกระบวนการ Health Check ไว้)
* **Health Check Grace Period (ระยะผ่อนผัน):** Auto Scaling จะรอจนกว่าช่วงเวลานี้จะหมดลงก่อนเริ่มตรวจสอบสถานะ เพื่อให้แอปพลิเคชันของคุณมีเวลาในการเริ่มต้นระบบ (Startup) โดยระยะผ่อนผันนี้จะเริ่มนับหลังจากจบ Lifecycle hook และอินสแตนซ์เข้าสู่สถานะ `InService` แล้ว
