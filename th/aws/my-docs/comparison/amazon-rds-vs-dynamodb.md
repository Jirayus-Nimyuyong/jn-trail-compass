# การเปรียบเทียบ Amazon RDS และ Amazon DynamoDB

| หัวข้อ | Amazon RDS | Amazon DynamoDB |
| :--- | :--- | :--- |
| **ประเภทฐานข้อมูล** | ฐานข้อมูลเชิงสัมพันธ์ (SQL) แบบ Managed | ฐานข้อมูล Key-value และ Document (NoSQL) แบบ Managed เต็มรูปแบบ |
| **คุณสมบัติเด่น** | มี Instance หลายประเภทตามลักษณะงาน และรองรับ 6 Engine: Aurora, PostgreSQL, MySQL, MariaDB, Oracle และ SQL Server | มอบประสิทธิภาพในระดับเลขหลักเดียวมิลลิวินาที (Single-digit millisecond) ในทุกสเกลการใช้งาน |
| **ขนาดพื้นที่เก็บข้อมูล** | • **Aurora:** 128 TB<br>• **MySQL, MariaDB, Oracle, PostgreSQL:** 64 TB<br>• **SQL Server:** 16 TB | รองรับตารางได้แทบทุกขนาด (ไม่จำกัด) |
| **จำนวนตารางต่อหน่วย** | ขึ้นอยู่กับ Engine ของฐานข้อมูล | 256 ตาราง |
| **ประสิทธิภาพ** | • **General Purpose (SSD):** ค่าพื้นฐาน 3 IOPS ต่อ GB และ Burst ได้ถึง 3,000 IOPS<br>• **Provisioned IOPS (SSD):** กำหนดค่า IOPS คงที่ได้สูงสุด 40,000 IOPS เหมาะสำหรับงาน OLTP<br>• **Magnetic:** รองรับสำหรับการใช้งานรุ่นเก่า (Backward compatibility) | • ประสิทธิภาพการอ่าน/เขียนในระดับเลขหลักเดียวมิลลิวินาที รองรับคำขอนับล้านครั้งต่อวินาทีบนข้อมูลระดับ Petabytes<br>• **DAX (Accelerator):** แคชในหน่วยความจำที่ช่วยเพิ่มความเร็วการอ่านขึ้น 10 เท่า (จากมิลลิวินาทีเป็นไมโครวินาที)<br>• ผู้ใช้กำหนดค่า Read/Write Throughput ได้เอง |
| **ความพร้อมใช้งาน** | • **Multi-AZ:** จำลองข้อมูลแบบ Synchronous ไปยัง Instance สำรองใน AZ อื่น<br>• แทนที่ Compute Instance ให้อัตโนมัติหากฮาร์ดแวร์ขัดข้อง | • **Global Tables:** จำลองข้อมูลอัตโนมัติครอบคลุม 3 AZ ใน Region ที่เลือก และปรับขนาดความจุตามภาระงานโดยอัตโนมัติ |
| **การสำรองข้อมูล** | • **Automated Backup:** ย้อนคืนข้อมูลตามจุดเวลา (PITR)<br>• **Database Snapshots:** ผู้ใช้สั่งสำรองข้อมูลเองและเก็บไว้ใน S3 จนกว่าจะสั่งลบ | • **PITR:** สำรองข้อมูลต่อเนื่อง ย้อนคืนได้ทุกวินาทีในช่วง 35 วันล่าสุด<br>• **On-demand Backup:** สร้างการสำรองข้อมูลเต็มรูปแบบเพื่อการเก็บรักษาไฟล์ระยะยาว (Archiving) |
| **การขยายระบบ** | • **Aurora:** ขยายขนาด Storage อัตโนมัติ<br>• **Engine อื่นๆ:** ขยายขนาดได้ทันทีโดยไม่มี Downtime และรองรับ Storage Auto Scaling<br>• **Read Replicas:** รองรับในเกือบทุก Engine รวมถึง Aurora | • ขยายระบบในแนวราบ (Horizontal scaling) รองรับตารางได้ทุกขนาด<br>• **On-demand mode:** ปรับความจุตามการใช้งานจริงทันที<br>• **Provisioned mode:** ปรับขนาด Throughput และ Storage อัตโนมัติคามค่าที่ตั้งไว้ |
| **ความปลอดภัย** | • แยกฐานข้อมูลในเครือข่ายเสมือน (VPC)<br>• เชื่อมต่อ On-premises ผ่าน IPsec VPN มาตรฐาน<br>• ตั้งค่า Firewall และควบคุมการเข้าถึงเครือข่าย<br>• เชื่อมต่อกับ IAM | • เชื่อมต่อกับ IAM อย่างสมบูรณ์ |
| **การเข้ารหัส** | • เข้ารหัส At rest ผ่าน AWS KMS (รวมถึง Backup, Replica, Snapshot)<br>• รองรับ Transparent Data Encryption ใน SQL Server และ Oracle<br>• รองรับ SSL สำหรับข้อมูลระหว่างรับส่ง | • เข้ารหัสข้อมูล At rest เป็นค่าเริ่มต้นโดยใช้กุญแจจาก AWS KMS |
| **การบำรุงรักษา** | อัปเดต Patches ล่าสุดให้ตามช่วงเวลาที่กำหนด (ควบคุมช่วงเวลาได้) | **ไม่ต้องบำรุงรักษา** เนื่องจากเป็นบริการแบบ Serverless |
| **ราคา** | • จ่ายรายเดือนตาม Instance ที่เปิดใช้งาน<br>• มีตัวเลือก Reserved Instance (1 หรือ 3 ปี) เพื่อรับส่วนลด | คิดค่าบริการตามการอ่าน, เขียน และจัดเก็บข้อมูล รวมถึงฟีเจอร์เสริมที่เปิดใช้ (มีรูปแบบราคาตามโหมดความจุที่เลือก) |
| **กรณีการใช้งาน** | แอปพลิเคชันดั้งเดิม, ERP, CRM และ E-commerce | แอปพลิเคชันระดับอินเทอร์เน็ต, การประมูลแบบเรียลไทม์, ตะกร้าสินค้า, โปรไฟล์ผู้ใช้, การจัดการเนื้อหา และแอปมือถือ |

-----

### **หมายเหตุเพิ่มเติม:**

  * DynamoDB รองรับการทำ **ACID Transactions** ในตัว
  * DynamoDB ใช้ **Filter Expressions** ในการกรองข้อมูล เนื่องจากไม่รองรับการคิวรีที่ซับซ้อน (Complex Queries) เหมือน SQL
  * การติดตั้งแบบ Multi-AZ สำหรับ MySQL, MariaDB, Oracle และ PostgreSQL จะใช้การจำลองข้อมูลทางกายภาพแบบ Synchronous ส่วน SQL Server จะใช้การจำลองทางตรรกะแบบ Synchronous
