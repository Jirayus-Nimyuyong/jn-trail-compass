# การเปรียบเทียบ Global Secondary Index และ Local Secondary Index

| หัวข้อ | Global Secondary Index (GSI) | Local Secondary Index (LSI) |
| :--- | :--- | :--- |
| **คำนิยาม** | ดัชนีที่มี Partition Key และ Sort Key ที่ **แตกต่าง** ไปจากตารางหลักได้ | ดัชนีที่ใช้ Partition Key **เดียวกับตารางหลัก** แต่มี Sort Key ที่แตกต่างกัน |
| **ขอบเขตการคิวรี** | สามารถดึงข้อมูลครอบคลุม **ทุก Partition** ในตารางหลัก | ขอบเขตจำกัดอยู่เฉพาะ **ภายใน Partition เดียวกัน** กับตารางหลัก (ที่มีค่า Partition Key เดียวกัน) |
| **โครงสร้าง Primary Key** | มีทั้ง Partition Key และ Sort Key (Sort Key เป็นตัวเลือกเสริม) | **ต้องมี** ทั้ง Partition Key และ Sort Key |
| **คุณสมบัติ Partition Key** | เป็นแอตทริบิวต์ใดก็ได้ในตารางหลัก (String, Number, Binary) | **ต้องเป็นแอตทริบิวต์เดียวกับ** Partition Key ของตารางหลัก |
| **คุณสมบัติ Sort Key** | เป็นแอตทริบิวต์ใดก็ได้ในตารางหลัก (String, Number, Binary) | เป็นแอตทริบิวต์ใดก็ได้ในตารางหลัก (String, Number, Binary) |
| **ค่าของคีย์ (Key Values)** | ไม่จำเป็นต้องไม่ซ้ำกัน (Non-unique) | Sort Key ไม่จำเป็นต้องไม่ซ้ำกันสำหรับ Partition Key นั้นๆ |
| **ข้อจำกัดขนาด** | **ไม่จำกัดขนาด** ต่อ Partition Key | ขนาดรวมของไอเทมทั้งหมดที่ทำดัชนีในหนึ่ง Partition Key **ต้องไม่เกิน 10 GB** |
| **การจัดการดัชนี** | • สร้างพร้อมตารางได้<br>• สร้างบนตารางที่มีอยู่แล้วได้<br>• ลบออกจากตารางที่มีอยู่ได้ | • **ต้องสร้างพร้อมการสร้างตารางเท่านั้น**<br>• ไม่สามารถสร้างหรือลบบนตารางที่มีอยู่แล้วได้ |
| **ความสอดคล้อง (Read Consistency)** | รองรับเฉพาะ **Eventual Consistency** (จากการอัปเดตแบบ Asynchronous) | เลือกได้ทั้ง **Eventual Consistency** หรือ **Strong Consistency** |
| **การใช้ Throughput** | **มีค่าความจุ (Capacity) แยกเป็นของตัวเอง** ทั้งอ่านและเขียน การคิวรี GSI จะใช้ความจุจากดัชนี ไม่ใช่จากตารางหลัก | **ใช้ความจุร่วมกับตารางหลัก** ทั้งการอ่านและการเขียน (การอัปเดตดัชนีจะหักความจุเขียนจากตารางหลัก) |
| **แอตทริบิวต์ที่เลือกได้ (Projected)** | ขอได้เฉพาะแอตทริบิวต์ที่ถูกเลือก (Projected) ลงในดัชนีเท่านั้น | ขอแอตทริบิวต์ที่ไม่ได้อยู่ในดัชนีได้ โดย DynamoDB จะไปดึงข้อมูลจากตารางหลักให้โดยอัตโนมัติ (Fetch) |
| **จำนวนดัชนีสูงสุด** | 20 ดัชนี (ค่าเริ่มต้น) | 5 ดัชนีต่อตาราง |

-----

### **การคำนวณ Read/Write Capacity (โหมด Provisioned)**

#### **Global Secondary Index (GSI)**

  * **การอ่าน:** การอ่านแบบ Eventually Consistent ใช้ 1/2 Read Capacity Unit (RCU) ดังนั้น 1 RCU สามารถดึงข้อมูลได้สูงสุด 8KB (4KB x 2) ผลลัพธ์สูงสุดต่อการคิวรีคือ 1 MB
  * **การเขียน:** ต้นทุนรวมคือ [การเขียนตารางหลัก] + [การอัปเดต GSI]
      * หากเขียนตารางแล้วไม่ต้องอัปเดต GSI จะไม่เสียค่าความจุของดัชนี
      * หากอัปเดตค่า Key ของดัชนี จะเสียค่าเขียน 2 ครั้ง (ลบค่าเก่า + ใส่ค่าใหม่)
      * หากลบแอตทริบิวต์ที่ทำดัชนีทิ้ง จะเสียค่าเขียน 1 ครั้งเพื่อลบข้อมูลในดัชนี
      * หากอัปเดตเฉพาะแอตทริบิวต์ที่ถูก Projection ไว้ (แต่ Key ไม่เปลี่ยน) เสียค่าเขียน 1 ครั้ง

#### **Local Secondary Index (LSI)**

  * **การอ่าน:** เลือกได้ทั้ง Strong (1 RCU) หรือ Eventual (1/2 RCU) โดยคำนวณจากขนาดแอตทริบิวต์ทั้งหมดที่ส่งกลับมา (รวมทั้งจากดัชนีและตารางหลักถ้ามีการ Fetch) แล้วปัดขึ้นเป็นพหุคูณของ 4 KB
  * **การเขียน:** ต้นทุนรวมคือ [การเขียนตารางหลัก] + [การอัปเดต LSI] (ใช้ความจุรวมของตารางหลัก)
      * หลักการคิดต้นทุนการเขียน (เพิ่ม/เปลี่ยนคีย์/ลบ) เหมือนกับ GSI แต่หักจากหน่วยความจุของตารางหลักโดยตรง
