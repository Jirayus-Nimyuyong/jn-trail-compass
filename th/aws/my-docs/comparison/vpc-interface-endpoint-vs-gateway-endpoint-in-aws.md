# VPC Endpoint คืออะไร?

**VPC Endpoint** ช่วยให้คุณสามารถสร้างการเชื่อมต่อแบบส่วนตัว (Private Connection) ไปยังบริการต่างๆ ของ AWS และบริการ VPC Endpoint อื่นๆ ผ่าน **AWS PrivateLink** โดยไม่จำเป็นต้องใช้ Public IP Address ในการสื่อสารระหว่างบริการเหล่านั้นกับอินสแตนซ์ใน Amazon VPC ของคุณ นอกจากนี้ยังมีความปลอดภัยสูงเนื่องจากข้อมูลจะไม่หลุดออกไปนอกเครือข่ายของ Amazon ในขณะที่รับส่งระหว่าง VPC และบริการปลายทาง

VPC Endpoints เป็นอุปกรณ์เสมือน (Virtual Devices) ที่ช่วยให้การสื่อสารระหว่างอินสแตนซ์ใน VPC และบริการต่างๆ มีประสิทธิภาพมากขึ้นโดยไม่กระทบต่อความพร้อมใช้งาน (Availability) หรือจำกัดแบนด์วิดท์ (Bandwidth) ทั้งยังถูกออกแบบมาให้ขยายตัวในแนวราบ (Horizontal Scale) เพื่อรองรับความซ้ำซ้อนและมีความพร้อมใช้งานสูงภายใน VPC

ในบทความนี้ เราจะพูดถึง VPC Endpoint ทั้ง 2 ประเภท:

1.  **Interface Endpoint** – กลุ่มของ Elastic Network Interfaces (ENI) ที่ถูกสร้างขึ้นโดย VPC ใน Subnet ที่คุณระบุ โดยแต่ละ ENI จะได้รับ Private IP และทำหน้าที่เป็นจุดรับส่งข้อมูลหลักไปยังบริการที่รองรับ แม้ว่าคุณจะมองเห็น ENI เหล่านี้ในบัญชีของคุณ แต่ Amazon VPC จะเป็นผู้จัดการทั้งหมด Interface Endpoint มีค่าบริการเป็นรายชั่วโมงและมีค่าธรรมเนียมเพิ่มเติมตามปริมาณการประมวลผลข้อมูล
2.  **Gateway Endpoint** – ทำหน้าที่คล้ายกับ Internet Gateway แต่ถูกออกแบบมาเพื่อส่งทราฟฟิกภายใน VPC ไปยังรายการ IP (Prefix List) ที่กำหนดไว้ล่วงหน้า ซึ่งประกอบด้วยช่วง IP ของ **Amazon DynamoDB** และ **Amazon S3** การใช้งานทำได้ง่ายๆ เพียงเพิ่มเส้นทาง (Route) ในตารางเส้นทางของ VPC ให้ชี้ไปยัง Gateway Endpoint โดยระบุปลายทางเป็น Prefix List ของ S3 หรือ DynamoDB ทั้งนี้ Gateway Endpoint ไม่ได้ใช้ AWS PrivateLink และ **ไม่มีค่าใช้จ่ายเพิ่มเติม** ในการใช้งาน

### **ความแตกต่างระหว่าง Interface Endpoint และ Gateway Endpoint**

| หัวข้อ | Interface Endpoint | Gateway Endpoint |
| :--- | :--- | :--- |
| **บริการที่รองรับ** | รองรับบริการของ AWS มากมาย รวมถึงบริการที่โฮสต์โดยลูกค้า/พาร์ทเนอร์รายอื่น และบริการใน AWS Marketplace | รองรับเฉพาะ **Amazon S3** และ **Amazon DynamoDB** เท่านั้น |
| **กลไกการทำงาน** | ทำหน้าที่เป็นจุดรับส่งข้อมูลผ่าน **AWS PrivateLink** | ไม่ต้องใช้ Elastic Network Interface (ENI) |
| **ที่อยู่ IP** | ใช้ **Private IP Address** | (ทำงานผ่าน Route Table) |
| **การเข้าถึง** | อนุญาตให้เข้าถึงจาก **On-premise** ได้ | คำขอต้องมาจาก **ภายใน VPC เท่านั้น** |
| **การเชื่อมต่อข้ามภูมิภาค** | อนุญาตให้เข้าถึงข้าม Region ผ่าน VPC Peering หรือ Transit Gateway | **ไม่ไม่อนุญาต** ให้เข้าถึงข้าม Region |
| **ค่าใช้จ่าย** | **มีค่าธรรมเนียมเพิ่มเติม** | **ไม่มีค่าใช้จ่าย (ฟรี)** |
| **ระดับการเชื่อมโยง** | เชื่อมโยงในระดับ **Subnet** | เชื่อมโยงในระดับ **VPC** |
| **รูปแบบทราฟฟิก** | ทราฟฟิกไหลผ่าน Interface Endpoint ไปยังบริการนั้นๆ โดยตรง | ทราฟฟิกถูกส่งต่อผ่าน Gateway Endpoint ไปยังบริการ AWS ที่ระบุ |

โดยสรุป เราได้เห็นความแตกต่างระหว่าง VPC Interface Endpoint และ Gateway Endpoint แล้ว โดย Interface Endpoint รองรับบริการที่หลากหลายกว่า ในขณะที่ Gateway Endpoint ถูกออกแบบมาเฉพาะสำหรับการส่งทราฟฟิกไปยัง S3 และ DynamoDB หวังว่าบทความนี้จะเป็นประโยชน์เนื่องจากเป็นหนึ่งในหัวข้อสำคัญสำหรับการสอบ AWS Associate ครับ
