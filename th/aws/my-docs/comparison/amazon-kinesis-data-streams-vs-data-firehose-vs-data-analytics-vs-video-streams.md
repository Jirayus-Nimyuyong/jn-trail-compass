# การเปรียบเทียบ Amazon Kinesis Services

| หัวข้อ | Data Streams | Data Firehose | Data Analytics | Video Streams |
| :--- | :--- | :--- | :--- | :--- |
| **คำนิยามสั้นๆ** | บริการสตรีมมิ่งข้อมูลแบบเรียลไทม์ที่ขยายขนาดได้และมีความทนทานสูง | จับข้อมูล, แปลงสภาพ และส่งข้อมูลสตรีมมิ่งไปยัง Data Lakes, แหล่งจัดเก็บข้อมูล และบริการวิเคราะห์ต่างๆ | แปลงสภาพและวิเคราะห์ข้อมูลสตรีมมิ่งแบบเรียลไทม์ด้วย Apache Flink | สตรีมวิดีโอจากอุปกรณ์ที่เชื่อมต่อมายัง AWS เพื่อการวิเคราะห์, Machine Learning, การเล่นวิดีโอ และการประมวลผลอื่นๆ |
| **แหล่งที่มาข้อมูล (Sources)** | แหล่งข้อมูลใดๆ (เซิร์ฟเวอร์, มือถือ, IoT ฯลฯ) ที่สามารถเรียก Kinesis API เพื่อส่งข้อมูลได้ | แหล่งข้อมูลใดๆ (เซิร์ฟเวอร์, มือถือ, IoT ฯลฯ) ที่สามารถเรียก Kinesis API เพื่อส่งข้อมูลได้ | Amazon MSK, Amazon Kinesis Data Streams, เซิร์ฟเวอร์, มือถือ, อุปกรณ์ IoT ฯลฯ | อุปกรณ์สตรีมมิ่งใดๆ ที่รองรับ Kinesis Video Streams SDK |
| **ผู้รับข้อมูล (Consumers)** | Kinesis Data Analytics, Amazon EMR, Amazon EC2, AWS Lambda | Amazon S3, Amazon Redshift, Amazon OpenSearch Service, HTTP endpoints ทั่วไป, Datadog, New Relic, MongoDB และ Splunk | ผลการวิเคราะห์สามารถส่งไปยัง Kinesis Data Streams อื่น, Firehose หรือฟังก์ชัน Lambda ได้ | Amazon Rekognition, Amazon SageMaker, MxNet, TensorFlow, การเล่นสื่อผ่าน HLS, แอปพลิเคชันประมวลผลสื่อที่ปรับแต่งเอง |
| **กรณีการใช้งาน** | • การรวบรวมข้อมูล Log และเหตุการณ์ต่างๆ<br>• การวิเคราะห์แบบเรียลไทม์<br>• การดึงข้อมูลจากมือถือ<br>• ข้อมูล Feed จากเกม | • การวิเคราะห์ข้อมูล IoT<br>• การวิเคราะห์ Clickstream<br>• การวิเคราะห์ Log<br>• การเฝ้าติดตามด้านความปลอดภัย | • Streaming ETL (การดึง แปลง และโหลดข้อมูลแบบสตรีม)<br>• การวิเคราะห์แบบเรียลไทม์<br>• การประมวลผลเหตุการณ์แบบมีสถานะ (Stateful event processing) | • เทคโนโลยีอัจฉริยะ (Smart technologies)<br>• AI/ML ที่เกี่ยวข้องกับวิดีโอ<br>• การประมวลผลวิดีโอ |
