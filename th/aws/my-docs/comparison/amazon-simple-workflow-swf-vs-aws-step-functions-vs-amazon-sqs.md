# บริการจัดการเวิร์กโฟลว์และข้อความของ AWS

### **Amazon Simple Workflow (SWF)**
* เป็นเว็บเซอร์วิสที่ช่วยให้การประสานงาน (Coordinate) งานระหว่างส่วนประกอบต่างๆ ของแอปพลิเคชันแบบกระจายตัว (Distributed Application) เป็นเรื่องง่าย
* ใน Amazon SWF **งาน (Tasks)** คือตัวแทนของการเรียกใช้ขั้นตอนตรรกะในแอปพลิเคชัน งานเหล่านี้จะถูกประมวลผลโดย **Workers** ซึ่งเป็นโปรแกรมที่โต้ตอบกับ SWF เพื่อรับงานไปทำ ประมวลผล และส่งผลลัพธ์กลับมา
* การประสานงานของงานรวมถึงการจัดการการพึ่งพากันของการประมวลผล (Execution dependencies), การจัดตารางเวลา (Scheduling) และการทำงานพร้อมกัน (Concurrency) ตามลำดับตรรกะของแอปพลิเคชัน

### **AWS Step Functions**
* บริการแบบ Managed เต็มรูปแบบที่ช่วยประสานส่วนประกอบของแอปพลิเคชันและ Microservices โดยใช้ **เวิร์กโฟลว์แบบภาพ (Visual Workflows)**
* คุณต้องนิยาม **State Machines** เพื่ออธิบายเวิร์กโฟลว์เป็นลำดับขั้นตอน รวมถึงความสัมพันธ์ ข้อมูลเข้าและข้อมูลออก แต่ละสถานะ (State) สามารถทำงาน, ตัดสินใจ, ส่งพารามิเตอร์, เริ่มการทำงานแบบขนาน, จัดการการหมดเวลา (Timeouts) หรือจบเวิร์กโฟลว์ด้วยความสำเร็จหรือล้มเหลว

### **Amazon SQS**
* บริการคิวข้อความ (Message Queue) ที่แอปพลิเคชันใช้แลกเปลี่ยนข้อมูลผ่านโมเดลการดึงข้อมูล (Polling) เพื่อแยกส่วนประกอบ (Decouple) ระหว่างผู้ส่งและผู้รับ
* **FIFO Queue:** รักษาลำดับการรับส่งข้อความให้ถูกต้องแม่นยำ
* **Standard Queue:** พยายามรักษาลำดับข้อความแบบยืดหยุ่น (Loose-FIFO)

### **การเปรียบเทียบและการเลือกใช้งาน**

#### **1. AWS Step Functions vs Amazon SWF**
* **ควรใช้ Step Functions:** สำหรับแอปพลิเคชันใหม่ทั้งหมด เพราะมีประสิทธิภาพและคล่องตัวกว่าด้วยเวิร์กโฟลว์แบบภาพ และเขียน State Machines ด้วย **JSON (ASL)**
* **ควรใช้ SWF:** หากคุณต้องการ **สัญญาณจากภายนอก (External Signals)** หรือตัวตัดสินใจ (Deciders) เข้ามาแทรกแซงกระบวนการ หรือต้องการรัน Child Processes ที่ส่งผลลัพธ์กลับไปยัง Parent
* **การควบคุม:** SWF ให้คุณเขียนโปรแกรมตัวตัดสินใจ (Decider) แยกจากขั้นตอนกิจกรรม ทำให้ควบคุมตรรกะได้สมบูรณ์ แต่เพิ่มความซับซ้อนในการพัฒนา (สามารถใช้ Flow Framework ช่วยได้)



#### **2. AWS Step Functions vs Amazon SQS**
* **ใช้ Step Functions:** เมื่อต้องการประสานส่วนประกอบของบริการในแอปพลิเคชันที่ต้องการความสามารถในการขยายตัวและตรวจสอบย้อนหลังได้ (Auditable)
* **ใช้ SQS:** เมื่อต้องการ **คิว (Queue)** ที่เชื่อถือได้สำหรับการรับ, ส่ง และจัดเก็บ **ข้อความ (Messages)** ระหว่างบริการ
* **การติดตาม:** Step Functions ติดตามงานและเหตุการณ์ทั้งหมดให้โดยอัตโนมัติ ในขณะที่ SQS กำหนดให้คุณต้องติดตั้งระบบติดตามในระดับแอปพลิเคชันเอง
* **มุมมองการจัดการ:** Step Functions มี Console ที่มองเห็นรายละเอียดการประมวลผล (Execution) ในระดับแอปพลิเคชัน แต่ SQS ต้องพัฒนาระบบดังกล่าวขึ้นมาเองหากต้องการใช้งาน

#### **3. Amazon SQS vs Amazon SWF**
* **รูปแบบการทำงาน:** SWF เน้นที่ **"งาน" (Task-oriented)** ในขณะที่ SQS เน้นที่ **"ข้อความ" (Message-oriented)**
* **ความสามารถ:** SWF มีฟีเจอร์ที่ช่วยในการพัฒนาแอปพลิเคชัน เช่น การส่งข้อมูลระหว่างงาน, การส่งสัญญาณ (Signaling) และความยืดหยุ่นในการกระจายงาน ซึ่ง SQS ต้องติดตั้งฟังก์ชันเหล่านี้เองในระดับแอปพลิเคชัน
* **Framework:** นอกจาก SDK แล้ว SWF ยังมี **Flow Framework** ที่ช่วยให้เขียนแอปพลิเคชันแบบกระจายตัวโดยใช้โครงสร้างโปรแกรมสำหรับการโต้ตอบแบบอซิงโครนัสได้
