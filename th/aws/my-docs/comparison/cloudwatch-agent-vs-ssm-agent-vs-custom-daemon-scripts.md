### **CloudWatch Agent**
* **CloudWatch Agent** ช่วยให้คุณรวบรวมตัวชี้วัด (Metrics) ระดับระบบจากอินสแตนซ์ EC2 และเซิร์ฟเวอร์ On-premises ได้ละเอียดกว่าตัวชี้วัดมาตรฐานของ CloudWatch
* รองรับการดึงตัวชี้วัดที่กำหนดเอง (Custom Metrics) จากแอปพลิเคชันหรือบริการโดยใช้โปรโตคอล **StatsD** และ **collectd**
    * *StatsD:* รองรับทั้งบน Linux และ Windows Server
    * *collectd:* รองรับเฉพาะบน Linux เท่านั้น
* สามารถใช้ CloudWatch Agent เพื่อรวบรวม **Logs** จากเซิร์ฟเวอร์และส่งไปยัง CloudWatch Logs ได้
* ตัวชี้วัดที่รวบรวมโดย CloudWatch Agent จะถูกคิดค่าบริการในฐานะ **Custom Metrics**
* **คุณสามารถติดตั้ง CloudWatch Agent ได้ 3 วิธี:**
    1. ผ่าน Command Line (บรรทัดคำสั่ง)
    2. ผ่าน SSM Agent
    3. ผ่าน AWS CloudFormation

### **SSM Agent (AWS Systems Manager Agent)**
* **SSM Agent** เป็นซอฟต์แวร์ของ Amazon ที่ทำงานบนอินสแตนซ์ EC2 และ Hybrid Instances ที่กำหนดค่าไว้สำหรับ Systems Manager
* ทำหน้าที่ประมวลผลคำขอจากบริการ Systems Manager บนคลาวด์ และกำหนดค่าเครื่องตามที่ระบุในคำขอ ช่วยให้คุณจัดการเซิร์ฟเวอร์ได้โดยไม่ต้องล็อกอินเข้าเครื่องผ่านระบบอัตโนมัติ (Automation)
* ส่งข้อมูลสถานะและผลการทำงานกลับไปยัง Systems Manager ผ่านบริการ **EC2 Messaging**
* SSM Agent ทำงานโดยใช้สิทธิ์ **Root** (บน Linux) หรือสิทธิ์ **SYSTEM** (บน Windows)
* ปัจจุบัน CloudWatch Agent ได้เข้ามาทำหน้าที่แทน SSM Agent ในการส่ง Log ของตัวชี้วัดไปยัง CloudWatch Logs

### **Custom Daemon Scripts (สคริปต์ที่เขียนขึ้นเอง)**
* คุณจะใช้สคริปต์ที่ปรับแต่งเอง (เช่น **Cron** หรือ **Bash scripts**) ก็ต่อเมื่อเอเจนต์ทั้งสองที่กล่าวมาข้างต้นไม่ตอบโจทย์ความต้องการของคุณ
* **กรณีการใช้งาน:**
    * แม้ CloudWatch Agent จะมีประโยชน์ในการเก็บ Log และ Metrics ระดับระบบ แต่คุณอาจสร้างสคริปต์ขึ้นมาเองเพื่อทำการแก้ไขข้อมูลบางอย่างก่อนที่จะส่งข้อมูลออกไป
    * แม้ SSM Agent จะมีประโยชน์ด้านการทำงานอัตโนมัติ แต่บางกรณี Systems Manager อาจไม่มีเอกสาร (Document) รองรับทุกสถานการณ์ หรือคุณอาจมีข้อกำหนดด้านการปฏิบัติตามกฎระเบียบ (Compliance) ที่สั่งให้ปิดการใช้งาน SSM Agent (เนื่องจากเอเจนต์นี้ทำงานด้วยสิทธิ์ระดับสูงสุดหรือ Root)
