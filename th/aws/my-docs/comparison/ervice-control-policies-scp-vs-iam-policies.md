# การเปรียบเทียบ SCP และ IAM Policies

### **Service Control Policies (SCP)**
* **SCP** ส่วนใหญ่จะใช้ร่วมกับ **Organizational Units (OUs)** ภายใน AWS Organizations
* **SCP ไม่ได้มาแทนที่ IAM Policies:** ตัวมันเองไม่ได้ให้สิทธิ์การใช้งานจริง หากต้องการดำเนินการใดๆ คุณยังคงต้องมอบสิทธิ์ผ่าน IAM Policy ที่เหมาะสมอยู่ดี
* **การทำงานร่วมกัน:** แม้ว่าตัวตน (Principal) จะได้รับอนุญาตให้ทำบางอย่างผ่าน IAM Policy แล้วก็ตาม แต่ถ้ามี SCP ที่สั่ง **ปฏิเสธ (Deny)** การกระทำนั้นแนบอยู่ SCP จะเข้ามามีผลเหนือกว่าทันที (SCP มีลำดับความสำคัญสูงกว่า IAM Policies)
* สามารถนำ SCP ไปใช้กับ **Root** ขององค์กร หรือใช้กับ **แต่ละบัญชี** ใน OU ได้
* **รูปแบบการควบคุม:** เมื่อคุณใช้ SCP กับ OU หรือบัญชี คุณสามารถเลือกที่จะ **อนุญาต (Whitelist)** หรือ **ไม่อนุญาต (Blacklist)** บริการที่ระบุได้ หากบริการใดไม่ได้รับอนุญาตอย่างชัดเจนใน SCP ที่เกี่ยวข้องกับบัญชีนั้น หรือ OU ต้นทาง บัญชีเหล่านั้นจะถูกปฏิเสธการเข้าถึงบริการนั้นทันที
* **หลักการสืบทอดสิทธิ์:** บัญชีใดๆ จะมีสิทธิ์เฉพาะเท่าที่ได้รับอนุญาตจาก "ต้นทาง (Parent)" ทุกระดับที่อยู่เหนือขึ้นไปเท่านั้น หากสิทธิ์ถูกบล็อกในระดับใดระดับหนึ่งที่อยู่เหนือบัญชีขึ้นไป (ไม่ว่าจะบล็อกทางอ้อมโดยไม่ระบุใน Allow หรือบล็อกโดยตรงใน Deny) ผู้ใช้หรือ Role ในบัญชีนั้นจะไม่สามารถใช้สิทธิ์นั้นได้ **แม้ว่าจะมี IAM Policy ที่ให้สิทธิ์ Administrator แนบอยู่ก็ตาม**
* SCP มีผลเฉพาะกับ Principal ที่จัดการโดยบัญชีที่เป็นส่วนหนึ่งของ Organization เท่านั้น

### **IAM Policies**
* **IAM Policies** ทำงานใน **ระดับตัวตน (Principal Level)**
* **ประเภทของ IAM Policies:**
    * **Identity-based policies:** แนบกับผู้ใช้ (User), กลุ่ม (Group) หรือบทบาท (Role) ของ IAM
    * **Resource-based policies:** แนบกับทรัพยากรของ AWS เช่น S3 bucket
* ใช้สำหรับให้สิทธิ์ (Grant) หรือปฏิเสธ (Deny) ให้ตัวตนสามารถดำเนินการบางอย่างกับทรัพยากรที่ระบุได้ สามารถใช้ร่วมกับ SCP เพื่อให้เกิดการควบคุมที่เข้มงวดขึ้นใน AWS Organizations
* IAM Policy สามารถใช้ได้กับ IAM users, groups หรือ roles เท่านั้น และ **ไม่สามารถจำกัดสิทธิ์ของ Root Identity** ของบัญชี AWS ได้
* **ไม่สามารถ** แนบ IAM Policies เข้ากับ OUs ได้
* **ลำดับการตัดสินใจ:** IAM Policy สามารถอนุญาตหรือปฏิเสธการกระทำได้ โดยที่ **การอนุญาตโดยตรง (Explicit Allow) จะชนะการปฏิเสธโดยอ้อม (Implicit Deny)** แต่ **การปฏิเสธโดยตรง (Explicit Deny) จะชนะการอนุญาตโดยตรงเสมอ**
