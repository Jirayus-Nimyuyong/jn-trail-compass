# การเปรียบเทียบ Amazon Aurora และ Amazon RDS

| หัวข้อ | Amazon Aurora | Amazon RDS |
| :--- | :--- | :--- |
| **ประเภทฐานข้อมูล** | ฐานข้อมูลเชิงสัมพันธ์ (Relational Database) | ฐานข้อมูลเชิงสัมพันธ์ (Relational Database) |
| **คุณสมบัติเด่น** | • รองรับ MySQL และ PostgreSQL<br>• เร็วกว่า MySQL มาตรฐาน 5 เท่า และเร็วกว่า PostgreSQL มาตรฐาน 3 เท่า<br>• ใช้ Parallel Query เพื่อรันงานทั้งแบบ Transactional และ Analytical พร้อมกันได้โดยประสิทธิภาพไม่ตก<br>• สามารถทำ Load Balance งานผ่าน Custom Endpoints ได้<br>• **Aurora Serverless** ปรับขนาดความจุ (Capacity) อัตโนมัติแบบ On-demand | • รองรับ 5 Engine: MySQL, PostgreSQL, MariaDB, Oracle และ SQL Server<br>• มี Instance หลายประเภทตามลักษณะงาน<br>• ใช้ General Purpose หรือ Provisioned IOPS Storage เพื่อประสิทธิภาพ IOPS ที่สม่ำเสมอ |
| **ความจุสูงสุด** | 128 TB | • 64 TB สำหรับ MySQL, MariaDB, Oracle และ PostgreSQL<br>• 16 TB สำหรับ SQL Server |
| **คลาสของ Instance** | • **Memory Optimized** – สำหรับงานประมวลผลชุดข้อมูลขนาดใหญ่ในหน่วยความจำ<br>• **Burstable** – เพิ่มประสิทธิภาพ CPU ชั่วคราวได้เมื่อจำเป็น | • **Standard** – สำหรับงานทั่วไปที่สมดุลทั้ง Compute, Memory และ Network<br>• **Memory Optimized**<br>• **Burstable** |
| **ความพร้อมใช้งาน (Availability)** | • ใช้ RDS Multi-AZ เพื่อ Failover อัตโนมัติไปยัง Aurora Replicas (สูงสุด 15 ตัว) ครอบคลุม 3 AZ<br>• **Global Database** จำลองข้อมูลข้าม Region (Latency \< 1 วินาที)<br>• **Self-healing** สแกนหาข้อผิดพลาดของ Disk และแทนที่ให้อัตโนมัติ | • **Multi-AZ Deployment** จำลองข้อมูลแบบ Synchronous ไปยัง Instance สำรองใน AZ อื่น<br>• แทนที่ Compute Instance ให้อัตโนมัติในกรณีที่ฮาร์ดแวร์ขัดข้อง |
| **การสำรองข้อมูล (Backups)** | • Point-in-time recovery ย้อนคืนข้อมูลได้ทุกวินาที (ห่างจากปัจจุบันไม่เกิน 5 นาที)<br>• เก็บข้อมูลสำรองอัตโนมัติสูงสุด 35 วัน<br>• **Backtrack** ย้อนสถานะฐานข้อมูลกลับไปได้ทันทีโดยไม่ต้อง Restore | • Point-in-time recovery ย้อนคืนข้อมูลได้ตามจุดเวลาที่ต้องการ<br>• **Database Snapshots** ผู้ใช้สั่งสำรองข้อมูลเองและเก็บไว้ใน S3 จนกว่าจะสั่งลบ |
| **การขยายระบบ (Scalability)** | • เพิ่มขนาด Storage อัตโนมัติครั้งละ 10 GB<br>• **Replica Auto-scaling** เพิ่ม/ลดจำนวน Read Replica ตามตัวชี้วัดประสิทธิภาพ<br>• **Cross-region Replicas** อ่านข้อมูลจากพื้นที่ใกล้เคียงได้เร็วขึ้น | • ขยายขนาด Storage อัตโนมัติโดยไม่มี Downtime<br>• **Read Replicas** รองรับเกือบทุก Engine โดยใช้การจำลองข้อมูลแบบ Asynchronous<br>• ขยายทรัพยากรแนวตั้ง (Vertical) ได้สูงสุด 32 vCPUs และ 244 GiB RAM |
| **ความปลอดภัย** | • แยกฐานข้อมูลในเครือข่ายเสมือนผ่าน VPC<br>• เชื่อมต่อกับ On-premises ผ่าน VPN หรือ Direct Connect<br>• ตั้งค่า Security Group Firewall<br>• เชื่อมต่อกับ IAM | • แยกฐานข้อมูลผ่าน VPC<br>• เชื่อมต่อ On-premises ผ่าน VPN หรือ Direct Connect<br>• ตั้งค่า Security Group Firewall<br>• เชื่อมต่อกับ IAM |
| **การเข้ารหัส** | • เข้ารหัสข้อมูล At rest (รวม Backup/Snapshot/Replica) ผ่าน AWS KMS<br>• รองรับ SSL (AES-256) สำหรับข้อมูลระหว่างรับส่ง (In transit) | • เข้ารหัสข้อมูล At rest ผ่าน AWS KMS<br>• รองรับ **Transparent Data Encryption** ใน SQL Server และ Oracle<br>• รองรับ SSL สำหรับข้อมูลระหว่างรับส่ง |
| **การยืนยันตัวตน** | • รหัสผ่าน (Password)<br>• รหัสผ่านร่วมกับ IAM Database Authentication | • รหัสผ่าน (Password)<br>• รหัสผ่านร่วมกับ IAM Database Authentication<br>• รหัสผ่านร่วมกับ Kerberos |
| **การบำรุงรักษา** | • อัปเดต Patches ล่าสุดให้อัตโนมัติ<br>• **Aurora Serverless** ไม่ต้องจัดการโครงสร้างพื้นฐานใดๆ | • อัปเดต Patches (Major/Minor) ตามช่วงเวลา Maintenance ที่กำหนดไว้ (ควบคุมช่วงเวลาเองได้) |
| **การเฝ้าติดตาม** | • **Enhanced Monitoring** เก็บตัวชี้วัดจาก OS<br>• **Performance Insights** ตรวจจับปัญหาประสิทธิภาพ<br>• แจ้งเตือนเหตุการณ์ผ่าน Amazon SNS | • **Enhanced Monitoring** เก็บตัวชี้วัดจาก OS<br>• **Performance Insights** ตรวจจับปัญหาประสิทธิภาพ<br>• แจ้งเตือนเหตุการณ์ผ่าน Amazon SNS |
| **ราคา** | • จ่ายรายเดือนตามการใช้งาน (On-demand) รวมถึง Storage ที่ใช้จริง<br>• มีตัวเลือก **Reserved Instance** (1 หรือ 3 ปี) เพื่อรับส่วนลด | • จ่ายรายเดือนตามการใช้งาน (On-demand) รวมถึง Storage ที่ใช้จริง<br>• มีตัวเลือก **Reserved Instance** (1 หรือ 3 ปี) เพื่อรับส่วนลด |
| **กรณีการใช้งาน** | • **แอปพลิเคชันองค์กร** ที่ต้องการระบบจัดการ Patch และ Recovery อัตโนมัติ<br>• **แอปพลิเคชัน SaaS** ที่ต้องการเน้นพัฒนาแอปโดยไม่กังวลเรื่องฐานข้อมูล<br>• **เกมบนเว็บ/มือถือ** ที่ต้องการ Throughput สูง และการขยายตัวที่ยืดหยุ่น | • **เว็บและโมบายแอป** ที่ต้องการความพร้อมใช้งานสูงและขยายตัวได้ดี<br>• **แอปพลิเคชัน E-commerce** ที่ต้องการความปลอดภัยตามมาตรฐาน PCI<br>• **เกมออนไลน์** ที่นักพัฒนาไม่ต้องกังวลเรื่องการจัดการโครงสร้างพื้นฐาน |
