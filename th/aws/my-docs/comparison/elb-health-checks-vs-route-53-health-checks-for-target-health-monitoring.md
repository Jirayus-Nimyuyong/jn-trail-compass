# การเปรียบเทียบระบบตรวจสอบสถานะ (Health Check)

| หัวข้อ | AWS Elastic Load Balancing (ELB) | Amazon Route 53 |
| :--- | :--- | :--- |
| **วัตถุประสงค์** | ตรวจสอบสถานะของอินสแตนซ์, เซิร์ฟเวอร์ หรือฟังก์ชันเป็นระยะ เพื่อยืนยันว่าพร้อมรับคำขอทราฟฟิกหรือไม่ | เฝ้าติดตามสถานะของเป้าหมายในระเบียน (Record) ซึ่งอาจเป็นอินสแตนซ์ EC2, เซิร์ฟเวอร์ หรือบริการ AWS ที่มี Endpoint |
| **การตั้งค่าเป้าหมาย** | ระบุพอร์ตและเส้นทาง (Path) ปกติของเป้าหมายที่ Load Balancer จะส่งคำขอตรวจสอบไป | ระบุชื่อโดเมน หรือ IP Address, พอร์ต และเส้นทางที่ Route 53 จะใช้ส่งคำขอ (กรณีไม่ใช่ Alias Record) หรือตั้งค่า **Evaluate Target Health** เป็น **Yes** (กรณีเป็น Alias Record) |
| **ขอบเขตพื้นที่** | ตรวจสอบเป้าหมายที่ครอบคลุมหลาย **Availability Zones** ได้ แต่ไม่ครอบคลุมหลายภูมิภาค (Regions) | ตรวจสอบเป้าหมายได้ทุกที่ **ไม่ว่าจะอยู่ที่ใด** ตราบเท่าที่ Route 53 สามารถเชื่อมต่อถึงได้ |
| **ความถี่ในการตรวจสอบ** | กำหนดค่าได้ระหว่าง **5 วินาที ถึง 300 วินาที** | เลือกได้ระหว่างทุกๆ **10 วินาที** หรือทุกๆ **30 วินาที** |
| **เวลาที่รอการตอบกลับ (Timeout)** | กำหนดค่าได้ระหว่าง **2 วินาที ถึง 60 วินาที** | **ไม่สามารถกำหนดค่าได้** |
| **เกณฑ์การตัดสินว่าผ่าน** | กำหนดค่าเกณฑ์ (Threshold) จำนวนครั้งที่เป้าหมายต้องผ่านหรือล้มเหลวเพื่อตัดสินสถานะ | หากเซิร์ฟเวอร์ตรวจสอบมากกว่า **18%** รายงานว่าปกติ Route 53 จะถือว่า Healthy หากน้อยกว่านั้นจะถือว่า Unhealthy (เซิร์ฟเวอร์ตรวจสอบกระจายอยู่ทั่วโลก) |
| **การเข้าถึง** | ต้องมั่นใจว่าเป้าหมายสามารถติดต่อกับ Load Balancer ได้ และสามารถเพิ่มหรือลดเป้าหมายได้ง่าย | ต้องมั่นใจว่า Endpoint เข้าถึงและแปลผลชื่อได้เมื่อผู้ใช้เรียก URL (เนื่องจากมีการทำ DNS Caching อาจต้องใช้เวลาสักพักกว่าการเปลี่ยนเป้าหมายจะส่งผลถึงผู้ใช้) |
| **วัตถุประสงค์หลัก** | เพื่อความพร้อมใช้งานสูง (**High Availability**) และการทนทานต่อความผิดพลาด (**Fault Tolerance**) | เพื่อการทำ **DNS Failover Routing** (การสลับเส้นทางเมื่อระบบล่มที่ระดับ DNS) |
