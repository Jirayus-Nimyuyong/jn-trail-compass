ในโลกปัจจุบันที่สมาร์ทโฟนแพร่หลายและเชื่อมต่อถึงกันมากขึ้น นักพัฒนาจำนวนมากเริ่มหันมาใช้งานคลาวด์ในการติดตั้งแอปพลิเคชันอย่างรวดเร็ว หนึ่งในความท้าทายแรกของการพัฒนาแอปคือการอนุญาตให้ผู้ใช้เข้าสู่ระบบและยืนยันตัวตน ซึ่งขั้นตอนการตรวจสอบผู้ใช้มีหลายระยะและส่วนใหญ่มักเป็นส่วนที่ผู้ใช้มองไม่เห็น AWS จึงมอบโซลูชันที่ง่ายดายสำหรับสถานการณ์นี้

การตรวจสอบตัวตนผู้ใช้ (User Identity verification) คือหัวใจหลักของ **Amazon Cognito** โดยมุ่งเน้นโซลูชันใน 3 ด้านสำคัญ:

* **Authentication (การพิสูจน์ตัวตน):** มอบตัวเลือกให้ผู้ใช้สมัครสมาชิกและเข้าสู่ระบบ รองรับการเชื่อมต่อกับตัวตนระดับองค์กร (Microsoft AD) หรือตัวตนบนโซเชียลมีเดีย (Amazon, Facebook, Google และอื่นๆ)
* **Authorization (การกำหนดสิทธิ์):** กำหนดชุดสิทธิ์การใช้งานหรือการดำเนินการที่อนุญาตสำหรับผู้ใช้รายนั้นๆ โดยสามารถควบคุมการเข้าถึงทรัพยากรต่างๆ ได้อย่างละเอียด
* **User Management (การจัดการผู้ใช้):** ช่วยในการจัดการวงจรชีวิตของผู้ใช้ เช่น การนำเข้าข้อมูลผู้ใช้, การรับผู้ใช้ใหม่เข้าสู่ระบบ, การระงับการใช้งาน ตลอดจนการจัดเก็บและจัดการโปรไฟล์ผู้ใช้

ในโพสต์นี้ เราจะพูดถึง **Cognito User Pools** และ **Identity Pools** รวมถึงภาพรวมของวิธีการทำงานเพื่อมอบฟังก์ชันการพิสูจน์ตัวตนและการกำหนดสิทธิ์ที่สามารถนำไปผสานรวมกับแอปพลิเคชันมือถือของคุณได้

### Amazon Cognito User Pools
**Amazon Cognito User Pools** ใช้สำหรับการ **Authentication (พิสูจน์ตัวตน)** หากคุณต้องการตรวจสอบตัวตนของผู้ใช้ คุณต้องมีวิธีให้เขาเข้าสู่ระบบด้วยชื่อผู้ใช้/รหัสผ่าน หรือการล็อกอินผ่านผู้ให้บริการภายนอก (Identity Providers) เช่น Amazon, Facebook, Google หรือระบบที่รองรับ SAML อย่าง Microsoft Active Directory คุณสามารถตั้งค่าผู้ให้บริการเหล่านี้บน Cognito ได้ และระบบจะจัดการการโต้ตอบกับผู้ให้บริการเหล่านั้นให้เอง คุณจึงมีหน้าที่เพียงแค่จัดการกับ Authentication Tokens บนแอปของคุณเท่านั้น

ด้วย Cognito User Pools คุณสามารถมอบฟังก์ชันการสมัครสมาชิกและเข้าสู่ระบบให้กับผู้ใช้แอปมือถือหรือเว็บแอปได้ โดยไม่จำเป็นต้องสร้างหรือดูแลโครงสร้างพื้นฐานเซิร์ฟเวอร์ใดๆ สำหรับการตรวจสอบผู้ใช้เอง

**แผนภาพแสดงการทำงานของ Authentication ด้วย Cognito User Pools:**
1.  ผู้ใช้ส่งคำขอการตรวจสอบตัวตน (Authentication Request) ไปยัง Cognito User Pools
2.  Cognito User Pool ตรวจสอบตัวตนของผู้ใช้ หรือส่งคำต่อไปยังผู้ให้บริการตัวตน (Identity Providers) เช่น Facebook, Google, Amazon หรือ SAML (Microsoft AD)
3.  Cognito User Pool Token จะถูกส่งกลับไปให้ผู้ใช้
4.  ผู้ใช้สามารถนำ Token นี้ไปเข้าถึง backend API ที่โฮสต์อยู่บน EC2, API Gateway หรือ Lambda ได้

หากคุณต้องการหน้าล็อกอินแบบด่วน คุณยังสามารถใช้ UI การล็อกอินสำเร็จรูปที่ Amazon Cognito จัดเตรียมไว้ให้ ซึ่งคุณเพียงแค่นำไปเชื่อมต่อกับแอปพลิเคชันของคุณเท่านั้น นอกจากนี้ ในหน้าจัดการของ Amazon Cognito User Pool คุณยังสามารถจัดการผู้ใช้ได้ เช่น การรีเซ็ตรหัสผ่าน, การระงับ/เปิดใช้งานผู้ใช้ และการลงทะเบียนหรือลบผู้ใช้

### Amazon Cognito Identity Pools
**Cognito Identity Pools (Federated Identities)** มอบฟังก์ชันที่แตกต่างจาก User Pools โดยใช้สำหรับการ **User Authorization (กำหนดสิทธิ์ผู้ใช้)** คุณสามารถสร้างอัตลักษณ์เฉพาะ (Unique Identities) ให้กับผู้ใช้และเชื่อมโยงเข้ากับผู้ให้บริการตัวตนได้ การใช้ Identity Pools จะทำให้ผู้ใช้ได้รับ **AWS Credentials ชั่วคราว** เพื่อเข้าถึงบริการอื่นๆ ของ AWS ได้โดยตรง

อาจเรียกได้ว่า Identity Pools คือกลไกที่แท้จริงในการ "อนุญาต" การเข้าถึงทรัพยากรของ AWS เมื่อคุณสร้าง Identity Pools ให้คุณนึกถึงการกำหนดว่า "ใคร" ได้รับอนุญาตให้ขอรับ AWS Credentials และนำไปใช้เข้าถึงทรัพยากรต่างๆ

**แผนภาพแสดงการทำงานของ Authorization ด้วย Cognito Identity Pools:**
1.  เว็บแอปหรือแอปมือถือส่ง Authentication Token ไปยัง Cognito Identity Pools โดย Token นี้ต้องมาจากผู้ให้บริการที่ถูกต้อง เช่น Cognito User Pools, Amazon หรือ Facebook
2.  Cognito Identity Pool จะแลกเปลี่ยน Token นั้นเป็น AWS Credentials ชั่วคราว เพื่อเข้าถึงทรัพยากรอย่าง S3 หรือ DynamoDB แล้วส่ง Credentials กลับไปให้ผู้ใช้
3.  Credentials ชั่วคราวนี้จะถูกนำไปใช้เพื่อเข้าถึงทรัพยากรของ AWS
4.  คุณสามารถกำหนดกฎ (Rules) ใน Cognito Identity Pools เพื่อจับคู่ผู้ใช้กับ IAM Roles ที่แตกต่างกันเพื่อมอบสิทธิ์การใช้งานที่ละเอียดได้

### ตารางสรุปเปรียบเทียบ Cognito User Pool และ Identity Pool

| หัวข้อเปรียบเทียบ | Cognito User Pools | Cognito Identity Pools |
| :--- | :--- | :--- |
| **หน้าที่หลัก** | จัดการการโต้ตอบกับ IdP แทนคุณ | มอบ AWS Credentials เพื่อเข้าถึงทรัพยากรในนามของผู้ใช้ |
| **การจัดการข้อมูล** | มีโปรไฟล์สำหรับจัดการผู้ใช้ | รองรับการตั้งกฎเพื่อจับคู่ผู้ใช้กับ IAM Roles ต่างๆ |
| **มาตรฐานที่ใช้** | มอบ Token มาตรฐาน OpenID Connect และ OAuth | (ไม่มีค่าใช้จ่ายสำหรับส่วนนี้) |
| **ราคา** | **ฟรี** | **คิดราคาตามจำนวนผู้ใช้ที่มีการใช้งานรายเดือน (Monthly Active User)** |
