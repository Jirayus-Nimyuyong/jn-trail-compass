### **Amazon EFS (Elastic File System)**
* **Amazon EFS** เป็นระบบไฟล์บนคลาวด์แบบ Serverless, ปรับขนาดได้, ประสิทธิภาพสูง และเป็นไปตามมาตรฐาน POSIX
* สามารถเข้าถึงได้โดยอินสแตนซ์ Amazon EC2 (Linux), Amazon ECS, Amazon EKS, AWS Fargate และ AWS Lambda ผ่านโปรโตคอล **NFS**
* รองรับรูปแบบการเข้าถึงไฟล์แบบ Strong Consistency (ความสอดคล้องของข้อมูลสูง) และ File Locking (การล็อกไฟล์)
* **การขยายระบบ:** ปรับขนาดพื้นที่เก็บข้อมูลอัตโนมัติได้ถึงระดับ Petabytes
    * **Bursting mode:** ความเร็ว (Throughput) จะเพิ่มขึ้นตามขนาดไฟล์ที่ใหญ่ขึ้น
    * **Provisioned Throughput mode:** กำหนดความเร็วคงที่ได้โดยไม่ขึ้นกับปริมาณข้อมูลที่จัดเก็บ
* รองรับการเข้าถึงพร้อมกันจากบริการประมวลผลหลายพันตัวโดยประสิทธิภาพไม่ลดลง
* **กรณีการใช้งานทั่วไป:** งาน Big Data และการวิเคราะห์, การประมวลผลสื่อ (Media), การจัดการเนื้อหา (CMS), Web Serving และ Home Directories
* **คลาสการจัดเก็บข้อมูล:** มี 4 คลาส ได้แก่ Standard, Standard Infrequent Access (IA), One Zone และ One Zone IA
* มีระบบ **Lifecycle Management** เพื่อย้ายข้อมูลจากคลาสปกติไปยังคลาสที่เข้าถึงไม่บ่อย (IA) เพื่อประหยัดค่าใช้จ่าย
* **ความทนทาน:** ข้อมูลในคลาส Standard จะถูกจัดเก็บสำรองไว้ในหลาย Availability Zones (AZs)
* **ความปลอดภัย:** เข้ารหัสข้อมูลทั้งขณะจัดเก็บ (At rest) ผ่าน AWS KMS และระหว่างรับส่ง (In transit) ผ่าน TLS 1.2
* การเข้าถึงจาก On-premises ต้องใช้ AWS Direct Connect หรือ AWS VPN

### **Amazon FSx for Windows File Server**
* เป็นบริการจัดเก็บไฟล์แบบ Managed เต็มรูปแบบ ปรับขนาดได้ และเข้าถึงผ่านโปรโตคอล **SMB**
* สร้างขึ้นบน Windows Server จึงรองรับฟีเจอร์ของ Windows โดยกำเนิด เช่น **User Quotas, การกู้คืนไฟล์โดยผู้ใช้ปลายทาง และการเชื่อมต่อกับ Microsoft Active Directory**
* เข้าถึงได้จากอินสแตนซ์และอุปกรณ์ทั้ง Windows, Linux และ MacOS พร้อมกันได้หลายพันตัว
* เชื่อมต่อกับ EC2, ECS, VMware Cloud on AWS, Amazon WorkSpaces และ AppStream 2.0
* **กรณีการใช้งานทั่วไป:** CRM, ERP, แอปพลิเคชัน .NET, Home Directories, การวิเคราะห์ข้อมูล, งาน Media & Entertainment, สภาพแวดล้อมการสร้างซอฟต์แวร์ และ Microsoft SQL Server
* สามารถเลือกประเภทพื้นที่เก็บข้อมูลได้:
    * **SSD:** สำหรับงานที่อ่อนไหวต่อความหน่วง (Latency) หรือต้องการ IOPS/Throughput สูงสุด
    * **HDD:** สำหรับงานที่เน้นความเร็วในการรับส่งข้อมูลเป็นหลักแต่ไม่อ่อนไหวต่อความหน่วง
* กำหนดความเร็ว (Throughput capacity) ได้ตอนสร้างและเปลี่ยนได้ตลอดเวลา
* จัดเก็บข้อมูลได้สูงสุด **64 TB ต่อระบบไฟล์** และต้องขยายขนาดพื้นที่ด้วยตนเอง (Manual)
* เลือกติดตั้งได้ทั้งแบบ Single-AZ หรือ **Multi-AZ** (ซึ่งมีระบบ Failover อัตโนมัติ)
* เข้ารหัสข้อมูลขณะจัดเก็บด้วย AWS KMS และเข้ารหัสระหว่างรับส่งด้วย SMB Kerberos Session Keys

### **Amazon FSx for Lustre**
* เป็นระบบไฟล์แบบ Serverless ตามมาตรฐาน POSIX ที่รันบน **Lustre** ซึ่งเป็นระบบไฟล์ประสิทธิภาพสูงแบบ Open-source
* ออกแบบมาสำหรับแอปพลิเคชันที่ต้องการพื้นที่เก็บข้อมูลที่รวดเร็วมาก สามารถขยายความเร็วได้ถึงหลัก **ร้อย GB/s และหลักล้าน IOPS** รองรับการเข้าถึงไฟล์หรือไดเรกทอรีเดียวกันพร้อมกันจากอินสแตนซ์หลายพันตัว
* **การขยายระบบ:** ต้องเพิ่มขนาดพื้นที่ด้วยตนเอง และทำได้เพียงทุกๆ 6 ชั่วโมงเท่านั้น (ต่างจาก EFS ที่อัตโนมัติ)
* **การเชื่อมต่อ:** ทำงานร่วมกับ **Amazon S3** ได้อย่างแนบเนียน ช่วยให้ประมวลผลชุดข้อมูลใน S3 ด้วยความเร็วของ Lustre ได้
* **กรณีการใช้งานทั่วไป:** Machine Learning, การประมวลผลประสิทธิภาพสูง (HPC), การประมวลผลวิดีโอ, การจำลองแบบจำลองทางการเงิน, การจัดลำดับจีโนม และ Electronic Design Automation (EDA)
* **ระบบปฏิบัติการ:** ใช้ได้กับ **Linux เท่านั้น** โดยต้องติดตั้ง Lustre Client และ Mount ด้วยคำสั่งมาตรฐานของ Linux รองรับการใช้กับ Amazon EKS และ AWS Batch
* **ตัวเลือกการติดตั้ง (Deployment Options):**
    1.  **Scratch file systems:** สำหรับการจัดเก็บชั่วคราวและการประมวลผลระยะสั้น ข้อมูลจะไม่มีการคัดลอกสำรองและจะหายไปหากเซิร์ฟเวอร์ไฟล์ขัดข้อง
    2.  **Persistent file systems:** สำหรับการจัดเก็บระยะยาว งานมีความพร้อมใช้งานสูง (High Availability) และข้อมูลจะถูกคัดลอกสำรองโดยอัตโนมัติภายใน AZ เดียวกัน
* เลือกประเภทพื้นที่เก็บข้อมูลได้ทั้ง **SSD** และ **HDD** เช่นเดียวกับ FSx for Windows
* เข้ารหัสข้อมูลขณะจัดเก็บด้วย AWS KMS และเข้ารหัสระหว่างรับส่งเมื่อเข้าถึงจากอินสแตนซ์ EC2 ที่รองรับ
