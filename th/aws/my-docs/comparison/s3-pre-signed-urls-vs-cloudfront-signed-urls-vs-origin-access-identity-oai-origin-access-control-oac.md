# การควบคุมการเข้าถึงไฟล์ใน S3 และ CloudFront

### **1. S3 Pre-signed URLs**
โดยค่าเริ่มต้น บักเก็ตและวัตถุ (Objects) ทั้งหมดใน S3 จะเป็น **ส่วนตัว (Private)** เฉพาะเจ้าของเท่านั้นที่มีสิทธิ์เข้าถึง **Pre-signed URLs** จึงถูกนำมาใช้เพื่อมอบสิทธิ์การเข้าถึงชั่วคราวให้ผู้อื่นสามารถดาวน์โหลดหรืออัปโหลดไฟล์ได้ โดยใช้สิทธิ์ความปลอดภัยของผู้เจ้าของเอง
* **สิ่งที่ต้องระบุเมื่อสร้าง Pre-signed URL:**
    * ข้อมูลสิทธิ์ความปลอดภัยของคุณ (Security credentials)
    * ชื่อบักเก็ต S3 และชื่อวัตถุ (Object key)
    * ระบุวิธีการ HTTP (ใช้ **GET** เพื่อดาวน์โหลด หรือ **PUT** เพื่ออัปโหลด)
    * วันและเวลาที่ URL จะหมดอายุ

### **2. CloudFront Signed URLs**
คุณสามารถควบคุมการเข้าถึงเนื้อหาที่เป็นส่วนตัวผ่าน CloudFront ได้ 2 ทาง คือ จำกัดการเข้าถึงไฟล์ที่ Edge Caches และจำกัดการเข้าถึงไฟล์ต้นทางใน S3 (ยกเว้นกรณีที่ตั้งค่าเป็น Website Endpoint)
* CloudFront สามารถกำหนดให้ผู้ใช้ต้องเข้าถึงไฟล์ผ่าน **Signed URLs** หรือ **Signed Cookies** เท่านั้น
* **ข้อกำหนดที่ระบุได้ใน Signed URLs/Cookies:**
    * วันและเวลาที่ URL หมดอายุ
    * (ตัวเลือกเสริม) วันและเวลาที่ URL เริ่มมีผลใช้งาน
    * (ตัวเลือกเสริม) หมายเลข IP หรือช่วงของ IP ที่ได้รับอนุญาตให้เข้าถึงเนื้อหา
* สามารถใช้ได้กับ CloudFront ทุกประเภท ไม่ว่าต้นทาง (Origin) จะเป็น S3 หรือเซิร์ฟเวอร์ HTTP ทั่วไป

### **3. Origin Access Identity (OAI)**
ใช้ในกรณีที่คุณตั้งค่า S3 เป็นต้นทางของ CloudFront โดย **OAI** จะช่วยป้องกันไม่ให้ผู้ใช้เข้าถึงไฟล์ใน S3 โดยตรงผ่าน URL ของ S3 เอง แต่จะบังคับให้ต้องเข้าถึงผ่าน URL ของ CloudFront เท่านั้น
* **ขั้นตอนการตั้งค่า:**
    1. สร้างผู้ใช้พิเศษของ CloudFront ที่เรียกว่า **Origin Access Identity**
    2. มอบสิทธิ์ให้ OAI สามารถอ่านไฟล์ในบักเก็ตของคุณได้
    3. ลบสิทธิ์การเข้าถึงไฟล์ผ่าน URL ของ S3 สำหรับบุคคลอื่นออก (ผ่าน Bucket Policies หรือ ACLs)
* **ข้อจำกัด:** ไม่สามารถใช้ OAI ได้หากบักเก็ต S3 ของคุณถูกตั้งค่าเป็น Website Endpoint

### **4. Origin Access Control (OAC)**
เป็นวิธีที่ **แนะนำมากกว่า OAI** ในการจำกัดการเข้าถึงต้นทางที่เป็น Amazon S3
* ช่วยให้ลูกค้า CloudFront รักษาความปลอดภัยของ S3 Origin ได้ง่ายขึ้น โดยอนุญาตให้เฉพาะ CloudFront Distributions ที่กำหนดเท่านั้นที่สามารถเข้าถึงบักเก็ต S3 ได้
* รองรับ **AWS Signature Version 4 (SigV4)** ในคำขอจาก CloudFront ไปยัง S3 โดยสามารถตั้งค่าได้ว่า CloudFront ควรลงนามในคำขอ (Sign requests) หรือไม่ และจะลงนามเมื่อใด
* รองรับการใช้งานการเข้ารหัสฝั่งเซิร์ฟเวอร์ด้วย **AWS KMS (SSE-KMS)** เมื่อทำการอัปโหลดหรือดาวน์โหลดผ่าน CloudFront Distribution
