### **กรณีการใช้งาน (Use Cases)**

#### **เลือกใช้ Redis (Cluster Mode Enabled) เมื่อ:**
* ต้องการแบ่งส่วนข้อมูล (Partition) กระจายไปยังโหนดต่างๆ ตั้งแต่ 2 ถึง 250 หรือ 500 โหนด (ในเวอร์ชัน 5.0.6 ขึ้นไป)
* ต้องการใช้งาน Geospatial Indexing (รองรับทั้งแบบ Clustered และ Non-clustered)
* ไม่จำเป็นต้องรองรับฐานข้อมูลหลายชุด (Multiple Databases)
* ต้องการฟีเจอร์เพิ่มเติมที่มีในโหมด Non-clustered ทั้งหมด

#### **เลือกใช้ Redis (Cluster Mode Disabled) เมื่อ:**
* ต้องการประเภทข้อมูลที่ซับซ้อน เช่น Hashes, Lists, Sets, Sorted Sets และ Bitmaps
* ต้องการจัดเรียงลำดับ (Sort/Rank) ชุดข้อมูลในหน่วยความจำ
* ต้องการความคงทนของข้อมูล (Persistence)
* ต้องการทำ Replication จากโหนดหลักไปยังโหนดรองเพื่อแอปพลิเคชันที่เน้นการอ่านข้อมูลสูง
* ต้องการระบบ Failover อัตโนมัติเมื่อโหนดหลักขัดข้อง
* ต้องการความสามารถ Pub/Sub และการสำรอง/กู้คืนข้อมูล
* ต้องการรองรับฐานข้อมูลหลายชุด (Multiple Databases)

#### **เลือกใช้ Memcached เมื่อ:**
* ต้องการโมเดลการทำงานที่เรียบง่ายที่สุดเท่าที่จะเป็นไปได้
* ต้องการรันโหนดขนาดใหญ่ที่ใช้ประโยชน์จากหลาย Core หรือหลาย Thread (Multi-threaded)
* ต้องการความสามารถในการ Scale-out และ Scale-in (เพิ่ม/ลดโหนด) ตามความต้องการของระบบ
* ต้องการแคชวัตถุ (Objects) เช่น แคชจากฐานข้อมูล
* ต้องการระบบ Auto Discovery เพื่อช่วยให้แอปพลิเคชันเชื่อมต่อกับคลัสเตอร์ได้ง่ายขึ้น
