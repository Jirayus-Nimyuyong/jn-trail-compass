# การเปรียบเทียบ AWS DataSync และ AWS Storage Gateway

| หัวข้อ | AWS DataSync | AWS Storage Gateway |
| :--- | :--- | :--- |
| **คำอธิบาย** | บริการโอนย้ายข้อมูลออนไลน์ที่ช่วยให้การคัดลอกข้อมูลจำนวนมหาศาล เข้าและออกจากบริการเก็บข้อมูลของ AWS ผ่านอินเทอร์เน็ตหรือ AWS Direct Connect เป็นเรื่องง่าย โดยทำงานแบบอัตโนมัติและรวดเร็ว | บริการเก็บข้อมูลแบบ Hybrid Cloud ที่ช่วยให้แอปพลิเคชัน On-premises เข้าถึงพื้นที่เก็บข้อมูลบนคลาวด์ได้ไม่จำกัดผ่านการเชื่อมต่อกับ S3 โดยมีอินเทอร์เฟซ 3 ประเภท ได้แก่ File, Volume และ Tape |
| **วิธีการทำงาน** | ใช้ **Agent** ซึ่งเป็น Virtual Machine (VM) ของผู้ใช้ ทำหน้าที่อ่านหรือเขียนข้อมูลจากระบบจัดเก็บข้อมูลของคุณ โดย Agent จะอ่านข้อมูลจากต้นทางและซิงค์ไปยัง Amazon S3, Amazon EFS หรือ Amazon FSx | ใช้ **Storage Gateway Appliance** (VM จาก Amazon) ติดตั้งในดาต้าเซ็นเตอร์ของคุณ จากนั้นใช้ AWS Console กำหนดค่าประเภทการใช้งาน: File Gateway, Cached Volumes หรือ Stored Volumes เพื่อบันทึกข้อมูลลง Amazon S3 (หรือซื้อเป็นฮาร์ดแวร์สำเร็จรูปแทนการลง VM ได้) |
| **โปรโตคอล** | เชื่อมต่อกับระบบจัดเก็บข้อมูลเดิมด้วยโปรโตคอลมาตรฐาน (**NFS, SMB**) หรือใช้ **Amazon S3 API** | ให้บริการผ่านโปรโตคอลจัดเก็บข้อมูลมาตรฐาน เช่น **iSCSI, SMB และ NFS** |
| **การจัดเก็บข้อมูล** | สามารถคัดลอกข้อมูลระหว่าง NFS, SMB หรือระบบเก็บข้อมูล Object Storage ที่จัดการเอง รวมถึงย้ายข้อมูลระหว่าง On-premises กับ AWS Snowcone, S3, EFS หรือ FSx | • **File Gateway:** เก็บและเรียกใช้ Object ใน S3 ผ่านโปรโตคอลไฟล์ (NFS/SMB)<br>• **Volume Gateway:** เก็บข้อมูลไว้ใน Gateway ท้องถิ่นและซิงค์ไป S3 พร้อมทำ EBS Snapshot เพื่อกู้คืนเป็นอุปกรณ์ iSCSI<br>• **Tape Gateway:** เก็บข้อมูลลง S3 ทันทีและสามารถทำ Archive ลง Glacier หรือ Deep Archive ได้ |
| **ราคา** | คิดตามค่าคำขอมาตรฐาน (Request), ค่าจัดเก็บ และค่าโอนย้ายข้อมูลเมื่ออ่านหรือเขียนไปยังบริการต่างๆ เช่น S3, EFS, FSx และ AWS KMS | คิดตามประเภทและปริมาณข้อมูลที่จัดเก็บ, จำนวนคำขอที่ส่ง และปริมาณข้อมูลที่โอนย้ายออกจาก AWS |
| **การใช้งานร่วมกัน** | คุณสามารถใช้ทั้ง DataSync และ File Gateway ร่วมกันเพื่อลดต้นทุนการดำเนินงาน On-premises โดยใช้ **DataSync** เพื่อเร่งการย้ายข้อมูลขึ้นคลาวด์แบบอัตโนมัติ และใช้ **File Gateway** เพื่อให้แอปพลิเคชัน On-premises เข้าถึงข้อมูลที่ย้ายไปแล้วด้วยความหน่วง (Latency) ที่ต่ำ |
