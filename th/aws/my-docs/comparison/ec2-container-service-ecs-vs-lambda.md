### **Amazon EC2 Container Service (ECS)**
* **Amazon ECS** เป็นบริการจัดการคอนเทนเนอร์ (Container Management) ที่มีความยืดหยุ่นและประสิทธิภาพสูง รองรับ **Docker Containers** ช่วยให้คุณรันแอปพลิเคชันบนคลัสเตอร์ของ Amazon EC2 ที่มีการจัดการให้เสร็จสรรพ ทำให้คุณไม่ต้องติดตั้ง ดำเนินงาน หรือขยายโครงสร้างพื้นฐานการจัดการคลัสเตอร์ด้วยตนเอง
* การติดตั้งแอปพลิเคชันแบบคอนเทนเนอร์ทำได้ง่าย เหมาะอย่างยิ่งสำหรับการรันงานแบบ Batch jobs หรือสถาปัตยกรรมแบบ Microservice
* มีพื้นที่จัดเก็บส่วนกลางสำหรับอัปโหลด Docker Images จากคอนเทนเนอร์ ECS เพื่อความปลอดภัยที่เรียกว่า **Amazon ECR**
* แอปพลิเคชันใน ECS สามารถเขียนได้ทั้งแบบมีสถานะ (Stateful) หรือไม่มีสถานะ (Stateless)
* **Amazon ECS CLI** รองรับ Docker Compose ซึ่งช่วยให้การพัฒนาในเครื่อง (Local) ง่ายขึ้น และสามารถตั้งค่ารันคอนเทนเนอร์บน ECS ได้สะดวก
* เนื่องจากแอปพลิเคชันยังรันบนอินสแตนซ์ EC2 **การจัดการเซิร์ฟเวอร์จึงเป็นความรับผิดชอบของคุณ** ซึ่งช่วยให้คุณควบคุมระบบได้อย่างละเอียด
* คุณต้องเป็นผู้ **จัดการการขยายระบบ (Scaling) และการทำ Load Balancing** ของอินสแตนซ์ EC2 เอง ซึ่งต่างจาก AWS Lambda ที่ฟังก์ชันจะสเกลโดยอัตโนมัติ
* **ค่าใช้จ่าย:** คิดตามต้นทุนที่เกิดขึ้นจากอินสแตนซ์ EC2 ในคลัสเตอร์ โดยส่วนใหญ่ ECS จะมีราคาสูงกว่า Lambda เนื่องจากอินสแตนซ์ EC2 ที่ทำงานอยู่จะถูกคิดเงินเป็นรายชั่วโมง
* มีเวอร์ชันหนึ่งของ ECS ที่ชื่อว่า **AWS Fargate** ซึ่งจะจัดการโครงสร้างพื้นฐานให้คุณทั้งหมด เพื่อให้คุณโฟกัสแค่การติดตั้งคอนเทนเนอร์ โดย Fargate จะมีรูปแบบราคาที่แตกต่างจากคลัสเตอร์ EC2 มาตรฐาน
* ECS จะกู้คืนคอนเทนเนอร์ที่ไม่สมบูรณ์ (Unhealthy) ให้โดยอัตโนมัติ เพื่อให้มั่นใจว่ามีจำนวนคอนเทนเนอร์ที่พร้อมรองรับแอปพลิเคชันตามที่กำหนดไว้

### **AWS Lambda**
* **AWS Lambda** เป็นบริการแบบ **Function-as-a-service** ที่จะรันโค้ดของคุณ **เพื่อตอบสนองต่อเหตุการณ์ (Events)** และจัดการทรัพยากรประมวลผลให้โดยอัตโนมัติ เนื่องจาก Lambda เป็นบริการประมวลผลแบบ Serverless คุณจึงไม่ต้องกังวลเรื่องการจัดการเซิร์ฟเวอร์และโฟกัสไปที่โค้ดของแอปพลิเคชันได้โดยตรง
* Lambda ปรับสเกลฟังก์ชันโดยอัตโนมัติเพื่อรองรับความต้องการ อย่างไรก็ตาม Lambda มีข้อจำกัดเรื่อง **ระยะเวลาการทำงานสูงสุดที่ 900 วินาที หรือ 15 นาทีต่อหนึ่งคำขอ**
* ในการอนุญาตให้ฟังก์ชัน Lambda เข้าถึงบริการอื่นๆ เช่น CloudWatch Logs คุณจำเป็นต้องสร้าง Execution Role ที่มีสิทธิ์การใช้งานที่จำเป็น
* คุณสามารถเชื่อมต่อฟังก์ชันเข้ากับบริการต่างๆ ได้ง่าย เช่น API Gateway, DynamoDB, CloudFront ฯลฯ ผ่านทาง Lambda Console
* สามารถทดสอบโค้ดฟังก์ชันในเครื่องผ่าน Lambda Console ก่อนที่จะใช้งานจริง (Production)
* ปัจจุบัน Lambda รองรับภาษาโปรแกรมที่จำกัด เช่น Java, Go, PowerShell, Node.js, C#, Python และ Ruby ส่วน ECS ไม่จำกัดภาษาโปรแกรมเนื่องจากรองรับ Docker เป็นหลัก
* ฟังก์ชัน Lambda ต้องเป็นแบบ **ไม่มีสถานะ (Stateless)** เนื่องจากไม่มี Volume สำหรับจัดเก็บข้อมูลถาวร
* **ค่าใช้จ่าย:** คิดตามจำนวนคำขอ (Requests) และระยะเวลาที่โค้ดใช้ในการประมวลผล (Duration) คุณสามารถจำกัดค่าใช้จ่ายได้โดยการจำกัดจำนวนการรันพร้อมกัน (Concurrent executions) และกำหนดเวลาสูงสุดในการทำงานของฟังก์ชัน
* ด้วย **Lambda@Edge** บริการนี้สามารถรันโค้ดของคุณตามตำแหน่งที่ตั้งของ AWS ทั่วโลกเพื่อตอบสนองต่อเหตุการณ์ของ Amazon CloudFront เช่น คำขอเนื้อหาจากเซิร์ฟเวอร์ต้นทางหรือผู้เข้าชม ช่วยให้ส่งเนื้อหาถึงผู้ใช้ปลายทางด้วยความหน่วงที่ต่ำลง
