# การเปรียบเทียบ VPC Endpoints

### **1. Interface Endpoint**
* คือ Elastic Network Interface (ENI) ที่มี **Private IP address** ทำหน้าที่เป็นจุดรับส่งข้อมูล (Entry point) สำหรับทราฟฟิกที่มุ่งหน้าไปยังบริการของ AWS, บริการ Endpoint อื่นๆ หรือบริการใน AWS Marketplace ที่รองรับ
* สำหรับแต่ละ Interface Endpoint คุณสามารถเลือกได้เพียง **1 Subnet ต่อ 1 Availability Zone** เท่านั้น โดย Endpoint จะทำงานในระดับภูมิภาค (Regional) หมายความว่าใช้งานได้เฉพาะภายในภูมิภาคที่สร้างขึ้น
* เนื่องจากใช้ ENI จึงต้องใช้ **Security Groups** ในการควบคุมทราฟฟิก
* **การเข้าถึง:** สามารถเข้าถึงได้ผ่าน AWS VPN, AWS Direct Connect, VPC Peering ภายในภูมิภาคเดียวกัน (จาก Nitro instances) และ VPC Peering ข้ามภูมิภาค (จากอินสแตนซ์ทุกประเภท)
* Endpoint จะส่งข้อมูลตอบกลับเฉพาะทราฟฟิกที่เริ่มต้นจากทรัพยากรภายใน VPC ของคุณเท่านั้น
* รองรับทราฟฟิกแบบ **IPv4 TCP เท่านั้น**
* สามารถเพิ่ม **Endpoint Policies** เพื่อกำหนดสิทธิ์ว่าใคร (Principal) สามารถดำเนินการใดกับทรัพยากรใดได้บ้าง ซึ่งเป็นนโยบายแยกต่างหากและไม่ทับซ้อนกับ IAM Policy ปกติ
* หลังจากสร้างแล้ว จะใช้งานได้เมื่อผู้ให้บริการ (Service Provider) กดยอมรับ (Accept) โดยทั่วไปบริการของ AWS และ Marketplace จะยอมรับอัตโนมัติ
* Interface Endpoint (ยกเว้นของ S3) จะมีชื่อ Private DNS Hostnames ให้ใช้งาน

### **2. Gateway Endpoint**
* คือ Gateway ที่ทำหน้าที่เป็น **เป้าหมาย (Target)** ในตารางเส้นทาง (Route Table) ของคุณ ใช้สำหรับทราฟฟิกที่มุ่งหน้าไปยังบริการของ AWS ที่รองรับ ซึ่งได้แก่ **DynamoDB** หรือ **S3** เท่านั้น
* คุณสามารถสร้าง Gateway Endpoint หลายอันใน VPC เดียวเพื่อไปยังหลายบริการได้ หรือสร้างหลายอันเพื่อไปบริการเดียวกันแต่ใช้คนละ Route Table เพื่อบังคับใช้นโยบายการเข้าถึงที่ต่างกันในแต่ละ Subnet
* **ข้อจำกัด:** ไม่สามารถมีเส้นทาง (Route) ไปยังบริการเดียวกันมากกว่าหนึ่งเส้นทางในตารางเส้นทางเดียว
* สามารถแก้ไข Endpoint Policy ที่แนบอยู่ หรือเพิ่ม/ลด Route Table ที่ใช้งานร่วมกับ Endpoint ได้
* รองรับเฉพาะภายในภูมิภาคเดียวกันเท่านั้น (ข้ามภูมิภาคไม่ได้) และรองรับทราฟฟิก **IPv4 เท่านั้น**
* ต้องเปิดใช้งาน DNS resolution ใน VPC หรือหากใช้ DNS server ของตนเอง ต้องมั่นใจว่าคำขอ DNS ไปยังบริการที่ต้องการนั้นสามารถแปลเป็น IP Address ของ AWS ได้ถูกต้อง
* เมื่อเชื่อมโยงเส้นทางเข้ากับ Gateway Endpoint แล้ว อินสแตนซ์ทั้งหมดใน Subnet ที่ใช้ตารางเส้นทางนั้นจะใช้ Endpoint เข้าถึงบริการโดยอัตโนมัติ
* **ไม่สามารถใช้งานนอกขอบเขตของ VPC** ที่เชื่อมโยงอยู่ได้

### **3. Gateway Load Balancer Endpoint (GWLBE)**
* ช่วยให้คุณสามารถ **ดักจับทราฟฟิก (Intercept)** และส่งต่อไปยังบริการที่คุณกำหนดค่าไว้โดยใช้ **Gateway Load Balancers**
* คุณต้องเลือก VPC และ Subnet ที่จะสร้าง Endpoint โดยระบบจะมอบ Private IP จากช่วง IP ของ Subnet นั้นให้ และไม่สามารถเปลี่ยน Subnet ในภายหลังได้
* หลังจากสร้างแล้ว จะใช้งานได้เมื่อผู้ให้บริการกดยอมรับคำขอ (อาจเป็นแบบอัตโนมัติหรือด้วยตนเอง)
* **ไม่รองรับ** Security Groups และ Endpoint Policies
* รองรับทราฟฟิก **IPv4 เท่านั้น**
* ไม่สามารถย้าย Endpoint จาก VPC หนึ่งไปอีก VPC หนึ่ง หรือจากบริการหนึ่งไปอีกบริการหนึ่งได้
