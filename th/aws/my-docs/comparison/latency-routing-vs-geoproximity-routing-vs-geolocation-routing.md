# การเปรียบเทียบรูปแบบการกำหนดเส้นทางของ Route 53

| หัวข้อ | Latency Routing (ตามความหน่วง) | Geoproximity Routing (ตามความใกล้ทางภูมิศาสตร์) | Geolocation Routing (ตามตำแหน่งที่ตั้งของผู้ใช้) |
| :--- | :--- | :--- | :--- |
| **คำนิยาม** | ให้ Route 53 ตอบสนองคำขอของผู้ใช้จาก **AWS Region ที่มีความหน่วงต่ำที่สุด** อย่างไรก็ตาม ไม่ได้รับประกันว่าผู้ใช้ในภูมิภาคเดียวกันจะถูกส่งไปยังตำแหน่งเดียวกันเสมอ | ให้ Route 53 ส่งทราฟฟิกไปยังทรัพยากรโดยพิจารณาจาก **ตำแหน่งทางภูมิศาสตร์ของผู้ใช้และทรัพยากรของคุณร่วมกัน** | ทรัพยากรจะให้บริการทราฟฟิกโดยพิจารณาจาก **ตำแหน่งทางภูมิศาสตร์ของผู้ใช้** (พิจารณาจากตำแหน่งที่คำคิวรี DNS นั้นกำเนิดขึ้น) |
| **จุดเด่น** | พิจารณาจากผลการวัดความหน่วงในช่วงเวลาหนึ่ง ซึ่งสะท้อนถึงการเปลี่ยนแปลงของการเชื่อมต่อเครือข่ายและการเลือกเส้นทาง | สามารถเลือกส่งทราฟฟิกให้ทรัพยากรใดทรัพยากรหนึ่ง "มากหรือน้อยลง" ได้โดยการระบุค่าที่เรียกว่า **Bias** (การปรับอคติ) เพื่อขยายหรือหดขนาดพื้นที่บริการของทรัพยากรนั้น | ช่วยให้แสดงเนื้อหาตามภาษาของผู้ใช้ หรือจำกัดการเผยแพร่เนื้อหาเฉพาะพื้นที่ที่ได้รับสิทธิ์เท่านั้น |
| **วิธีการทำงาน** | คุณต้องสร้าง **Latency Records** สำหรับทรัพยากรในหลายๆ AWS Regions เมื่อมีการคิวรีเข้ามา Route 53 จะดูว่า Region ไหนให้ความหน่วงต่ำสุดสำหรับผู้ใช้รายนั้น แล้วจึงส่งค่า (เช่น IP) ของ Region นั้นกลับไป | **ต้องใช้ Route 53 Traffic Flow** โดยสร้างนโยบายและระบุค่าอย่างใดอย่างหนึ่ง:<br>• หากใช้ทรัพยากร AWS: ระบุ AWS Region ที่ทรัพยากรนั้นอยู่<br>• หากไม่ใช่ทรัพยากร AWS: ระบุค่า **ละติจูดและลองจิจูด** ของทรัพยากรนั้น | ทำงานโดยการ **จับคู่ IP Address เข้ากับตำแหน่งที่ตั้ง** หากมี IP ที่ระบุตำแหน่งไม่ได้ คุณสามารถสร้าง **Default Record** เพื่อจัดการคำขอจากตำแหน่งที่ไม่ได้ระบุไว้ หากไม่มีเรคคอร์ดนี้ Route 53 จะตอบกลับว่า "No answer" |
| **ข้อกำหนดเพิ่มเติม** | สร้างได้กับเรคคอร์ดทุกประเภท ยกเว้น NS หรือ SOA | (ต้องใช้งานผ่านหน้าจอ Traffic Flow ในคอนโซล) | **ห้าม** มีเรคคอร์ดสองอันที่ระบุตำแหน่งทางภูมิศาสตร์เดียวกันซ้ำกัน |
| **กรณีการใช้งาน (Use Case)** | ใช้เมื่อคุณมีทรัพยากรในหลาย AWS Regions และต้องการส่งผู้ใช้ไปยัง **Region ที่ประสิทธิภาพความเร็วดีที่สุด** | ใช้เมื่อต้องการคุมทราฟฟิกตามตำแหน่งของทรัพยากร และต้องการความยืดหยุ่นในการ **โยกย้ายทราฟฟิก** จากจุดหนึ่งไปอีกจุดหนึ่ง | ใช้เมื่อต้องการคุมทราฟฟิกตามตำแหน่งของผู้ใช้ เช่น:<br>• ปรับแต่งภาษาบนเว็บไซต์ตามที่อยู่ผู้ใช้<br>• จำกัดสิทธิ์การเข้าถึงเนื้อหาตามพื้นที่<br>• จัดสมดุลโหลดให้ผู้ใช้จากที่เดิมถูกส่งไปที่ Endpoint เดิมอย่างสม่ำเสมอ |
