ในการกำหนดค่า Volume ใดๆ ลักษณะของ I/O จะเป็นตัวขับเคลื่อนพฤติกรรมประสิทธิภาพของ EBS โดย Volume ประเภท **SSD** เช่น General Purpose SSD (gp2/gp3) และ Provisioned IOPS SSD (io1/io2) จะให้ประสิทธิภาพที่สม่ำเสมอไม่ว่าการทำงานของ I/O จะเป็นแบบสุ่ม (Random) หรือแบบลำดับ (Sequential) ส่วน Volume ประเภท **HDD** เช่น Throughput Optimized HDD (st1) และ Cold HDD (sc1) จะให้ประสิทธิภาพสูงสุดเฉพาะเมื่อการทำงานของ I/O มีขนาดใหญ่และเป็นแบบลำดับเท่านั้น

สำหรับการสอบ ให้พิจารณาความแตกต่างระหว่าง SSD และ HDD ตามตารางด้านล่างเสมอ เพื่อให้คุณตัดตัวเลือกประเภท EBS ที่ไม่ตรงตามโจทย์ออกได้ง่ายขึ้น โดยดูว่าโจทย์ต้องการการจัดเก็บข้อมูลแบบ **ขนาดเล็ก/สุ่ม (Small/Random)** หรือ **ขนาดใหญ่/เป็นลำดับ (Large/Sequential)**

### **ตารางเปรียบเทียบคุณสมบัติ SSD และ HDD**

| คุณสมบัติ (FEATURES) | SSD (Solid State Drive) | HDD (Hard Disk Drive) |
| :--- | :--- | :--- |
| **เหมาะสำหรับงานที่มี I/O แบบ:** | **ขนาดเล็ก และแบบสุ่ม** | **ขนาดใหญ่ และเป็นลำดับ** |
| **ใช้เป็น Boot Volume ได้ไหม?** | **ได้** | **ไม่ได้** |
| **กรณีการใช้งานที่เหมาะสม** | เหมาะสำหรับงานแบบ Transactional, แอปพลิเคชันธุรกิจที่สำคัญซึ่งต้องการค่า IOPS ที่สม่ำเสมอ, งานฐานข้อมูลขนาดใหญ่ เช่น MongoDB, Oracle, MS SQL Server เป็นต้น | เหมาะสำหรับงานสตรีมมิ่งขนาดใหญ่ที่ต้องการความเร็ว (Throughput) ที่สม่ำเสมอในราคาประหยัด, งาน Big Data, Data Warehouses, การประมวลผล Log, หรือการเก็บข้อมูลจำนวนมากที่เข้าถึงไม่บ่อย |
| **ต้นทุน** | ปานกลาง / สูง | ต่ำ |
| **ตัวชี้วัดประสิทธิภาพหลัก** | **IOPS** | **Throughput (MiB/s)** |

### **รายละเอียดกลุ่ม SSD (General Purpose & Provisioned IOPS)**

**Provisioned IOPS SSD (io1, io2)** ถูกออกแบบมาเพื่อตอบสนองความต้องการของงานที่ใช้ I/O เข้มข้น โดยเฉพาะฐานข้อมูลที่อ่อนไหวต่อประสิทธิภาพและความสม่ำเสมอ ต่างจาก **gp2** ที่ใช้ระบบเครดิต (Bucket/Credit model) โดย **io1** ให้คุณระบุค่า IOPS ที่คงที่ได้ และ EBS จะส่งมอบประสิทธิภาพภายใน 10% ของค่าที่ระบุไว้ 99.9% ของเวลาในหนึ่งปี ส่วน **io2** เป็นรุ่นอัปเกรดที่ให้ความทนทานสูงถึง 99.999% และมีอัตรา IOPS ต่อ GiB สูงกว่า (500 IOPS/GiB) ในราคาเท่าเดิม

| ชื่อ Volume | **General Purpose SSD** | **Provisioned IOPS SSD** |
| :--- | :--- | :--- |
| **ประเภท (Type)** | **gp3** / **gp2** | **io2** / **io1** |
| **คำอธิบาย** | เน้นความสมดุลระหว่างราคาและประสิทธิภาพสำหรับงาน Transactional ที่หลากหลาย | SSD ประสิทธิภาพสูง ออกแบบมาสำหรับแอปพลิเคชันที่สำคัญ (Business-critical) และไวต่อความหน่วง |
| **กรณีการใช้งาน** | Virtual desktops, ฐานข้อมูลขนาดกลางอินสแตนซ์เดียว, แอปโต้ตอบความหน่วงต่ำ, งานทดสอบและพัฒนา, Boot volumes | งานที่ต้องการความหน่วงระดับ Sub-millisecond, ต้องการ IOPS ต่อเนื่องมากกว่า 64,000 หรือ Throughput มากกว่า 1,000 MiB/s |
| **ขนาด Volume** | 1 GB – 16 TB | 4 GB – 16 TB |
| **ความทนทาน (Durability)** | 99.8% – 99.9% | **io2: 99.999%** / io1: 99.8% – 99.9% |
| **IOPS สูงสุด / Volume** | 16,000 | 64,000 |
| **Throughput สูงสุด / Vol** | gp3: 1,000 MB/s (gp2: 250) | 1,000 MB/s |
| **ความหน่วง (Latency)** | เลขหลักเดียวมิลลิวินาที | เลขหลักเดียวมิลลิวินาที |
| **Multi-Attach** | ไม่รองรับ | **รองรับ** |

### **รายละเอียดกลุ่ม HDD (Throughput Optimized & Cold HDD)**

| ชื่อ Volume | **Throughput Optimized HDD** | **Cold HDD** |
| :--- | :--- | :--- |
| **ประเภท (Type)** | **st1** | **sc1** |
| **คำอธิบาย** | HDD ราคาประหยัด สำหรับงานที่เข้าถึงบ่อยและเน้นความเร็วในการรับส่งข้อมูล (Throughput-intensive) | สำหรับการเก็บข้อมูลที่เน้น Throughput แต่เข้าถึงไม่บ่อย เน้นราคาประหยัดที่สุดเป็นสำคัญ |
| **กรณีการใช้งาน** | Big data, Data warehouses, ประมวลผล Log | ข้อมูล "เย็น" (Cold data) ที่ต้องการการสแกนข้อมูลเพียงไม่กี่ครั้งต่อวัน |
| **ขนาด Volume** | 125 GB – 16 TB | 125 GB – 16 TB |
| **IOPS สูงสุด / Volume** | 500 | 250 |
| **Throughput สูงสุด / Vol** | 500 MB/s | 250 MB/s |
| **Multi-Attach** | ไม่รองรับ | ไม่รองรับ |
