### **AWS Elastic Beanstalk**
* **AWS Elastic Beanstalk** ช่วยให้นักพัฒนาสามารถ **ติดตั้งและจัดการแอปพลิเคชันได้อย่างรวดเร็ว** บน AWS Cloud โดยนักพัฒนาเพียงแค่อัปโหลดโค้ดแอปพลิเคชัน จากนั้นระบบจะ **จัดการรายละเอียดการติดตั้งให้โดยอัตโนมัติ** ทั้งเรื่องการจัดเตรียมความจุ (Capacity provisioning), การทำ Load balancing, Auto-scaling และการเฝ้าติดตามสถานะของแอปพลิเคชัน
* โซลูชันแบบ **Platform-as-a-Service (PaaS)** นี้ เหมาะสำหรับผู้ที่ต้องการติดตั้งแอปพลิเคชันภายในไม่กี่นาทีโดยไม่ต้องกังวลเรื่องโครงสร้างพื้นฐานเบื้องหลัง
* **รองรับภาษาและ Stack ต่างๆ ดังนี้:** Apache Tomcat (Java), PHP, Python, Node.js (Nginx/Apache), Ruby (Passenger/Puma), .NET (IIS), Java SE, Docker และ Go
* รองรับ **Deployment Versioning** (การจัดเก็บเวอร์ชัน) ทำให้สามารถย้อนกลับ (Rollback) ไปยังเวอร์ชันก่อนหน้าได้ง่าย

---

### **AWS CloudFormation**
* เป็นบริการที่ช่วยให้นักพัฒนาและธุรกิจสร้าง **กลุ่มของทรัพยากร AWS ที่เกี่ยวข้องกัน** และจัดเตรียมทรัพยากรเหล่านั้นอย่างเป็นระเบียบและคาดการณ์ได้ ซึ่งเรียกกันทั่วไปว่า **"Infrastructure as Code" (IaC)**
* ข้อแตกต่างหลักคือ CloudFormation เน้นจัดการที่ **โครงสร้างพื้นฐาน (Infrastructure)** มากกว่าตัวแอปพลิเคชัน
* **แนวคิดหลักของ CloudFormation:**
    * **Template:** ไฟล์ข้อความรูปแบบ JSON หรือ YAML ที่อธิบายทรัพยากรและการตั้งค่าทั้งหมดที่ต้องการ
    * **Stack:** ชุดของทรัพยากร AWS ที่ถูกสร้างและจัดการรวมกันเป็นหน่วยเดียวเมื่อรัน Template
* รองรับการ **Rollback** อัตโนมัติหากการติดตั้งล้มเหลวระหว่างทาง เพื่อกลับไปสู่สถานะล่าสุดที่ทำงานได้
* สามารถใช้จัดการสภาพแวดล้อมของ Elastic Beanstalk, OpsWorks และใช้ติดตั้งซอฟต์แวร์ (Bootstrap) อย่าง Chef และ Puppet บน EC2 ได้

---

### **AWS OpsWorks**
* เป็นบริการจัดการคอนฟิกูเรชัน (Configuration Management) ที่ให้บริการ **Chef และ Puppet** แบบ Managed
* ช่วยให้คุณใช้ Chef และ Puppet ในการทำระบบอัตโนมัติเพื่อตั้งค่า ติดตั้ง และจัดการเซิร์ฟเวอร์ทั้งบน EC2 หรือในดาต้าเซ็นเตอร์ On-premises
* **บริการย่อยของ OpsWorks:**
    * **OpsWorks for Puppet Enterprise / Chef Automate:** ใช้เครื่องมือมาตรฐานของแต่ละค่ายจัดการ Node ต่างๆ
    * **OpsWorks Stacks:** ช่วยจัดการทรัพยากรคลาวด์ในกลุ่มเฉพาะที่เรียกว่า **Layers** (เลเยอร์) โดยใช้ **Chef Recipes** ในการทำงานต่างๆ เช่น การลงแพ็กเกจหรือรันสคริปต์
* เมื่อเทียบกับ CloudFormation แล้ว OpsWorks จะเน้นไปที่การ **ประสานงาน (Orchestration) และการตั้งค่าซอฟต์แวร์** มากกว่าการจัดหาตัวทรัพยากรฮาร์ดแวร์

---

### **AWS CodeDeploy**
* เป็นบริการที่ประสานงานการ **ติดตั้งแอปพลิเคชัน (Deployment)** ไปยังอินสแตนซ์ EC2 และเซิร์ฟเวอร์ On-premises ช่วยให้การออกฟีเจอร์ใหม่ทำได้รวดเร็ว เลี่ยง Downtime และจัดการความซับซ้อนในการอัปเดตแอปฯ
* **ข้อแตกต่าง:**
    * ต่างจาก Elastic Beanstalk ตรงที่ CodeDeploy **ไม่จัดการ** เรื่องความจุ, การสเกล หรือการเฝ้าติดตามให้โดยอัตโนมัติ
    * ต่างจาก CloudFormation และ OpsWorks ตรงที่ CodeDeploy **ไม่ยุ่งเกี่ยว** กับการตั้งค่าโครงสร้างพื้นฐาน (Infrastructure)
* CodeDeploy เป็นเครื่องมือเฉพาะทาง (Building block) สำหรับการอัปเดตซอฟต์แวร์ ในขณะที่ Beanstalk และ OpsWorks เป็นโซลูชันการจัดการแอปพลิเคชันแบบครบวงจร (End-to-end)

---

### **หมายเหตุเพิ่มเติม:**
* **Blue-Green Deployment:** ทั้ง Beanstalk, CloudFormation และ OpsWorks มีประโยชน์มากสำหรับวิธีนี้ เพราะช่วยให้โคลน Stack ของแอปพลิเคชันที่รันอยู่ได้ง่าย
* **Prebaking AMIs (การเตรียมภาพตัวเครื่องล่วงหน้า):** CloudFormation และ OpsWorks เหมาะที่สุดสำหรับการทำสิ่งนี้
* **การอัปเกรดแอปพลิเคชัน:**
    * **In-place Upgrade:** (อัปเกรดบนเครื่องเดิม) เหมาะกับการใช้ **CodeDeploy และ OpsWorks**
    * **Disposable Upgrade:** (สร้างสภาพแวดล้อมใหม่แล้วลบของเก่า) เหมาะกับการใช้ **Elastic Beanstalk, CloudFormation และ OpsWorks**
