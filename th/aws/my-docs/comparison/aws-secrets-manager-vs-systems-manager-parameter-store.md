การจัดการความปลอดภัยของแอปพลิเคชันเป็นส่วนสำคัญของทุกองค์กร โดยเฉพาะโครงสร้างพื้นฐานบนคลาวด์ แง่มุมหนึ่งคือการจัดเก็บและเรียกใช้พารามิเตอร์ เช่น ตัวแปรสภาพแวดล้อม, รหัสผ่านฐานข้อมูล, API keys และ Product keys ตามหลักปฏิบัติที่ดี ข้อมูลที่เป็นความลับไม่ควรเก็บในรูปแบบข้อความธรรมดา (Plain text) และไม่ควรฝังไว้ในซอร์สโค้ด นอกจากนี้ยังแนะนำให้ตั้งระบบหมุนเวียนรหัสผ่าน (Rotation) อัตโนมัติ ซึ่งมักจะถูกลืมเมื่อจัดการด้วยตนเอง

เพื่อแก้ปัญหาความยุ่งยากนี้ Amazon จึงมอบบริการ **AWS Systems Manager Parameter Store** และ **AWS Secrets Manager** ซึ่งแม้จะเป็นสองบริการที่แยกกัน แต่มีฟังก์ชันที่คล้ายกันในการจัดการความลับจากส่วนกลาง

### AWS Systems Manager Parameter Store
**Parameter Store** เป็นส่วนหนึ่งของเครื่องมือจัดการแอปพลิเคชันในบริการ AWS Systems Manager (SSM) ช่วยให้คุณสร้างพารามิเตอร์แบบ Key-value เพื่อบันทึกการตั้งค่าแอปพลิเคชัน, ตัวแปรสภาพแวดล้อม, และรหัสผ่านไว้ในที่เดียว
* รองรับการรักษาความปลอดภัยข้อมูลด้วยการเข้ารหัสที่ทำงานร่วมกับ **AWS KMS**
* เมื่อสร้างพารามิเตอร์แล้ว สามารถเรียกใช้ผ่าน SSM Run Command, State Manager หรืออ้างอิงในแอปพลิเคชันที่รันบน EC2, ECS, Lambda ไปจนถึงดาต้าเซ็นเตอร์ On-premises
* ช่วยลดความจำเป็นในการ Hardcode ตัวแปรไว้ในโค้ด ทำให้การอัปเดตค่าต่างๆ ทำได้ง่ายโดยไม่ต้องแก้ไขซอร์สโค้ด

**ขั้นตอนการเรียกข้อมูล:**
1. แอปพลิเคชันส่งคำขอพารามิเตอร์ไปยัง SSM Parameter Store
2. หากเป็นข้อความธรรมดา ระบบจะตรวจสอบสิทธิ์กับ **IAM** ว่าอนุญาตหรือไม่
3. หากเป็นข้อมูลที่เข้ารหัส ระบบจะตรวจสอบว่า IAM มีสิทธิ์ทั้งการเรียกใช้และสิทธิ์ **KMS Decrypt** เพื่อถอดรหัสหรือไม่
4. หากผ่านการตรวจสอบ ระบบจะส่งค่าพารามิเตอร์กลับไปยังแอปพลิเคชัน

### AWS Secrets Manager
**AWS Secrets Manager** ช่วยให้คุณหมุนเวียน (Rotate), จัดการ และเรียกใช้รหัสผ่านฐานข้อมูล, API keys และความลับอื่นๆ ตลอดวงจรชีวิต ออกแบบมาเพื่อให้นักพัฒนาไม่ต้องกังวลเรื่องที่จัดเก็บข้อมูลที่ละเอียดอ่อน
* หากคุณเป็นผู้ดูแลความปลอดภัย Secrets Manager จะช่วยให้คุณจัดการงานเหล่านี้ได้จากจุดเดียว และมั่นใจได้ว่าองค์กรปฏิบัติตามกฎระเบียบ (Compliance)
* มีกระบวนการทำงานที่คล้ายคลึงกับ Parameter Store ที่กล่าวไปข้างต้น

### ความเหมือนและความแตกต่าง

| คุณสมบัติ | SSM Parameter Store | AWS Secrets Manager |
| :--- | :--- | :--- |
| **ขนาดข้อมูลสูงสุด** | 4KB (Standard) หรือ 8KB (Advanced) | **64KB** |
| **การเข้ารหัสด้วย KMS** | รองรับ (เลือกได้) | **บังคับใช้เสมอ** (เก็บ Plaintext ไม่ได้) |
| **อ้างอิงใน CloudFormation** | รองรับ | รองรับ |
| **ระบบสร้างรหัสผ่านในตัว** | ไม่มี | **มี** (ผ่าน AWS CLI) |
| **การหมุนเวียนความลับอัตโนมัติ** | ไม่มี | **มี** |
| **การเข้าถึงข้ามบัญชี** | ไม่มี | **รองรับ** (Cross-account access) |
| **ค่าใช้จ่ายเพิ่มเติม** | **ฟรี** สำหรับ Standard (จ่ายเพิ่มหากใช้ Advanced) | **มีค่าใช้จ่าย** ต่อความลับและต่อคำขอ |

**จุดที่แตกต่างกันอย่างชัดเจน:**
* **วัตถุประสงค์:** Parameter Store ออกแบบมากว้างกว่า (เก็บ URL, Hostname, ค่าคอนฟิกทั่วไป) จึงเลือกเก็บเป็น Plaintext ได้ ส่วน Secrets Manager ออกแบบมาเพื่อความลับโดยเฉพาะ จึงต้องเข้ารหัสเสมอ
* **เวอร์ชัน (Versioning):** ทั้งคู่รองรับการเก็บเวอร์ชันเก่า แต่ Parameter Store จะใช้งานได้เพียงเวอร์ชันเดียวในขณะใดขณะหนึ่ง ส่วน Secrets Manager สามารถมีหลายเวอร์ชันทำงานพร้อมกันได้ระหว่างที่กำลังทำการหมุนเวียนรหัสผ่าน (Secret Rotation) โดยใช้ Staging labels ในการแยกแยะ
* **นโยบายพารามิเตอร์ (Parameter Policies):** ในรุ่น Advanced ของ Parameter Store คุณสามารถตั้งนโยบายได้ เช่น:
    * **Expiration:** ลบพารามิเตอร์อัตโนมัติเมื่อถึงเวลา
    * **ExpirationNotification:** แจ้งเตือนผ่าน EventBridge เมื่อใกล้หมดอายุ
    * **NoChangeNotification:** แจ้งเตือนหากไม่มีการอัปเดตค่าในช่วงเวลาที่กำหนด (ช่วยเตือนให้เปลี่ยนรหัสผ่าน)

**หมายเหตุเพิ่มเติม:** Parameter Store ทำงานร่วมกับ Secrets Manager ได้ คุณสามารถอ้างอิงความลับที่เก็บใน Secrets Manager ผ่าน Parameter Store API ได้ หากแอปพลิเคชันของคุณเดิมถูกตั้งค่าให้เรียกใช้ผ่าน Parameter Store อยู่แล้ว
