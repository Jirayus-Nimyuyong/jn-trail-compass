# AWS Elastic Load Balancing Cheat Sheet

**Elastic Load Balancing (ELB)** ทำหน้าที่กระจายทราฟฟิกขาเข้าของแอปพลิเคชันหรือเครือข่ายไปยังเป้าหมายหลายตัว เช่น **อินสแตนซ์ EC2, คอนเทนเนอร์ (ECS), ฟังก์ชัน Lambda และ IP Address** ในหลาย Availability Zones (AZ)

* เมื่อสร้าง Load Balancer คุณต้องระบุ Public Subnet จากอย่างน้อย 2 AZ (ยกเว้น NLB ที่ระบุเพียง 1 ได้แต่แนะนำ 2)
* **Access Token Validation:** ALB รองรับการตรวจสอบ JSON Web Tokens (JWT) ของไคลเอนต์เพื่อความปลอดภัยในการสื่อสารแบบ Service-to-service
* **Mutual TLS (mTLS):** ALB รองรับการตรวจสอบสิทธิ์แบบ mTLS เพื่อยืนยันตัวตนทั้งฝั่งไคลเอนต์และเซิร์ฟเวอร์
* **IPv6 Target Groups:** สามารถลงทะเบียนที่อยู่ IPv6 เป็นเป้าหมายใน Target Groups ได้

### คุณสมบัติทั่วไป
* ตรวจสอบสถานะ (Health Check) ของเป้าหมายและส่งทราฟฟิกไปยังเป้าหมายที่ปกติเท่านั้น
* **Deletion Protection:** ป้องกันการลบ Load Balancer โดยไม่ตั้งใจ (ค่าเริ่มต้นคือปิดไว้)
* การลบ ELB จะไม่ลบอินสแตนซ์ที่ลงทะเบียนไว้กับมัน
* **SSL Offloading:** ช่วยถอดรหัส SSL ที่ ELB เพื่อลดภาระของเซิร์ฟเวอร์หลังบ้าน
* **Zonal Shift:** ทำงานร่วมกับ Route 53 ARC เพื่อสลับทราฟฟิกออกจาก AZ ที่มีปัญหาไปยัง AZ ที่ปกติได้ทันทีด้วยการสั่งการเดียว
* **Cross-Zone Load Balancing:**
    * **ALB:** เปิดใช้งานเป็นค่าเริ่มต้น (ไม่มีค่าบริการโอนถ่ายข้อมูล)
    * **NLB/GWLB:** ปิดไว้เป็นค่าเริ่มต้น (ถ้าเปิดจะมีค่าบริการโอนถ่ายข้อมูลระหว่าง AZ ตามปกติ)

## ประเภทของ Load Balancer

### 1. Application Load Balancer (ALB)
ทำงานในระดับ **Application Layer (Layer 7)** ของ OSI Model รองรับโปรโตคอล HTTP และ HTTPS
* **ส่วนประกอบ:** Load Balancer (จุดรับทราฟฟิก), Listener (ตัวคอยฟังคำขอตามเงื่อนไข), Target Group (กลุ่มเป้าหมายที่จะส่งคำขอไป)
* **ประโยชน์:**
    * รองรับการเราต์ตามเส้นทาง (Path-based) และโฮสต์ (Host-based)
    * รองรับแอปพลิเคชันแบบคอนเทนเนอร์ และฟังก์ชัน Lambda
    * **mTLS:** รองรับการตรวจสอบใบรับรองฝั่งไคลเอนต์ที่ระดับ Listener (ต้องใช้ Trust Store)
    * **gRPC:** รองรับสำหรับเป้าหมายแบบ Instance และ IP
    * **Automatic Target Weights (ATW):** ลดทราฟฟิกไปยังเป้าหมายที่มีพฤติกรรมผิดปกติโดยอัตโนมัติ
    * **Identity Support:** รองรับ OIDC, การตรวจสอบ JWT และ Amazon Cognito

### 2. Network Load Balancer (NLB)
ทำงานในระดับ **Transport Layer (Layer 4)** รองรับโปรโตคอล TCP, UDP และ TLS
* **ประโยชน์:**
    * รองรับเวิร์กโหลดที่มีความผันผวนสูง สเกลได้ถึงระดับล้านคำขอต่อวินาที
    * **Static IP:** รองรับ IP แบบคงที่ หรือกำหนด Elastic IP ต่อ Subnet ได้
    * **Source IP Preservation:** รักษา IP ต้นทางของไคลเอนต์สำหรับเป้าหมายประเภท Instance
    * **Security Groups:** ปัจจุบันสามารถเชื่อมต่อ Security Groups กับ NLB ได้โดยตรง
    * **QUIC Protocol:** รองรับสำหรับการสตรีมข้อมูลที่ต้องการความหน่วงต่ำเป็นพิเศษ
* **ข้อจำกัด:** ไม่สามารถเปิดหรือปิด AZ หลังจากสร้าง NLB ไปแล้วได้

### 3. Gateway Load Balancer (GWLB)
ใช้สำหรับติดตั้ง สเกล และจัดการ **Virtual Appliances** จากบุคคลที่สาม เช่น Firewall, ระบบตรวจจับการบุกรุก (IDS/IPS)
* ทำงานในระดับ **Layer 3 (IP)**
* ใช้โปรโตคอล **GENEVE** บนพอร์ต 6081 เพื่อส่งทราฟฟิกไปยังเป้าหมาย
* **GWLB Endpoint:** สร้างการเชื่อมต่อที่ปลอดภัยและความหน่วงต่ำไปยัง Virtual Appliance

### 4. Classic Load Balancer (CLB)
**เป็นรุ่นเก่า (Legacy):** AWS แนะนำให้ย้ายไปใช้ ALB หรือ NLB แทน
* กระจายทราฟฟิกในระดับ Layer 4 หรือ Layer 7
* รองรับ Sticky Sessions และ SSL Listeners พื้นฐาน

## แนวคิดเพิ่มเติมที่สำคัญ
* **Idle Timeout:** ค่าเริ่มต้นคือ 60 วินาที
* **Slow Start Mode:** ให้เวลาเป้าหมายในการ "Warm up" ก่อนจะส่งทราฟฟิกไปให้เต็มจำนวน
* **Sticky Sessions:** ส่งคำขอจากไคลเอนต์เดิมไปยังเป้าหมายเดิมเสมอ (เหมาะกับแอปที่มีการเก็บ State)
* **Deregistration Delay (Connection Draining):** ให้เวลาในการเคลียร์คำขอที่ค้างอยู่ก่อนจะถอนเป้าหมายออกจากระบบ

---

## การรักษาความปลอดภัยและการยืนยันตัวตน
* **TLS 1.3:** รองรับทั้งบน ALB และ NLB
* **One-Click WAF Integration:** เชื่อมต่อ AWS WAF กับ ALB ได้ง่ายในขั้นตอนเดียว
* **Desync Mitigation Mode (ALB):** ป้องกันการโจมตีแบบ HTTP Desync
* **FIPS 140-3:** รองรับนโยบายความปลอดภัย TLS ตามมาตรฐาน FIPS สำหรับเวิร์กโหลดที่มีการควบคุมเข้มงวด

## ตารางสรุปคุณสมบัติ (ย่อ)
| ฟีเจอร์ | ALB | NLB | GWLB |
| :--- | :--- | :--- | :--- |
| โปรโตคอล | HTTP, HTTPS, gRPC | TCP, UDP, TLS | IP |
| เลเยอร์ OSI | Layer 7 | Layer 4 | Layer 3 |
| IP คงที่ (Static IP) | ไม่รองรับ | **รองรับ** | ไม่รองรับ |
| สลับสายงานข้าม AZ | รองรับ | รองรับ | รองรับ |
| การเราต์ตาม Path/Host | **รองรับ** | ไม่รองรับ | ไม่รองรับ |
| SSL Offloading | **รองรับ** | **รองรับ** | ไม่รองรับ (Transparent) |

## ค่าบริการ (Pricing)
* **ALB/NLB/GWLB:** คิดตามรายชั่วโมงที่รัน และจำนวนหน่วยความจุ (LCU/GLCU) ที่ใช้งาน
* **GWLB Endpoint:** คิดตามรายชั่วโมงต่อ Endpoint และปริมาณข้อมูลที่ประมวลผล (GB)
* **mTLS:** มีค่าบริการรายชั่วโมงสำหรับการเชื่อมต่อกับ Trust Store บน ALB
* **CLB:** คิดตามรายชั่วโมงและปริมาณข้อมูลที่ผ่าน Load Balancer
