# AWS Outposts Cheat Sheet

**AWS Outposts** เป็นบริการแบบ Managed ที่ยกโครงสร้างพื้นฐาน, บริการ, APIs และเครื่องมือต่างๆ ของ AWS ไปไว้ที่สถานที่ติดตั้งของลูกค้า (On-premises)

### แนวคิดหลัก (Concepts)
* **Outpost site:** สถานที่ทางกายภาพที่ AWS จะเข้าไปติดตั้ง Outpost ให้คุณ
* **Outpost configurations:** ประกอบด้วย EC2, EBS และความสามารถด้านเครือข่าย ซึ่งแต่ละการตั้งค่าจะมีข้อกำหนดด้านพลังงาน การระบายความร้อน และการรองรับน้ำหนักที่ต่างกัน
* **Outpost capacity:** ทรัพยากรประมวลผล (Compute) และพื้นที่จัดเก็บ (Storage)
* **อุปกรณ์ Outposts:** เพื่อใช้งานบริการนี้ คุณต้องมีอุปกรณ์ที่ AWS จัดการให้ ซึ่งรวมถึงตู้ Rack, เซิร์ฟเวอร์, สวิตช์ และการเดินสายไฟ
* **การจัดการความจุระดับทรัพย์สิน (Asset-level):** ช่วยให้มองเห็นและจัดการความจุของ EC2 ต่อตู้ Rack หรือต่อเซิร์ฟเวอร์ได้

#### Outpost racks (ตู้แร็ค)
* ตู้แร็คขนาด 42U ที่รวมเซิร์ฟเวอร์แบบติดตั้งในแร็ค, สวิตช์, แผงกระจายสายเครือข่าย, ชั้นวางอุปกรณ์ไฟฟ้า และแผ่นปิดช่องว่าง
* รองรับ **Outposts racks รุ่นที่สอง** ที่มาพร้อมกับตระกูลอินสแตนซ์ EC2 ใหม่ ประสิทธิภาพที่ดีขึ้น และสถาปัตยกรรมเครือข่ายที่อัปเดต
* สามารถใช้งาน **Outpost subnet** เพื่อเปิดใช้งานอินสแตนซ์ EC2 และ EBS volumes รวมถึงรองรับการทำ EBS snapshots บน Outpost

#### Outpost servers (เซิร์ฟเวอร์)
* เซิร์ฟเวอร์ขนาด 1U หรือ 2U ที่ให้บริการประมวลผลและเครือข่ายในท้องถิ่น
* สามารถเปิดใช้งานอินสแตนซ์ EC2 ที่ใช้ Instance Store หรือ **Boot เครื่องจากอุปกรณ์จัดเก็บข้อมูลภายนอก** ผ่านโปรโตคอลที่รองรับได้
* สำรองข้อมูลอินสแตนซ์ไปยัง Amazon EBS ใน AWS Region โดยใช้ EBS direct APIs

### การเชื่อมต่อและเครือข่าย
* **Service link:** ช่องทางสื่อสารระหว่าง Outpost และ AWS Region ที่เกี่ยวข้อง (Outpost เปรียบเสมือนส่วนขยายของ Availability Zone)
* **Local gateway (LGW):**
    * ช่วยให้ตู้แร็ค Outpost สื่อสารกับเครือข่ายภายใน (On-premises) ของลูกค้าได้
    * ทำหน้าที่เป็นเป้าหมาย (Target) ใน VPC Route tables สำหรับทราฟฟิกภายใน และทำ NAT สำหรับอินสแตนซ์ที่ใช้ IP จาก Pool ของลูกค้า
    * แต่ละตู้แร็ค Outpost รองรับ 1 Local gateway และสามารถแชร์ Route table ผ่าน AWS RAM ได้
* **Local network interface (LNI):** ช่วยให้ Outpost server สื่อสารกับเครือข่ายภายในได้

### การแชร์ทรัพยากร (Outpost sharing)
* เจ้าของ Outpost สามารถแชร์ทรัพยากรให้กับบัญชี AWS อื่นๆ ในองค์กรเดียวกันได้
* บัญชี AWS ต่างๆ ไม่สามารถมองเห็นหรือแก้ไขทรัพยากรที่บัญชีอื่นเป็นเจ้าของได้

### การตรวจสอบและติดตาม (Monitoring)
* **Amazon CloudWatch:** ดึงมาตรวัด (Metrics) ของ Outposts รวมถึงสถานะการเชื่อมต่อ Virtual Interface และ BGP
* **AWS CloudTrail:** บันทึกการเรียกใช้ API ของบริการต่างๆ บน Outpost
* **VPC Flow Logs:** ดูข้อมูลรายละเอียดทราฟฟิกทั้งเข้า-ออก และทราฟฟิกภายใน Outpost
* **Traffic Mirroring:** ใช้สำหรับการตรวจสอบเนื้อหา, เฝ้าระวังภัยคุกคาม หรือแก้ไขปัญหาเครือข่าย
* **AWS Health Dashboard:** ดูการเปลี่ยนแปลงสถานะความพร้อมใช้งานของทรัพยากร

### ค่าบริการ (Pricing)
* **ความจุของ Outposts rack:** คิดค่าบริการตามระยะสัญญา 3 ปี หรือ 5 ปี (เลือกจ่ายได้แบบ: จ่ายล่วงหน้าทั้งหมด, จ่ายบางส่วน หรือไม่จ่ายล่วงหน้า)
* **ค่าบริการอื่นๆ:**
    * บริการ AWS ที่รันอยู่บน Outposts
    * AWS Marketplace AMIs
    * ทรัพยากร Outpost ที่คุณแชร์
    * การถ่ายโอนข้อมูล (Data Transfer) ที่เกี่ยวข้องกับทราฟฟิก VPN ของ Service link จาก AWS Region
* **หมายเหตุ:** **ไม่มีค่าบริการ** สำหรับการถ่ายโอนข้อมูลจาก Outpost กลับไปยัง AWS Region ต้นทาง (Parent Region)
