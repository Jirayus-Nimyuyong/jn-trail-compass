# AWS Config Cheat Sheet

**AWS Config** เป็นบริการแบบ Managed ที่ช่วยจัดทำรายการทรัพยากร (Inventory), ประวัติการตั้งค่า (Configuration History) และการแจ้งเตือนเมื่อมีการเปลี่ยนแปลงการตั้งค่า เพื่อสนับสนุนด้านความปลอดภัยและการกำกับดูแล (Governance)

### คุณสมบัติเด่น (Features)
* **การรวมข้อมูลหลายบัญชี/ภูมิภาค:** ให้ภาพรวมสถานะการปฏิบัติตามกฎ (Compliance) ทั่วทั้งองค์กร และสามารถเชื่อมต่อกับ AWS Organizations ได้
* **กฎสำเร็จรูป (Pre-built Rules):** มีกฎให้เลือกใช้เพื่อประเมินการตั้งค่าทรัพยากร หรือสร้างกฎเองผ่าน AWS Lambda เพื่อกำหนดแนวทางปฏิบัติภายในองค์กร
* **การบันทึกประวัติ:** บันทึกรายละเอียดการเปลี่ยนแปลงทรัพยากรและส่งไฟล์ประวัติไปยัง S3 Bucket ที่ระบุโดยอัตโนมัติ
* **การแจ้งเตือน:** รับการแจ้งเตือนทุกครั้งที่มีการสร้าง, แก้ไข หรือลบทรัพยากร
* **การบันทึกซอฟต์แวร์ภายในเครื่อง:** บันทึกการเปลี่ยนแปลงภายในอินสแตนซ์ EC2 หรือเซิร์ฟเวอร์ On-premises (เช่น OS, การอัปเดตระบบ, แอปที่ติดตั้ง)
* **Configuration Snapshot:** การจับภาพสถานะทรัพยากรทั้งหมด ณ เวลาใดเวลาหนึ่ง
* **Advanced Query:** ค้นหาข้อมูลทรัพยากรและประวัติด้วยภาษาที่คล้าย SQL
* **การแก้ไขอัตโนมัติ (Remediation):** รองรับการแก้ไขทรัพยากรที่ไม่ปฏิบัติตามกฎโดยอัตโนมัติผ่าน AWS Systems Manager Automation

---

### แนวคิดหลัก (Concepts)

#### 1. Configuration Item (CI)
* บันทึกการตั้งค่าของทรัพยากร ณ จุดเวลาหนึ่ง ประกอบด้วย 5 ส่วน: ข้อมูลพื้นฐาน, ข้อมูลการตั้งค่าเฉพาะ, ความสัมพันธ์กับทรัพยากรอื่น, CloudTrail Event IDs และ Metadata

#### 2. Configuration History
* คอลเลกชันของ CI ของทรัพยากรใดทรัพยากรหนึ่งในช่วงเวลาต่างๆ AWS Config จะส่งไฟล์ประวัตินี้ไปยัง S3 ทุกๆ 6 ชั่วโมง

#### 3. Configuration Recorder
* ตัวบันทึกการตั้งค่าทรัพยากรที่รองรับ โดยปกติจะบันทึกทุกอย่างในภูมิภาคนั้นๆ แต่สามารถกำหนดเฉพาะเจาะจงหรือเลือกบันทึกทรัพยากรระดับ Global (เช่น IAM) ได้

#### 4. Configuration Stream
* รายการ CI ที่อัปเดตอัตโนมัติเพื่อเฝ้าสังเกตการเปลี่ยนแปลงที่เกิดขึ้นทันที (Real-time) เพื่อระบุปัญหาที่อาจเกิดขึ้นหรือส่งข้อมูลไปยังระบบภายนอก

#### 5. Config Rule (กฎการตั้งค่า)
* ตัวแทนของการตั้งค่าที่ "ควรจะเป็น" หากทรัพยากรใดละเมิดกฎ ระบบจะติดธงว่า **Noncompliant** และแจ้งเตือนผ่าน Amazon SNS
* การประเมินผลเกิดขึ้นได้ 2 แบบ: **เมื่อมีการเปลี่ยนแปลงการตั้งค่า** หรือ **ตามระยะเวลาที่กำหนด (Periodic)**

#### 6. Conformance Packs (แพ็กเกจการปฏิบัติตามกฎ)
* กลุ่มของกฎ (Rules) และการดำเนินการแก้ไข (Remediation) ที่รวมกันไว้ในเทมเพลต YAML เดียว เพื่อให้ง่ายต่อการ Deploy ทั่วทั้งองค์กร

### การตรวจสอบและการรักษาความปลอดภัย (Monitoring & Security)
* **Amazon SNS:** รับแจ้งเตือนเมื่อทรัพยากรถูกสร้างหรือแก้ไข
* **CloudWatch Events:** ตรวจจับและตอบสนองต่อสถานะเหตุการณ์ของ Config
* **AWS CloudTrail:** บันทึกการเรียกใช้ API ของ Config
* **IAM:** ควบคุมสิทธิ์ผู้ใช้ในการเข้าถึงและจัดการ Config
* **มาตรฐานการรองรับ:** รองรับมาตรฐาน ISO, PCI DSS, HIPAA และ FedRAMP

---

### ค่าบริการ (Pricing)
* คิดค่าบริการตาม **จำนวน Configuration Items ที่ถูกบันทึก** และ **จำนวนการประเมินผลกฎ (Rule Evaluations)** แทนการคิดตามจำนวนกฎที่มีอยู่
* คิดค่าบริการตามจำนวนการประเมินผลของ **Conformance Pack** ต่อภูมิภาค
* มีระยะเวลาการเก็บรักษาข้อมูล (Retention) เริ่มต้นที่ 7 ปี (สามารถกำหนดเองได้)
