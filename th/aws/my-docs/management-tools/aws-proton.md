# AWS Proton Cheat Sheet

**AWS Proton** เป็นบริการจัดการการส่งมอบ (Managed Delivery Service) สำหรับการติดตั้งใช้งานแอปพลิเคชันแบบคอนเทนเนอร์และ Serverless

* ใช้ **เทมเพลต (Templates)** เพื่อกำหนดและรักษามาตรฐานของ Application Stacks ซึ่งรวมถึงสถาปัตยกรรม, ทรัพยากรโครงสร้างพื้นฐาน และ CI/CD Pipeline
* **ประกาศยุติการสนับสนุน:** AWS Proton จะ **สิ้นสุดการสนับสนุนในวันที่ 7 ตุลาคม 2026**
* **หลังจากวันที่ดังกล่าว:**
    * จะไม่สามารถเข้าถึงหน้าคอนโซลและทรัพยากรของ AWS Proton ได้อีกต่อไป
    * โครงสร้างพื้นฐานที่ถูกติดตั้งไปแล้ว (Deployed Infrastructure) จะยังคงอยู่เหมือนเดิมไม่ถูกลบ
    * ข้อมูลเกี่ยวกับเทมเพลต, สภาพแวดล้อม (Environments) และ Pipeline จะยังคงมีไว้เพื่อการรับรู้ในเชิงประวัติศาสตร์และการสอบ

---

### แนวคิดหลัก (Concepts)

#### 1. เทมเพลต (Templates)
* **Environment Template:** โครงสร้างพื้นฐานส่วนกลางที่ใช้งานร่วมกันโดยหลายแอปพลิเคชัน (เช่น VPC, Cluster)
* **Service Template:** โครงสร้างพื้นฐานที่จำเป็นในสภาพแวดล้อมเฉพาะเพื่อรันแอปพลิเคชันหรือ Microservice รายตัว
* **เครื่องมือ IaC ที่รองรับ:** AWS CloudFormation และ Terraform
* **เวอร์ชันของเทมเพลต:**
    * **Minor version:** รองรับการเข้ากันได้ย้อนหลัง (Backward compatibility)
    * **Major version:** ไม่รองรับการเข้ากันได้ย้อนหลัง

#### 2. สภาพแวดล้อม (Environments)
* ตัวแทนของชุดทรัพยากรส่วนกลางและนโยบายที่บริการของ AWS Proton ถูกส่งไปติดตั้ง
* **ทรัพยากรที่มักอยู่ใน Environment:** VPC, Clusters, Load Balancers, API Gateways
* **ตัวเลือกการจัดสรร (Provisioning):** สามารถเลือกให้ AWS จัดการให้ (AWS-managed) หรือจัดการเอง (Self-managed) ก็ได้

#### 3. บริการ (Services)
* คือการสร้างอินสแตนซ์จาก Service Template รวมถึงอินสแตนซ์ของบริการและ Pipeline
* **Service Instance:** คอลเลกชันของทรัพยากรโครงสร้างพื้นฐาน AWS ที่ใช้รันแอปในหนึ่ง Environment
* เมื่อสร้าง Service คุณต้องสร้าง Service Instance อย่างน้อยหนึ่งรายการเสมอ

#### 4. ส่วนประกอบ (Components)
* ช่วยให้คุณกำหนดทรัพยากรโครงสร้างพื้นฐาน AWS เพิ่มเติมที่แอปพลิเคชันบางตัวต้องการ นอกเหนือจากที่มีให้ใน Environment หรือ Service Instance ปกติ

#### 5. พื้นที่เก็บข้อมูล (Repositories)
* **Code Repository:** ที่เก็บโค้ดแอปพลิเคชัน (สำหรับการ Deploy โค้ด)
* **Template Repository:** ที่เก็บชุดเทมเพลต (สำหรับการซิงค์เทมเพลต)
* **Infrastructure Repository:** เก็บเทมเพลตโครงสร้างพื้นฐานที่ถูกประมวลผลแล้ว (สำหรับการจัดสรรแบบจัดการเอง)

### การตรวจสอบและติดตาม (Monitoring)
* ใช้ **Amazon EventBridge** เพื่อรับการแจ้งเตือนเมื่อสถานะของกระบวนการจัดสรรทรัพยากร (Provisioning workflows) ของ AWS Proton มีการเปลี่ยนแปลง
* **กฎเหตุการณ์ (Event Rule):** ใช้ดักจับการเปลี่ยนสถานะของบริการ และส่งข้อมูลไปยังเป้าหมาย (Targets) เช่น แจ้งเตือน หรือเริ่มกระบวนการแก้ไขอัตโนมัติ

---

### ค่าบริการ (Pricing)
* **ไม่มีค่าธรรมเนียมสำหรับตัวบริการ AWS Proton โดยตรง**
* คุณจ่ายเพียงค่าทรัพยากร AWS ที่คุณสร้างขึ้นเพื่อจัดเก็บและรันแอปพลิเคชันของคุณตามปกติ
