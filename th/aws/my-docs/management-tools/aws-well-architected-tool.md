# AWS Well-Architected Tool Cheat Sheet

**AWS Well-Architected Tool** เป็นบริการที่ช่วยคุณตรวจสอบเวิร์กโหลด (Workloads) และเปรียบเทียบกับแนวทางปฏิบัติที่ดีที่สุด (Best Practices) ล่าสุดด้านสถาปัตยกรรมของ AWS โดยเครื่องมือนี้จะให้คำแนะนำเพื่อให้เวิร์กโหลดของคุณมีความน่าเชื่อถือ ปลอดภัย มีประสิทธิภาพ และคุ้มค่ากับค่าใช้จ่ายมากยิ่งขึ้น

### ส่วนประกอบสำคัญ (Key Components)

* **Workload (เวิร์กโหลด):** คำที่ใช้เรียกชุดของส่วนประกอบที่รวมตัวกันเพื่อมอบคุณค่าทางธุรกิจ ตั้งแต่เว็บไซต์การตลาด, แพลตฟอร์มอีคอมเมิร์ซ, ระบบหลังบ้านของแอปมือถือ ไปจนถึงแพลตฟอร์มวิเคราะห์ข้อมูล ความซับซ้อนมีได้ตั้งแต่เว็บไซต์แบบ Static ง่ายๆ ไปจนถึงสถาปัตยกรรม Microservices ที่ซับซ้อน
* **Milestones (จุดสำคัญ):** จุดสำคัญในวิวัฒนาการของสถาปัตยกรรมตลอดวงจรชีวิตผลิตภัณฑ์ รวมถึงช่วงการออกแบบ, การทดสอบ, การเปิดตัว และการใช้งานจริง (Production)
* **Lenses (เลนส์):** กลไกที่ช่วยให้คุณประเมินสถาปัตยกรรมตามแนวทางปฏิบัติที่ดีที่สุดได้อย่างสม่ำเสมอ และระบุจุดที่ต้องปรับปรุง AWS มีเลนส์ให้เลือกใช้หลากหลาย และคุณยังสามารถสร้างเลนส์ของตัวเองหรือใช้เลนส์ที่ผู้อื่นแชร์มาให้ได้
    * มีส่วน **Well‑Architected Framework Review (WAFR)** เพื่อเป็นแนวทางในการตรวจสอบเวิร์กโหลดอย่างเป็นระบบ
* **High Risk Issues (HRIs - ปัญหาระดับความเสี่ยงสูง):** การตัดสินใจด้านสถาปัตยกรรมหรือการดำเนินงานที่อาจส่งผลกระทบเชิงลบอย่างรุนแรงต่อธุรกิจ ทรัพย์สิน หรือบุคลากร
* **Medium Risk Issues (MRIs - ปัญหาระดับความเสี่ยงปานกลาง):** การตัดสินใจที่อาจส่งผลกระทบเชิงลบต่อธุรกิจ แต่โดยปกติจะมีความรุนแรงน้อยกว่า HRIs
* **การเชื่อมต่อภายนอก:** มีตัวเชื่อมต่อ (Connectors) สำหรับทำงานร่วมกับระบบภายนอก เช่น **Jira** เพื่อประสานงานขั้นตอนการตรวจสอบ

---

### การใช้งานเครื่องมือ (Using the Tool)

ในการใช้งาน คุณจะเริ่มจากการนิยามเวิร์กโหลด (Define workload) จากนั้นตอบชุดคำถามตาม **5 เสาหลักของ AWS Well-Architected Framework** เมื่อตรวจสอบเสร็จ เครื่องมือจะสร้างรายงานที่ระบุรายการปัญหาความเสี่ยงสูงพร้อมแผนการปรับปรุง (Improvement plan)

* **Review templates:** ช่วยให้คุณกำหนดมาตรฐานและนำการตั้งค่าการตรวจสอบที่ใช้บ่อยกลับมาใช้ซ้ำกับหลายเวิร์กโหลดได้

---

### แนวทางปฏิบัติที่ดีที่สุด (Best Practices)

AWS Well-Architected Tool มอบชุดแนวทางปฏิบัติสำหรับแต่ละเสาหลัก ดังนี้:

* **การนิยามเวิร์กโหลด:** กำหนดขอบเขตชุดแอปพลิเคชันที่ส่งมอบคุณค่าทางธุรกิจร่วมกัน
* **กระบวนการตรวจสอบ:** ประเมินเวิร์กโหลดผ่านชุดคำถามเพื่อให้ได้แผนการปรับปรุงสถาปัตยกรรม
* **การติดตามจุดสำคัญ:** บันทึก Milestones ตามช่วงเวลาเพื่อติดตามการพัฒนาสถาปัตยกรรมของคุณเมื่อเวลาผ่านไป
* **คำแนะนำด้านสถาปัตยกรรม:** มอบวิธีการที่สม่ำเสมอในการประเมินและออกแบบระบบที่รองรับการขยายตัว (Scalable designs)
* **การผนวกรวมเข้ากับขั้นตอนงาน:** ขยายการใช้งานเครื่องมือไปยังกระบวนการกำกับดูแล แอปพลิเคชัน และ Workflow ของคุณผ่าน **APIs**
* **การวัดผลการปรับปรุง:** ดำเนินการตามแผนปรับปรุงและติดตามการเปลี่ยนแปลงเพื่อวัดความคืบหน้า
* **การประเมินอย่างสม่ำเสมอ:** มีกลไกสำหรับตรวจสอบเวิร์กโหลดเป็นประจำ เพื่อระบุความเสี่ยงสูงและบันทึกการพัฒนา

---

### ประโยชน์ (Benefits)

* **คำแนะนำด้านสถาปัตยกรรม:** ช่วยให้คุณมีแนวทางที่เป็นมาตรฐานในการประเมินสถาปัตยกรรมและการออกแบบที่ยืดหยุ่น
* **แนวทางปฏิบัติในขั้นตอนการทำงาน:** สามารถเชื่อมต่อเครื่องมือเข้ากับระบบกำกับดูแลและ Workflow เดิมของคุณผ่าน API ที่ทรงพลัง
* **การวัดผลการพัฒนา:** สามารถบันทึกจุดสำคัญ (Milestones) ณ เวลาต่างๆ เพื่อติดตามและวัดผลความสำเร็จจากการปรับปรุงแก้ไข
