# AWS CloudFormation Cheat Sheet

**AWS CloudFormation** เป็นบริการที่ช่วยให้นักพัฒนาและธุรกิจมีวิธีที่ง่ายและน่าเชื่อถือในการสร้างและจัดการกลุ่มของทรัพยากร AWS ที่เกี่ยวข้องกัน โดยจะช่วยจัดการการจัดสรร (Provisioning) และการอัปเดตทรัพยากรโดยอัตโนมัติอย่างปลอดภัยและคาดการณ์ได้ ช่วยให้สามารถนำแนวทาง **Infrastructure as Code (IaC)** มาใช้เพื่อให้การควบคุมเวอร์ชัน การทดสอบ และการทำงานร่วมกันดียิ่งขึ้น

### คุณสมบัติเด่น (Features)
* **Infrastructure as Code:** จำลองโครงสร้างพื้นฐานทั้งหมดในรูปแบบไฟล์ข้อความที่เรียกว่า **Template** (JSON หรือ YAML)
* **CloudFormation Designer:** เครื่องมือแบบกราฟิกที่ช่วยสร้างและแก้ไขเทมเพลตด้วยการลากวาง (Drag-and-drop)
* **Rollback Triggers:** ตรวจสอบ CloudWatch Alarms ระหว่างการทำงานของ Stack หากเกิดปัญหาจะทำการย้อนกลับ (Rollback) การเปลี่ยนแปลงโดยอัตโนมัติ
* **Change Sets:** ตรวจสอบผลกระทบของการเปลี่ยนแปลงก่อนที่จะกดอัปเดตจริง เพื่อดูว่าทรัพยากรที่รันอยู่จะได้รับผลกระทบอย่างไร
* **StackSets:** จัดสรรชุดทรัพยากรทั่วไปข้ามหลายบัญชี (Accounts) และหลายภูมิภาค (Regions) ผ่านเทมเพลตเดียว รองรับการทำงานร่วมกับ AWS Organizations
* **Drift Detection:** ตรวจจับว่าการตั้งค่าจริงของทรัพยากรใน Stack เปลี่ยนไป (Drift) จากที่ระบุไว้ในเทมเพลตหรือไม่
* **Stack Refactoring:** ปรับปรุงโครงสร้างทรัพยากรใหม่โดยที่ยังรักษาข้อมูลและสถานะเดิมไว้ได้
* **สร้างเทมเพลตจากทรัพยากรที่มีอยู่:** สามารถสร้างไฟล์ CloudFormation จากทรัพยากร AWS ที่ถูก Deploy ไปก่อนหน้านี้แล้วได้

### แนวคิดสำคัญ (Concepts)

#### 1. Templates
* ไฟล์ข้อความรูปแบบ JSON หรือ YAML ที่ทำหน้าที่เป็น "พิมพ์เขียว" (Blueprints) ในการสร้างทรัพยากร AWS

#### 2. Stacks
* การจัดการทรัพยากรที่เกี่ยวข้องกันในฐานะหน่วยเดียว (Single Unit) ทรัพยากรทั้งหมดใน Stack จะถูกนิยามโดยเทมเพลตของ Stack นั้นๆ
* **การจัดการข้อผิดพลาด:** หากสร้างทรัพยากรใดไม่สำเร็จ CloudFormation จะทำการ Rollback และลบทรัพยากรที่เพิ่งสร้างขึ้นใน Stack นั้นโดยอัตโนมัติ

#### 3. Change Sets
* บทสรุปของการเปลี่ยนแปลงที่เสนอมา ช่วยให้คุณเห็นผลกระทบก่อนการเริ่มอัปเดต Stack จริงๆ โดยเฉพาะกับทรัพยากรที่สำคัญระดับวิกฤต

#### 4. StackSets
* ช่วยในการ Deploy Stack ข้ามหลายบัญชีและหลายภูมิภาคได้ในไม่กี่คลิก
* **Administrator Account:** บัญชีที่ใช้สร้างและจัดการ Stack Set
* **Target Account:** บัญชีปลายทางที่ Stack จะถูกสร้าง อัปเดต หรือลบ

### การทำงานร่วมกับเครื่องมืออื่น (Integration)
* **AWS CodePipeline:** ใช้ทำ Continuous Delivery เพื่อสร้างและทดสอบการเปลี่ยนแปลงของเทมเพลตโดยอัตโนมัติก่อนส่งไปยัง Production
* **AWS PrivateLink:** เรียกใช้ CloudFormation API ภายใน VPC ผ่านเครือข่ายของ AWS โดยตรง ไม่ต้องผ่านอินเทอร์เน็ตสาธารณะ
* **Git Sync:** ติดตามเหตุการณ์การซิงโครไนซ์เทมเพลตจาก Git ผ่าน EventBridge

---

### ความแตกต่างระหว่าง CloudFormation และ Elastic Beanstalk
* **Elastic Beanstalk:** มอบ "สภาพแวดล้อม" (Environment) เพื่อให้ง่ายต่อการ **Deploy และรันแอปพลิเคชัน** บนคลาวด์
* **CloudFormation:** เป็น **กลไกการจัดสรรทรัพยากร** (Provisioning mechanism) ที่ครอบคลุมบริการของ AWS ในวงกว้างกว่ามาก

---

### การตรวจสอบและความปลอดภัย (Monitoring & Security)
* **AWS CloudTrail:** บันทึกการเรียกใช้ API ของ CloudFormation ทั้งหมดโดยผู้ใช้ บทบาท (Roles) หรือบริการอื่นๆ
* **IAM Control:** ควบคุมสิทธิ์ว่าใครสามารถดู สร้าง หรือลบ Stack ได้
* **Service Role:** เป็น IAM Role ที่อนุญาตให้ CloudFormation ทำการเรียกใช้ทรัพยากรใน Stack แทนคุณ เพื่อความปลอดภัยโดยไม่ต้องมอบสิทธิ์ที่มากเกินไปให้แก่ผู้ใช้รายบุคคล

---

### ค่าบริการ (Pricing)
* **ไม่มีค่าบริการเพิ่มเติมสำหรับ CloudFormation**
* คุณจ่ายเพียงค่าทรัพยากร AWS ที่ถูกสร้างขึ้น (เช่น ค่าเครื่อง EC2, ค่าฐานข้อมูล RDS) ในอัตราปกติเสมือนว่าคุณสร้างทรัพยากรเหล่านั้นด้วยตัวเอง
