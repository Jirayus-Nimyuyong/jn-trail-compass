# AWS Systems Manager Cheat Sheet

ช่วยให้คุณรวมศูนย์ข้อมูลการดำเนินงานจากบริการต่างๆ ของ AWS และสร้างระบบอัตโนมัติสำหรับทรัพยากรทั้งหมดของคุณ
* **SSM Agent:** รองรับการอัปเดตอัตโนมัติและการเสริมความปลอดภัยบนระบบปฏิบัติการที่รองรับ

### คุณสมบัติเด่น (Features)
* **Resource Groups:** สร้างกลุ่มทรัพยากรเชิงตรรกะ เช่น ตามแอปพลิเคชัน, ตามชั้นของซอฟต์แวร์ (Layer) หรือแยกตามสภาพแวดล้อม (Prod vs Dev)
* **Insights:** เลือกกลุ่มทรัพยากรเพื่อดูประวัติ API, การเปลี่ยนแปลงการตั้งค่า, การแจ้งเตือน และสถานะการปฏิบัติตามกฎของซอฟต์แวร์
* **Inventory:** รวบรวมข้อมูลเกี่ยวกับอินสแตนซ์และซอฟต์แวร์ที่ติดตั้งอยู่ภายใน
* **Automation:** สร้างระบบอัตโนมัติสำหรับงานไอทีที่ทำซ้ำๆ ได้อย่างปลอดภัย
* **Session Manager:** จัดการอินสแตนซ์ผ่านเบราว์เซอร์หรือ CLI โดยไม่ต้องเปิดพอร์ตขาเข้า (Inbound ports), ไม่ต้องจัดการกุญแจ SSH และไม่ต้องใช้ Bastion Host
* **Patch Manager:** ช่วยให้ซอฟต์แวร์ทันสมัยอยู่เสมอและเป็นไปตามนโยบายขององค์กร
* **Maintenance Window:** กำหนดช่วงเวลาสำหรับงานบำรุงรักษาเพื่อไม่ให้กระทบต่อธุรกิจ

---

### ความสามารถหลัก (Capabilities)

#### 1. Automation (ระบบอัตโนมัติ)
* **Automation Document:** กำหนดขั้นตอนการทำงาน (Workflow)
* **Automation Action:** แต่ละขั้นตอนเชื่อมโยงกับปลั๊กอินหรือการทำงานเฉพาะอย่าง
* **Automation Queue:** หากรันเกิน 25 งานพร้อมกัน งานที่เหลือจะไปอยู่ในคิวสถานะ Pending

#### 2. Inventory & Compliance (รายการทรัพยากรและความสอดคล้อง)
* **Inventory Manager:** รวบรวม Metadata ของซอฟต์แวร์ตามกำหนดเวลา
* **Configuration Compliance:** สแกนหาความไม่สอดคล้องของการตั้งค่าและประวัติการ Patch โดยเชื่อมต่อกับ **AWS Config**

#### 3. Run Command & Session Manager
* **Run Command:** จัดการการตั้งค่าอินสแตนซ์จำนวนมากจากระยะไกลอย่างปลอดภัย โดยใช้แท็กหรือกลุ่มทรัพยากรเป็นเป้าหมาย
* **Session Manager:** ให้การเข้าถึงอินสแตนซ์แบบคลิกเดียว รองรับการทำ SSH/SCP Tunneling และ Port Forwarding โดยไม่ต้องเปิดพอร์ต Firewall

#### 4. Patch Manager & Maintenance Window
* **Patch Manager:** ใช้ **Patch Baselines** เพื่ออนุมัติและติดตั้ง Patch อัตโนมัติ รองรับทั้ง Windows, Linux และ Container
* **Maintenance Window:** กำหนดตารางเวลาทำซ้ำสำหรับงานบำรุงรักษา รองรับการจัดลำดับความสำคัญของงาน

#### 5. Systems Manager Document (SSM Document)
นิยามการกระทำที่ SSM จะดำเนินการ (รองรับรูปแบบ JSON หรือ YAML)
* **Command Document:** ใช้กับ Run Command และ State Manager
* **Policy Document:** บังคับใช้นโยบายผ่าน State Manager
* **Automation Document:** ใช้กับระบบงานบำรุงรักษาหรือการสร้าง AMI
* **Package Document:** ใช้กับ Distributor สำหรับติดตั้งซอฟต์แวร์

#### 6. Parameter Store & Secrets Management
* เก็บข้อมูลการตั้งค่าและรหัสลับ (Secrets) แบบลำดับชั้น
* รองรับข้อมูลแบบข้อความธรรมดาหรือเข้ารหัสด้วย **SecureString** (เชื่อมต่อกับ AWS KMS)

#### 7. OpsCenter & Incident Manager
* **OpsCenter:** รวมศูนย์ปัญหาด้านการดำเนินงาน (OpsItems) เพื่อช่วยลดเวลาในการแก้ไขปัญหา (MTTR)
* **Incident Manager:** ช่วยบรรเทาและกู้คืนระบบจากเหตุการณ์ที่กระทบต่อแอปพลิเคชัน พร้อมรายงานวิเคราะห์หลังเกิดเหตุ (Post-incident analysis)

#### 8. Change Manager & AppConfig
* **Change Manager:** กรอบการทำงานสำหรับส่งคำขอ, อนุมัติ และดำเนินการเปลี่ยนแปลงโครงสร้างพื้นฐานทั่วทั้งองค์กร
* **AppConfig:** จัดการและ Deploy การตั้งค่าแอปพลิเคชันอย่างรวดเร็ว พร้อมระบบตรวจสอบความถูกต้อง (Validation)

---

### การตรวจสอบและการรักษาความปลอดภัย (Monitoring & Security)
* **Logging:** บันทึกข้อมูลผ่าน SSM Agent ไปยัง CloudWatch Logs
* **CloudTrail:** บันทึกการเรียกใช้ API ของ Systems Manager ทั้งหมด
* **EventBridge:** ใช้ตรวจจับเงื่อนไขและสั่งงานอัตโนมัติ (Event-driven)
* **Security:** เชื่อมต่อโดยตรงกับ IAM เพื่อควบคุมสิทธิ์แบบ Least-privilege

---

### ค่าบริการ (Pricing)
* **ไม่มีค่าธรรมเนียมพื้นฐาน:** จ่ายตามการใช้งานจริง เช่น จำนวนขั้นตอน Automation, จำนวนพารามิเตอร์ขั้นสูง (Advanced Parameters), จำนวนการเรียกใช้ API และพื้นที่จัดเก็บใน Distributor
* ฟีเจอร์มาตรฐานส่วนใหญ่มักจะฟรีภายใต้ข้อกำหนดการใช้งานปกติของ AWS
