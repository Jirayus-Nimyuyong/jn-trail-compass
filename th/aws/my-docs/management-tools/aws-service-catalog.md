# AWS Service Catalog Cheat Sheet

ช่วยให้คุณสร้าง จัดการ และแจกจ่ายแคตตาล็อกของ "ผลิตภัณฑ์ที่ได้รับอนุมัติแล้ว" ให้กับผู้ใช้งานทั่วไป (End-users) ซึ่งสามารถเข้าถึงผลิตภัณฑ์ที่ต้องการผ่านพอร์ทัลส่วนตัวได้
* ผู้ดูแลระบบสามารถควบคุมการเข้าถึงผลิตภัณฑ์เพื่อบังคับใช้นโยบายทางธุรกิจขององค์กร
* สามารถตั้งค่า **Adopted Roles** เพื่อให้ผู้ใช้ทั่วไปมีสิทธิ์เพียงแค่เข้าถึง Service Catalog ก็สามารถติดตั้งทรัพยากรที่ได้รับอนุมัติได้โดยไม่ต้องมีสิทธิ์ IAM ในบริการนั้นๆ โดยตรง
* เป็นบริการแบบ **Regional (แยกตามภูมิภาค)**

---

### คุณสมบัติเด่น (Features)
* การกำหนดมาตรฐานของทรัพยากร (Standardization)
* การค้นหาและติดตั้งด้วยตนเอง (Self-service)
* การควบคุมสิทธิ์ที่ละเอียด (Fine-grain access control)
* การจัดการเวอร์ชันและการต่อขยาย (Extensibility)

---

### แนวคิดหลัก (Concepts)

#### 1. ผู้ใช้งาน (Users)
* **Catalog Administrators:** จัดการแคตตาล็อก, จัดกลุ่มเป็น Portfolio, กำหนดสิทธิ์ และเตรียมเทมเพลต CloudFormation
* **End Users:** ผู้ใช้งานที่ได้รับสิทธิ์ให้เข้ามาเลือกติดตั้งผลิตภัณฑ์

#### 2. ผลิตภัณฑ์ (Products)
* ประกอบด้วยทรัพยากร AWS ตั้งแต่หนึ่งอย่างขึ้นไป (เช่น EC2, Storage, Database) หรือผลิตภัณฑ์จาก AWS Marketplace
* สร้างโดยการนำเข้า **AWS CloudFormation Templates** เพื่อกำหนดความสัมพันธ์ของทรัพยากรและพารามิเตอร์การตั้งค่า
* รองรับผลิตภัณฑ์จากภายนอก เช่น **Terraform**

#### 3. พอร์ตโฟลิโอ (Portfolio)
* ชุดสะสมของผลิตภัณฑ์พร้อมข้อมูลการตั้งค่า ช่วยจัดการว่าใครสามารถใช้ผลิตภัณฑ์อะไรได้บ้างและใช้อย่างไร
* เมื่อเพิ่มเวอร์ชันใหม่ใน Portfolio ผู้ใช้ทุกคนจะเห็นเวอร์ชันนั้นโดยอัตโนมัติ
* สามารถแชร์ Portfolio ไปยังบัญชี AWS อื่นๆ ได้

#### 4. การจัดการเวอร์ชัน (Versioning)
* **Active:** ปรากฏในรายการและอนุญาตให้ผู้ใช้ติดตั้งได้
* **Inactive:** ถูกซ่อนจากรายการ (ไม่กระทบผลิตภัณฑ์เดิมที่ติดตั้งไปแล้ว)
* **Deleted:** ถูกลบออกจากรายการ (ย้อนกลับไม่ได้)

#### 5. การควบคุมข้อจำกัด (Constraints)
* **Template constraints:** จำกัดพารามิเตอร์ที่ผู้ใช้สามารถเลือกได้ตอนติดตั้ง
* **Launch constraints:** ระบุบทบาท (Role) ที่ใช้ในการติดตั้งทรัพยากร เพื่อจำกัดสิทธิ์ผู้ใช้ไม่ให้ทำนอกเหนือจากที่อนุญาต
* **Notification constraints:** ระบุ Amazon SNS เพื่อรับการแจ้งเตือนเหตุการณ์ของ Stack
* **Tag update constraints:** อนุญาตหรือไม่อนุญาตให้ผู้ใช้แก้ไข Tag ของทรัพยากร

#### 6. สแต็ก (Stack)
* ทุกผลิตภัณฑ์จะถูกติดตั้งในรูปแบบของ **AWS CloudFormation Stack**
* สามารถใช้ **CloudFormation StackSets** เพื่อติดตั้งผลิตภัณฑ์ข้ามภูมิภาคและข้ามบัญชีได้พร้อมกัน

---

### บริการเพิ่มเติม (AppRegistry & Service Actions)
* **Service Actions:** ใช้เอกสาร **AWS Systems Manager** เพื่อให้ผู้ใช้ทั่วไปสามารถทำงานบางอย่างกับทรัพยากรที่ติดตั้งไปแล้วได้ (เช่น การ Reboot หรือ Backup) โดยไม่ต้องมีสิทธิ์เต็ม
* **AppRegistry:** สร้างและจัดการข้อมูลเมทาดาตาของแอปพลิเคชันจากส่วนกลาง เพื่อให้มองเห็นกลุ่มทรัพยากรข้ามบัญชีได้ชัดเจนขึ้น

---

### ความปลอดภัย (Security)
* ข้อมูลใน S3 และ DynamoDB ที่ Service Catalog ใช้จะถูกเข้ารหัส (Encryption at rest)
* ใช้ TLS สำหรับการเข้ารหัสข้อมูลระหว่างการสื่อสาร (In transit)
* ทำงานร่วมกับ **AWS CloudTrail** เพื่อบันทึกประวัติการใช้งาน

---

### ค่าบริการ (Pricing)
* **Free Tier:** รวมการเรียกใช้ API ฟรี 1,000 ครั้งต่อเดือน (สำหรับ Service Catalog และ AppRegistry)
* จ่ายค่าบริการตามจำนวนการเรียกใช้ API ที่เกินจากสิทธิ์ฟรีที่กำหนดไว้
