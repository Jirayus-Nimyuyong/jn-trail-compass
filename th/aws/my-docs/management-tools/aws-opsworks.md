# Amazon OpsWorks Cheat Sheet

**AWS OpsWorks** เป็นบริการจัดการการกำหนดค่า (Configuration Management) ที่ช่วยคุณตั้งค่าและใช้งานแอปพลิเคชันในระดับองค์กรบนคลาวด์โดยใช้ **Puppet** หรือ **Chef**

* **OpsWorks for Chef Automate** และ **OpsWorks Stacks** ช่วยให้คุณใช้ Chef Cookbooks ในการจัดการการตั้งค่า
* **OpsWorks for Puppet Enterprise** ช่วยให้คุณกำหนดค่าเซิร์ฟเวอร์หลัก (Master Server) ของ Puppet ใน AWS
* **การใช้งาน:** ช่วยให้คุณกำหนดค่า ติดตั้ง และจัดการ Node ต่างๆ ได้โดยอัตโนมัติ ไม่ว่าจะเป็นอินสแตนซ์ EC2 หรืออุปกรณ์ On-premises
* **หมายเหตุสำคัญ:** บริการนี้ถูกยกเลิก (Deprecated) และสิ้นสุดอายุการใช้งาน (End of Life) ตั้งแต่วันที่ **26 พฤษภาคม 2024**

---

### 1. OpsWorks for Puppet Enterprise
ให้บริการ Puppet Master แบบจัดการให้เบ็ดเสร็จ (Fully-managed)
* **การจัดการ:** AWS ดูแลเซิร์ฟเวอร์ Puppet Master บน EC2 ให้ แต่คุณยังควบคุมทรัพยากรที่รันอยู่ได้
* **การบำรุงรักษา:** เลือกช่วงเวลาบำรุงรักษาประจำสัปดาห์เพื่ออัปเดตอัตโนมัติ มีระบบตรวจสอบความสมบูรณ์และ Rollback หากเกิดปัญหา
* **การสำรองข้อมูล:** ตั้งค่าสำรองข้อมูลอัตโนมัติเก็บไว้ใน S3 Bucket
* **ความปลอดภัย:** ใช้ SSL และกระบวนการอนุมัติใบรับรอง (Certification Approval) เพื่อให้มั่นใจว่าเซิร์ฟเวอร์ตอบสนองเฉพาะคำขอที่เชื่อถือได้
* **ราคา:** จ่ายตามจำนวน Node ที่เชื่อมต่อ (รายชั่วโมง) และค่าอินสแตนซ์ EC2 ที่รัน Puppet Master

---

### 2. OpsWorks for Chef Automate
ช่วยสร้างเซิร์ฟเวอร์ Chef ที่ AWS จัดการให้ ซึ่งรวมคุณสมบัติระดับพรีเมียมของ Chef Automate (เช่น Workflow, Visibility, Compliance)
* **เทคโนโลยี:** รองรับ Chef Automate 2 และใช้ `chef-client`
* **การเข้าถึง:** สามารถใช้ Knife เพื่อ SSH เข้าไปยังอินสแตนซ์เซิร์ฟเวอร์ Chef ได้ตลอดเวลา
* **การลงทะเบียน Node:** ลงทะเบียน Node ใหม่ผ่าน Auto Scaling Groups โดยใช้ Code Snippets ที่ระบบจัดเตรียมไว้ให้
* **ราคา:** จ่ายตามจำนวน Node ที่เชื่อมต่อ (รายชั่วโมง) และค่าอินสแตนซ์ EC2 ที่รันเซิร์ฟเวอร์ Chef

---

### 3. OpsWorks Stacks
วิธีการที่เรียบง่ายและยืดหยุ่นในการสร้างและจัดการ Stack และแอปพลิเคชัน
* **Stacks:** กลุ่มของทรัพยากร AWS ที่ประกอบกันเป็นแอปพลิเคชัน (1 Stack สร้างได้สูงสุด 40 Layers/Instances/Apps)
* **Layers:** กลุ่มย่อยของอินสแตนซ์ EC2 ที่ทำหน้าที่เฉพาะอย่าง (เช่น Layer ของ Database หรือ Web App) โดยใช้ **Chef Recipes** ในการจัดการงานต่างๆ
* **จุดเด่น:** **OpsWorks Stacks ไม่ต้องการหรือไม่ได้สร้างเซิร์ฟเวอร์ Chef ขึ้นมา**

#### ประเภทของอินสแตนซ์ (Instance Types)
1.  **24/7 instances:** เริ่มรันด้วยมือและรันตลอดไปจนกว่าจะสั่งหยุด
2.  **Time-based instances:** รันตามตารางเวลาที่กำหนดรายวัน/สัปดาห์ เพื่อรองรับโหลดที่คาดการณ์ได้
3.  **Load-based instances:** เริ่มและหยุดโดยอัตโนมัติตาม Metrics (เช่น CPU) เพื่อรองรับทราฟฟิกที่ผันผวน (รองรับเฉพาะ Linux เท่านั้น)

#### เหตุการณ์วงจรชีวิต (Lifecycle Events)
สามารถตั้งค่าให้ Recipe ทำงานอัตโนมัติผ่าน 5 เหตุการณ์:
* **Setup:** เมื่ออินสแตนซ์ใหม่ Boot สำเร็จ
* **Configure:** เมื่อมีอินสแตนซ์ใน Stack เข้าหรือออกจากสถานะ Online
* **Deploy:** เมื่อมีการติดตั้งแอป
* **Undeploy:** เมื่อมีการลบแอป
* **Shutdown:** เมื่อสั่งหยุดอินสแตนซ์

---

### การตรวจสอบและความปลอดภัย (Monitoring & Security)
* **Monitoring:** ส่ง Metrics ไปยัง CloudWatch และบันทึก Log การกระทำต่างๆ รวมถึง CloudTrail สำหรับการเรียก API
* **Security:** กำหนดสิทธิ์ผู้ใช้ IAM แยกตาม Stack ว่าใครสามารถติดตั้งแอปหรือสร้างทรัพยากรได้
* **Networking:** อินสแตนซ์ EC2 จะถูกควบคุมการเข้าถึงผ่าน Security Groups
