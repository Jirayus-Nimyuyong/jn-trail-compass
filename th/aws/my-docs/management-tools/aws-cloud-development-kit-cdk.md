# AWS Cloud Development Kit (CDK) Cheat Sheet

**AWS CDK** เป็นเฟรมเวิร์กโอเพนซอร์สสำหรับการพัฒนาซอฟต์แวร์ เพื่อใช้ในการนิยามโครงสร้างพื้นฐานคลาวด์ด้วยการเขียนโค้ด (Infrastructure as Code) และจัดสรรทรัพยากรผ่าน **AWS CloudFormation**

* ให้การจำลองภาพระดับสูงแบบ Object-oriented ครอบทับ CloudFormation อีกชั้นหนึ่ง ช่วยให้คุณใช้ส่วนประกอบคลาวด์สำเร็จรูปที่เรียกว่า **Constructs** ได้
* รองรับภาษาโปรแกรมที่คุ้นเคย เช่น **TypeScript, JavaScript, Python, C#, .Net, Java และ Go** โดยทุกอย่างจะถูก Deploy ในรูปแบบของ CloudFormation Stacks

---

### แนวคิดสำคัญ (Concepts)

* **Stacks:** หน่วยการ Deploy ทรัพยากร AWS ที่นิยามใน CDK App ของคุณ แต่ละ Stack คือ CloudFormation Stack หนึ่งอัน และสามารถบรรจุทรัพยากร AWS ได้หลายรายการ
* **Constructs:** ส่วนประกอบคลาวด์สำเร็จรูปที่ใช้โมเดลและจัดสรรทรัพยากร เป็นอิฐบล็อกพื้นฐานของโครงสร้าง CDK แบ่งออกเป็น 3 ระดับ:
    * **L1 Constructs (CFN Resources):** ระดับต่ำสุดที่จับคู่โดยตรงกับทรัพยากรใน CloudFormation (เช่น S3 Bucket หรือ DynamoDB Table แบบระบุรายละเอียดครบถ้วน)
    * **L2 Constructs:** เพิ่มความสะดวกสบายโดยใส่ค่าเริ่มต้น (Default settings) และตรรกะการเชื่อมต่อที่ต้องเขียนซ้ำๆ มาให้แล้ว
    * **L3 Constructs (Patterns):** ระดับสูงสุดที่นิยามโครงสร้างพื้นฐานตามแนวทางปฏิบัติที่ดีที่สุด (Best Practices) เช่น การสร้าง API Gateway ที่เชื่อมกับ Lambda ได้ในคำสั่งเดียว
* **App:** คอนเทนเนอร์ที่บรรจุ Stack ตั้งแต่หนึ่งอันขึ้นไป กำหนดว่าทรัพยากรจะถูกสร้างและเชื่อมต่อกันอย่างไร
* **Environment:** เป้าหมายในการ Deploy Stack (ระบุ Account, Region หรือ Stage เช่น dev, staging, prod)
* **cdk.out:** ไดเรกทอรีที่เก็บผลลัพธ์จากการ Synthesize รวมถึงเทมเพลต CloudFormation และไฟล์ Assets ต่างๆ
* **Stack Drift:** ฟีเจอร์ที่ช่วยตรวจจับและเปรียบเทียบทรัพยากรจริงในระบบ กับทรัพยากรที่คาดหวังในเทมเพลต CloudFormation

---

### การเปลี่ยนแปลงใน CDK v2
* ใช้แพ็กเกจเดียวคือ **`aws-cdk-lib`** สำหรับ Stable APIs ทั้งหมด
* แยก Library สำหรับ Construct ที่ยังอยู่ในขั้นทดลอง (Alpha) ออกมาต่างหาก
* CLI และ Construct Library แยกเวอร์ชันและตารางการอัปเดตออกจากกัน
* รองรับการสร้างและ Deploy ทรัพยากรที่เป็น Container Image Assets

---

### ข้อดีของการใช้ AWS CDK
* **การจำลองระดับสูง (Higher-level abstraction):** ช่วยให้นักพัฒนาแสดงโครงสร้างพื้นฐานได้อย่างเป็นธรรมชาติผ่านภาษาโปรแกรมที่ถนัด สร้างระบบที่ซับซ้อนได้ด้วยโค้ดเพียงไม่กี่บรรทัด
* **การทำงานร่วมกันและการทดสอบที่ดียิ่งขึ้น:** เมื่อเป็นโค้ด (IaC) จึงสามารถทำ Version Control, ทดสอบ (Testing) และทำงานร่วมกันในทีมได้ง่าย
* **การรวมเข้ากับ CI/CD ที่ง่ายขึ้น:** เชื่อมต่อกับ CodePipeline, CodeBuild และ CodeDeploy เพื่อสร้างระบบอัตโนมัติในการ Deploy และจัดการโครงสร้างพื้นฐาน
* **CDK Refactor:** ช่วยให้ปรับปรุงโครงสร้างโค้ด (เช่น เปลี่ยนชื่อ Construct หรือจัดระเบียบ Stack ใหม่) ได้อย่างปลอดภัย โดยไม่ส่งผลให้ต้องลบทิ้งและสร้างทรัพยากร AWS จริงใหม่ทั้งหมด
