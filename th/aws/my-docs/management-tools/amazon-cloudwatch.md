# Amazon CloudWatch Cheat Sheet

เครื่องมือตรวจสอบ (Monitoring) สำหรับทรัพยากรและแอปพลิเคชันบน AWS ของคุณ
แสดงผลตัวชี้วัด (Metrics) และสร้างการแจ้งเตือน (Alarms) เพื่อเฝ้าดูตัวชี้วัดและส่งการแจ้งเตือน หรือทำการเปลี่ยนแปลงทรัพยากรที่คุณตรวจสอบโดยอัตโนมัติเมื่อมีการละเมิดเกณฑ์ที่กำหนด

* CloudWatch เปรียบเสมือนคลังเก็บ Metrics บริการของ AWS (เช่น EC2) จะส่ง Metrics เข้ามา และคุณสามารถดึงสถิติเหล่านั้นออกมาดูได้
* คุณสามารถใส่ Custom Metrics ของคุณเองได้เช่นกัน
* **ไม่รวมข้อมูลข้ามภูมิภาค:** Metrics ในแต่ละภูมิภาคจะแยกจากกันโดยสิ้นเชิง

---

### แนวคิดหลัก (CloudWatch Concepts)

#### 1. Namespaces (พื้นที่ชื่อ)
* ตู้คอนเทนเนอร์สำหรับเก็บ Metrics
* ไม่มี Namespace เริ่มต้น (Default)
* บริการของ AWS ใช้รูปแบบ: `AWS/service`

#### 2. Metrics (ตัวชี้วัด)
* ชุดข้อมูลที่เรียงตามเวลา (Time-ordered set)
* เก็บแยกตามภูมิภาค
* **การหมดอายุ:** ไม่สามารถลบได้ แต่จะหมดอายุอัตโนมัติหลังจาก **15 เดือน** หากไม่มีข้อมูลใหม่ส่งเข้ามา
* **Timestamp:** ระบุเวลาล่วงหน้าได้ 2 ชั่วโมง หรือย้อนหลังได้ 2 สัปดาห์
* **EC2 Metrics:** CloudWatch ไม่ได้เก็บข้อมูลการใช้ Memory และพื้นที่ Disk โดยอัตโนมัติ **ต้องติดตั้ง CloudWatch Agent** ก่อน

#### 3. Dimensions (มิติ)
* คู่ Name/Value ที่ใช้ระบุตัวตนของ Metric (ใส่ได้สูงสุด 10 Dimensions ต่อ 1 Metric)

#### 4. Resolution (ความละเอียด)
* **Standard Resolution:** ข้อมูลราย 1 นาที (ค่าเริ่มต้นของ AWS)
* **High Resolution:** ข้อมูลราย 1 วินาที (Custom Metric เท่านั้น)

#### 5. Statistics (สถิติ)
* **Minimum/Maximum:** ค่าต่ำสุด/สูงสุดในรอบช่วงเวลา
* **Sum:** ผลรวมของข้อมูลทั้งหมด
* **Average:** ค่าเฉลี่ย (Sum / SampleCount)
* **SampleCount:** จำนวนข้อมูลที่นำมาคำนวณ
* **Percentiles (pNN.NN):** ค่าเปอร์เซ็นไทล์ (เช่น p95) ช่วยให้เข้าใจการกระจายตัวของข้อมูลได้ดีขึ้น

### Alarms (การแจ้งเตือน)

เฝ้าดู Metric เดียวในช่วงเวลาที่กำหนด และดำเนินการตามเงื่อนไขที่ตั้งไว้
* **สถานะของ Alarm:**
    * **OK:** ข้อมูลปกติ อยู่ในเกณฑ์
    * **ALARM:** ข้อมูลอยู่นอกเกณฑ์ที่กำหนด
    * **INSUFFICIENT_DATA:** เพิ่งเริ่มทำงาน หรือข้อมูลไม่เพียงพอที่จะระบุสถานะ
* **การตั้งค่าหลัก:**
    * **Period:** ช่วงเวลาประเมินข้อมูล (เป็นวินาที)
    * **Evaluation Period:** จำนวนช่วงเวลาล่าสุดที่นำมาประเมิน
    * **Datapoints to Alarm:** จำนวนจุดข้อมูลที่ต้องละเมิดเกณฑ์เพื่อให้ Alarm ทำงาน

---

### CloudWatch Dashboard (แดชบอร์ด)

หน้าแรกที่ปรับแต่งได้เพื่อดูทรัพยากรทั้งหมดในหน้าเดียว
* **Global:** แดชบอร์ดเป็นแบบ Global ไม่แยกตามภูมิภาค (ดูข้อมูลข้ามภูมิภาคได้)
* ไม่มีการจำกัดจำนวนแดชบอร์ด
* แชร์แดชบอร์ดให้ผู้อื่นที่ไม่มีบัญชี AWS ได้ (ผ่าน Email, Link สาธารณะ หรือ SSO)

---

### CloudWatch Events / Amazon EventBridge

ส่งข้อมูลเหตุการณ์ในระบบแบบ Real-time เมื่อมีการเปลี่ยนแปลงในทรัพยากร AWS
* **Events:** การเปลี่ยนแปลงที่เกิดขึ้น
* **Targets:** ตัวประมวลผลเหตุการณ์ (เช่น Lambda, SNS)
* **Rules:** ตัวจับคู่เหตุการณ์เพื่อส่งไปยัง Target
* *หมายเหตุ:* ปัจจุบันแนะนำให้ใช้ **Amazon EventBridge** ซึ่งพัฒนาต่อยอดมาจาก CloudWatch Events และรองรับแอปภายนอก (SaaS)

---

### CloudWatch Logs (บันทึก)

* **Logs Insights:** ค้นหาและวิเคราะห์ข้อมูล Log ด้วยการเขียน Query
* **Metric Filters:** สร้างตัวกรองเพื่อดึงข้อมูลจาก Log มาสร้างเป็น Metric (ไม่ส่งผลย้อนหลัง)
* **Vended Logs:** Log ที่ AWS ส่งให้ในนามลูกค้า (เช่น VPC Flow Logs)
* **Retention:** โดยค่าเริ่มต้น Log จะถูกเก็บไว้ตลอดไปและไม่มีวันหมดอายุ (ยกเว้นจะตั้งค่าไว้)

---

### CloudWatch Agent

* ใช้เก็บ Log และ Metrics ระดับระบบ (System-level) เพิ่มเติมจาก EC2 หรือเซิร์ฟเวอร์ On-premises
* ต้องทำการติดตั้งลงในเครื่องก่อน

---

### CloudWatch Application Insights

ช่วยวิเคราะห์แอปพลิเคชันและทรัพยากรเพื่อหาสาเหตุของปัญหาโดยอัตโนมัติ
* ใช้ Machine Learning เพื่อตรวจหาความผิดปกติ (Anomalies) และความผิดพลาดของ Log
* เชื่อมต่อกับ **SSM OpsCenter** เพื่อแก้ไขปัญหาได้ทันที

---

### CloudWatch Container Insights

* รวบรวม Metrics และ Logs จากแอปที่รันบน Container (ECS, EKS, Kubernetes บน EC2, Fargate)
* ให้ข้อมูลการวินิจฉัย เช่น Container สั่ง Restart ล้มเหลว

---

### การรักษาความปลอดภัยและการเข้าถึง

* ใช้ IAM Users/Roles ในการยืนยันตัวตน
* ไม่มี ARN เฉพาะเจาะจงสำหรับ CloudWatch ในนโยบาย IAM ให้ใช้เครื่องหมาย `*` (Asterisk) แทนในส่วน Resource

---

### ค่าบริการ (Pricing)

* คิดตามจำนวน Metrics ต่อเดือน
* คิดตามจำนวนการเรียกใช้ API (CloudWatch API calls)
* คิดตามจำนวน Dashboard และ Alarm ต่อเดือน
* คิดตามปริมาณข้อมูล Log (GB) ที่เก็บ, จัดเก็บถาวร และวิเคราะห์
* การส่งข้อมูลเข้า (Data Transfer IN) ฟรี แต่เสียค่าส่งข้อมูลออก (Data Transfer Out)
