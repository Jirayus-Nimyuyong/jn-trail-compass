# Amazon Aurora Cheat Sheet

**Amazon Aurora** เป็นเอนจินฐานข้อมูลเชิงสัมพันธ์แบบ Managed เต็มรูปแบบที่เข้ากันได้กับ **MySQL** และ **PostgreSQL**
* สำหรับบางเวิร์กโหลด Aurora สามารถให้ทรูพุตได้สูงถึง 5 เท่าของ MySQL และ 3 เท่าของ PostgreSQL
* มีระบบจัดเก็บข้อมูลประสิทธิภาพสูง พื้นที่เก็บข้อมูลจะขยายตัวโดยอัตโนมัติตามความต้องการ สูงสุดถึง **128 TiB** (ขั้นต่ำ 10GB)
* Aurora จะอัปเดตฐานข้อมูลให้เป็นเวอร์ชันล่าสุดด้วยแพตช์ใหม่ๆ เสมอ
* รองรับการทำ **Cloning** ที่รวดเร็วและมีประสิทธิภาพ และสามารถแชร์ DB Cluster กับบัญชี AWS อื่นเพื่อการทำ Clone ได้
* Aurora มีความทนทานต่อความผิดพลาด (Fault-tolerant) และสามารถซ่อมแซมตัวเองได้ (Self-healing)

---

## DB Clusters (คลัสเตอร์ฐานข้อมูล)
ประกอบด้วย DB Instance หนึ่งตัวหรือมากกว่า และ Cluster Volume ที่จัดการข้อมูลสำหรับอินสแตนซ์เหล่านั้น



### ประเภทของอินสแตนซ์:
* **Primary DB instance:** รองรับการอ่านและเขียน และทำการแก้ไขข้อมูลทั้งหมดลงใน Cluster Volume มีได้เพียง 1 ตัวต่อคลัสเตอร์
* **Aurora Replica:** เชื่อมต่อกับ Storage Volume เดียวกับตัวหลัก รองรับการอ่านอย่างเดียวเท่านั้น มีได้สูงสุด 15 ตัว ช่วยแบ่งเบาภาระการอ่านและทำหน้าที่เป็นตัวสำรอง (Failover) อัตโนมัติ

---

## จุดเชื่อมต่อของ Aurora (Aurora Endpoints)
* **Cluster endpoint:** เชื่อมต่อกับ Primary instance ปัจจุบัน ใช้สำหรับการเขียนข้อมูล
* **Reader endpoint:** เชื่อมต่อกับ Aurora Replica ที่พร้อมใช้งาน ทำหน้าที่ Load-balancing สำหรับการอ่านข้อมูล
* **Custom endpoint:** ชุดของ DB Instance ที่คุณเลือกเองเพื่อวัตถุประสงค์เฉพาะ
* **Instance endpoint:** เชื่อมต่อโดยตรงกับ DB Instance เฉพาะตัวในคลัสเตอร์ ใช้สำหรับการวินิจฉัยปัญหาประสิทธิภาพ

---

## พื้นที่จัดเก็บและความน่าเชื่อถือ (Storage and Reliability)
* ข้อมูลถูกเก็บไว้ใน **Cluster Volume** ซึ่งทำสำเนาไว้หลายชุดกระจายไปตาม Availability Zones (AZs) ในภูมิภาคเดียว
* **การซ่อมแซมตัวเอง:** หากส่วนใดส่วนหนึ่งของดิสก์ล้มเหลว Aurora จะซ่อมแซมส่วนนั้นทันทีโดยใช้ข้อมูลจากจุดอื่น
* **การกู้คืนที่รวดเร็ว:** ออกแบบมาให้กู้คืนจากเหตุการณ์ระบบล่มได้เกือบจะทันทีและไม่ต้องพึ่งพา Binary Log
* **Dynamic resizing:** ลดพื้นที่จัดเก็บที่จัดสรรไว้โดยอัตโนมัติเมื่อมีการลบข้อมูลออกจากคลัสเตอร์

---

## ความพร้อมใช้งานสูง (High Availability)
* ทำสำเนาข้อมูล **6 ชุดกระจายใน 3 Availability Zones**
* **Failover:** หากอินสแตนซ์หลักเสีย ระบบจะสลับไปใช้ Aurora Replica แทน หรือสร้างอินสแตนซ์ใหม่โดยอัตโนมัติ
* **Backtrack:** ฟีเจอร์ที่ช่วยย้อนเวลาฐานข้อมูลไปยังจุดที่ระบุ (สูงสุด 72 ชั่วโมง) โดยไม่ต้องกู้คืนจาก Backup
* **Backup:** สำรองข้อมูลอัตโนมัติและเก็บข้อมูลไว้ได้นาน 1 ถึง 35 วัน

---

## Aurora Global Database
* ครอบคลุมหลายภูมิภาค (Regions) เพื่อให้การอ่านข้อมูลทั่วโลกมีความหน่วงต่ำและรองรับ Disaster Recovery
* ประกอบด้วยภูมิภาคหลัก (Primary) 1 แห่ง และภูมิภาคสำรอง (Secondary) ที่อ่านได้อย่างเดียว
* สามารถกู้คืนระบบได้ภายในเวลาไม่ถึง 1 นาที แม้ภูมิภาคหลักจะล่มทั้งภูมิภาค (RPO ประมาณ 5 วินาที / RTO น้อยกว่า 1 นาที)

## รูปแบบการติดตั้ง (Configurations)

### 1. Aurora Serverless v2 (แนะนำ)
* **สถาปัตยกรรม:** สเกลได้ทันทีจากหลักร้อยเป็นหลักแสนธุรกรรมภายในเสี้ยววินาที โดยปรับทรัพยากร (Compute/Memory) ในระดับละเอียด
* **ความจุ:** วัดเป็น **Aurora Capacity Units (ACUs)** (0.5 ถึง 128 ACUs)
* **ข้อดี:** รองรับฟีเจอร์ระดับ Enterprise ทั้งหมด เช่น Multi-AZ, Global Database และ Reader Replicas

### 2. Aurora Serverless v1 (รุ่นเก่า)
* *ไม่แนะนำสำหรับแอปพลิเคชันใหม่* เหมาะสำหรับเวิร์กโหลดที่มาเป็นพักๆ หรือคาดการณ์ไม่ได้ มีข้อจำกัดมากกว่า v2 เช่น ไม่รองรับการเชื่อมต่อจากสาธารณะ (ต้องใช้ภายใน VPC เท่านั้น)

## ฟีเจอร์ขั้นสูง (Advanced Features)

* **Aurora Multi Master:** (MySQL 5.6) อนุญาตให้มีอินสแตนซ์ที่เขียนได้มากกว่าหนึ่งตัว กระจายไปตาม AZ ต่างๆ เพื่อให้การเขียนข้อมูลทำงานได้ต่อเนื่องแม้เครื่องใดเครื่องหนึ่งเสีย
* **Aurora PostgreSQL Limitless Database:** ความสามารถในการสเกลในแนวราบ (Sharding) อัตโนมัติ เพื่อรองรับทรูพุตและการจัดเก็บข้อมูลที่เกินขีดจำกัดเดิมของ Aurora
* **Amazon RDS Data API:** เชื่อมต่อผ่าน HTTPS API สำหรับงาน Serverless (เช่น Lambda) โดยไม่ต้องจัดการ Connection Pooling เอง
* **Zero-ETL Integrations:** เชื่อมต่อข้อมูลจาก Aurora ไปยัง **Amazon Redshift** เพื่อการวิเคราะห์แบบเกือบเรียลไทม์โดยไม่ต้องเขียนโปรแกรมย้ายข้อมูลเอง

---

## ความปลอดภัย (Security)
* ใช้ **IAM** ควบคุมการเข้าถึง และใช้ **VPC Security Group** ควบคุมการเชื่อมต่อเครือข่าย
* รองรับการเข้ารหัสข้อมูลขณะจัดเก็บ (Encryption at rest) และการเชื่อมต่อผ่าน TLS/SSL
* **IAM Database Authentication:** ใช้ Token แทนรหัสผ่านในการเชื่อมต่อฐานข้อมูล

---

## การเปรียบเทียบ Aurora Replicas vs MySQL Replicas
| ฟีเจอร์ | Aurora Replicas | MySQL Replicas |
| :--- | :--- | :--- |
| จำนวนสูงสุด | 15 | 5 |
| ประเภทการทำสำเนา | Asynchronous (ระดับมิลลิวินาที) | Asynchronous (ระดับวินาที) |
| ผลกระทบต่อเครื่องหลัก | ต่ำ | สูง |
| การสลับสายงานอัตโนมัติ | ใช่ | ไม่ใช่ |

---

## ค่าบริการ (Pricing)
* คิดค่าบริการตาม **ชั่วโมงอินสแตนซ์, จำนวนคำขอ I/O, พื้นที่เก็บ Backup และการโอนย้ายข้อมูล**
* มีตัวเลือกแบบ **On-Demand** (จ่ายตามจริง) และ **Reserved Instances** (จองล่วงหน้า 1 หรือ 3 ปีเพื่อส่วนลด)
