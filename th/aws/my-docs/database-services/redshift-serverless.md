# Amazon Redshift Serverless Cheat Sheet

**Amazon Redshift Serverless** ช่วยให้ผู้ใช้สามารถรันและปรับขนาดการวิเคราะห์ข้อมูลได้โดยไม่ต้องจัดการโครงสร้างพื้นฐานของคลังข้อมูล (Data Warehouse) โดยระบบจะปรับกำลังการประมวลผล (**Compute Capacity**) ให้สอดคล้องกับโหลดการคิวรีที่ผันผวนโดยอัตโนมัติ เพื่อมอบประสิทธิภาพและความคุ้มค่าสูงสุดสำหรับงานวิเคราะห์ข้อมูล

---

## กรณีการใช้งาน (Use Cases)
* **การวิเคราะห์ข้อมูลที่คาดเดาไม่ได้:** เหมาะสำหรับงานที่มีรูปแบบการใช้งานไม่แน่นอน ซึ่งโซลูชันคลังข้อมูลแบบดั้งเดิมอาจไม่คุ้มทุนหรือไม่สะดวกในการจัดการ
* **Business Intelligence (BI):** รองรับการเชื่อมต่อกับเครื่องมือ BI เช่น Tableau และ Amazon QuickSight เพื่อวิเคราะห์ข้อมูลทั้งแบบเรียลไทม์และข้อมูลย้อนหลัง
* **การวิเคราะห์ Data Lake:** ทำงานร่วมกับ Amazon S3 ได้อย่างราบรื่น ช่วยให้คิวรีชุดข้อมูลขนาดใหญ่ใน Data Lake ผ่าน Redshift Spectrum ได้อย่างมีประสิทธิภาพ
* **กระบวนการ ETL:** มีประสิทธิภาพสูงสำหรับขั้นตอนการสกัด, แปลง และนำเข้าข้อมูล (Extract, Transform, and Load) ช่วยให้วิศวกรข้อมูลจัดการโครงสร้างพื้นฐานน้อยที่สุด

---

## คุณสมบัติเด่น (Features)
* **ไม่ต้องจัดการเซิร์ฟเวอร์:** เข้าถึงและวิเคราะห์ข้อมูลได้โดยไม่ต้องตั้งค่า ปรับจูน หรือจัดการคลัสเตอร์แบบ Provisioned
* **คิวรีข้อมูลข้ามแหล่งเก็บ:** ใช้ความสามารถของ SQL ในการคิวรีข้อมูลได้ทั้งจาก Data Warehouse, Data Lake และฐานข้อมูล Operational
* **การปรับขนาดอัจฉริยะ:** มอบประสิทธิภาพสูงและลดความยุ่งยากด้วยการปรับขนาด (Scaling) อัตโนมัติอัจฉริยะตามความต้องการของงาน
* **การควบคุมต้นทุน:** จัดระเบียบทรัพยากรประมวลผลและข้อมูลด้วย **Workgroups** และ **Namespaces** เพื่อการควบคุมค่าใช้จ่ายที่แม่นยำ
* **จ่ายตามการใช้งานจริง:** คุณเสียค่าใช้จ่ายเฉพาะช่วงเวลาที่มีการใช้งานคลังข้อมูลเท่านั้น

---

## ส่วนประกอบหลัก (Components)
* **Namespace:** คอนเทนเนอร์เชิงตรรกะที่เก็บการตั้งค่าฐานข้อมูล, Workgroups และรายละเอียดการกำหนดค่าต่างๆ ทำหน้าที่เป็นหน่วยกลางในการจัดการทรัพยากร
* **Workgroup:** กลุ่มของทรัพยากรประมวลผลที่ทำหน้าที่รันคิวรี สามารถกำหนดค่าความจุพื้นฐาน (Base Capacity) และตัวเลือกการปรับขนาดเพื่อให้ตรงตามความต้องการของงาน
* **Data Lake Integration:** ช่วยให้คิวรีข้อมูลใน Amazon S3 ผ่าน Redshift Spectrum ได้โดยไม่ต้องโหลดข้อมูลลงใน Redshift

---

## การตรวจสอบ (Monitoring)
* **CloudWatch Metrics:** ให้รายละเอียดด้านประสิทธิภาพ, การใช้ทรัพยากร และสุขภาพของระบบ เช่น ความหน่วงของคิวรี (Query Latency), การใช้ CPU และปริมาณการใช้พื้นที่เก็บข้อมูล
* **Audit Logging:** บันทึกกิจกรรมของผู้ใช้และการเปลี่ยนแปลงในฐานข้อมูล เพื่อใช้ในการตรวจสอบการปฏิบัติตามกฎระเบียบ (Compliance) และการแก้ไขปัญหา
* **Query Monitoring:** หน้าคอนโซลของ Redshift มีเครื่องมือวิเคราะห์ประสิทธิภาพคิวรี เพื่อระบุคิวรีที่ทำงานช้าและปรับแต่งเวิร์กโหลดให้ดีขึ้น

---

## ความปลอดภัย (Security)
* **การเข้ารหัส:** ข้อมูลที่จัดเก็บ (At rest) จะถูกเข้ารหัสด้วย AWS KMS และข้อมูลระหว่างรับ-ส่ง (In transit) สามารถเข้ารหัสด้วย SSL เพื่อรักษาความถูกต้องและเป็นความลับของข้อมูล
* **การควบคุมการเข้าถึง:** ใช้นโยบาย IAM เพื่อกำหนดสิทธิ์การเข้าถึงที่ละเอียดถี่ถ้วน มั่นใจได้ว่าเฉพาะผู้ที่ได้รับอนุญาตเท่านั้นที่จะเข้าถึงข้อมูลสำคัญได้
* **เครือข่ายส่วนตัว:** ติดตั้งภายใน VPC เพื่อแยกส่วนเครือข่ายและควบคุมการเข้าถึงให้ปลอดภัย
* **มาตรฐานสากล:** ปฏิบัติตามมาตรฐานอุตสาหกรรม เช่น HIPAA, GDPR และ SOC เพื่อความปลอดภัยและความเป็นส่วนตัวของข้อมูล

---

## ค่าบริการ (Pricing)
* **กำลังประมวลผล:** คิดค่าบริการตามจำนวน **Redshift Processing Units (RPUs)** ต่อชั่วโมง ซึ่งจะปรับขนาดขึ้นลงตามความต้องการของงาน
* **พื้นที่จัดเก็บ:** จ่ายตามปริมาณข้อมูลที่จัดเก็บในสภาพแวดล้อม Serverless ซึ่งครอบคลุมทั้งข้อมูลใน S3 และพื้นที่จัดเก็บที่ Redshift จัดการ (Managed Storage)
* **การถ่ายโอนข้อมูล:** การรับส่งข้อมูลระหว่าง Redshift Serverless กับบริการอื่นๆ ของ AWS หรืออินเทอร์เน็ตอาจมีค่าธรรมเนียมเพิ่มเติม (ปกติการรับส่งภายใน Region เดียวกันจะไม่มีค่าใช้จ่าย)
