# Amazon RDS Cheat Sheet

**Amazon RDS** เป็นบริการฐานข้อมูลเชิงสัมพันธ์ (Relational Database) มาตรฐานอุตสาหกรรม
* RDS จัดการเรื่องการสำรองข้อมูล, การติดตั้งแพตช์ซอฟต์แวร์, การตรวจจับความล้มเหลวอัตโนมัติ และการกู้คืนระบบ
* คุณสามารถตั้งค่าการสำรองข้อมูลอัตโนมัติหรือสร้าง Snapshot ด้วยตัวเองเพื่อใช้ในการกู้คืนฐานข้อมูล
* **เอนจินที่รองรับ:** Aurora, MySQL, MariaDB, PostgreSQL, Oracle, และ Microsoft SQL Server
* **ความพร้อมใช้งานสูง (High Availability):** ใช้การติดตั้งแบบ Multi-AZ (มีเครื่องหลักและเครื่องสำรองที่ซิงค์ข้อมูลกัน) และใช้ Read Replicas เพื่อขยายประสิทธิภาพการอ่าน

---

## ส่วนประกอบพื้นฐาน
* **DB Instance:** สภาพแวดล้อมฐานข้อมูลที่แยกส่วนกันบนคลาวด์ (จำกัดสูงสุด 40 อินสแตนซ์ต่อบัญชี)
* **DB Engine:** ซอฟต์แวร์ฐานข้อมูลที่รันบนอินสแตนซ์
* **DB Instance Class:** กำหนดกำลังการประมวลผลและหน่วยความจำ (CPU/RAM)
* **Multi-AZ Deployment:** ระบบจะสร้างเครื่อง Standby ไว้ใน Availability Zone (AZ) อื่นโดยอัตโนมัติ และซิงค์ข้อมูลแบบ Synchronous เพื่อป้องกันข้อมูลสูญหายและช่วยในการ Failover



---

## รายละเอียดของแต่ละเอนจิน (DB Engines)

### MySQL / MariaDB / PostgreSQL
* รองรับพื้นที่จัดเก็บสูงสุด **64 TiB** และประสิทธิภาพ IOPS สูงสุด **80,000 IOPS**
* **MySQL:** แนะนำให้ใช้เอนจิน InnoDB เพื่อรองรับการกู้คืนข้อมูลแบบ Point-in-time และรองรับปลั๊กอิน `validate_password` เพื่อความปลอดภัยของรหัสผ่าน
* **PostgreSQL:** รองรับฟีเจอร์ autovacuum เพื่อรักษาประสิทธิภาพของฐานข้อมูล

### Microsoft SQL Server
* รองรับโมเดลใบอนุญาตทั้งแบบ "License Included" (สูงสุด 10 เครื่อง) และ "BYOL" (สูงสุด 40 เครื่อง)
* **ข้อจำกัดจำนวนฐานข้อมูล:** ขึ้นอยู่กับ Class และโหมดความพร้อมใช้งาน (สูงสุด 100 ฐานข้อมูลต่ออินสแตนซ์)
* **Multi-AZ:** ใช้ฟีเจอร์ Mirroring หรือ Always On Availability Groups (AGs)

### Oracle
* รองรับพื้นที่จัดเก็บสูงสุด **64 TiB**
* `Database name` จะถูกนำไปใช้ตั้งค่าเป็น `ORACLE_SID`
* รองรับการจัดการรหัสผ่าน Master User ผ่าน **AWS Secrets Manager**

## พื้นที่จัดเก็บข้อมูล (Storage)
RDS ใช้ Amazon EBS เป็นพื้นฐานในการจัดเก็บข้อมูล แบ่งเป็น 3 ประเภท:
1. **General Purpose SSD (gp2/gp3):** เหมาะสำหรับเวิร์กโหลดทั่วไป ขนาด 20 GiB – 64 TiB
2. **Provisioned IOPS SSD (io1):** ออกแบบมาสำหรับงาน OLTP ที่ต้องการประสิทธิภาพ I/O สูงและคาดการณ์ได้ (สูงสุด 80,000 IOPS)
3. **Magnetic (รุ่นเก่า):** จำกัดขนาดที่ 3 TiB และความเร็ว 1,000 IOPS ไม่รองรับการขยายขนาดแบบยืดหยุ่น

## คุณสมบัติการจัดการที่สำคัญ

### Storage Auto Scaling
ปรับเพิ่มความจุพื้นที่จัดเก็บโดยอัตโนมัติเมื่อข้อมูลใกล้เต็ม โดยไม่มีช่วงเวลาที่ระบบหยุดทำงาน (Zero Downtime)

### Blue/Green Deployments
สร้างสภาพแวดล้อมจำลอง (Green) เพื่อทดสอบการอัปเดตหรือการเปลี่ยนแปลงก่อนนำไปใช้กับสภาพแวดล้อมจริง (Blue) เพื่อความปลอดภัยสูงสุด

### RDS Proxy
ตัวกลางจัดการ Connection Pool ช่วยให้แอปพลิเคชันสเกลได้ดีขึ้น ทนทานต่อการล้มเหลวของฐานข้อมูล และลดภาระการใช้ CPU/RAM ของฐานข้อมูลจากการเชื่อมต่อจำนวนมาก

## ความปลอดภัย (Security)
* **Security Groups:** ใช้ VPC Security Group ควบคุมทราฟฟิกในระดับเครือข่าย
* **IAM Database Authentication:** รองรับใน MySQL และ PostgreSQL (ใช้ Token แทนรหัสผ่าน)
* **การเข้ารหัส (Encryption):** รองรับทั้งขณะจัดเก็บ (At rest) โดยใช้ **AWS KMS** และขณะรับ-ส่ง (In-transit) โดยใช้ **SSL/TLS**
* **Deletion Protection:** ป้องกันไม่ให้ผู้ใช้ลบฐานข้อมูลโดยไม่ตั้งใจ

---

## ความพร้อมใช้งานและการขยายขนาด (HA & Scaling)

### Multi-AZ (High Availability)
* ข้อมูลถูกคัดลอกแบบ **Synchronous**
* สลับสายงาน (Failover) อัตโนมัติเมื่อ AZ ล่ม, เครื่องหลักเสีย หรือมีการเปลี่ยนประเภทเครื่อง
* **เป้าหมาย:** เพื่อความทนทานของข้อมูล (Data Durability)

### Read Replicas (Scaling)
* ข้อมูลถูกคัดลอกแบบ **Asynchronous**
* ใช้เพื่อขยายประสิทธิภาพการอ่าน (Read Scaling) โดยแยกโหลดการอ่านออกจากเครื่องหลัก
* สามารถยกฐานะ (Promote) ขึ้นเป็นเครื่องหลักแบบ Standalone ได้

## การตรวจสอบและติดตาม (Monitoring)
* **Amazon CloudWatch:** ดูมาตรวัดทั่วไป เช่น CPU, Memory
* **Enhanced Monitoring:** ดูรายละเอียดในระดับระบบปฏิบัติการ (OS) เช่น IOPS, Latency, Throughput และ Queue Depth
* **Performance Insights:** วิเคราะห์ภาระงานของฐานข้อมูลเพื่อระบุคิวรีที่ทำให้ระบบช้า (AWS แนะนำให้เตรียมอัปเกรดเป็น **Database Insights** ภายในปลายปี 2025)

---

## ค่าบริการ (Pricing)
* จ่ายตามการใช้งานจริง (ชั่วโมงอินสแตนซ์, พื้นที่จัดเก็บ, จำนวน I/O, และการถ่ายโอนข้อมูล)
* **ตัวเลือกการซื้อ:**
    * **On-Demand:** จ่ายรายชั่วโมง/วินาที ตามการใช้งาน
    * **Reserved Instances:** จองล่วงหน้า 1 หรือ 3 ปี เพื่อรับส่วนลดสูงสุด
* มีขั้นต่ำในการเรียกเก็บเงิน 10 นาทีเมื่อสร้าง, กู้คืน หรือเริ่มอินสแตนซ์ใหม่

---

## แนวทางปฏิบัติที่ดี (Best Practices)
* ตรวจสอบ CPU, Memory และ Storage อย่างสม่ำเสมอ
* เปิดใช้งานสำรองข้อมูลอัตโนมัติ (Automated Backups)
* ตั้งค่า DNS TTL ให้ต่ำกว่า 30 วินาที เพื่อให้แอปพลิเคชันหาเครื่องใหม่เจอทันทีหลังเกิด Failover
* ทดสอบการ Failover เป็นระยะเพื่อให้มั่นใจในแผนกู้คืนระบบ
