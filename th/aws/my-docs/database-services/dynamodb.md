# Amazon DynamoDB Cheat Sheet

**Amazon DynamoDB** เป็นบริการฐานข้อมูลแบบ NoSQL ที่ให้ประสิทธิภาพที่รวดเร็วและคาดการณ์ได้ พร้อมการสเกลที่ราบรื่น
* รองรับการเข้ารหัสข้อมูลขณะจัดเก็บ (Encryption at rest)
* สามารถสร้างตารางเพื่อจัดเก็บและดึงข้อมูลปริมาณเท่าใดก็ได้ และรองรับทราฟฟิกคำขอในทุกระดับ
* ปรับเพิ่มหรือลดกำลังการผลิต (Throughput) ได้โดยไม่มีช่วงเวลาที่ระบบหยุดทำงาน (Downtime)
* มีระบบสำรองข้อมูลแบบ On-demand และการกู้คืนย้อนหลังตามจุดเวลา (**Point-in-time recovery**) ย้อนหลังได้สูงสุด **35 วัน**
* ข้อมูลถูกจัดเก็บใน **Partition** บน SSD และทำสำเนาอัตโนมัติข้ามหลาย AZ ภายใน Region
* **Global Tables:** รองรับการทำสำเนาข้อมูลข้าม Region แบบ Multi-master writes อัตโนมัติ

---

## ส่วนประกอบหลัก (Core Components)

### 1. Tables (ตาราง)
* เป็นกลุ่มของรายการข้อมูล (Items) และเป็นแบบ Schemaless (ไม่ต้องกำหนดโครงสร้างล่วงหน้า)
* ค่าเริ่มต้นจำกัดที่ 256 ตารางต่อภูมิภาค (Region)
* **Console-to-Code:** ฟีเจอร์ที่ช่วยแปลงขั้นตอนการสร้างตารางในหน้า Console ให้เป็นโค้ด IaC (CDK, CloudFormation, Python)

### 2. Items และ Attributes
* **Items:** คือแถวข้อมูล (เปรียบได้กับ Row ใน SQL)
* **Attributes:** คือองค์ประกอบพื้นฐานของข้อมูล (เปรียบได้กับ Column) รองรับการซ้อนกัน (Nested) ได้ลึกสูงสุด 32 ระดับ

### 3. Primary Key (คีย์หลัก)
* **Partition Key:** คีย์เดี่ยวที่ใช้ในการกระจายข้อมูลลงใน Partition ผ่านฟังก์ชัน Hash
* **Composite Primary Key:** ประกอบด้วย **Partition Key** และ **Sort Key** ข้อมูลที่มี Partition Key เดียวกันจะถูกเก็บไว้ด้วยกันและเรียงลำดับตาม Sort Key

### 4. Secondary Indexes (ดัชนีรอง)
ช่วยให้คิวรีข้อมูลด้วยคีย์อื่นนอกเหนือจากคีย์หลัก:
* **Global Secondary Index (GSI):** มี Partition Key และ Sort Key ที่ต่างจากตารางหลัก (สร้างได้สูงสุด 20 index ต่อตาราง)
* **Local Secondary Index (LSI):** มี Partition Key เหมือนตารางหลัก แต่ใช้ Sort Key ต่างกัน (สร้างได้สูงสุด 5 index ต่อตาราง)

### 5. DynamoDB Streams
* บันทึกการเปลี่ยนแปลงข้อมูลในตาราง (เพิ่ม, แก้ไข, ลบ)
* บันทึก (Stream records) มีอายุ 24 ชั่วโมง
* มักใช้คู่กับ **AWS Lambda** เพื่อสร้าง **Trigger** ให้ทำงานอัตโนมัติเมื่อข้อมูลเปลี่ยน

## รูปแบบการจัดการความจุ (Throughput Management)

1.  **Provisioned Capacity:** กำหนดค่าสูงสุดที่แอปพลิเคชันจะใช้เอง (รองรับ Auto Scaling) เหมาะสำหรับงานที่ทราฟฟิกนิ่งหรือคาดเดาได้
2.  **On-Demand Capacity:** จ่ายตามจริงตามจำนวน Request เหมาะสำหรับงานที่ทราฟฟิกไม่แน่นอน (ปรับเปลี่ยนโหมดได้สูงสุด 4 ครั้งต่อ 24 ชั่วโมง)



### หน่วยวัดความจุ (Capacity Units)
* **Read Capacity Unit (RCU):** 1 RCU = อ่านแบบ Strongly Consistent ได้ 1 ครั้ง/วินาที หรือแบบ Eventually Consistent ได้ 2 ครั้ง/วินาที (สำหรับ Item ขนาดไม่เกิน 4 KB)
* **Write Capacity Unit (WCU):** 1 WCU = เขียนได้ 1 ครั้ง/วินาที (สำหรับ Item ขนาดไม่เกิน 1 KB)

---

## การคิวรีและการสแกน (Query vs Scan)
* **Query:** ค้นหาข้อมูลโดยใช้คีย์หลัก ให้ประสิทธิภาพสูงและเจาะจง ข้อมูลที่ดึงได้สูงสุด 1 MB ต่อรอบ
* **Scan:** อ่านข้อมูล**ทุกรายการ**ในตารางหรือดัชนี มีค่าใช้จ่ายสูงและช้ากว่าหากตารางมีขนาดใหญ่

---

## Global Tables
* โซลูชันฐานข้อมูลแบบ Multi-region และ Multi-master
* **Multi-Region Strong Consistency (MRSC):** รองรับการอ่านแบบ Strongly Consistent ข้าม Region เมื่อใช้งาน 3 Region (หรือ 2 Region + 1 Witness)
* ใช้กฎ "Last writer wins" ในการจัดการเมื่อมีการเขียนข้อมูลชนกัน

---

## DynamoDB Accelerator (DAX)
* เป็น In-memory cache สำหรับ DynamoDB แบบ Managed เต็มรูปแบบ
* ช่วยลดเวลาตอบสนองจากมิลลิวินาทีเหลือเพียง **ไมโครวินาที**
* **กรณีใช้งาน:** แอปที่ต้องการการอ่านเร็วที่สุด, แอปที่มีข้อมูลบางตัวถูกอ่านบ่อยมาก (Hot keys), หรือแอปที่ต้องการลดค่า RCU ในตารางหลัก



---

## คุณสมบัติพิเศษอื่นๆ
* **Time To Live (TTL):** กำหนดเวลาหมดอายุให้ข้อมูลลบตัวเองโดยอัตโนมัติ
* **Transactions:** รองรับ ACID (Atomicity, Consistency, Isolation, Durability) สำหรับการจัดการหลาย Item พร้อมกัน (สูงสุด 25 Item หรือ 4 MB ต่อคำขอ)
* **Conditional Writes:** การเขียนข้อมูลจะสำเร็จก็ต่อเมื่อตรงตามเงื่อนไขที่กำหนดเท่านั้น

---

## แนวทางปฏิบัติที่ดี (Best Practices)
* **การออกแบบ NoSQL:** เน้นออกแบบตาม "รูปแบบการเข้าถึง" (Access Patterns) ไม่ใช่แค่การ Normalize ข้อมูลเหมือน SQL
* **Single Table Design:** แอปพลิเคชันที่ออกแบบมาดีมักจะใช้เพียง **ตารางเดียว**
* **Partition Key:** เลือกคีย์ที่มีความหลากหลายสูง (High Cardinality) เพื่อเลี่ยงปัญหา "Hot Partition" (Partition ที่ถูกใช้งานหนักเกินไปเครื่องเดียว)
* **Adaptive Capacity:** DynamoDB จะช่วยปรับสมดุลทราฟฟิกให้โดยอัตโนมัติเพื่อรับมือกับทราฟฟิกที่ไม่สม่ำเสมอ

---

## ค่าบริการ (Pricing)
* คิดตามปริมาณพื้นที่จัดเก็บ (25 GB แรกฟรี)
* คิดตามหน่วยความจุ (WCU/RCU) สำหรับแบบ Provisioned หรือตามจำนวน Request สำหรับแบบ On-demand
* มีค่าใช้จ่ายเพิ่มเติมสำหรับฟีเจอร์เสริม เช่น DAX, Global Tables, Backups, Streams และการโอนข้อมูลออก

---
