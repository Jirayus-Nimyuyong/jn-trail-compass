# Amazon Redshift Cheat Sheet

**Amazon Redshift** เป็นบริการคลังข้อมูล (Data Warehouse) แบบ Managed เต็มรูปแบบที่รองรับข้อมูลระดับ **Petabyte**
* Redshift ขยายการคิวรีคลังข้อมูลไปยัง Data Lake ของคุณได้ คุณสามารถรันการคิวรีวิเคราะห์ข้อมูลระดับ Petabyte ที่เก็บไว้ใน Redshift และขยายไปถึงระดับ Exabyte ใน S3 ได้โดยตรง
* Redshift เป็นฐานข้อมูลประเภท **OLAP** (Online Analytical Processing)
* รองรับการติดตั้งทั้งแบบ **Single-AZ** และ **Multi-AZ** (สำหรับคลัสเตอร์ RA3) รวมถึงมีตัวเลือกแบบ **Serverless** ที่ปรับขนาดความจุอัตโนมัติ

---

## คุณสมบัติเด่น (Features)
* **ประสิทธิภาพ:** ใช้การจัดเก็บข้อมูลแบบคอลัมน์ (**Columnar Storage**), การบีบอัดข้อมูล และ Zone Maps เพื่อลดปริมาณ I/O ในการคิวรี
* **Massively Parallel Processing (MPP):** ใช้สถาปัตยกรรมแบบขนานเพื่อกระจายการทำงาน SQL ไปยังโหนดต่างๆ
* **Result Caching:** ใช้การแคชผลลัพธ์เพื่อให้การคิวรีซ้ำๆ ตอบสนองได้เร็วในระดับต่ำกว่าวินาที
* **Multi-AZ Deployments:** สำหรับคลัสเตอร์ RA3 จะมีการวางโหนดในหลาย AZ (Active-Active) เพื่อให้ได้ค่า **RPO เป็นศูนย์** และ RTO ที่ต่ำลง
* **Zero-ETL Integrations:** วิเคราะห์ข้อมูลจาก **Amazon Aurora** และ **Amazon DynamoDB** ได้เกือบเรียลไทม์โดยไม่ต้องสร้าง Pipeline ETL ที่ซับซ้อน
* **Redshift Query Editor v2:** เครื่องมือ SQL บนเว็บที่รองรับการเขียน Notebook และใช้ **Amazon Q** (Generative SQL) เพื่อเขียนคิวรีด้วยภาษาธรรมชาติ

## ตัวเลือกการติดตั้ง (Deployment Options)

### 1. Amazon Redshift Serverless
* ปรับขนาดความจุ (RPUs) อัตโนมัติภายในไม่กี่วินาทีตามความต้องการของงาน
* **กรณีใช้งาน:** งานที่โหลดไม่แน่นอนหรือคาดเดายาก เหมาะสำหรับการเริ่มโปรเจกต์วิเคราะห์ใหม่ๆ ได้ง่าย
* **การคิดเงิน:** จ่ายตามวินาทีสำหรับกำลังประมวลผล (RPU) และพื้นที่จัดเก็บ (RMS)

### 2. Amazon Redshift Provisioned (กำหนดเอง)
* **RA3 Nodes (แนะนำ):** ใช้ **Redshift Managed Storage (RMS)** แยกส่วนประมวลผลออกจากพื้นที่จัดเก็บ ทำให้สเกลแยกกันได้ ข้อมูลจะถูกแคชไว้ใน SSD ประสิทธิภาพสูงและสำรองลง S3 อัตโนมัติ
* **DC2 Nodes:** ปรับแต่งมาเพื่อเน้นการประมวลผล (Compute-optimized) สำหรับชุดข้อมูลขนาดเล็กที่ต้องการความหน่วงต่ำ

---

## ส่วนประกอบของคลัสเตอร์ (Components)
* **Leader Node:** รับคิวรีจากแอปพลิเคชัน, วางแผนการทำงาน (Execution Plans) และประสานงานกับ Compute Nodes ก่อนจะสรุปผลส่งกลับให้ลูกค้า
* **Compute Nodes:** รันแผนการคิวรีและรับส่งข้อมูลระหว่างกันเพื่อประมวลผล
* **Cluster Subnet Group:** ใช้กำหนดชุดของ Subnet ใน VPC สำหรับการสร้างคลัสเตอร์
* **Maintenance Window:** ช่วงเวลาบำรุงรักษา 30 นาทีต่อสัปดาห์ (ระบบจะสุ่มเวลาให้) ซึ่งในช่วงนี้คลัสเตอร์จะไม่สามารถใช้งานได้ตามปกติ

---

## ตัวเลือกการคิวรีและรับส่งข้อมูล (Data Options)

* **Redshift Spectrum:** รันคิวรีข้อมูลระดับ Exabyte ใน S3 ได้โดยไม่ต้องโหลดข้อมูลเข้า Redshift รองรับฟอร์แมต Apache Iceberg, Delta Lake และ Hudi
* **Streaming Ingestion:** รับข้อมูลโดยตรงจาก **Amazon Kinesis** หรือ **MSK** (Kafka) เข้าสู่ Redshift ด้วย SQL โดยไม่ต้องพักข้อมูลใน S3 ทำให้ได้ความเร็วสูงและความหน่วงต่ำ
* **Redshift ML:** สร้างและใช้งานโมเดล Machine Learning โดยใช้คำสั่ง SQL ง่ายๆ (CREATE MODEL) โดยมี **Amazon SageMaker** ทำงานอยู่เบื้องหลัง
* **Data Sharing:** แชร์ข้อมูลที่สอดคล้องกันข้ามคลัสเตอร์, ข้ามบัญชี และข้ามภูมิภาคได้โดยไม่ต้องคัดลอกข้อมูล

---

## การสำรองข้อมูล (Cluster Snapshots)
* **Automated Snapshots:** สำรองข้อมูลอัตโนมัติทุก 8 ชั่วโมง หรือเมื่อข้อมูลเปลี่ยนไป 5 GB ต่อโหนด โดยเก็บไว้ใน S3
* **Manual Snapshots:** สร้างด้วยมือและจะถูกเก็บไว้ตลอดไปจนกว่าจะลบ (แม้ลบคลัสเตอร์ไปแล้วก็ตาม)
* **Cross-Region Copy:** ตั้งค่าให้คัดลอก Snapshot ไปยังภูมิภาคอื่นอัตโนมัติเพื่อใช้ในการกู้คืนจากภัยพิบัติ (Disaster Recovery)

---

## ความปลอดภัยและการตรวจสอบ (Security & Monitoring)
* **การควบคุมการเข้าถึง:** ใช้ **IAM** จัดการสิทธิ์ และใช้ **VPC Security Group** ควบคุมการเข้าถึงระดับเครือข่าย
* **การเข้ารหัส:** สามารถเลือกเข้ารหัสคลัสเตอร์ได้ในตอนสร้าง (Snapshot ที่สร้างจากคลัสเตอร์ที่เข้ารหัสก็จะถูกเข้ารหัสด้วย)
* **Audit Logging:** ติดตามการล็อกอิน, การเชื่อมต่อ และการรันคิวรีในฐานข้อมูล โดยเก็บ Log ไว้ใน S3
* **CloudWatch:** ติดตามประสิทธิภาพ เช่น CPU Utilization, Latency และทรูพุต

---

## ค่าบริการ (Pricing)
* **Provisioned:** จ่ายรายวินาทีตามประเภทและจำนวนโหนด (สามารถจองแบบ 1 หรือ 3 ปีเพื่อลดค่าใช้จ่าย)
* **Serverless:** จ่ายตามกำลังประมวลผล (RPU) ต่อวินาที และพื้นที่จัดเก็บที่ใช้
* **Spectrum:** จ่ายตามปริมาณข้อมูล (Bytes) ที่ถูกสแกนใน S3
