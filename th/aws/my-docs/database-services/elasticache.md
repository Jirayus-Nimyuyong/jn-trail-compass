# Amazon ElastiCache Cheat Sheet

**ElastiCache** เป็นสภาพแวดล้อมระบบจัดการการแคชในหน่วยความจำ (In-memory cache) แบบกระจายตัวบน AWS Cloud ทำงานร่วมกับเอนจิน **Valkey**, **Redis** และ **Memcached**

---

## ส่วนประกอบ (Components)
* **ElastiCache Nodes:** หน่วยประมวลผลขนาดคงที่ซึ่งเป็น RAM ที่เชื่อมต่อกับเครือข่ายปลอดภัย แต่ละโหนดรันเอนจินและประเภทอินสแตนซ์เดียวกัน และมีชื่อ DNS และพอร์ตของตัวเอง
* **การใช้งาน:** มักใช้สำหรับจัดเก็บสถานะเซสชัน (Session state)

---

## รูปแบบการติดตั้ง (Deployment Options)
1. **Serverless (ไร้เซิร์ฟเวอร์):** จัดการง่ายที่สุด ปรับขนาดอัตโนมัติทั้งแนวตั้งและแนวนอนตามความต้องการ ไม่ต้องจัดการความจุเอง เหมาะกับงานที่คาดเดาปริมาณทราฟฟิกไม่ได้
2. **Self-Designed (Provisioned):** คุณเลือกประเภทโหนด ขนาด และจำนวนเอง ต้องวางแผนความจุเอง เหมาะกับงานที่คาดเดาโหลดได้และต้องการการควบคุมที่ละเอียด

---

## Amazon ElastiCache for Redis
แอปพลิเคชันเดิมที่ใช้ Redis สามารถเปลี่ยนมาใช้ ElastiCache ได้โดยแทบไม่ต้องแก้ไขโค้ด

### คุณสมบัติเด่น
* ตรวจสอบและกู้คืนโหนดที่เสียโดยอัตโนมัติ
* **Multi-AZ:** สลับสายงานอัตโนมัติ (Failover) จากเครื่องหลักไปยังเครื่องสำรอง (Read Replica)
* รองรับการเข้ารหัสข้อมูลทั้งขณะรับ-ส่ง (In-transit) และขณะจัดเก็บ (At-rest) เพื่อสร้างแอปพลิเคชันตามมาตรฐาน HIPAA
* ข้อมูลมีความคงทน (Persistent) และใช้เป็นฐานข้อมูลหลัก (Datastore) ได้
* **Redis Shard:** กลุ่มของโหนด (1-6 โหนด) โดยในโหมด Cluster Mode Enabled สามารถมีได้สูงสุด 500 โหนดต่อคลัสเตอร์

### ตารางเปรียบเทียบ Redis (Cluster Mode Disabled vs Enabled)
| คุณสมบัติ | Cluster Mode Disabled | Cluster Mode Enabled |
| :--- | :---: | :---: |
| จำนวน Shards | 1 | 1-90 (สูงสุด 500 โหนด) |
| การแบ่งส่วนข้อมูล (Partitioning) | ไม่รองรับ | รองรับ |
| การเพิ่ม/ลด Node Groups | ไม่รองรับ | รองรับ |
| สลับสายงานอัตโนมัติ (Multi-AZ) | ไม่บังคับ (แต่ควรมี) | บังคับใช้งาน |
| จุดเชื่อมต่อ (Endpoints) | มี Primary และ Read Endpoint | มี Configuration Endpoint ตัวเดียว |

## Amazon ElastiCache for Valkey (ใหม่!)
* **Valkey:** เป็นตัวเลือก Open-source ประสิทธิภาพสูงที่ใช้แทน Redis OSS ได้ทันที (ดูแลโดย Linux Foundation)
* **Multi-threaded I/O:** ให้ทรูพุตสูงขึ้นสูงสุด ~230% และความหน่วงต่ำลงสูงสุด ~70% เมื่อเทียบกับ Redis รุ่นก่อน
* **ความเข้ากันได้:** รองรับคำสั่งและโครงสร้างข้อมูลเดียวกับ Redis OSS ทำให้ย้ายระบบได้ง่ายและมีความเสี่ยงต่ำ

## Amazon ElastiCache for Memcached
* เน้นความง่าย (Simplicity) และการรันโหนดขนาดใหญ่ที่มีหลายคอร์หรือหลายเธรด
* **Auto Discovery:** แอปพลิเคชันสามารถค้นหาโหนดทั้งหมดในคลัสเตอร์ได้โดยอัตโนมัติ
* **ข้อจำกัด:** ข้อมูลไม่คงทน (ไม่ Persistent), ไม่รองรับ Multi-AZ Failover, ไม่รองรับการทำ Replication และไม่รองรับ Snapshot

---

## กลยุทธ์การแคช (Caching Strategies)
1. **Lazy Loading:** โหลดข้อมูลเข้าแคชเฉพาะเมื่อมีการเรียกใช้ ข้อดีคือแคชเฉพาะสิ่งที่ใช้จริง แต่ข้อเสียคือมีช่วงเวลาที่หาข้อมูลในแคชไม่เจอ (Cache miss) ในครั้งแรก
2. **Write Through:** อัปเดตข้อมูลในแคชทุกครั้งที่มีการเขียนลงฐานข้อมูล ข้อมูลจะใหม่เสมอแต่จะเพิ่มความหน่วงในตอนเขียน (Write penalty)
* **คำแนะนำ:** ควรใช้ค่า **Time to Live (TTL)** ร่วมกับทั้งสองวิธีเพื่อล้างข้อมูลที่ไม่ได้ใช้งานออก

---

## การตรวจสอบ (Monitoring)
* **CloudWatch Metrics:** ตรวจสอบสุขภาพโหนดทุกๆ 60 วินาที
* **ElastiCache Events:** แจ้งเตือนผ่าน SNS เมื่อเกิดเหตุการณ์สำคัญ เช่น การเพิ่มโหนดสำเร็จหรือล้มเหลว
* **Tags:** ใช้สำหรับติดตามค่าใช้จ่าย

---

## ตารางเปรียบเทียบ Redis vs Memcached
| คุณสมบัติ | Redis | Memcached |
| :--- | :--- | :--- |
| ประเภทข้อมูล | หลากหลาย (Strings, Lists, Sets, Hashes, ฯลฯ) | Strings, Objects |
| ความคงทน (Persistence) | รองรับ | ไม่รองรับ |
| การสำรอง/กู้คืน (Backup/Restore) | รองรับ | ไม่รองรับ |
| การสลับสายงาน (Failover) | รองรับ (Multi-AZ) | ไม่รองรับ |
| เธรด (Threading) | Single-threaded | Multi-threaded |
| **กรณีใช้งาน** | ต้องการโครงสร้างข้อมูลซับซ้อน, ต้องจัดลำดับ (Sorting), ต้องการสำรองข้อมูล | ต้องการความง่ายที่สุด, ต้องการความเร็วในการสเกลเข้า-ออก |

## ค่าบริการ (Pricing)
* **On-demand:** จ่ายรายชั่วโมงตามทรัพยากรที่ใช้จริง
* **Reserved Nodes:** จ่ายล่วงหน้า (1 หรือ 3 ปี) เพื่อรับส่วนลดสูงสุด
* **Snapshot:** ฟรีพื้นที่เก็บ Snapshot 1 ชุดต่อหนึ่งคลัสเตอร์ Redis ที่ใช้งานอยู่
* **Data Transfer:** มีค่าบริการโอนย้ายข้อมูลข้าม Availability Zones
