# Amazon MemoryDB for Redis Cheat Sheet

**Amazon MemoryDB** เป็นบริการฐานข้อมูลแบบ In-memory สำหรับแอปพลิเคชันที่ใช้สถาปัตยกรรม Microservices เข้ากันได้กับ **Redis OSS** และ **Valkey**
* MemoryDB จัดเก็บข้อมูลทั้งหมดไว้ในหน่วยความจำ (In-memory) ช่วยให้คุณบรรลุความหน่วงในการอ่านระดับไมโครวินาที (Microsecond) และความหน่วงในการเขียนระดับมิลลิวินาทีเลขหลักเดียว (Single-digit millisecond) พร้อมทรูพุตที่สูง
* ใช้ Transactional log แบบ Multi-AZ เพื่อจัดเก็บข้อมูลกระจายไปหลาย AZ เพื่อรองรับการทำ Failover ที่รวดเร็ว, การกู้คืนฐานข้อมูล และการรีสตาร์ทโหนดใหม่
* **เอนจินที่รองรับ:**
    * **Redis OSS:** เข้ากันได้กับ Redis Open-source อย่างสมบูรณ์
    * **Valkey:** เอนจินแบบ Open-source ประสิทธิภาพสูง โดย MemoryDB สำหรับ Valkey ให้ความทนทานและความสอดคล้องของข้อมูลเช่นเดียวกับ Redis แต่ใช้ประโยชน์จากการปรับปรุงประสิทธิภาพของ Valkey

---

## คุณสมบัติ (Features)
* **ความสอดคล้องของข้อมูล:** โหนดหลัก (Primary nodes) มีความสอดคล้องแบบรุนแรง (Strong consistency) ส่วนโหนดสำรอง (Replica nodes) รับประกันความสอดคล้องในท้ายที่สุด (Eventual consistency)
* **การสเกล:** ปรับขนาดแนวนอนโดยการเพิ่ม/ลดโหนด หรือแนวตั้งโดยการเปลี่ยนประเภทโหนด
    * **Write throughput:** เพิ่มได้โดยการเพิ่ม Shards
    * **Read throughput:** เพิ่มได้โดยการเพิ่ม Replicas
* **Snapshot:** จัดเก็บ Snapshot ใน Amazon S3 โดยมีระยะเวลาเก็บรักษาสูงสุด 35 วัน
* **การจัดการ:** แพตช์ซอฟต์แวร์และอัปเกรดคลัสเตอร์อัตโนมัติ
* **ความปลอดภัย:** รองรับการเข้ารหัสทั้งขณะรับ-ส่งและขณะจัดเก็บ รวมถึงการยืนยันตัวตนผ่าน ACLs

## แนวคิดหลัก (Concepts)

### คลัสเตอร์ (Clusters)
* คือกลุ่มของโหนดที่ให้บริการชุดข้อมูลชุดเดียว แบ่งข้อมูลออกเป็น Shards
* แต่ละ Shard มีโหนดหลัก (Primary) 1 ตัว และโหนดสำรอง (Replica) ได้สูงสุด 5 ตัว
    * **Primary node:** รองรับทั้งคำขออ่านและเขียน
    * **Replica node:** รองรับเฉพาะคำขออ่านเท่านั้น
* หากโหนดหลักล้มเหลว โหนดสำรองจะถูกยกสถานะขึ้นเป็นโหนดหลักใหม่แทน
* **Global Clusters:** รองรับการทำสำเนาข้อมูลข้ามภูมิภาค (Multi-Region) ประกอบด้วยคลัสเตอร์หลัก (Read/Write) 1 แห่ง และคลัสเตอร์สำรอง (Read-only) ได้สูงสุด 5 แห่งในภูมิภาคอื่น เพื่อใช้ทำ Disaster Recovery

### โหนด (Nodes)
* เป็นส่วนประกอบที่เล็กที่สุด รันบนอินสแตนซ์ Amazon EC2
* แต่ละโหนดมีชื่อ DNS และพอร์ตของตัวเอง
* หากมีการเปลี่ยนโหนดใหม่ โหนดนั้นอาจได้รับ IP Address ใหม่ คุณต้องอัปเดตการตั้งค่าแอปพลิเคชันให้รองรับ

### ชาร์ด (Shards)
* คือการจัดกลุ่มของโหนด (1 ถึง 6 โหนด) โดยมีโหนดหลัก 1 ตัวสำหรับเขียน และที่เหลือเป็น Read Replicas
* หนึ่งคลัสเตอร์ต้องมีอย่างน้อยหนึ่ง Shard เสมอ

## การตั้งค่าและการเข้าถึง (Configuration & Access)
* **Parameter groups:** ชุดการตั้งค่าเฉพาะของเอนจินที่ใช้กับทุกโหนดในคลัสเตอร์เพื่อให้มีการตั้งค่าเหมือนกัน
* **Subnet Groups:** ชุดของ Subnet ใน VPC สำหรับใช้งานร่วมกับคลัสเตอร์
* **Access Control Lists (ACLs):** ใช้จัดการกลุ่มผู้ใช้และสิทธิ์การเข้าถึง

---

## ความปลอดภัย (Security)
* สร้างผู้ใช้พร้อมสิทธิ์เฉพาะเจาะจงและเพิ่มเข้าไปใน ACLs เพื่อควบคุมการเข้าถึง
* ตั้งค่าการเข้ารหัส TLS (In-transit) และการเข้ารหัสข้อมูลที่จัดเก็บ (At-rest) โดยใช้คีย์จาก AWS KMS
* ใช้ VPC Security Group เพื่อควบคุมอุปกรณ์หรืออินสแตนซ์ EC2 ที่จะเชื่อมต่อเข้ามายังพอร์ตของโหนด

---

## การเครือข่าย (Networking)
* อินสแตนซ์ EC2 ใน VPC เดียวกันสามารถเชื่อมต่อกับโหนด MemoryDB ได้ หรือใช้ VPC Peering หากอยู่คนละ VPC
* แอปพลิเคชันเชื่อมต่อผ่าน **Endpoint** ซึ่งเป็นที่อยู่เฉพาะ (Unique address) ของคลัสเตอร์

---

## ค่าบริการ (Pricing)
* **Node Usage:** คิดตามรายชั่วโมงสำหรับโหนดแบบ On-demand 
    * *หมายเหตุ:* **Reserved nodes** ไม่ใช่โหนดจริง แต่เป็นส่วนลดทางการเรียกเก็บเงินเมื่อทำข้อตกลงใช้งาน 1 หรือ 3 ปี (มีแบบ No Upfront, Partial Upfront และ All Upfront)
* **Data Written:** คิดตามปริมาณข้อมูล (GB) ที่เขียนลงในคลัสเตอร์ MemoryDB
* **Snapshot Storage:** คิดค่าบริการพื้นที่จัดเก็บ Snapshot เพิ่มเติม
