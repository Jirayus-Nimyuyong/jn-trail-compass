# Amazon DocumentDB Cheat Sheet

**Amazon DocumentDB** เป็นบริการฐานข้อมูลประเภท Document แบบ Managed เต็มรูปแบบที่ออกแบบมาเพื่อความรวดเร็ว การสเกล และความพร้อมใช้งานสูง
* ข้อมูลถูกจัดเก็บในรูปแบบเอกสารคล้าย JSON
* เข้ากันได้กับ MongoDB (Compatible)
* โครงสร้างข้อมูล (Schema) และการทำ Index มีความยืดหยุ่น
* นิยมใช้สำหรับระบบจัดการเนื้อหา (CMS), โปรไฟล์ผู้ใช้ และข้อมูล Big Data แบบเรียลไทม์

---

## รูปแบบการทำงาน (How it Works)
Amazon DocumentDB แยกส่วนการจัดเก็บข้อมูล (Storage) และการประมวลผล (Compute) ออกจากกัน
* **Cluster Volume:** คือชั้นการจัดเก็บข้อมูล (Storage Layer) ที่ครอบคลุมหลาย Availability Zones โดยแต่ละ AZ จะมีสำเนาข้อมูลของคลัสเตอร์อยู่
* **Instances:** คือชั้นการประมวลผล (Compute Layer) ให้กำลังในการเขียนและอ่านข้อมูลจาก Cluster Volume

### จุดเชื่อมต่อของ Amazon DocumentDB (Endpoints)
* **Cluster endpoint:** เชื่อมต่อกับ Primary Instance ปัจจุบัน ใช้ได้ทั้งการ **อ่าน** และ **เขียน**
* **Reader endpoint:** เชื่อมต่อกับ Replica ที่พร้อมใช้งาน ใช้สำหรับการ **อ่านอย่างเดียว** เท่านั้น (รองรับการทำ Load-balancing ระหว่าง Replica)
* **Instance endpoint:** เชื่อมต่อกับอินสแตนซ์เฉพาะตัวในคลัสเตอร์ ใช้สำหรับงานเฉพาะทางที่ต้องการระบุเครื่อง

---

## กรณีการใช้งาน (Use Cases)
* **ระบบจัดการเนื้อหา (CMS):** จัดเก็บและคิวรีเนื้อหาที่หลากหลาย
* **E-commerce:** จัดการแคตตาล็อกสินค้าและตะกร้าสินค้า
* **แอปพลิเคชันมือถือและเว็บ:** ใช้เป็น Backend สำหรับข้อมูลผู้ใช้ที่สเกลได้ง่าย
* **Generative และ Agentic AI:** ใช้ **Vector Search** เพื่อจัดเก็บและคิวรี Vector Embeddings สำหรับแอปพลิเคชัน AI

---

## ประสิทธิภาพและการสเกล (Performance & Scaling)
* รองรับคำขอนับล้านรายการต่อวินาที ด้วยความหน่วงระดับมิลลิวินาที (มีทรูพุตสูงเป็น 2 เท่าของ MongoDB)
* **การจัดเก็บข้อมูล:** เริ่มต้นที่ 10GB และจะสเกลเพิ่มขึ้นอัตโนมัติสูงสุดถึง **64 TB** (เพิ่มทีละ 10GB) โดยไม่กระทบต่อประสิทธิภาพ
* **การประมวลผล:** สเกลได้โดยการเปลี่ยน Instance Class
* **Replicas:** สร้างเพิ่มได้สูงสุด **15 ตัว** โดยมีความล่าช้าในการทำสำเนา (Replication Lag) มักจะน้อยกว่า 100 มิลลิวินาที

---

## ความน่าเชื่อถือ (Reliability)
* **ความทนทาน:** เก็บข้อมูลสำรอง 6 ชุด กระจายใน 3 Availability Zones
* **การกู้คืน:** โดยปกติจะใช้เวลา Restart น้อยกว่า 1 นาทีหลังจากฐานข้อมูลล่ม
* **Failover:** รองรับการสลับสายงานอัตโนมัติ (Automatic Failover) โดยสามารถกำหนดลำดับความสำคัญ (Promotion Priority) ของ Replica ได้
* **Global Clusters:** ทำสำเนาข้อมูลไปยังภูมิภาคสำรอง (Secondary Regions) ได้สูงสุด 5 แห่ง เพื่อการอ่านทั่วโลกที่รวดเร็วและการกู้คืนจากภัยพิบัติ
* **Event Subscriptions:** ติดตามสถานะคลัสเตอร์ (เช่น การทำ Failover) ผ่าน **Amazon SNS**

---

## การสำรองข้อมูลและการกู้คืน (Backup And Restore)
* **Automated Backups:** เปิดใช้งานเสมอเป็นค่าเริ่มต้น
* **Point-In-Time Restoration:** กู้คืนข้อมูลย้อนหลังได้สูงสุดถึง 5 นาทีที่ผ่านมา
* **Snapshots:** สามารถกู้คืนจาก Snapshot, แชร์ Manual Snapshot ที่เข้ารหัส และคัดลอก Snapshot ข้ามภูมิภาคได้

---

## ความปลอดภัย (Security)
* **การยืนยันตัวตน:** รองรับ SCRAM ผ่านเครื่องมือ MongoDB มาตรฐาน และใช้ IAM สำหรับจัดการ API
* **การเข้ารหัส:**
    * ข้อมูลระหว่างรับ-ส่ง (In transit) เข้ารหัสด้วย TLS
    * ข้อมูลที่จัดเก็บ (At rest) เข้ารหัสด้วยคีย์ที่จัดการผ่าน AWS KMS
* **RBAC:** รองรับการควบคุมการเข้าถึงตามบทบาท (Role Based Access Control) เพื่อบังคับใช้หลักการให้สิทธิ์เท่าที่จำเป็น (Least Privilege)

---

## ค่าบริการ (Pricing)
คิดค่าบริการตาม 4 หมวดหลัก:
1. **On-demand instances:** จ่ายรายวินาที (ขั้นต่ำ 10 นาที)
2. **Database I/O:** จ่ายต่อจำนวนล้านรายการ I/O
3. **Database Storage:** จ่ายต่อ GB/เดือน
4. **Backup Storage:** จ่ายต่อ GB/เดือน

---

## ข้อจำกัด (Limitations)
* ไม่รองรับการเปิดใช้งานการเข้ารหัส (Encryption) บนอินสแตนซ์ที่มีอยู่แล้ว (ต้องทำตอนสร้าง)
* ไม่สามารถแชร์ Snapshot ที่เป็นแบบอัตโนมัติ (Automatic) ไปยังบัญชีอื่นได้โดยตรง (ต้องคัดลอกเป็น Manual Snapshot ก่อน)
