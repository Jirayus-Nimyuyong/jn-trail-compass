# Amazon Bedrock AgentCore Identity Cheat Sheet

**Amazon Bedrock AgentCore Identity** เป็นบริการจัดการตัวตนและข้อมูลประจำตัว (Identity & Credential Management) สำหรับเอเจนท์ AI และกระบวนการทำงานอัตโนมัติ ช่วยให้การยืนยันตัวตน การอนุญาตสิทธิ์ และการจัดการข้อมูลลับมีความปลอดภัย ทำให้เอเจนท์เข้าถึงบริการของ AWS และบริการภายนอกในนามของผู้ใช้ได้ โดยที่ยังคงการควบคุมความปลอดภัยและบันทึกประวัติการตรวจสอบไว้ ตัวตนของเอเจนท์จะถูกใช้งานในรูปแบบ "Workload Identity" โดยเฉพาะ

### คุณสมบัติของ Amazon Bedrock AgentCore Identity
* **การจัดการตัวตนเอเจนท์แบบศูนย์กลาง:** มีไดเรกทอรีส่วนกลางสำหรับสร้างและจัดระเบียบตัวตน (Workload Identity) ที่ไม่ซ้ำกันสำหรับเอเจนท์แต่ละตัว พร้อม Metadata เฉพาะทาง
* **โมเดลความปลอดภัย 2 ชั้น:** * **Inbound Authentication:** ตรวจสอบผู้ใช้หรือบริการที่พยายามเรียกใช้เอเจนท์ (รองรับ JWT, OAuth 2.0, AWS IAM)
    * **Outbound Authentication:** ช่วยให้เอเจนท์เข้าถึงทรัพยากรปลายทางด้วยข้อมูลประจำตัวที่ได้รับการจัดการอย่างปลอดภัย
* **การจัดการข้อมูลประจำตัว (Credential Orchestration):** ดูแลวงจรชีวิตของข้อมูลลับทั้งหมด (OAuth tokens, API keys) โดยจัดเก็บไว้ใน Vault ที่เข้ารหัส จัดการกระบวนการ OAuth (รวมถึงการขอความยินยอมจากผู้ใช้) และส่งข้อมูลลับเข้าสู่การเรียกใช้เครื่องมือของเอเจนท์โดยอัตโนมัติ
* **การเชื่อมต่อกับบริการภายนอก:** รองรับการเชื่อมต่อกับบริการยอดนิยมอย่าง GitHub, Salesforce และ Slack ผ่านโปรโตคอลมาตรฐานได้ทันที

---

### การทำงาน (How It Works)
* **ส่วนประกอบหลัก:** 1. **Agent Identity Directory:** แหล่งข้อมูลความจริงสำหรับตัวตนเอเจนท์ 
    2. **Agent Authorizer:** ตรวจสอบคำขอขาเข้า 
    3. **Resource Credential Provider:** เก็บการตั้งค่าการเข้าถึง 
    4. **Resource Token Vault:** จัดเก็บและดึงข้อมูล Token/API Key อย่างปลอดภัย
* **รูปแบบ Workload Identity:** เอเจนท์จะได้รับตัวตนแยกต่างหาก (ไม่ใช่การสวมรอยเป็นผู้ใช้) มีหมายเลข ARN และ URL สำหรับ OAuth ของตัวเอง ทำให้สามารถจัดการและตรวจสอบสิทธิ์ในฐานะ Principal อิสระได้
* **การตรวจสอบคำขอแบบแยกขาด:** ทุกความพยายามในการเข้าถึงจะถูกตรวจสอบอย่างชัดเจน ไม่มีการเชื่อถือต่อกันเป็นทอดๆ (Zero-trust model) ทุกคำขอต้องพิสูจน์สิทธิ์การใช้งานเสมอ

---

### การนำไปใช้งาน (Implementation)
1. **สร้าง Workload Identities:** กำหนดตัวตนเฉพาะให้เอเจนท์ในไดเรกทอรี AgentCore Identity
2. **ตั้งค่า Inbound Authorizer:** ตั้งค่า JWT Authorizer เพื่อตรวจสอบ Token จากผู้ให้บริการตัวตน (เช่น Cognito, Okta)
3. **เพิ่ม Credential Providers:** ลงทะเบียนผู้ให้บริการสำหรับแต่ละบริการภายนอก (เช่น GitHub OAuth) ที่เอเจนท์ต้องเข้าถึง
4. **ใช้ SDK Annotations:** ใช้ Decorator ในโค้ด Python เช่น `@requires_access_token` เพื่อส่งต่อหน้าที่การจัดการ Token ให้กับบริการ AgentCore Identity
5. **Deploy และเรียกใช้:** เมื่อเอเจนท์ถูกเรียกใช้พร้อม JWT ของผู้ใช้ ระบบจะจัดการกระบวนการยืนยันตัวตนและการส่งข้อมูลลับไปยัง API ภายนอกให้โดยอัตโนมัติ

---

### ความปลอดภัย (Security)
* **การเข้ารหัสและการแยกส่วน:** ข้อมูลลับทั้งหมดใน Vault จะถูกเข้ารหัส (Encryption at rest/in transit) ด้วย AWS KMS และมีการแยกส่วนข้อมูลอย่างเข้มงวด โดยผูก Token เข้ากับคู่ "เอเจนท์-ผู้ใช้" เฉพาะราย เพื่อป้องกันการเข้าถึงข้ามผู้ใช้
* **การควบคุมสิทธิ์อย่างละเอียด:** ใช้ AWS IAM เพื่อบังคับใช้หลักการ Least Privilege (ให้สิทธิ์ขั้นต่ำที่จำเป็น) ทั้งสำหรับการเข้าถึงทรัพยากรของ AWS และภายนอก
* **บันทึกการตรวจสอบที่ครอบคลุม:** เชื่อมต่อกับ **AWS CloudTrail** เพื่อบันทึกเหตุการณ์ที่เกี่ยวข้องกับตัวตนทั้งหมด เช่น การพยายามยืนยันตัวตน และการใช้งานข้อมูลประจำตัว

---

### แนวทางปฏิบัติที่ดีที่สุด (Best Practices)
* **ยึดหลัก Least Privilege:** ให้สิทธิ์แก่เอเจนท์เฉพาะที่จำเป็นสำหรับงานนั้นๆ และตรวจสอบ OAuth Scopes หรือ IAM Policies อย่างสม่ำเสมอ
* **ใช้ Managed Token Vault:** เก็บและดึง API Key หรือ OAuth Token ผ่านระบบจัดการของ AWS เสมอ **ห้าม Hardcode** ข้อมูลลับลงในโค้ดหรือไฟล์คอนฟิก
* **ใช้ SDK Annotations:** ใช้การกำหนดค่าแบบ Declarative (เช่น `@requires_access_token`) เพื่อลดความเสี่ยงจากข้อผิดพลาดในการเขียนตรรกะการจัดการข้อมูลประจำตัวด้วยตนเอง

---

### ค่าบริการ (Pricing)
* **การใช้งานแบบรวมศูนย์:** **ไม่มีค่าบริการเพิ่มเติม** หากใช้งานผ่าน Amazon Bedrock AgentCore Runtime หรือ AgentCore Gateway (รวมอยู่ในค่าบริการของบริการเหล่านั้นแล้ว)
* **การเรียกใช้ API โดยตรง:** หากเรียกใช้ API ของ AgentCore Identity โดยตรงจากภายนอก จะคิดราคาตาม **จำนวนคำขอ (Pay-per-use)** ในการดึงข้อมูล OAuth Token หรือ API Key
