# Amazon Bedrock Prompt Management Cheat Sheet

**Amazon Bedrock Prompt Management** เป็นระบบจัดการ Prompt ส่วนกลางสำหรับ Generative AI ช่วยให้การสร้าง, ทดสอบ, ทำเวอร์ชัน และติดตั้งใช้งาน Prompt ที่มีโครงสร้างทำได้ง่ายขึ้น โดยแยกส่วนการทำ Prompt Engineering ออกจากโค้ดของแอปพลิเคชัน

### แนวคิดหลัก (Core Concepts)
* **Prompt:** ข้อความหรือคำสั่งที่ส่งให้โมเดลเพื่อควบคุมผลลัพธ์
* **Variable (ตัวแปร):** ช่องว่างสำหรับเติมข้อมูลไดนามิก (เช่น `{{variable_name}}`) ซึ่งจะถูกเติมด้วยค่าจริงระหว่างการทดสอบหรือใช้งานจริง
* **Prompt Variant:** เวอร์ชันที่แตกต่างกันของ Prompt (เช่น การใช้โมเดลคนละตัวหรือคำสั่งคนละแบบ) เพื่อใช้ในการทดสอบเปรียบเทียบและหาค่าที่เหมาะสมที่สุด
* **Prompt Builder:** เครื่องมือแบบภาพ (Visual Tool) ในคอนโซลของ Bedrock สำหรับสร้าง แก้ไข และทดสอบ Prompt โดยไม่ต้องแก้ไขไฟล์ JSON ด้วยตนเอง

---

### ข้อกำหนดเบื้องต้น (Prerequisites)
* **สิทธิ์การใช้งาน (Permissions):** ผู้ใช้หรือ IAM Role ต้องมีสิทธิ์เข้าถึง (เช่น `bedrock:CreatePrompt`, `bedrock:GetPrompt`)
* **การเข้าถึงโมเดล (Model Access):** ต้องเปิดใช้งานการเข้าถึงโมเดลพื้นฐาน (Foundation Models) ที่ต้องการใช้ในหน้า Model Access ของคอนโซล Bedrock

---

### การสร้างและการกำหนดค่า Prompt
เมื่อสร้าง Prompt คุณต้องกำหนดองค์ประกอบดังนี้:
* **Prompt Message:** คำสั่งในรูปแบบข้อความเพื่อให้โมเดลสร้างผลลัพธ์
* **Variables:** ตัวแปรที่กำหนดด้วยปีกกาคู่ (เช่น `{{customer_name}}`)
* **การเลือกโมเดล:** ระบุโมเดลที่จะใช้เพื่อตั้งค่าพารามิเตอร์การอนุมาน (Inference Parameters)
* **พารามิเตอร์การอนุมาน:**
    * **maxTokens:** ขีดจำกัดจำนวน Token ที่โมเดลจะสร้างในคำตอบ
    * **stopSequences:** รายการตัวอักษรที่ถ้าโมเดลสร้างขึ้นมาแล้ว จะต้องหยุดการทำงานทันที
    * **temperature:** ควบคุมความ "สร้างสรรค์" หรือการสุ่มของผลลัพธ์ (ค่าสูง = สุ่มมาก)
    * **topP:** เทคนิคการสุ่มตัวอย่างที่จำกัดตัวเลือก Token เฉพาะกลุ่มที่มีความน่าจะเป็นสูงสุด

---

### การทดสอบและปรับปรุง Prompt (Testing & Optimizing)
* **การทดสอบ:** สามารถใส่ค่าทดสอบในตัวแปรและรันเพื่อดูผลลัพธ์ (Run Inference) ได้ทันทีในหน้า Prompt Builder ก่อนจะสร้างเวอร์ชันใช้งานจริง
* **การปรับปรุง (Optimize):** มีปุ่มรูปไม้กายสิทธิ์เพื่อสั่งให้ระบบ **เขียน Prompt ใหม่โดยอัตโนมัติ** เพื่อเพิ่มประสิทธิภาพและคุณภาพผลลัพธ์ให้เหมาะกับโมเดลที่เลือก โดยสามารถเปรียบเทียบผลลัพธ์ก่อนและหลังการปรับปรุงได้แบบ Side-by-side

---

### การติดตั้งใช้งานด้วยเวอร์ชัน (Deployment using Versions)
การจะนำ Prompt ไปใช้ในระดับ Production ต้องสร้าง **Version** เสมอ:
* **Version:** คือ Snapshot ของ Prompt ณ เวลาที่กำหนดซึ่งแก้ไขไม่ได้ (Immutable) ช่วยให้สลับการตั้งค่าได้อย่างปลอดภัย
* **การจัดการเวอร์ชัน:** สามารถดูประวัติการเปลี่ยนแปลง, เปรียบเทียบความแตกต่างระหว่างสองเวอร์ชัน และลบเวอร์ชันที่ไม่ใช้งานแล้วออกได้

---

### ความปลอดภัย (Security)
* **การควบคุมการเข้าถึง:** ใช้ IAM Policies เพื่อกำหนดว่าใครสามารถสร้าง แก้ไข หรือเรียกใช้ Prompt ได้
* **การเข้ารหัส:** Prompt และเวอร์ชันต่างๆ จะถูกเข้ารหัสขณะจัดเก็บด้วย AWS KMS keys
* **การรวมเข้ากับ Guardrails:** สามารถเชื่อมต่อ Amazon Bedrock Guardrails เข้ากับ Prompt เพื่อบังคับใช้พโยบายความปลอดภัย กรองเนื้อหาที่ไม่เหมาะสม หรือปกปิดข้อมูลละเอียดอ่อน

---

### แนวทางปฏิบัติที่ดีที่สุด (Best Practices)
* **ใช้ตัวแปรเสมอ:** ใช้ `{{variables}}` สำหรับข้อมูลที่เปลี่ยนแปลงได้ เพื่อลดความเสี่ยงจากการถูกแทรกแซงคำสั่ง (Prompt Injection) และช่วยให้ Prompt นำกลับมาใช้ซ้ำได้
* **การควบคุมเวอร์ชัน:** **ห้ามใช้เวอร์ชัน DRAFT ในระบบ Production** ให้ใช้เวอร์ชันที่เป็นตัวเลข (เช่น v1, v2) เสมอเพื่อความเสถียร
* **ความเฉพาะเจาะจงของโมเดล:** Prompt มักจะให้ผลลัพธ์ดีที่สุดกับโมเดลเฉพาะตัว หากเปลี่ยนโมเดล (เช่น จาก Claude เป็น Llama) ควรสร้าง Variant ใหม่ที่เหมาะกับโมเดลนั้นๆ

---

### ค่าบริการ (Pricing)
* **การจัดการ:** โดยปกติไม่มีค่าบริการเพิ่มเติมสำหรับการจัดเก็บและจัดระเบียบ Prompt ใน Library
* **การทดสอบและปรับปรุง:** คิดค่าบริการตามอัตรา **On-Demand** มาตรฐานของโมเดล (ตามจำนวน Token ขาเข้า/ขาออก) ทุกครั้งที่มีการสั่งรันเพื่อทดสอบหรือปรับปรุง Prompt
* **Prompt Flows:** หากใช้ Prompt ภายใน Amazon Bedrock Flows จะคิดค่าบริการตามจำนวนการเปลี่ยนโหนด (Node Transition)
