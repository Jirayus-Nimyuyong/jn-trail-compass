# Amazon Bedrock Knowledge Bases Cheat Sheet

**Amazon Bedrock Knowledge Bases** เป็นบริการ Retrieval-Augmented Generation (RAG) แบบ Managed เต็มรูปแบบ ที่เชื่อมต่อโมเดลพื้นฐาน (Foundation Models) เข้ากับแหล่งข้อมูลส่วนตัวของบริษัทได้อย่างปลอดภัย ช่วยจัดการกระบวนการทั้งหมดโดยอัตโนมัติ ตั้งแต่การนำเข้าข้อมูล (Ingestion), การทำดัชนี (Indexing) ไปจนถึงการค้นหา (Retrieval) และการอ้างอิงแหล่งที่มา (Source Attribution) ทำให้ AI ตอบคำถามได้อย่างแม่นยำ มีบริบท และตรวจสอบได้ โดยไม่ต้องสร้าง Data Pipeline เอง

### คุณสมบัติของ Amazon Bedrock Knowledge Bases
* **RAG Pipeline แบบเบ็ดเสร็จ:** จัดการเวิร์กโฟลว์ตั้งแต่ต้นจนจบ รวมถึงการแยกเนื้อหาจากเอกสารที่ซับซ้อน (ข้อความ, ตาราง, รูปภาพ), การแบ่งส่วนข้อมูลอัจฉริยะ (Chunking), การสร้าง Vector Embedding และการจัดเก็บในฐานข้อมูลเวกเตอร์
* **รองรับแหล่งข้อมูลและพื้นที่จัดเก็บที่หลากหลาย:**
    * **แหล่งข้อมูล:** Amazon S3, Confluence, Salesforce, SharePoint, Web Crawlers และรองรับการนำเข้าข้อมูลผ่าน API
    * **Vector Stores:** Amazon OpenSearch Serverless (ง่ายที่สุด), Amazon Aurora, Pinecone, Redis Enterprise Cloud, MongoDB หรือเชื่อมต่อกับ Amazon Kendra เพื่อการค้นหาแบบไฮบริด (คำสำคัญ + ความหมาย)
    * **ข้อมูลที่มีโครงสร้าง:** เชื่อมต่อกับคลังข้อมูล (เช่น Amazon Redshift) โดยใช้ Natural Language-to-SQL เพื่อคิวรีข้อมูลได้ทันทีโดยไม่ต้องย้ายข้อมูล
* **การปรับแต่งขั้นสูงเพื่อความแม่นยำ:**
    * **Multimodal Parsing:** ใช้โมเดล AI ช่วยอ่านเอกสารที่มีแผนภูมิ ไดอะแกรม หรือตาราง
    * **Flexible Chunking:** เลือกกลยุทธ์การแบ่งข้อมูลได้ทั้งแบบตามความหมาย (Semantic), ตามลำดับชั้น (Hierarchical) หรือขนาดคงที่
    * **Enhanced Retrieval:** ใช้โมเดล Re-ranking เพื่อจัดลำดับความเกี่ยวข้องของข้อมูลใหม่ก่อนส่งให้โมเดลสร้างคำตอบ
    * **Source Attribution:** ระบบอ้างอิงแหล่งที่มาอัตโนมัติ (Citations) เพื่อความโปร่งใสและตรวจสอบได้

### กรณีการใช้งาน (Use Cases)
* **การตอบคำถามจากความรู้ภายในองค์กร:** แชทบอทที่ตอบคำถามจากคู่มือหรือวิกิภายในบริษัท พร้อมระบุแหล่งที่มา ช่วยลดเวลาค้นหาข้อมูล
* **ระบบสนับสนุนลูกค้าด้วยข้อมูลเฉพาะตัว:** ให้บริการลูกค้าด้วย AI ที่อ้างอิงจากเอกสารผลิตภัณฑ์และบันทึกการใช้งานจริง เพื่อคำตอบที่ถูกต้องสม่ำเสมอ
* **Business Intelligence ผ่านภาษาธรรมชาติ:** ช่วยให้นักวิเคราะห์คิวรีฐานข้อมูลด้วยภาษาอังกฤษทั่วไป (เช่น "ขอยอดขายไตรมาส 3 ของสินค้า X") แล้วได้คำตอบจากข้อมูลสดทันที

### การนำไปใช้งาน (Implementation)
**สถาปัตยกรรมหลัก: เวิร์กโฟลว์ RAG 2 ระยะ**
1. **การนำเข้าและทำดัชนี (Pre-processing):** ข้อมูลต้นทาง → แยกเนื้อหาและแบ่งส่วน → สร้าง Embeddings → จัดเก็บในดัชนีเวกเตอร์
2. **การคิวรีและสร้างคำตอบ (Runtime):** คำถามผู้ใช้ → แปลงเป็นเวกเตอร์ → ค้นหาความหมายในฐานข้อมูล → ดึงส่วนข้อมูลที่เกี่ยวข้อง → เพิ่มเข้าไปใน Prompt → โมเดลสร้างคำตอบสุดท้ายพร้อมการอ้างอิง

**APIs หลักสำหรับการเชื่อมต่อ:**
* **Retrieve:** ดึงเฉพาะส่วนข้อมูล (Text chunks) และแหล่งที่มา เหมาะสำหรับผู้ที่ต้องการปรับแต่ง Prompt เอง
* **RetrieveAndGenerate:** รวมการดึงข้อมูลและการสร้างคำตอบไว้ในการเรียกครั้งเดียว ได้ผลลัพธ์สุดท้ายจาก AI ทันที

### ความปลอดภัย (Security)
* **การเข้ารหัสและ IAM:** ข้อมูลได้รับการเข้ารหัสทั้งขณะรับส่งและจัดเก็บ ใช้ IAM Policy เพื่อควบคุมการเข้าถึงในแต่ละส่วนอย่างละเอียด
* **Private Network:** สามารถรันฐานข้อมูลเวกเตอร์ใน VPC และเชื่อมต่อผ่าน VPC Endpoints (AWS PrivateLink) เพื่อให้ทราฟฟิกทั้งหมดอยู่ภายในเครือข่ายของ AWS
* **Auditability:** ระบบอ้างอิงแหล่งที่มาช่วยให้ตรวจสอบย้อนกลับได้ว่าข้อมูลแต่ละส่วนในคำตอบมาจากเอกสารต้นฉบับชุดไหน

### แนวทางปฏิบัติที่ดีที่สุด (Best Practices)
* **เริ่มต้นด้วยความง่าย:** สำหรับตัวต้นแบบ (Prototype) แนะนำให้ใช้ Amazon OpenSearch Serverless เพื่อให้ AWS จัดการเรื่องการปรับสเกลและการดูแลรักษาให้ทั้งหมด
* **เลือกกลยุทธ์การแบ่งข้อมูลให้เหมาะสม:** ใช้ Semantic Chunking สำหรับเนื้อหาทั่วไปที่เน้นใจความสำคัญ หรือ Hierarchical Chunking สำหรับเอกสารยาวที่ต้องการรักษาบริบทของหัวข้อใหญ่
* **การแสดงแหล่งที่มา:** ควรแสดงการอ้างอิง (Citations) ใน UI ของแอปพลิเคชันเสมอ เพื่อสร้างความเชื่อมั่นแก่ผู้ใช้
* **รักษาความสดใหม่ของข้อมูล:** ใช้ API `StartIngestionJob` เพื่อซิงค์ข้อมูลใหม่เสมอ หรือใช้ Amazon EventBridge เพื่อตั้งเวลาซิงค์อัตโนมัติ

### ค่าบริการ (Pricing)
คิดตามการใช้งานจริง (Consumption-based) โดยมีส่วนประกอบดังนี้:

| ส่วนประกอบ | สิ่งที่คุณจ่าย | หมายเหตุ |
| :--- | :--- | :--- |
| **การนำเข้าข้อมูล** | ค่า Token สำหรับ Embedding และค่า Parsing รายหน้า | จ่ายตามปริมาณข้อมูลที่โมเดลประมวลผลเป็นเวกเตอร์ |
| **พื้นที่เก็บเวกเตอร์** | ค่า Storage และ Compute ของฐานข้อมูลที่เลือก | หากใช้ OpenSearch Serverless จะคิดตาม OCU (OpenSearch Compute Unit) |
| **การดึงข้อมูล** | ค่าการประมวลผล (Compute) ของฐานข้อมูลเวกเตอร์ | คิดตามทรัพยากรที่ใช้ระหว่างการค้นหา (เช่น OCU) |
| **การค้นหาข้อมูลมีโครงสร้าง (SQL)** | $2.00 ต่อ 1,000 คิวรี | คิดค่าบริการการแปลงภาษาธรรมชาติเป็นคำสั่ง SQL |
| **Rerank Models** | ตามจำนวนคิวรี (เช่น $1.00 ต่อ 1,000 คิวรี) | ใช้เพื่อเพิ่มความแม่นยำในการจัดลำดับข้อมูลที่ดึงมา |
| **โมเดลพื้นฐาน (Inference)** | ค่า Token ตามราคามาตรฐานของโมเดลที่เลือก | คิดตาม Input/Output Token เมื่อใช้ `RetrieveAndGenerate` |
