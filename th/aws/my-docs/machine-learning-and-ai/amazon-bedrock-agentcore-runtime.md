# Amazon Bedrock AgentCore Runtime Cheat Sheet

**Amazon Bedrock AgentCore Runtime** เป็นเอนจินการประมวลผล (Execution Engine) ภายในแพลตฟอร์ม Bedrock AgentCore ซึ่งให้บริการสภาพแวดล้อมแบบ Serverless ที่มีความหน่วงต่ำ (Low-latency) สำหรับรันเอเจนท์ AI โดยระบบจะจัดการโครงสร้างพื้นฐานที่ซับซ้อน ทั้งการขยายขนาด ความปลอดภัย และการจัดการเซสชัน (Session Management) ช่วยให้คุณโฟกัสกับการพัฒนาตรรกะของเอเจนท์ได้อย่างเต็มที่ รองรับตั้งแต่การสร้างตัวต้นแบบไปจนถึงการใช้งานจริงระดับองค์กร

### คุณสมบัติของ Amazon Bedrock AgentCore Runtime
* **Framework Agnostic:** เปลี่ยนโค้ดเอเจนท์ที่รันในเครื่อง (Local) ให้กลายเป็น Cloud-native ได้ด้วยโค้ดเพียงไม่กี่บรรทัด รองรับเฟรมเวิร์กยอดนิยมอย่าง **LangGraph, Strands, และ CrewAI** หรือเอเจนท์ที่เขียนขึ้นเอง
* **ความยืดหยุ่นของโมเดลและโปรโตคอล:** เอเจนท์สามารถใช้ LLM ใดก็ได้ (Bedrock, Claude, Gemini, OpenAI) และรองรับโปรโตคอลการสื่อสารที่หลากหลาย เช่น **Model Context Protocol (MCP)**, Agent to Agent (A2A) และ HTTP มาตรฐาน
* **ความปลอดภัยและการแยกส่วน (Isolation):** แต่ละเซสชันของผู้ใช้จะรันใน **microVM** แยกเฉพาะ พร้อมทรัพยากร CPU, Memory และระบบไฟล์ที่แยกขาดจากกัน เพื่อป้องกันข้อมูลรั่วไหลระหว่างเซสชัน และจะทำการทำลาย microVM ทันทีเมื่อจบเซสชัน
* **ขีดความสามารถระดับองค์กร:**
    * **Extended Execution:** รองรับการทำงานต่อเนื่องยาวนานสูงสุดถึง **8 ชั่วโมง** สำหรับงานที่ซับซ้อน
    * **Built-in Authentication:** เชื่อมต่อกับระบบระบุตัวตนองค์กร เช่น **Okta, Microsoft Entra ID หรือ Amazon Cognito**
    * **Observability:** มีระบบ Tracing ในตัวที่ออกแบบมาเพื่อติดตามขั้นตอนการใช้เหตุผล (Reasoning), การเรียกใช้เครื่องมือ และการโต้ตอบกับโมเดล
    * **Large Payloads:** ประมวลผลข้อมูลได้สูงสุดถึง **100MB** รองรับทั้งข้อความ, รูปภาพ, เสียง และวิดีโอ

### กรณีการใช้งาน (Use Cases)
* **การสร้างและทดสอบเอเจนท์อย่างรวดเร็ว:** ใช้การ Deploy โค้ดโดยตรงเพื่อทดสอบตรรกะโดยไม่ต้องจัดการ Container ช่วยเร่งวงจรการพัฒนา
* **เวิร์กโฟลว์ Multi-Agent ระดับโปรดักชัน:** ติดตั้งเอเจนท์ที่ทำงานร่วมกันเพื่อแก้ปัญหาที่ซับซ้อนและต้องใช้เวลานาน เช่น การวิเคราะห์ข้อมูลเชิงลึก หรือระบบบริการลูกค้าอัตโนมัติ
* **การปฏิบัติการ AI ที่ปลอดภัยและตรวจสอบได้:** รันเอเจนท์ที่จัดการข้อมูลละเอียดอ่อนที่ต้องการความปลอดภัยสูง โดยใช้ประโยชน์จากการแยกเซสชันและบันทึกประวัติการตรวจสอบ (Audit trails) ที่ละเอียด

### การนำไปใช้งาน (Implementation)
**วิธีการ Deploy (Deployment Methods)**
มี 2 เส้นทางหลักในการติดตั้งโค้ดเอเจนท์:

| หัวข้อเปรียบเทียบ | Direct Code Deployment | Container-Based Deployment |
| :--- | :--- | :--- |
| **กระบวนการ** | แพ็กโค้ดเป็นไฟล์ **ZIP** อัปโหลดไปที่ **S3** | สร้าง Docker Image (ARM) ส่งไปที่ **Amazon ECR** |
| **เหมาะสำหรับ** | ตัวต้นแบบ, เอเจนท์ Python แบบง่าย, เน้นความเร็ว | งานที่มี Dependency ซับซ้อน, รองรับหลายภาษา, CI/CD เดิม |
| **ขนาดแพ็กเกจสูงสุด** | **250MB** | **2GB** |
| **เวลาอัปเดตเฉลี่ย** | ประมาณ 10 วินาที | ประมาณ 30 วินาที |
| **ที่เก็บ Artifact** | S3 (ระบบจัดการให้) | ECR (ในบัญชีของคุณเอง) |

### ความปลอดภัย (Security)
* **MicroVM-per-session:** สถาปัตยกรรมที่แยกส่วนในระดับฮาร์ดแวร์ เพื่อรับประกันว่าสถานะของเอเจนท์และข้อมูลที่ประมวลผลจะไม่รั่วไหลไปยังผู้ใช้หรือเซสชันอื่น
* **Integrated Identity:** มอบตัวตน (Identity) ที่ชัดเจนให้กับเอเจนท์ และจัดการการยืนยันตัวตนไปยังบริการภายนอก (เช่น Slack, GitHub) ผ่าน OAuth หรือ API Keys อย่างปลอดภัย
* **Network Security:** กำหนดค่า Runtime Endpoints ภายใน **Amazon VPC** ของคุณเพื่อควบคุมทราฟฟิกขาเข้าและขาออกผ่านเครือข่ายส่วนตัว

### แนวทางปฏิบัติที่ดีที่สุด (Best Practices)
* **เลือกวิธี Deploy ให้ถูก:** เริ่มจาก **Direct Code** เพื่อความรวดเร็วในการพัฒนา และสลับไปใช้ **Container-based** เมื่อต้องการใช้ Dependency เฉพาะทางหรือไฟล์มีขนาดเกิน 250MB
* **เพิ่มประสิทธิภาพและลดต้นทุน:** ออกแบบงานที่เป็นแบบอซิงโครนัส (Asynchronous) เพื่อใช้ประโยชน์จากเวลาทำงาน 8 ชั่วโมง และใช้ประโยชน์จากรูปแบบราคาที่ **ไม่คิดเงินในช่วงที่รอ I/O** (เช่น ช่วงที่รอคำตอบจาก LLM)
* **วงจรการพัฒนา:** ใช้ระบบ Tracing เฉพาะของเอเจนท์เพื่อ Debug รูปแบบการใช้เหตุผลที่ซับซ้อน และจัดการ Environment Variables ผ่าน API หรือ CloudFormation เพื่อความสม่ำเสมอ

### ค่าบริการ (Pricing)
* **รูปแบบ Pay-as-you-go:** คิดค่าบริการตามทรัพยากร (Compute และ Memory) ที่เอเจนท์ใช้งานจริงระหว่างประมวลผล
* **จุดเด่นด้านต้นทุน:** **ไม่คิดค่าบริการในช่วงที่รอ I/O** (ขณะรอคำตอบจากโมเดล) แม้จะยังคงรักษาสถานะเซสชันไว้ก็ตาม
* **ค่าจัดเก็บข้อมูล:** จ่ายค่าพื้นที่เก็บไฟล์ ZIP ใน S3 หรือ Image ใน ECR ตามอัตรามาตรฐานของบริการนั้นๆ
