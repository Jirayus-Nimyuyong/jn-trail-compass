# Amazon SageMaker Feature Store Cheat Sheet

**Amazon SageMaker Feature Store** คือคลังเก็บข้อมูลส่วนกลางสำหรับจัดการ "ฟีเจอร์" (คุณลักษณะ) ของ Machine Learning
* ช่วยลดความยุ่งยากในกระบวนการสำรวจข้อมูล, การฝึกโมเดล และการทำนายผลแบบกลุ่ม (Batch) โดยการรวมมุมมองของฟีเจอร์ทั้งหมดไว้ในที่เดียว
* ช่วยเพิ่มประสิทธิภาพในการพัฒนาและติดตั้งใช้งานโมเดล ML

### การทำงานของ Feature Store
* SageMaker Feature Store จัดเก็บฟีเจอร์ไว้ในรูปแบบของ **Feature Groups**
* **Feature Group:** คือกลุ่มของฟีเจอร์ที่เกี่ยวข้องกันซึ่งใช้สำหรับงานเฉพาะอย่าง สามารถสร้างขึ้นจากแหล่งข้อมูลต่างๆ เช่น Amazon S3, Amazon RDS และ Amazon DynamoDB
* **โหมดการทำงานมี 3 รูปแบบ:**
    1. **Online:** ให้การเข้าถึงฟีเจอร์ด้วยความหน่วงต่ำ (Low-latency) เหมาะสำหรับแอปพลิเคชันที่ต้องการการทำนายผลที่มีปริมาณงานสูง (High-throughput)
    2. **Offline:** ใช้สำหรับการประมวลผลชุดข้อมูลขนาดใหญ่แบบกลุ่มที่เก็บไว้ใน S3 รองรับการดึงข้อมูลโดยใช้คำสั่ง Athena คิวรี เพื่อใช้ในการฝึกโมเดลหรือทำ Batch Inference
    3. **Online and Offline:** เป็นการผสมผสานทั้งโหมด Online และ Offline เข้าด้วยกัน

### การนำเข้าข้อมูล (Ingestion)
รองรับการนำเข้าข้อมูลทั้งแบบ Streaming และ Batch:
* **Stream Ingestion:** ช่วยให้คุณพุชข้อมูลฟีเจอร์ใหม่หรืออัปเดตข้อมูลเข้าสู่คลังได้ต่อเนื่องแบบเรียลไทม์ โดยใช้ **PutRecord API** เพื่อให้มั่นใจว่าค่าของฟีเจอร์ล่าสุดพร้อมใช้งานเสมอ
* **Batch Ingestion:** ใช้เครื่องมืออย่าง SageMaker Data Wrangler เพื่อสร้างฟีเจอร์แล้วส่งออกเป็น Notebook เพื่อนำเข้าข้อมูลเข้าสู่ Feature Group เป็นชุดๆ

### แนวคิดหลัก (Key Concepts)
* **Feature Store:** คลังส่วนกลางที่เป็นแหล่งข้อมูลความจริงหนึ่งเดียว (Single source of truth) สำหรับการจัดเก็บ, เรียกใช้, ลบ, ติดตาม, แชร์ และควบคุมการเข้าถึงฟีเจอร์
* **Feature Group:** ชุดของฟีเจอร์ที่เกี่ยวข้องกันซึ่งใช้อธิบายเรคคอร์ดชุดหนึ่ง เปรียบเสมือนตารางข้อมูล ML
* **Feature:** คุณสมบัติหรือลักษณะที่ใช้เป็นข้อมูลนำเข้า (Input) สำหรับโมเดล ML (เปรียบเสมือนคอลัมน์ในตาราง)
* **Feature Definition:** การระบุชื่อและประเภทข้อมูล (ตัวเลข, ข้อความ หรือทศนิยม) ของฟีเจอร์
* **Record:** ชุดของค่าฟีเจอร์สำหรับเอนทิตีเฉพาะ (เปรียบเสมือนแถวในตาราง)
* **Record Identifier:** ชื่อของฟีเจอร์ที่ใช้ระบุตัวตนของเรคคอร์ดใน Feature Group ไม่ให้ซ้ำกัน
* **Event Time:** การประทับเวลา (Timestamp) เพื่อบอกว่าข้อมูลนั้นถูกบันทึกหรืออัปเดตเมื่อใด (Online store จะเก็บเฉพาะเรคคอร์ดล่าสุด แต่ Offline store จะเก็บประวัติย้อนหลังทั้งหมด)

### การคิวรีข้อมูลแบบย้อนกลับ (Point-in-Time Querying)
Feature Store รองรับการคิวรีข้อมูล ณ ช่วงเวลาใดเวลาหนึ่งผ่าน Offline store เพื่อหลีกเลี่ยง **ปัญหาข้อมูลรั่วไหล (Data Leakage)** ขณะสร้างชุดข้อมูลสำหรับฝึกโมเดล
* ผู้ใช้สามารถ Join ชุดข้อมูลโดยใช้ Event Time
* สามารถตัดค่าใน "อนาคต" (ข้อมูลที่ยังไม่มีอยู่ ณ เวลาที่ทำการทำนาย) ออกไปได้ ซึ่งเป็นแนวคิดสำคัญในทาง ML Engineering

### ประโยชน์ของ SageMaker Feature Store
* **การจัดการแบบศูนย์กลาง:** หาตำแหน่ง ติดตาม และอัปเดตฟีเจอร์ได้ง่าย
* **คุณภาพข้อมูล:** มีฟีเจอร์สำหรับติดตามที่มาของข้อมูล (Lineage tracking) และการตรวจสอบความถูกต้อง (Validation)
* **ลดเวลาการฝึกโมเดล:** ด้วยมุมมองฟีเจอร์ที่เป็นหนึ่งเดียว ช่วยลดเวลาที่ต้องใช้ในการเตรียมข้อมูลเพื่อฝึกโมเดล
* **การทำงานร่วมกัน:** ช่วยให้ Data Scientists และ ML Engineers ทำงานร่วมกันได้ดีขึ้นผ่านมุมมองฟีเจอร์ที่แชร์ร่วมกัน

### กรณีการใช้งาน (Use Cases)
* ใช้เพื่อสำรวจข้อมูลและระบุรูปแบบ (Patterns) หรือแนวโน้ม (Trends)
* ใช้เพื่อฝึกโมเดล Machine Learning
* ใช้เพื่อทำการทำนายผลแบบกลุ่ม (Batch Predictions) กับข้อมูลใหม่ๆ
