# Amazon Bedrock Flows Cheat Sheet

**Amazon Bedrock Flows** เป็นฟีเจอร์หลักสำหรับการสร้างแอปพลิเคชัน Generative AI ที่ซับซ้อนและพร้อมใช้งานในระดับ Production โดยระบบจะช่วยลดความยุ่งยากในการเขียนโค้ดเพื่อเชื่อมต่อบริการต่างๆ การจัดการสถานะ (State Management) และการทำ Pipeline การ Deploy ให้กลายเป็นอินเทอร์เฟซแบบลากวาง (Visual Interface) หรือเรียกใช้งานผ่าน API ช่วยให้ทีมพัฒนาและผู้เชี่ยวชาญเฉพาะด้านสามารถทำงานร่วมกันและสร้างเวิร์กโฟลว์ AI ที่ขยายขนาดได้ภายในไม่กี่นาที

### คุณสมบัติของ Amazon Bedrock Flows
* **Visual Builder (Low-Code/No-Code):** ออกแบบเวิร์กโฟลว์ด้วยการลากและวางใน **Amazon Bedrock Studio** เชื่อมต่อโหนด (Nodes) ต่างๆ เช่น Prompt, โมเดลพื้นฐาน (FMs), Knowledge Bases และ AWS Lambda เพื่อกำหนดตรรกะทางธุรกิจโดยไม่ต้องเขียนโค้ดเชื่อมต่อเอง
* **การรวมส่วนประกอบที่หลากหลาย:** เชื่อมต่อองค์ประกอบหลักของ Bedrock (FMs, Prompts, Knowledge Bases, Guardrails, Agents) และบริการ AWS อื่นๆ (Lambda สำหรับตรรกะเฉพาะ, S3 สำหรับเก็บข้อมูล, Lex สำหรับแชทบอท)
* **การควบคุมตรรกะ:** มีโหนดสำหรับการทำซ้ำ (Iterator), การรวบรวมข้อมูล (Collector) และโหนดเงื่อนไข (Condition) เพื่อจัดการลูป การรวมข้อมูล และการแยกสาขาการทำงาน
* **การทดสอบและทำเวอร์ชันในตัว:** * **Test Iteratively:** รันและ Debug Flow ได้โดยตรงบน Console พร้อมตรวจสอบ Input/Output ของแต่ละโหนด
    * **Versioning:** สร้าง Snapshot ของเวอร์ชันเพื่อการทำ Rollback, การทำ A/B Testing และการ Deploy ตามขั้นตอน (Staged Promotion)
* **Serverless Execution:** Deploy โดยการเผยแพร่เวอร์ชันและเรียกใช้ผ่าน **InvokeFlow API** โดยไม่ต้องเตรียมหรือจัดการโครงสร้างพื้นฐานเอง

---

### กรณีการใช้งาน (Use Cases)
* **การประมวลผลและสรุปเนื้อหาอัตโนมัติ:** สร้าง Flow ดึงเอกสารจาก S3, ใช้โหนด Iterator เพื่อสรุปเอกสารแต่ละฉบับด้วย FM, รวบรวมผลลัพธ์ และเขียนรายงานสรุปกลับไปยัง S3
* **ระบบสนับสนุนลูกค้าอัจฉริยะ:** เมื่อมีคำถามจากลูกค้า ระบบจะสั่งค้นหาข้อมูลใน Knowledge Base, ส่งบริบทให้โมเดลสร้างคำตอบ, ตรวจสอบความปลอดภัยด้วย Guardrail และเรียกใช้ Lambda เพื่อเปิดตั๋วสนับสนุน (Support Ticket) หากจำเป็น
* **การสร้างรายงานจากข้อมูล:** ดึงข้อมูลตัวเลขยอดขายจากฐานข้อมูล, ใช้ FM วิเคราะห์แนวโน้มและสร้างบทวิเคราะห์, จัดรูปแบบผลลัพธ์ และส่งรายงานรายสัปดาห์ผ่านอีเมลหรือพอร์ทัลของบริษัทโดยอัตโนมัติ

---

### การนำไปใช้งาน (Implementation)
* **สถาปัตยกรรมแบบโหนด (Node-Based):** Flow คือกราฟของโหนด (Processing units) ที่เชื่อมต่อกันด้วยเส้น (Edges) เริ่มต้นจากโหนด Input ผ่านโหนดประมวลผล (เช่น Lambda) ไปจนถึงโหนด Output
* **วงจรการทำงาน (Workflow Lifecycle):**
    1. **Design:** ลากและวางโหนดใน Visual Builder
    2. **Test & Iterate:** ใช้ฟังก์ชัน "Prepare" เพื่อทดลองการเปลี่ยนแปลงและตรวจสอบ Trace ในแต่ละโหนดเพื่อ Debug
    3. **Version:** "Publish" เพื่อสร้างเวอร์ชันที่แก้ไขไม่ได้ (Immutable version) สำหรับเรียกใช้ผ่าน API
    4. **Deploy & Invoke:** สร้าง **Alias** (เช่น Prod) เพื่อชี้ไปยังเวอร์ชันที่ต้องการ และให้แอปพลิเคชันเรียกใช้ผ่าน **InvokeFlow API**

### ความปลอดภัย (Security)
* **IAM Permissions:** Flow ต้องใช้ IAM Role ที่มีสิทธิ์เฉพาะเจาะจงสำหรับบริการที่ไปเชื่อมต่อ (เช่น `bedrock:InvokeModel`, `lambda:InvokeFunction`) โดยยึดหลัก Least Privilege
* **Data Isolation:** ทำงานในสภาพแวดล้อม Serverless ที่ปลอดภัย ข้อมูลระหว่างโหนดได้รับการปกป้อง และคุณเป็นผู้ควบคุมการจัดเก็บข้อมูลผ่านการตั้งค่าโหนด
* **Auditing:** การสร้าง, เผยแพร่ หรือเรียกใช้ Flow จะถูกบันทึกใน **AWS CloudTrail** เพื่อการตรวจสอบย้อนหลัง

### แนวทางปฏิบัติที่ดีที่สุด (Best Practices)
* **เริ่มจากจุดเล็กๆ:** เริ่มต้นด้วย Flow ง่ายๆ 3-4 โหนดเพื่อทำความเข้าใจการส่งข้อมูล และใช้ระบบ **Traceability** ตรวจสอบ Input/Output ในทุกขั้นตอน
* **จัดการเวอร์ชันด้วย Alias:** ใช้ Alias (เช่น Dev, Staging, Prod) เพื่อชี้ไปยังเวอร์ชันที่ใช้งานจริง ช่วยให้การสลับเวอร์ชันหรือทำ Rollback ทำได้ทันที
* **ประหยัดต้นทุนด้วยการออกแบบโหนด:** เนื่องจากค่าบริการคิดตาม **Node Transition** (การเปลี่ยนโหนด) ควรออกแบบ Flow ให้มีประสิทธิภาพ เช่น ใช้โหนด Iterator จัดการรายการข้อมูลภายใน Flow เดียว แทนการเรียก API แยกทีละรายการจากภายนอก
* **กำหนดพารามิเตอร์เพื่อใช้ซ้ำ:** ใช้โหนด Input เพื่อส่งตัวแปร (เช่น Customer ID, วันที่) เข้าไปใน Flow เพื่อให้เทมเพลตเดียวสามารถใช้งานได้ในหลายสถานการณ์

### ค่าบริการ (Pricing)
คิดตามการใช้งานจริง (Consumption-based) โดยมี 2 ส่วนหลัก:

| ส่วนประกอบ | สิ่งที่คุณจ่าย | รายละเอียดและตัวอย่าง |
| :--- | :--- | :--- |
| **Flow Execution** | **Node Transitions** | **$0.035 ต่อ 1,000 การเปลี่ยนโหนด** (นับทุกครั้งที่โหนดถูกรัน) |
| **AWS Services** | **การใช้ทรัพยากร** | ราคามาตรฐานของบริการที่ถูกเรียก (เช่น ค่า Token ของ FM, ค่าเรียกใช้งาน Lambda, ค่าเก็บข้อมูล S3) |

**ตัวอย่างการคำนวณ:**
หาก Flow สร้างรายงานรัน 20 ครั้งต่อเดือน แต่ละครั้งผ่าน 15 โหนด
* ค่า Node Transition: 20 ครั้ง * 15 โหนด * ($0.035 / 1000) = **$0.0105**
* ค่าใช้จ่ายรวม: $0.0105 + ค่า Token ของโมเดล + ค่า Lambda ฯลฯ ที่เกิดขึ้นในโหนดเหล่านั้น
