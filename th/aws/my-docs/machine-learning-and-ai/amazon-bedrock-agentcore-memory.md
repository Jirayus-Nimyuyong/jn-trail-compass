# Amazon Bedrock AgentCore Memory Cheat Sheet

**Amazon Bedrock AgentCore Memory** เป็นบริการแบบ Managed ที่ช่วยให้เอเจนท์ AI สามารถจัดเก็บ เรียกใช้ และคงบริบท (Context) ของการสนทนาไว้ได้ ช่วยให้เอเจนท์จำข้อมูลผู้ใช้ ความชอบ และประวัติการโต้ตอบ เพื่อการตอบสนองที่ต่อเนื่องและเป็นส่วนตัวมากขึ้น

### การทำงานของระบบความจำ (How Memory Works)
* **การจัดเก็บและการเรียกใช้:** ระบบจะจับข้อมูลที่เกี่ยวข้องจากการสนทนาโดยอัตโนมัติ เมื่อเอเจนท์ต้องการบริบท จะทำการคิวรีความจำเพื่อดึงข้อมูลในอดีตมาใช้ โดยใช้การค้นหาเชิงความหมาย (Semantic Search) เพื่อหาความจำที่เกี่ยวข้องที่สุดกับบทสนทนาปัจจุบัน
* **ความจำระยะสั้น vs. ระยะยาว:**
    * **ความจำระยะสั้น (Short-term):** จัดการบริบทภายในเซสชันเดียว เพื่อให้การคุยโต้ตอบยาวๆ มีความสอดคล้องกัน
    * **ความจำระยะยาว (Long-term):** คงอยู่ข้ามหลายเซสชัน ช่วยให้เอเจนท์จำผู้ใช้และความชอบได้นานเป็นวัน เป็นสัปดาห์ หรือเป็นเดือน
* **การจัดระเบียบความจำ:** แบ่งตามหัวข้อสนทนา (Thread), ID ผู้ใช้ หรือหมวดหมู่ที่กำหนดเอง โดยแต่ละข้อมูลจะประกอบด้วยเนื้อหา, Metadata (เวลา, แหล่งที่มา) และแท็กความเกี่ยวข้อง

---

### ประเภทของความจำ (Memory Types)
* **Conversation Memory (ความจำการสนทนา):** เก็บประวัติการโต้ตอบเพื่อให้เอเจนท์อ้างอิงถึงสิ่งที่คุยไปก่อนหน้าได้ สามารถตั้งค่าได้ว่าจะให้จำย้อนหลังไปกี่ลำดับ (Turns)
* **User Profile Memory (ความจำโปรไฟล์ผู้ใช้):** เก็บข้อมูลถาวรเกี่ยวกับผู้ใช้ เช่น ความชอบส่วนตัว และรูปแบบพฤติกรรม เพื่อให้เอเจนท์ปรับแต่งการบริการให้เข้ากับบุคคลนั้นๆ โดยระบบจะอัปเดตข้อมูลนี้อัตโนมัติเมื่อเรียนรู้สิ่งใหม่เกี่ยวกับผู้ใช้
* **Knowledge Memory (ความจำความรู้):** เก็บข้อมูลข้อเท็จจริง แนวคิดที่เรียนรู้ หรือข้อมูลที่ค้นพบ เพื่อให้เอเจนท์นำไปใช้อ้างอิงในอนาคต ช่วยเพิ่มพูนความเชี่ยวชาญของเอเจนท์เมื่อเวลาผ่านไป
* **Custom Memory Schemas:** กำหนดโครงสร้างความจำเองด้วย JSON Schema สำหรับงานเฉพาะทาง เช่น รายละเอียดโปรเจกต์ หรือรายการงาน (Task lists)

---

### การนำไปใช้งาน (Implementation)
* **การเปิดใช้งาน:** เปิดใช้ผ่านคอนโซลหรือ API โดยกำหนดนโยบายการเก็บรักษาข้อมูล (Retention), ขีดจำกัดพื้นที่จัดเก็บ และการควบคุมความเป็นส่วนตัว
* **การเพิ่มข้อมูล:** เอเจนท์จะเพิ่มข้อมูลลงความจำโดยอัตโนมัติตามกฎที่ตั้งไว้ หรือผู้พัฒนาสามารถเพิ่มข้อมูลเองผ่าน API เพื่อโหลดข้อมูลเริ่มต้น (Initial data)
* **การตั้งค่าการเรียกใช้:** กำหนดเกณฑ์ความเกี่ยวข้อง (Relevance thresholds) และพารามิเตอร์การค้นหา เพื่อให้เอเจนท์ดึงความจำมาใช้ได้อย่างแม่นยำและรวดเร็ว
* **นโยบายการลบข้อมูล (Eviction Policies):** กำหนดกฎการลบข้อมูลเก่าหรือไม่เกี่ยวข้องออกโดยอัตโนมัติ ตามประเภทความจำ ความสำคัญ หรือข้อจำกัดของพื้นที่จัดเก็บ

---

### การเชื่อมต่อและความปลอดภัย (Integration & Security)
* **Multi-Agent Sharing:** แชร์ความจำระหว่างเอเจนท์ที่ทำงานเกี่ยวข้องกับผู้ใช้คนเดียวกัน โดยมีนโยบายควบคุมว่าข้อมูลใดที่แชร์ได้บ้าง
* **การเชื่อมต่อภายนอก:** เชื่อมต่อกับฐานข้อมูลภายนอกหรือระบบ CRM เพื่อเสริมบริบทข้อมูล และรองรับการซิงค์ข้อมูลแบบสองทิศทาง
* **ความปลอดภัย:** * **การเข้ารหัส:** เข้ารหัสข้อมูลที่จัดเก็บด้วย AWS KMS และเข้ารหัสขณะรับส่งด้วย TLS
    * **Access Control:** ใช้ IAM Policies ควบคุมสิทธิ์เอเจนท์ในการอ่าน/เขียนความจำ และมีการบันทึก Audit Log ทุกครั้ง
    * **Privacy:** รองรับมาตรฐาน GDPR, CCPA โดยมีฟีเจอร์ลบข้อมูลอัตโนมัติ (Data expiration) และการทำให้ข้อมูลเป็นนิรนาม (Anonymization)

---

### แนวทางปฏิบัติที่ดีที่สุด (Best Practices)
* **การออกแบบ:** สร้าง Schema ที่รักษาสมดุลระหว่างรายละเอียดข้อมูลกับประสิทธิภาพในการดึงข้อมูล และใช้การทำเวอร์ชัน (Versioning) เพื่อรองรับการอัปเดตโครงสร้างข้อมูล
* **การเพิ่มประสิทธิภาพ:** ตรวจสอบการเติบโตของพื้นที่จัดเก็บและทำระบบ Archive สำหรับบทสนทนาที่เก่ามาก รวมถึงใช้การแคช (Caching) สำหรับความจำที่ถูกเรียกใช้บ่อย
* **การจัดการคุณภาพ:** ตรวจสอบความถูกต้องของความจำอย่างสม่ำเสมอ และมีกลไกรับข้อเสนอแนะ (Feedback) เพื่อแก้ไขความจำที่ผิดพลาด

---

### ค่าบริการ (Pricing)
* **รูปแบบการใช้งานจริง (Usage-Based):** คิดราคาเป็นส่วนหนึ่งของบริการ Amazon Bedrock AgentCore โดยจ่ายตามปริมาณพื้นที่จัดเก็บ (Storage volume) และจำนวนครั้งในการอ่าน/เขียนข้อมูล (Read/Write operations)
* **ไม่มีค่าใช้จ่ายล่วงหน้า:** ไม่ต้องมีการผูกมัดหรือจ่ายขั้นต่ำ โดยสามารถตรวจสอบรายละเอียดค่าใช้จ่ายทั้งหมดได้ผ่าน AWS Cost Explorer
